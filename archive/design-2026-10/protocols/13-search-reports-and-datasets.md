# 搜索、报表与分析的数据供给

> 状态：2026-10-13 数据协议第十三份候选，尚未冻结。承接 C25（搜索、报表、分析），以及 D52（标准内置基础报表，自助 BI 按需选配）、D15（发生时归属与当前责任分开）、D29（用户任务按当前授权交付）与[报表、看板与自助分析的选择](../replacements/analytics-and-reporting.md)；按 D59 从零设计。

## 本页解决什么

报表、看板、自助 BI 与全局搜索都要读很多组件的数据，又不能越过组件边界直接读别人的表。本页回答：

1. 它们读什么？谁拥有这份数据、口径与版本？
2. 数据有延迟与缺口时，报表怎样如实说明“截至何时、是否完整”？
3. 行、字段、汇总、下钻、导出、订阅怎样都按当前授权？
4. 重查询怎样不拖慢在线交易？

## 方案比较

| 路线 | 判断 |
| --- | --- |
| 推荐：组件发布声明的**数据集**（投影），报表、BI 与搜索只读数据集；指标有属主与版本；完整水位与新鲜度显示在结果上；授权在查询时按当前授予编译 | 不跨边界读表；口径一致可核对；权限变化立即生效；分析负载与交易分开 |
| 报表直接查各组件的业务表 | 实现快，但跨库读别人的表违反组件边界；每个报表重新解释口径；重查询拖慢交易 |
| 先建完整数据仓库与管道 | 能力全面，但小客户要多维护一整套服务；不作为标准最低组合（D52） |
| BI 工具直连数据集、用工具自己的权限 | 工具的行级权限各不相同，用户可编辑查询时容易绕过；只作为受限的选配路线 |

## 数据集

**数据集**是一个组件为报表、分析与搜索发布的读取契约，以[协议 02](02-projections.md) 的投影方式维护。

| 声明项 | 说明 |
| --- | --- |
| 数据集 ID 与版本 | 属主组件命名；结构变化按契约演进规则（只追加；破坏性变化发新主版本并行一段时间） |
| 粒度 | 一行代表什么（一张订单、一条订单明细、一天一个产品的库存） |
| 列 | 名称、类型、字段类别（普通或受限，[安全 09](../security/09-encoding-and-profiles.md)）、单位与币种列 |
| 授权维度列 | 资源定义中声明的数据范围维度（法人、组织路径、负责人等），每行都带，用于查询时编译授权 |
| 时间语义 | 业务日期、记账期间、发生时刻；发生时的组织与当前组织分别成列（D15） |
| 更正方式 | 更正以新版本行或调整行表达；数据集声明哪一种 |
| 冷数据覆盖 | 是否包含已转层的单元（[协议 11](11-tiering.md)）；包含时按目录读取 |
| 时效等级 | 近实时（分钟级）、日批、按需重建 |
| 保留与擦除 | 跟随源数据的保留类别；擦除事件同步到数据集 |

数据集的存储默认在同一 PostgreSQL 实例中的独立分析库或 schema，由一个只读取数据集的报表服务访问；数据量或查询负载超过预算时，换到独立的分析库或分析引擎，数据集的契约不变。

## 指标

- 指标有 ID、版本、属主、定义（来源数据集、过滤、聚合、粒度、时间口径、币种与单位换算、退款与更正处理）。同名指标只有一个定义；新定义是新版本，报表标明使用的版本。
- 正式财务数字（余额、损益）只来自财务的账簿数据集；业务报表中的“销售额”等与财务数字不同时，说明口径差异，不悄悄对齐。
- 指标声明是否**敏感**（例如薪资、个人业绩）；敏感指标的分组人数少于最小分组数时不显示该组。

## 新鲜度与完整水位

每个数据集维护两个值：

- **完整水位**：在此之前（按源的序号或事件时间）的变化已经全部应用，没有缺口；
- **最新事件时间**：已应用的最新变化的时间。

报表与看板显示“数据截至”时使用完整水位，不使用最新事件时间：最新事件时间不能证明之前没有缺口（参考模型的“按已见最新时间显示”坏变体）。数据集的投影状态不完整时（协议 02），报表显示“数据可能不完整”，而不是空白或旧数字。

## 授权

### 行与字段

- 查询时取用户**当前**的完整授予，按[安全 07](../security/07-finite-expressions-containment-and-queries.md) 编译为数据集授权维度列上的谓词，与报表的筛选一起下推；受限字段按命中位图逐行掩码。
- 不在写入数据集时按当时的权限预先决定谁能看：权限之后变化，预先决定的结果就错了（参考模型的“按索引时的范围”坏变体）。
- 合计、排行、筛选项的候选值，都只基于用户可见的行计算。

### 汇总与下钻

- 汇总只包含可见行；敏感指标按最小分组数抑制。
- 下钻到明细时重新按当前授权查询；明细中的链接打开原组件页面，由原组件再检查。

### 导出与订阅

- 导出是后台工作项（[协议 01](01-background-work.md)），执行时与交付时都按发起人当前的授权（D29）；文件按[协议 12](12-attachments-and-object-storage.md) 的导出对象处理，只有发起人可领取。
- 订阅（定时发送的报表）在每次发送时按**收件人**当前的授权生成内容，不按创建者的范围（参考模型的“按创建者范围”坏变体）；收件人没有任何可见数据时发送“无可见数据”，不发送创建者能看到的内容。发送经通知（[协议 10](10-external-integration.md#通知)），默认是链接；带附件时附件同样按收件人生成。

### 自助 BI

选配的 BI 工具不直接持有数据集的全部读取权：

| 路线 | 做法 | 适用 |
| --- | --- | --- |
| 推荐：经数据集查询服务 | BI 通过项目适配器查询；适配器带上当前用户身份，按上面的规则编译授权后执行 | 用户可编辑查询、需要明细时 |
| 嵌入式看板 | 项目页面签发带用户过滤条件的嵌入令牌，BI 按令牌过滤 | 只看固定看板、BI 支持带过滤的嵌入时；按工具实际能力验收 |
| 只开放汇总数据集 | BI 只连接声明为“无受限行列”的汇总数据集 | BI 无法传递用户身份时 |

单点登录、隐藏菜单都不证明数据已经隔离。

## 搜索

- 全局搜索的索引是每个组件发布的搜索数据集：可搜索的文本字段、显示摘要字段（带字段类别）、授权维度列、指向原组件页面的链接。
- 查询时同样按当前授予过滤；摘要中的受限字段掩码。索引可能落后于原数据：结果打开时由原组件再检查，可能显示“已不存在或无权查看”，这是允许的。
- 删除与擦除以墓碑同步到索引；已转层的数据默认不进入全局搜索，需要时在历史查询中按目录读取。
- 引擎：标准组合使用 PostgreSQL 全文检索；中文分词需要扩展或按字符 n-gram 建索引，选型在代表部署实验中测量。客户数据量与查询需求超过预算时，按同一搜索数据集契约换用专门的搜索引擎。

## 资源隔离

- 报表与搜索只读数据集，不读组件的业务表。
- 报表服务有自己的连接池、并发上限、单次查询的超时与扫描上限；超过上限的查询转为后台导出或返回“范围过大”。
- 同一数据库实例时，用独立的数据库与角色、语句超时与资源上限隔离；预算不够时，用只读副本或独立分析库。外壳合并不取消这些上限。

## 重建与历史

- 数据集可以从属主的完整快照重建（协议 02）；历史部分从冷数据按目录读取（协议 11）。
- 关账后的财务报表以账簿在关账时的快照为准；之后的调整在新期间显示，不改写已关期间的报表结果（[协议 06](06-period-close.md)）。

## 参考模型

[数据集与搜索模型](../work/checks/25-datasets-and-search.py)（种子 20261013，3,000 次运行）：源事件乱序、有缺口地进入数据集，用户的范围随时变化，同时有搜索、带水位的报表与订阅发送。

| 检查 | 结果 |
| --- | --- |
| 用户收到的每一行都在其查询时的范围内 | 成立 |
| 报表声称“截至 t 完整”时，t 之前的变化都已应用 | 成立 |
| 订阅只发送收件人发送时范围内的行 | 成立 |
| 敏感汇总不对少于最小分组数的组显示 | 成立（这一项检查的是规则本身是否执行） |

4 个坏变体首轮全部被发现：按索引时的范围决定访问、按已见最新时间显示水位、按创建者范围生成订阅、不抑制少量分组。模型不是报表服务、搜索引擎或 BI 工具的运行结果。

## 独立预期

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| DS01 | 报表需要订单与库存的数据 | 读两个组件各自发布的数据集，不读业务表 |
| DS02 | 两张报表使用同名指标 | 同一个定义与版本 |
| DS03 | 业务销售额与财务收入不同 | 说明口径差异，不悄悄对齐 |
| DS04 | 数据集有缺口 | “数据截至”停在缺口之前 |
| DS05 | 投影不完整 | 显示“数据可能不完整” |
| DS06 | 用户权限收窄后刷新报表 | 立即只显示新范围内的数据 |
| DS07 | 受限字段 | 逐行掩码；合计不包含不可见行 |
| DS08 | 薪资汇总中某部门只有两人 | 不显示该组 |
| DS09 | 从汇总下钻到明细 | 按当前授权重新查询 |
| DS10 | 撤权后领取之前发起的导出 | 按当前授权，拒绝或重新生成 |
| DS11 | 订阅由经理创建、发给普通员工 | 按员工的范围生成 |
| DS12 | 收件人没有可见数据 | 发送“无可见数据” |
| DS13 | BI 用户编辑自定义查询 | 经数据集查询服务按当前授权执行 |
| DS14 | BI 工具无法传递用户身份 | 只能连接汇总数据集 |
| DS15 | 搜索结果打开时已无权 | 原组件拒绝并显示无权或不存在 |
| DS16 | 记录被擦除 | 搜索索引同步删除 |
| DS17 | 查询扫描超过上限 | 转为后台导出或返回范围过大 |
| DS18 | 历史组织变化后的业绩报表 | 按指标声明使用发生时组织或当前组织 |
| DS19 | 关账后调整 | 已关期间的报表不变，调整显示在新期间 |
| DS20 | 数据集从同库换到独立分析引擎 | 契约不变，报表不需修改 |
