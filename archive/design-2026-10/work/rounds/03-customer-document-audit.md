## 发现与修正

此前只把 IAM 扩成完整介绍样例，其他多篇仍只写“业务能力”“引擎”“换实现”，客户不能直接判断谁替换谁。统一介绍要求存在，不代表所有专篇已满足。

本轮逐篇补齐 12 个选型专篇的对象定位。实际组件写完整 ID 与仓库；资源、SDK 适配器、协作扩展、内部策略和部署选择分别定位；新身份未定或没有第二成员时明确说明，不虚构替代仓库。原有业务权威、安全、迁移与恢复要求继续保留。

用户随后指出部分关系是多选。展示图增加统一选择方式与作用范围：单选实现、多选并存、按范围单选／跨范围并存、多选协作与模型组合。渠道图直接标多选与路由，前端图分入口选择，薪资新增法人范围图，内置报表与自助 BI 标明可并存；必需依赖、业务控制与实现状态仍保留，虚实线与颜色不承担互斥含义。

授权专篇按“需求类型／模型 → 实现成员 → 场景选择 → 装配绑定 → 管理与部署 → 迁移 → 依据”重组。RBAC、范围、属性条件、字段、ACL 与 ReBAC 可以组合；标准／静态／OpenFGA 是已有或计划的成员路线，策略引擎、嵌入库及客户定制另标评估或定制状态。既有共同安全目标不降低，不因列出 OPA／Cedar 等候选就批准开发或登记身份。

## 依据与独立判断

读取项目权限与组件决定、既有族契约与 SDK 资料；知识库授权比较及 D7／D8／D10 提醒模型组合与执行落点。知识库为中立参考，本项目保持独立 provider 契约、受限管理和部署时合并的目标，不照搬其默认部署选择或时间数字。

核对 OpenFGA 授权概念、OPA 过滤／部分求值、Cedar 概念与 Casbin 概述的一手资料。OPA 已有过滤／部分求值路径，比较不能笼统断言所有策略引擎只有布尔 Check；转换子集、字段、查询与安全仍由项目验收。Cerbos 的所查 Query Plan 地址未取得正文，本次只保留评估名称，不据此作具体功能判断。Metabase／Superset 的官方嵌入与安全资料仅用于核对现有 BI 评估边界，不新增购买／支持承诺。

本轮没有因此认定知识库错误或平台 bug，也没有修改外部仓库、SDK、契约、运行锁、资源与注册表。
