# 时间与日历

项目怎么存储和传输时间、一张单据属于哪一天、由谁的时区决定、会计期间和会计年度怎么定义。加日期或时间戳列、写提到"今天"的 SQL、往期间里记账、给事件或契约加日期之前，先读这篇。

## 范围

覆盖：瞬时与业务日期、法人的业务时区、数据库会话时区、"今天"怎么进到 SQL 里、事件里的业务日期、会计期间与会计年度、日期怎么显示。不覆盖：截止时间与超时（[16-deadlines-and-retries.md](16-deadlines-and-retries.md)）；保留期与分区窗口（[09-data-lifecycle.md](09-data-lifecycle.md)）；作为数据维度的法人（[07-tenancy.md](07-tenancy.md)）。

## 选择

两种时间，绝不混用：

- **瞬时**是时间轴上的一点（`created_at`、`posted_at`、`confirmed_at`）。存成 `timestamptz`，用 UTC 传输。
- **业务日期**是单据所属的那一天（单据日期、过账日期、到期日、价格生效日）。存成 `DATE`，以 `YYYY-MM-DD` 传输，从不在时区之间换算。

以及把两者联系起来的规则：

- **业务时区属于法人**：一个 IANA 名字，默认 `Asia/Shanghai`。业务日期就是某个瞬时在该法人时区下的日历日期。
- **会计年度起始月属于法人**：默认 1（一月）。会计期间是带起止日期的行。
- **数据库会话时区永远是 UTC。** 业务 SQL 从不问数据库今天是几号；SDK 替法人算出"今天"，作为参数传进去。
- **事件带上它那张单据的业务日期。** 消费方按这些日期记账，绝不按它处理事件的时刻。
- **开会计年度是一条命令**，不是每年一份迁移：它为一个法人按起始月建出这一年的期间（以及对应的分区）。
- **显示**：业务日期原样显示。瞬时按法人时区显示，并标明时区。没有按用户的时区偏好（[0404](../02-decisions/04-frontend/0404-four-user-preferences.md)）。

**状态**：已定；随 3.0.0 统一升级落地。法人及其日历属性来自 mdm/org，这是本轮新建的组件，在其他组件升 3.0.0 之前建成；`BUSINESS_TIMEZONE` 仍是部署级默认值，Cron 计划按它求值（[19](19-background-jobs.md)）。今天 erp/finance 用 UTC 的处理时刻作过账日期，erp/sales 拿数据库的 `CURRENT_DATE` 判断价格生效日；两者都是已知 bug，在统一升级里修复（[已知限制](#已知限制)）。

## 端口契约

### 列类型

| 什么 | 列 | 例子 |
|---|---|---|
| 瞬时 | `timestamptz` | `created_at`、`posted_at` |
| 业务日期 | `date` | `document_date`、`posting_date`、`due_date`、`date_start`、`date_end` |
| 会计期间 | 一行：法人、会计年度、期间号、`start_date date`、`end_date date`（闭区间）、标签、状态 | 标签 `2026-10` 只用于显示 |

### 线上

| 什么 | proto | REST 与事件 |
|---|---|---|
| 瞬时 | `google.protobuf.Timestamp` | 带 `Z` 的 UTC RFC 3339：`2026-10-01T23:30:00Z` |
| 业务日期 | `google.type.Date` | `"2026-10-02"`（OpenAPI `format: date`） |

业务日期绝不以"午夜的瞬时"传输：哪个时区的午夜，正是业务日期要消除的那个歧义。

### 法人日历

| 属性 | 类型 | 默认值 | 放在哪里 |
|---|---|---|---|
| 业务时区 | IANA 时区名 | `Asia/Shanghai` | mdm/org 里的法人 |
| 会计年度起始月 | 整数 1–12 | 1 | 法人的日历，由开会计年度命令设定 |

换算 `业务日期 = （瞬时）在（法人时区）下的日历日期` 在每个官方 SDK 里只有一份实现，由共享向量校验。它处理夏令时；从不交给数据库去做。每个 SDK 都 MUST 内嵌自己的时区数据（Go 用 `time/tzdata`，Python 用 `tzdata` 包，Node 用 full ICU），所以答案从不取决于镜像里的时区文件；法人只存规范的 IANA 名称，从不存 `Asia/Calcutta` 这类别名。

**没有 mdm/org 时（降级模式）。** 没装 mdm/org 时（`MDM_ORG_ENDPOINT` 不存在），组件不崩溃：每个法人都用 `BUSINESS_TIMEZONE` 作时区、会计年度起始月为 1，运行时在 `/_be/info` 里标出日历处于降级状态。装上 mdm/org 之后，它的法人日历取代这些值。

### SQL

- 连接的 `TimeZone` 是 UTC，在会话级和事务级都从不修改。
- 业务 SQL 不用 `CURRENT_DATE`、`now()::date`、`date_trunc(…, now())`，也不对 `timestamptz` 用 `::date`。"今天"和每一个业务日期边界都由 SDK 算出、作为参数传入。有门禁扫描迁移和 repo SQL 里的这些写法。
- `DATE` 只和 `DATE` 比较。把 `DATE` 和 `timestamptz` 比较，会把日期转成会话时区下的午夜，这正是[已知限制](#已知限制)里那个月末 bug。
- 要选出落在某个业务日期范围里的瞬时，SDK 把 `[第一天, 最后一天]` 换算成法人时区下的半开瞬时区间 `[start, end)`，传两个 `timestamptz` 参数。

### 事件

- 每个关于带日期单据的事件，都在 payload 里带上这张单据的业务日期字段（`document_date`、`posting_date`……），作为可选字段新增（[0302](../02-decisions/03-contracts-and-data/0302-contracts-are-additive-only.md)）。
- 按日期记账的消费方使用这些字段。旧事件没有这些字段时，退回到"事件发生时刻在法人时区下的业务日期"，绝不退回到它处理事件的时刻。所以从死信队列跨月重放的事件，仍然记进原来的期间。

### 会计期间

- 过账按 `start_date <= business_date AND business_date <= end_date` 找期间，两边都是 `DATE`，限定在单据的法人内。
- 期间标签不用于查找：会计年度从四月开始时，标签 `2026-04` 是 2026/27 会计年度的第一期。
- 开会计年度的参数是法人、会计年度，第一次还要给起始月；它是幂等的，并报告建了哪些期间。

## 备选方案

| 问题 | 选项 |
|---|---|
| 由谁的时区决定是哪一天 | 用户的（SaaS 常见）；公司的（ERP 常见：一张单据对所有人是同一天）；服务器的；UTC |
| 在哪里换算 | 数据库会话时区；应用里按法人换算 |
| 业务日期怎么存 | `DATE`；午夜的 `timestamptz`；文本 |
| 会计年度怎么定义 | 只按自然月；起始月可配；13 期；4-4-5 周历。主流 ERP 用带日期区间的期间表 |

## 为什么选它

- **一张单据，一个日期，对所有人都一样。** 一张 10 月 1 日的销售订单，对仓库、对财务、对审计都是 10 月 1 日，不管他们在哪里。
- **法人可能在不同国家。** 集团多公司现在就在范围内，海外客户也在路线图上，所以时区不能永远是部署级的常量。
- **共享池上的会话状态不可靠。** 外壳里很多成员共用连接；会话级的 `SET TIME ZONE` 和不带 `LOCAL` 的 `SET` 是同一类雷。
- **`DATE` 没有时区**，所以不会被一次没人注意到的换算挪动。
- **带日期区间的期间行**能表达任何会计日历，包括不从一月开始的年度。

## 为什么不选其他

- **用户时区**：两个用户会看到同一张凭证在不同的日期，单据落进哪个期间还取决于是谁在看。
- **按法人设数据库会话时区**：池化连接上的会话状态，而且一个外壳同时服务好几个法人。
- **午夜的 `timestamptz`**：在另一个时区读出来就差一天；这本身就是 bug，而不是一种表示法。
- **只按自然月**：表达不了四月开始的会计年度，而且标签 `2026-04` 会误导人。

## 什么时候换

- **某个法人需要 13 期或 4-4-5 周历**：期间行本来就带日期区间；开会计年度命令新增一个日历模式参数，只增不破。
- **用户需要按自己的时区看瞬时**：只是前端的显示偏好，意味着要重新讨论 0404。业务日期保持不变。
- **某个法人换了时区**：是一次数据变更，不是设计变更（见下）。

## 怎么换

- **法人的时区**：在 mdm/org 里改这个法人的时区。此后算出的业务日期用新时区；已有单据保留原来的日期。
- **会计年度起始月**：在开下一个会计年度时传入。已经开过的年度不变。
- 两种情况都不改组件代码：组件向 SDK 要业务日期，按日期查期间。

## 一致性测试

共享向量放在 `be-protocol` 的 `vectors/calendar/`（`business_date.json`、`bounds.json`、`fiscal.json`）：瞬时加时区得出业务日期，包括夏令时边界（例如 `America/New_York`）以及北京时间 00:00–08:00 这段在 UTC 下属于前一天的时间。每个官方 SDK 都必须给出相同答案。每个向量文件写明它的期望值是按哪个时区数据版本算的；时区数据一变，先重新生成向量并跨语言交叉核对，SDK 才内嵌新版本。

要先写红的测试：

- erp/finance：月末最后一天下午的过账记进当月；北京时间 10 月 1 日 07:30 的过账记进 10 月；自动凭证按事件的 `posting_date` 记账，不按消费的时刻；月份关账之后重放的旧事件记进它原来的期间。
- erp/sales：10 月 1 日生效的价格从北京时间午夜起生效，而不是 08:00。
- SDK：跨夏令时切换的业务日期换算；同一瞬时下两个不同时区法人的"今天"。
- 门禁：迁移或 repo 查询里出现 `CURRENT_DATE`、`now()::date` 或对 `timestamptz` 用 `::date` 时，`make gates` 失败。

## 已知限制

- **mdm/org 是 3.0.0 统一升级的前提**：它发布之前，没有组件按法人日历记账。mdm/org 里的法人与 IAM 目录里的部门如何划分，在 mdm/org 自己的设计里定。
- **没有 mdm/org 时所有法人共用一份日历**：`BUSINESS_TIMEZONE` 加一月起始的会计年度，在 `/_be/info` 里标出。
- **改法人的时区不会重新给历史定日期**；单据保留它们当初拿到的业务日期。
- **开会计年度命令目前只生成按月的会计日历**；13 期和 4-4-5 日历要等日历模式参数。
- **统一升级之前还有两个已知 bug**：erp/finance 用 UTC 的处理时刻作过账日期，并把 `DATE` 和 `timestamptz` 比较，所以每月最后一天 UTC 00:00 之后的过账记进下个月，北京时间 00:00–08:00 的过账记到前一天，延迟或重放的事件记进它被处理时所在的期间；erp/sales 用数据库在 UTC 下的 `CURRENT_DATE` 判断价格生效日，所以 10 月 1 日生效的价格要到北京时间 08:00 才生效。
