# 种子数据清单

给本地开发与手工验证用的演示数据：每个组件灌了什么、多少、归谁，以及各测试账号能看到什么。它从不进入任何部署：种子命令只手工运行，不出现在任何部署脚本或 CI 流程中。规则见[种子与测试数据](01-conventions/07-seed-and-test-data.md)。

## 没有清除或没有种子的组件

按[清除与重置](01-conventions/07-seed-and-test-data.md#种子数据)的判据，每个例外组件在这里写一行：组件、属于哪一类、要清空时怎么做。

| 组件 | 属于哪一类 | 要清空时 |
| --- | --- | --- |
| `mdm/org`、`mdm/currency`、`mdm/partner`、`mdm/product` | 没有清除：全状态事件已经发出，删行之后消费者的投影对不上；主数据在业务上只停用、退役，不删除 | 只用于开发库：删掉该组件的 schema（`mdm_org`、`mdm_currency`、`mdm_partner`、`mdm_product`），再 `brickkit up` 让迁移重建，然后重灌；它的消费者一并重置 |
| `infra/iam-casdoor` | 没有清除：账号在 Casdoor 里，平台主体在组件里，删账号不删主体，授予还指着旧主体 | 在 Casdoor 里删账号并重置组件的 schema；之后各种子按新的主体重新授予（变更键里带主体身份） |
| `infra/authz` | 只有重置：授权记录只追加修订，撤销也是新的修订 | 只用于开发库：删掉 `infra_authz` schema，`brickkit up` 重建，安装认领重新指定管理员（`cells secure`），再重灌 |
| `infra/audit` | 没有种子：审计记录来自真实的业务写入（各种子的写入都会留下审计） | 删掉 `infra_audit` schema 后重建 |

## 怎样使用

- 前提：身份、授权组件与要灌的组件都已启动；授权组件的安装认领指定 `test.alice` 为管理员（格里由 `cells secure` 完成）。
- 环境：`SEED_PASSWORD`（测试账号的密码，即 `IAM_TEST_PASSWORD`）；建账号还要 `CASDOOR_URL`、`CASDOOR_ADMIN_PASSWORD`、`IAM_TEST_PASSWORD`。
- 全部：根目录 `make seed-data`，按依赖顺序：身份的账号、授权、组织、币种、伙伴、产品。
- 单个组件：`make -C components/<领域>/<名字> seed`，先灌它声明依赖的组件（伙伴与产品先灌组织；授权先建账号，Casdoor 连不上时跳过）。
- 每个种子先由 `test.alice` 建本组件的角色与授予，再等 `test.bob` 的授予到达组件，然后以 `test.bob` 写数据。
- 地址默认是格的主机端口（身份 `18200`、授权 `18223`、组织 `18083`、币种 `18226`、伙伴 `18225`、产品 `18082`），别的部署用 `SEED_IAM_URL`、`SEED_AUTHZ_URL`、`MDM_<组件>_URL` 改；每个组件的 `cmd/seed` 开头写着它读的变量。
