# 结构问题登记

本页登记在代码与文档里发现的**结构问题**：不是某个功能错了，而是代码或文档的组织方式会让以后的改动漏改、改错、互相冲突，或者让人找不到东西。设计新组件、给已有组件加状态或模块、改规范之前，先读“待处理”一表，看手上的设计会不会踩到同一类问题；“已修”一表留着教训与防止再犯的规则或检查。工作中（写代码、重排、审查、考试、复盘）发现这类问题，当场登记一条，修不修另说。

每条的写法：编号 `SF<两位数>`，只追加、不复用；**范围**（组件或规范）；**现象**；**会怎样出错**；**发现**（怎样、什么时候）；**状态**；**设计时怎样避免**（指向规则或检查，规则只写在那里，这里不重复）。一条修好之后从“待处理”移到“已修”，编号不变。
