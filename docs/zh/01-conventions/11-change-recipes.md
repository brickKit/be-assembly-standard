# 改动配方

本页按改动的类别，写每一类在[改动的循环](10-development-workflow.md#改动的循环)的各步要注意什么、守哪条规则，规则全文在链接里。顺序就是循环的顺序，本页不另排；没列出的步照循环做，这一类在那一步没有特别要注意的。写给在组件里动手的人与 AI：先在这里找到改动的类别，碰到要判断的地方再读链接的那一节。某个组件的特殊之处在它 `AGENTS.md` 的代码地图（“想改 → 从这里开始”）。一次改动常常同时是几类（加字段的同时加了接口），各类的条目合起来做。

## 给一个实体加字段

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | **先判断是不是这个组件的标准字段**：所有客户都要、组件自己的逻辑要读它的，是标准字段，写进 `docs/design.md` 的拥有的数据；只是某些客户想记录的（行业、来源渠道），用扩展字段（[协议 08 的扩展字段的边界](../06-protocols/08-extension-fields.md#扩展字段的边界)），标准逻辑从不读扩展字段。扩展字段的实现状态见组件的 `BRICKKIT.md` |
| ③ 契约 | OpenAPI 的请求与响应、事件的 schema（完整状态事件要带上新字段；两者都是 `additionalProperties: false`，不写进去的字段会被拒绝或校验失败）、proto；只追加，新字段对旧的调用方与消费者可选（[协议 19 的版本与产物](../06-protocols/19-config-secrets-registries-release.md#版本与产物)、[原有决定 0302](../02-decisions/10-earlier-decisions.md#0302-契约只做加法从新版本发布之后约束)）。**资源定义**里的字段是显式的列表，没列出的字段不输出：新字段加进去；要按角色隐藏的登记为受限字段（[安全 09a](../06-protocols/security/09a-encoding-and-records.md)） |
| ④ 测试 | 新字段的规则：校验、是否参与“有没有变化”的比较、受限字段对没有资格的角色不输出 |
| ⑤ 实现 | **数据库**：加列。进入正式之前，直接改组件的建表迁移并重建开发库；进入正式之后只加新的迁移文件（`NNNN_<名字>.up.sql`），扩展与收缩分开发（[协议 14 的结构迁移与版本兼容](../06-protocols/14-data-foundations.md#结构迁移与版本兼容)）。金额、数量、汇率、时间的列按[协议 14](../06-protocols/14-data-foundations.md#金额数量汇率与单位) 的类型。**代码**：记录的类型、读取的列与扫描、写入的 SQL（新建与修改各一处手写的列表）、“有没有变化”的比较、请求的校验（代码地图里“记录”与“模块”所在的文件）；照一个已有的同类字段搜一遍，就能找全要改的位置 |
| ⑥ 核对 | **下游**：投影只保存自己声明的字段，加字段不强迫消费者改；要用它的消费者自己升级（[协议 02](../06-protocols/02-projections.md)）。**种子**：一部分演示数据带上新字段（[种子与测试数据](07-seed-and-test-data.md)） |

## 加一个用户面接口

| 步 | 要做的与要守的 |
| --- | --- |
| ③ 契约 | `contract/openapi.yaml` 加路径，写 `x-operation`（权限键）、请求与响应、错误；有副作用的命令声明是否要求 `Idempotency-Key`。**资源定义**：在组件定义里登记操作（权限键、资源类型、用途、风险、副作用、是否审计）；新的权限键按[协议 19 的注册表](../06-protocols/19-config-secrets-registries-release.md#注册表)命名（[安全 06 的资源、动作与副作用声明](../06-protocols/security/06-security-contracts-and-capabilities.md#资源动作与副作用声明)） |
| ④ 测试 | 契约测试核对路由与 OpenAPI 一致；授权的反例（没有权限答 403，看不见答 404）；命令的业务规则 |
| ⑤ 实现 | **路由**：在模块的路由注册里加一条，带上操作键；没有操作定义的路由没有授权检查（[组件实现约定的权限与资源](06-component-implementation.md#权限与资源)）。**处理函数的顺序**：校验参数 → 授权目标 → 认领幂等键 → 检查状态 → 在一个事务里写入、写发件表与审计（[原有决定 0507](../02-decisions/10-earlier-decisions.md#0507-幂等键按调用方划分命名空间并绑定到命令)）；事务里不发网络调用。**列表接口**：游标分页、白名单的排序与筛选、数据范围在 SQL 里（[协议 14 的列表](../06-protocols/14-data-foundations.md#列表游标排序与筛选)、[安全 07](../06-protocols/security/07-finite-expressions-containment-and-queries.md)） |
| ⑥ 核对 | `BRICKKIT.md` 的契约索引写上新接口与权限键 |

## 加或改一个事件

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | **先定事件的种类**：完整状态（可覆盖的投影来源）还是不可遗漏的增量事实（[事务与消息的事件分类](../04-foundations/03-transactions-and-messaging.md#事件分类重放与去重寿命)）；种类决定消费者怎样去重与补取。**改载荷之前先看谁受影响**：订阅者在组件索引的[事件](../00-overview/09-component-index.md#事件)一节；完整状态事件的载荷通常也是来源方法（`SourceService`）返回的数据，经来源方法读它的依赖方同样受影响，看组件索引的“被谁必需依赖”，并在它们的代码里搜聚合名（例如 `AGGREGATE_LEGAL_ENTITY`）；还没重建的组件看边界卡与协议 |
| ③ 契约 | `contract/events/<事件类型>.schema.json`；类型名 `<领域>.<聚合>.<动作>.v<n>`。破坏性变化换新的类型名（`.v2`）并排发布，不改旧的（[协议 19 的版本与产物](../06-protocols/19-config-secrets-registries-release.md#版本与产物)）。`component.yaml` 的 `events.publishes` 列上它；订阅方在自己的 `events.subscribes` 列上（组件索引与 `brickkit deps` 由此得出谁订阅谁） |
| ④ 测试 | 发出的载荷按 schema 校验；什么时候发、发几次（每条转到这个状态的路径都发） |
| ⑤ 实现 | 业务变更与发件表在同一个事务（[协议 02](../06-protocols/02-projections.md)）；流与分区在组件定义里，分区数发布后不改 |

## 调用别的组件，或用别的组件的数据

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | **先问需要的是什么**：要此刻可用的证据（新单据引用客户、产品）→ 同步调用属主的资格查询（[协议 07 的资格引用的提交检查](../06-protocols/07-references.md#资格引用的提交检查)）；要显示或报表用的数据 → 投影（[协议 02 的什么时候可以用投影](../06-protocols/02-projections.md#什么时候可以用投影)）；要对方做一件事 → 系统命令。**依赖声明**：`component.yaml` 的 `dependencies` 写精确版本；可选依赖写清缺席时本组件怎样降级（边界卡、`BRICKKIT.md` 的依赖说明）。对方缺这个能力时先改对方（被依赖的先改） |
| ③ 契约 | 只经契约：引入被调方发布的契约模块；不导入代码，不读写别人的表（[组件实现约定的调用其他组件](06-component-implementation.md#调用其他组件)） |
| ④ 测试 | 对方缺席、不可达时的表现；替用户读时，用户看不见的数据不出现在响应里 |
| ⑤ 实现 | **在事务之外调用**：先取证或先调用，再在本地事务里写；证据有有效期（协议 07 的 W）。**对方不可达**：答“依赖不可用”，不当作“不存在”。**替用户读**走用户面并转发用户凭据；系统面的结果放进用户响应前先按用户的读取契约裁剪 |

## 加一张表

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | 写进组件的 `docs/design.md`（拥有的数据：表、终态、分区与保留） |
| ③ 契约 | 要按范围读的表，在资源定义里声明维度与列（[安全 07](../06-protocols/security/07-finite-expressions-containment-and-queries.md)） |
| ④ 测试 | 迁移连跑两次都成功（[各层的硬要求](02-testing-and-validation.md#各层的硬要求)） |
| ⑤ 实现 | 迁移是纯 SQL，不建角色、不授权、不建 schema、不写 `SET`（[协议 14 的结构迁移与版本兼容](../06-protocols/14-data-foundations.md#结构迁移与版本兼容)）；身份、单号、时间、金额的列按[协议 14](../06-protocols/14-data-foundations.md)；当队列用的表原子认领，去重表不分区（[协议 01](../06-protocols/01-background-work.md)、[协议 14 的数据库](../06-protocols/14-data-foundations.md#数据库)） |

## 加一个功能：放在哪个模块

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | 先读组件根 `AGENTS.md` 的模块表：功能动的是哪个模块拥有的表与路由，就放在那个模块；跨两个模块的，放在调用的一方，被调的一方导出它需要的函数。只有一个新业务能力有自己的表、路由与规则时才建新模块（拿不准时放进最近的模块）：建目录、写 `AGENTS.md` 与 `CLAUDE.md`，加进 `internal/AGENTS.md` 的模块表与组件根的模块表，在入口包登记它的路由与工作（[标准布局](05-ai-navigation.md#组件仓库的标准布局与代码地图)） |
| ④ 测试 | 单元测试放进模块目录；集成测试按业务流程放进 `itest/` 的对应文件，更新 `itest/AGENTS.md` 的索引 |
| ⑥ 核对 | 改到的目录的说明：“文件”一节、依赖与被依赖、测试（`make layout-check`） |

## 加一个状态或命令（有生命周期表的组件）

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | 先在 `docs/design.md` 的生命周期表上加一列或一行，**每一格都定下来**，规则目录加编号；再读结构检查登记的“表以外读状态的地方”，逐一决定新状态在那里怎样（[状态与不变量集中一处](06-component-implementation.md#状态与不变量集中一处)）。表的写法表达不了新规则时（例：“回到之前的状态”），先改表的写法，不在表外加例外 |
| ③ 契约 | 状态的枚举在 OpenAPI 与事件的 schema 里，只追加（[原有决定 0302](../02-decisions/10-earlier-decisions.md#0302-契约只做加法从新版本发布之后约束)）；读这个状态的其他组件（组件索引的订阅者、契约字段的使用者）要能处理新值 |
| ④ 测试 | 代码的表照文档改（单元测试逐格比较两边）；新格各有一个集成测试的步骤写明编号 |
| ⑤ 实现 | 命令按格行事，状态只经那一个写入函数；不在表以外比较状态 |

## 给 SDK 加一项组件要用的能力（例：流程内核）

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | 先改 `be-protocol` 的条款与向量，再改 SDK（[`be-sdk-go` 的 AGENTS.md](../../../tools/be-sdk-go/AGENTS.md) 的设计取舍）；意图里写清第一个要接它的组件 |
| ④ 测试 | SDK 自己的集成测试之外，**发布 SDK 之前**拿一个真实组件把接入写到能编译、能跑通一条集成测试（本地 `go.work` 指向未发布的 SDK，组件不发布）：接口的形状缺什么（钩子拿不到的参数、组件原有路由怎样接、可选的依赖缺席时）只有组件接上时才看得见，SDK 发布后再补就是又一轮全系统换 SDK |
| ⑤ 实现 | SDK 在组件的事务里调用组件的钩子时（例：流程实例结束），钩子不发网络调用：要外调的事排成工作项，要取证的提前到事务之前（例：付款的汇率在提交时取好存在单上）（[事务与消息](../04-foundations/03-transactions-and-messaging.md#本地事务)） |
| ⑥ 核对 | 全系统换 SDK（同一个库整个系统只用一个版本），各组件照常发布 |

## 新建一个组件

| 步 | 要做的与要守的 |
| --- | --- |
| ① 意图 | 先读[结构问题登记](12-structure-findings.md)的“待处理”，别把同一类问题带进新组件；走 `brickkit-component` 技能；布局按 [AI 导航的标准布局](05-ai-navigation.md#组件仓库的标准布局与代码地图)（入口包只组装、业务在 `internal/` 的模块里、集成测试在 `itest/`、每层一份说明），照一个已重建的同语言组件（`erp/sales` 最完整）；有生命周期或不变量的，按[状态与不变量集中一处](06-component-implementation.md#状态与不变量集中一处)；身份、端口、schema 先在 `registry/` 追加（[注册表](../../../registry/README.zh.md)）；开工前按边界卡写 `docs/design.md`（[组件的文档](03-documentation.md#组件的文档)）；上游缺的能力先列出来，先改上游 |
| ② 考设计 | 不跳过 |
| ⑥ 核对 | 重新生成组件索引（`make docs-index`）；要进外壳的，外壳的成员清单与依赖锁随它的第一个版本一起改 |
