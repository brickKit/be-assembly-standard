# 前端约定

本项目每个前端组件都遵守的规则：前端槽位族的每个成员，而不只是 `frontend/standard`。前端从不进外壳；它的约束来自别处：一个页面里只能有一套设计系统；换实现要改的是一个包，而不是四十个页面；AI 生成页面时不能靠猜。这些选择的理由见 [../02-decisions/README.md](../02-decisions/README.md)。

## 技术栈

| 层 | PC（`apps/pc`） | 移动端（`apps/mobile`） |
|---|---|---|
| 框架 | Vue 3 + TypeScript | Uni-app（Vue 3）+ TypeScript |
| 组件库 | Ant Design Vue 4 | wot-design-uni（退路 `uni-ui`） |
| 表格 | vxe-table，只经由 `<BeTable>` | 没有表格：卡片列表加下拉刷新 |
| 图表 | ECharts + `vue-echarts`（离线可用） | 同左，用 canvas 渲染 |
| 取数 | `@tanstack/vue-query` 加生成的 API 客户端 | 同左 |

- 任何地方都不用 React。
- `package.json` 写精确版本：不许出现 `^`、`~`、`latest`。必须配套的组合（vxe-table 与 vxe-pc-ui）连同版本记在 `packages/ui-kit-pc/README.md`。
- 两端用不同组件库是有意的。PC 是密集表格、多列筛选、多级联动长表单，用鼠标键盘整天盯着用；移动端是卡片列表、扫码、拍照上传、通过/驳回两个按钮，在路上用几十秒。几乎没有组件能原样复用，而且 Ant Design Vue 依赖 DOM，Uni-app 的目标平台没有 DOM。

## 包与共享

| 包 | 内容 | 谁用 |
|---|---|---|
| `packages/design-tokens` | 纯数据、零框架 import：主色、色阶规则、间距梯度、字号、行高、圆角 | 两端；**两端唯一共享的 UI 资产** |
| `packages/ui-kit-pc` | Ant Design Vue + vxe-table 的封装与接线、`<BeTable>`、页面模板、骨架；第三方 PC 组件的唯一出口 | `apps/pc` |
| `packages/ui-kit-mobile` | wot-design-uni 的封装；第三方移动端组件的唯一出口 | `apps/mobile` |
| 生成的 API 客户端与类型 | 从各组件契约生成的请求函数和类型 | 两端 |

共享 token，不共享组件。为了一致去共用组件，会同时得到一个难用的移动端和一个被移动端限制住的 PC 端。一个 import 了 Ant Design Vue 的共享 ui-kit，会把它一起拖进 Uni-app 的构建。

## 设计 token 与主题

- **设计 token 是运行时可写的 CSS 变量**，绝不是编译进 bundle 的 TypeScript 常量。亮/暗和密度都要在运行时切 token；写成常量就不可能做到，而发现的时候每个页面都得改。
- `packages/design-tokens` 是间距、字号、行高的唯一来源。两个 ui-kit 都从它取；页面只引用 token 和 ui-kit 组件。**页面里从不硬编码颜色或间距值。** 在本项目里"好看"就是"一致"：毁掉 AI 分批生成的页面观感的，是这一页间距 16、下一页 20。
- **PC 端主题只有一个源头。** Ant Design Vue 的 seed token 是源；`ui-kit-pc` 在启动时由它派生出 vxe-table 的 `--vxe-ui-*` 变量。`theme.algorithm` 和 `VxeUI.setTheme()` 在同一个函数里一起切。没接起来的话什么都不报错，只是每张表格都像贴进页面的。
- 可编辑单元格在 vxe 的编辑插槽里用 Ant Design Vue 控件（`<a-select>`、`<a-input-number>`、`<a-date-picker>`），一次注册成全局渲染器。
- **视觉方向：克制专业。** 只改 seed token 的主色，其余全部跟随 Ant Design Vue 的派生。紧凑密度用 `compactAlgorithm`，行高由 ui-kit 统一给。小圆角、克制阴影，不拿卡片包裹一切。系统字体栈，不下载也不内嵌字体（离线部署）。表格无斑马纹、只留横线、悬停高亮；固定表头、冻结列、虚拟滚动是默认。

## 第三方组件

- 第三方 UI 组件只出现在 `packages/ui-kit-pc` 或 `packages/ui-kit-mobile` 里，对外暴露我们自己的组件名。业务页面从不直接 import 第三方组件，`<vxe-grid>` 也不行。
- 只有 Ant Design Vue 缺的能力才允许混入别的库：甘特图、审批流设计器、富文本、代码编辑器、大屏可视化。每混一个，在组件的 `docs/design.md` 里记一行：哪个能力、为什么 Ant Design Vue 不行、许可证。绝不为了好看混：两个库的 token 体系对不齐，混得越多越难看。
- **表格一律经由 `<BeTable>`。** 它覆盖大约 80% 的用法（列定义、数据源、编辑、选择、导出、分页或虚拟滚动）。其余可以直接用引擎的 API，但每个这样的逃生口都要在 `packages/ui-kit-pc/README.md` 里记一行。这份清单必须数得过来：它有多长，换引擎那天就要改多少处。
- vxe-table 是默认表格引擎，要逐项确认：它有部分能力属于商业版。依赖某项能力之前（虚拟滚动、冻结列、可键盘连续录入的可编辑单元格、树表格、Excel 导入导出、分组与透视、甘特图），先对照免费档核一遍，结论写进 `docs/design.md`。可编辑单元格、虚拟滚动、冻结列中有任何一项是付费的，就换引擎；候选引擎也核同一份清单。

## 页面模板

业务页面从不从一个空 `<div>` 开始。它从 `ui-kit-pc` 的页面模板开始：`<BeListPage>`、`<BeDetailPage>`、`<BeFormPage>` 或 `<BeSettingsPage>`，然后填插槽。选模板、填插槽的页面在布局上不可能各走各的；这正是大型控制台最被诟病的毛病（每个服务看起来都像另一个产品）的解药。

## PC 骨架

PC 骨架是云控制台式的两级导航：先选服务，再在服务内导航。不是左侧多级树。

| 位置 | 内容 |
|---|---|
| 顶栏左 | "▾ 服务"：不离开当前页的覆盖层，含搜索、最近访问、按领域分组的组件，可加星标 |
| 顶栏中 | **收藏栏**：加了星标的组件，一次点击直达 |
| 顶栏右 | ⌘K 命令面板（搜全部页面、按单据号直达）、**组织 / 法人切换器**、通知、用户菜单 |
| 顶栏下 | 跨组件的**应用内标签页**，可关闭 |
| 主体左 | 该组件自己的页面，**扁平、3–5 项、不折叠**，底部固定"组件设置" |
| 主体右 | 面包屑和页面内容 |

- 为什么不是树：菜单在装配期从每个组件的 `assembly.yaml` 聚合，每个客户装的组件又不同，树的形状会家家不同，AI 生成一个页面时不知道它该挂在哪一层。按组件边界映射成两级之后，每个客户看到的结构都一样。
- 与云控制台不同的地方：有应用内标签页（一张没保存的 ERP 单据切走再回来必须还在，而浏览器早就开了二十个标签页）；服务内菜单永远扁平；Region 切换器换成组织 / 法人切换器，它同时也是数据范围的输入。
- 应用骨架自己写。想不清的部分去读 `vue-vben-admin` 的 layout、router + access、request 封装，绝不安装它（[10-reference-implementations.md](10-reference-implementations.md#看哪个项目)）。

## 偏好与品牌

| 设置 | 归属 |
|---|---|
| 收藏的组件及其顺序 | 用户 |
| 亮色 / 暗色 / 跟随系统 | 用户 |
| 标准 / 紧凑密度 | 用户 |
| 语言 | 用户 |
| 表格列宽、列序、隐藏列、筛选器 | 用户，只存本地，从不同步 |
| 主色、logo、产品名、水印、灰度模式 | 装配期配置，一家公司一份 |
| 布局模式（侧栏 / 顶栏 / 混合）、圆角、动画、页脚与面包屑开关 | 不存在 |

用户偏好存在 `localStorage`。在这四项之外每多一项偏好，就要在它下面把每个页面都测一遍；这就是清单很短的原因。

## 功能、权限与菜单

- 路由或菜单项只在三者同时成立时显示：组件已安装（`GET /api/tenant/features`）、用户有权使用（`GET /api/me/permissions`）、用户已登录。只查功能，结果是菜单看得见、点进去整页 403。按钮用 `ui-kit-pc` 的 `v-be-auth="'<权限键>'"`。
- 两个接口都只返回该用户能看的部分；绝不下发全量让前端自己过滤，那会暴露公司买了哪些模块。
- **前端隐藏从来不是安全边界。** 改了代码的用户能进到隐藏的页面；那时它必须是一个空壳，每个数据请求都被后端拒绝。
- 每个组件在 `assembly.yaml` 的 `menus` 段声明自己的菜单项，每项带一个本组件自己的权限键。be-ops 在装配期把它们聚合起来；服务选择器和服务内菜单都由这份聚合结果生成。没有中心菜单表。
- 带 `error="token_stale"` 的 `401` 触发一次静默刷新 token，并且只重试一次原请求（角色变更就是这样在几秒内生效的）。

## 业务逻辑与取数

- 金额计算、扣减库存、核心状态转移都在后端，从不在前端。
- 前端负责表单交互：校验规则、字段显隐联动、防抖节流、防丢失的本地草稿。不为了显隐一个字段去调后端。
- 依赖后端规则的实时估算（按客户等级和产品估价）防抖调用后端的 `DryRun` / `Validate` 接口；绝不在前端重写后端的公式。
- 不手写 `fetch('/api/…')`：请求一律走从契约生成的 API 客户端。
- 每个日期范围选择器默认选中最近 90 天，任何页面都不会无意中扫全表。

## 国际化

- 所有面向用户的文字都走 i18n 层，有中文和英文两套文案；页面里没有字面的界面文字。
- 每个交付的页面两种语言都完整。语言是用户偏好。
- 日期、数字、金额按语言区域格式化；金额从 API 到屏幕始终是十进制字符串。

## 测试

前端测试分层是 FE-1（逻辑：函数、composable、store）、FE-2（共享组件）、FE-3（真实浏览器对真实后端的端到端，一个测试一条业务流程）和 FE-4（在 FE-3 里对关键页面做截图比对，亮色和暗色各一份）。FE-3 和 FE-4 在页面交互稳定之后再写，并且只在用户同意范围之后才跑。细节见 [06-testing.md](06-testing.md#前端测试)。
