# 文档与设计推进方式

每条决定写明：决定了什么、为什么、没有采用什么、现在落在哪里。来源与日期见[决定目录](README.md)。

## D56 实验之前先把相关协议写到可冻结

- **决定**：授权的时间保证、有限表达与管理上限、代表业务的协调状态机、归档目录、重放与去重寿命、关账屏障、一致性恢复等协议，先写到可冻结，再按 D41 补最小条件、建代表链路做部署对照实验。
- **理由**：理论更完整，减少实验后因协议缺口返工。
- **不采用**：按改动代价分级，只把写进数据与契约的形状定到字段级，其余只留扩展位，尽快开始实验。这个思路仍可用于协议内部区分“必须现在定的形状”与“以后可加的能力”，但不能据此跳过本条要求的协议。
- **代价**：实验推迟；未经运行检验的协议仍可能在实验后修订。
- **落在**：[路线](../00-overview/06-roadmap.md)、[协议 21 的设计修订的状态](../06-protocols/21-verification-and-migration.md#设计修订的状态)。

## D59 终局设计按从零开始，不承担现有代码与契约的迁移兼容

- **决定**：终局设计视为第一个正式版本：不设计从现有 2.x 组件、已发布契约、现行 SDK 与外壳的过渡、并存或数据迁移；开发时组件、契约、数据库按新设计重建。新版本发布之后，面向真实客户的升级、契约演进、数据迁移、Fork 适配与停用规则（D25、D54、D55）照常设计；“契约只能追加”等规则从新版本发布后开始约束。
- **理由**：设计完整优先于开发；现有代码只作参考与教训。
- **不采用**：代码不约束设计，但把已发布契约与版本当作存量，保留迁移与并存章节。
- **落在**：全部正式文档；重建计划在设计完成后列出清单，经用户确认后执行：原仓库全部复用，旧代码挪到固定的 `legacy/v<旧主版本>` 分支（分支名见 A102，版本号见 A110）、主分支从零开始；组件 ID 变了的改名后复用，没有原仓库的新建。

## D67 开发完成之前，正式文档只写中文，预留多语言

- **决定**：开发完成之前，正式文档只写中文；结构与工具为多语言留好位置（语言目录、术语表的代码标识符一列、按语言启用的镜像检查），不写英文正文，也不要求中英镜像。开发完成后再决定何时补其他语言。
- **理由**：设计与开发阶段变化快，双语同步的成本落在每一次修改上；中文是维护者的工作语言。
- **取代**：项目原有约定“英文为准、中文镜像”与原迁移步骤中的“写英文正文、写中文镜像”；也取代用户前提 U08 中“构建双语新文档”的部分。
- **落在**：[文档规则的语言](../01-conventions/03-documentation.md#语言)、[协议 21 的正式文档的位置](../06-protocols/21-verification-and-migration.md#正式文档的位置)。

## D74 代码与提交信息全部用英文

- **决定**：代码全部用英文，包括标识符、注释、日志与错误信息；提交信息与 tag 的注释也用英文。文档与给维护者的回答、汇报用中文（D67）。
- **理由**：代码与提交历史主要由 AI 读写；维护者读的是文档与汇报。
- **取代**：项目原有约定“提交信息用中文”“代码注释用中文”。已有的中文提交不改。
- **落在**：文档规则的语言、根 `AGENTS.md`、开发流程规范。
