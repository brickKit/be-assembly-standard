# 0015 PC 端采用控制台式两层导航，带应用内标签页

## 决策

PC 端骨架采用云控制台式布局：服务选择器（组件按领域分组，可搜索、有最近访问、可加星标）、收藏栏、每个组件内 3–5 个页面的扁平菜单、跨组件的应用内标签页、⌘K 命令面板，以及放在控制台"区域切换器"位置上的组织 / 法人切换器。业务页面从 ui-kit 的页面模板开始——`<BeListPage>`、`<BeDetailPage>`、`<BeFormPage>`、`<BeSettingsPage>`——往插槽里填内容。

## 理由

菜单在生成项目时由各组件 `assembly.yaml` 汇总而来，而每个客户装的组件都不同，多级树在每个客户那里都会长成不同的形状，也没有可以重排的中心菜单表。两层导航对应组件边界，对所有客户都一样。保留应用内标签页，是因为 ERP 里一张没保存的表单在浏览器刷新时就没了。页面模板让分批生成的页面保持视觉一致。

## 挡下什么

- 左侧多级树形菜单（领域 → 组件 → 页面）
- 组件内可折叠或嵌套的菜单
- 去掉应用内标签页，改用浏览器标签页
- 把 vue-vben-admin、antdv-pro 或其他 admin 模板当依赖引入——可以读它们的布局、路由和请求代码，但不要安装
- 中心化的、手工维护的菜单表
- 从空白 `<div>` 开始手工排版一个页面

在服务选择器里隐藏某个组件只是方便，不是安全措施：后端仍然校验每一个请求。

## 何时重新讨论

某个组件的页面多到扁平菜单放不下时——先拆分组件，而不是加深菜单。
