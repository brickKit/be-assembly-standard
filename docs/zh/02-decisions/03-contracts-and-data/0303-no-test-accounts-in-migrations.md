# 0303 测试账号不写进迁移

**状态**：已在用；3.0.0 的修订（首个管理员按 IdP 登录名写在 `BOOTSTRAP_ADMIN_LOGIN` 里；种子工具不再把首个管理员直接写进库）已决定，随 3.0.0 统一升级落地。

## 决策

迁移里只放每个部署都需要的产品基线数据，例如一个默认仓库或一份会计科目模板。测试用户、角色、密码和演示数据只由开发者手动运行的种子工具创建（组件里的 `make seed`，本项目的 `make seed-data`），绝不由任何部署或 CI 步骤创建。首个真正的管理员由部署者按 IdP 登录名设定：共享配置键 `BOOTSTRAP_ADMIN_LOGIN` 写这个人的 IdP 登录名或电子邮件地址。平台 `sub` 没法事先写出来，因为平台只在这个人首次登录时才签发它（[0203](../02-permissions/0203-jwt-carries-identity-only.md)）。在这次首次登录时，身份 provider 把登录名绑定到新的平台 `sub`（每个部署只绑一次），并发布带 `bootstrap_admin: true` 的目录事件；授权 provider 收到后把管理员角色授给该身份，幂等执行。本地开发用同一个键，写在开发者自己的环境里；种子工具从不把首个管理员直接写进库。

## 理由

迁移在每一次部署时都会运行，包括每个客户的生产系统。写进迁移的账号就是一个密码公开、拥有全部权限的后门，被安装进每一个客户的系统。首个管理员只有一条路径，开发机和生产一样，这条路径就始终被测试着。

## 挡下什么

- "在迁移里建一个 `dev.superuser`，开箱即用"
- 默认的 `admin` / `admin` 账号或任何硬编码凭据
- 迁移里放演示客户、订单或其他样例数据
- 种子步骤把首个管理员的角色分配直接插进 authz 的表
- `BOOTSTRAP_ADMIN_SUB` 这样的键，或任何在这个人登录之前就按平台 `sub` 指定首个管理员的办法
- 在部署、镜像入口或 CI 里对真实环境运行种子工具
- 为了方便测试登录，在生产环境的 IAM 应用上开启密码授权方式

## 何时重新讨论

涉及身份和凭据时永不重新讨论。
