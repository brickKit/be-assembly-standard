# 0302 契约只做加法

## 决策

已发布的契约——`.proto`、OpenAPI 和 `events/*.json`——只增不减：可以加字段、加 RPC、加接口、加事件 subject。字段永不删除、改名、改类型或改编号，subject 永不移除，字段的含义永不改变。新字段对已有消费者的逻辑必须是可选的。组件里的 `make contract-check`（proto）和本项目的 `make gates`（事件）在出现破坏性变更时报红。

## 理由

消费者（包括客户的 Fork）会继续基于旧版本运行，并忽略自己不认识的字段。破坏性变更迫使所有消费者同步修改、同步发版；漏改的事件消费者会在运行时出错，而不是在构建时。

## 挡下什么

- "把这个字段改个名"、"把类型改成 int"、"复用这个 tag 编号"
- "把废弃的字段 / RPC / subject 删掉"
- 把已有的可选字段改成必填
- 名字不变，却改了已有字段的含义或单位

## 何时重新讨论

某个契约错到无法修补时。由人来决定发一个大版本：在旧契约旁边发布新的带版本号的包或 subject，消费者逐个迁过去，旧的稍后退役——绝不原地修改旧契约。
