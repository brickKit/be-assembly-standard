# 0020 测试账号不写进迁移

## 决策

迁移里只放每个部署都需要的产品基线数据，比如默认仓库，或默认法人及其科目表。测试用户、角色、密码和演示数据只由开发者手动运行的种子工具创建（组件里的 `make seed`、本项目的 `make seed-data`），绝不属于任何部署或 CI 步骤。首个真实管理员由部署者设置：`infra/authz` 通过配置键 `BOOTSTRAP_ADMIN_SUB` 接收该身份的 `sub`，并在启动时幂等地授予它管理员角色。

## 理由

迁移在每次部署时都会运行，包括每个客户的生产系统。写进迁移的账号，就是一个密码公开、拥有全部权限、装进每个客户系统里的后门。

## 挡下什么

- "在迁移里建一个 `dev.superuser`，开箱即用"
- 默认的 `admin` / `admin` 账号，或任何硬编码的凭据
- 在迁移里放演示客户、订单或其他示例数据
- 从部署流程、镜像入口或 CI 对真实环境运行种子工具
- 为了方便测试登录，在生产 IAM 应用上开启 password 授权方式

## 何时重新讨论

身份与凭据永远不重新讨论。
