# 0306 自有主键用 UUIDv7；单据号由 SDK 分配

**状态**：已决定，随 3.0.0 统一升级落地。

## 决策

- **每个自有主键都是 UUIDv7**（RFC 9562），以 PostgreSQL `uuid` 存储，由组件在插入前经 SDK 生成，从不靠列默认值。
- **对另一个组件记录的引用是 `TEXT`**，不透明，不建外键；契约里的每个 id 都是不透明字符串。
- **分区表上的 `created_at` 就是 id 里嵌着的时间戳**，所以按 id 查找只探一个分区。
- **两个例外**：必须严格单调的计数器（授权元组日志的 revision、outbox 的发布序号）用 `BIGINT GENERATED ALWAYS AS IDENTITY`；以标准代码为键的参照表（币种、计量单位）用代码作 `TEXT` 键。
- **给人读的单据号**来自 SDK 唯一的一套编号机制：组件自己 schema 里的一张号段表，按法人和期间划分范围，格式由配置决定。会计凭证号在每个法人的每个期间内连续、无缺号，每个法人串行过账；其他单据号允许缺号，但永不重复。

## 理由

UUIDv7 主键合并时不会冲突（集团合并报表、收购、把一家公司搬到另一个部署、脱敏的生产数据副本），可以在记录到达服务端之前生成（离线草稿、幂等的新建），也不会像连续整数那样向门户用户泄露业务量。它的时间前缀保持索引局部性，并让 id 自己说出所在分区。可读性是单据号的职责；国内会计实务要求凭证号在每个期间内连续编号。

## 挡下什么

- 自有主键用 `BIGSERIAL` 或 `SERIAL`；靠列默认值生成主键；id 里带类型前缀
- 指向另一个组件记录的外键；解析另一个组件的 id
- 由 id 拼出的单据号（`"SO" + id`），或组件里自己写的编号代码
- 期间内可能出现缺号的凭证编号方案

## 何时重新讨论

- id：总体上永不。某张极大的明细表，经测量 16 字节确实是瓶颈时，可以给它自己的主键用 identity，并且绝不暴露到组件之外。
- 凭证无缺号：某个法人的过账撞上串行计数器的吞吐上限（每秒几十到上百张），而业务接受换一个编号时点时。
