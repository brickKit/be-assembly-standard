# 0212 调用者看不见的记录答 404，读和命令都一样

**状态**：已决定，随 3.0.0 统一升级落地。

## 决策

| 情形 | 读 | 命令 |
|---|---|---|
| 记录不存在 | `404 NOT_FOUND` | `404 NOT_FOUND` |
| 记录存在，但没有任何规则、共享或关系让调用者看见它 | `404 NOT_FOUND`，与上一行无法区分 | `404 NOT_FOUND`，无法区分 |
| 看得见，但这个动作需要调用者没有的键（只共享了查看权的记录） | — | `403 MISSING_PERMISSION` |
| 看得见也允许，但状态不允许 | — | `400 FAILED_PRECONDITION`，带组件自己的 reason |

于是 `403` 永远意味着"你看得见它，但不能做这件事"。命令在查幂等键之前先检查可见性，所以看不见这条记录的人重放命令，得到的答复和键不匹配时一样，而不是存下的结果。

## 理由

对"存在但被隐藏"给出不同的答复，任何人都能靠读取或对 id 试一个命令，探测出哪些 id 存在；GitHub 和多数主流 API 正是为此答 404。让命令和读取答得一样，堵住了先前"范围外的命令答 403"留下的探测口，也让前端每个状态码只有一种含义。

## 挡下什么

- 对调用者范围外的记录答 `403`，不论读还是命令
- 能区分"被隐藏"和"不存在"的错误详情、耗时路径或 reason
- 把存下的幂等结果返回给看不见这条记录的调用者

## 何时重新讨论

法律或审计要求系统必须告诉用户某条记录存在但不予提供时。
