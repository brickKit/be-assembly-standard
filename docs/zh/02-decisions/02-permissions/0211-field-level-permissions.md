# 0211 字段级权限是一个键，在源头执行

**状态**：已决定，随 3.0.0 统一升级落地。

## 决策

只有部分人能看的字段（客户的信用额度、产品的标准成本、订单的定价明细），由一个 `type: field` 的权限键守护，连同它的列声明在属主组件 `resources` 的字段集里（一个读键，需要时再加一个改键）。

- **属主组件掩码**，在答复离开它之前完成：被掩码的字段为 `null`，并列在 `_masked` 里。
- 写入被掩码的字段答 `403`，reason 为 `FIELD_FORBIDDEN`。
- 按对调用者掩码的字段排序、过滤或聚合，一律拒绝（`SORT_FORBIDDEN`）：行的顺序或一个合计会泄露掩码想藏的东西。
- 字段只在它所在的行可见时才可见：`field(P, K, r) = visible(P, K, r) AND P 持有字段键`。
- 事件属于系统面，字段不掩码；事件从不原样展示给人。

## 理由

在源头掩码，是唯一绕不过去的地方：在 BFF、前端或下游组件里掩码，换一个调用方就能跳过。字段键就是一个键，所以角色、档位、委托天花板和解释都已覆盖它，不需要第二套机制。拒绝按掩码字段排序和过滤，堵住了"隐藏"列被用来排序时打开的侧信道。

## 挡下什么

- 在前端、BFF 或调用方组件里掩码，而不是在属主组件里
- 每个组件单独一张字段权限表或一份配置
- 按调用者看不到的字段排序或过滤；把它算进合计
- 把事件 payload 原样展示给人
- 用字段键扩大可见的行

## 何时重新讨论

同一个人对同一个字段，必须在某些行上可见、在另一些行上不可见，而行级范围表达不了这条规则时。
