# 0013 数据范围随版本发布

## 决策

用户能看到哪些行——按组织、负责人、仓库、法人等维度——在组件 `assembly.yaml` 的 `data_scopes` 段中声明，由组件代码执行。它通过发布新版本来改变，绝不在运行时修改。`data_scopes` 段是必填的：不需要数据范围的组件写 `data_scopes: none`，省略即报错。用户能*做*什么（功能权限）是另一套机制，由管理员在 `infra/authz` 中运行时修改。

## 理由

SAP、Odoo 和 PostgreSQL 行级安全都让行规则随代码发布；唯一能在运行时修改的 Salesforce，代价是一张物化的共享表，大型组织改一条规则要在后台重算几个小时。"销售只能看自己的客户"是公司制度，不是每天都要拨动的开关；写在代码里的规则可以评审、对比、回滚。安全机制的默认值必须是拒绝，所以省略这一段不能等同于"none"。

## 挡下什么

- 做一个后台界面来编辑谁能看哪些行
- 运行时开关，比如"让 A 部门能看 B 部门的订单"
- 先全部查出来再在调用方过滤——分页当场出错（查出 20 条、滤掉 12 条，用户只看到 8 条）
- 因为组件"用不上"就省略 `data_scopes`
- 在用户请求路径上用 `SystemClient`——它会绕过数据范围，而且不报错

把某一条记录分享给某人（把客户转给另一个销售）是业务功能：改这条记录的 `owner_id`。

## 何时重新讨论

某个客户必须在两次发布之间修改行规则，而且频率高到发布节奏跟不上时。
