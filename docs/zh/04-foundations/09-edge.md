# 边缘入口

本页说明浏览器与外部请求怎样进入部署：边缘负责什么、不负责什么、永不路由什么，选了哪个产品，以及比较、改变的条件与步骤。浏览器会话、令牌缓存与令牌陈旧的重试只在[协议 20 的登录与会话](../06-protocols/20-frontend.md)；开放接口与外部回调在[协议 10](../06-protocols/10-external-integration.md)。

## 选择

- **路由由声明派生，绝不手写**：每个组件声明自己的公网路径前缀，契约里的每个用户面操作都落在某个前缀之下；装配工具把声明变成 BrickKit 读取的部署字段（Kubernetes 上的 Ingress 路径，Docker 与 Podman 上的路由标签），服务名与版本由 BrickKit 解析。路由以路径段为界，`/erp/sales` 永远接不走 `/erp/salesman`。生成的字段与声明不一致，或某个操作不在任何声明的前缀之下时，检查失败；标为内部的操作不计入，因为它们永不被路由。
- **默认产品是 Traefik**：体量小，能发现带标签的容器，内建 OpenTelemetry。Kubernetes 上任何能合并同一主机多份 Ingress 的控制器都可以（Traefik、nginx-ingress、HAProxy）。
- **边缘负责**：TLS；按最长路径前缀路由；每条路由的请求体上限；由路由截止时间推出的边缘超时；按来源的粗粒度限流；开启追踪与请求身份；剥掉内部头与可伪造的头；浏览器会话与令牌缓存（D61，由身份适配组件随附的边缘插件或旁挂进程实现）；改变状态的请求要求自定义请求头；只对已登录会话提供 `features`；只在存在独立来源时才配跨域白名单。
- **边缘不负责**：充当唯一一道认证或授权、套用数据范围、按业务内容路由、缓存接口响应、重试带请求体的请求（唯一的例外是协议 20 的 `TOKEN_STALE` 重试一次）。每个服务自己验证令牌，所以绕过边缘或单独部署一个组件都不会让安全变弱。
- **永不路由**：gRPC 端口；健康、就绪、指标与组件自描述端点；标为内部的操作（只有其他组件调用的提供方接口）；组件有意不声明的内部路径（身份产品的回调等）。
- **默认同源**：前端与接口经边缘共用一个主机名，不需要跨域；静态资源由入口自己的容器带缓存头发出，边缘不缓存。对象存储用独立的主机名（协议 12）。
- **聚合只给移动端**：移动入口经 `infra/bff-mobile`；PC 入口直接调用各组件的用户面，名称靠属主的批量读取补全，没有 PC 的聚合层。

## 方案比较

| 产品 | 单机资源 | 动态配置 | 限流 | 适合 |
| --- | --- | --- | --- | --- |
| **采用**：Traefik | 小 | Docker、文件、Kubernetes 的 provider，监视变化、不用重载 | 每实例，内存里 | 单机到小集群 |
| nginx | 最小 | 改配置要重载 | 每实例 | 统一用 nginx 的客户；作为一个生成器保留 |
| Envoy Gateway | 中 | xDS、Gateway API | 本地，加一个限流服务可做全局 | 多节点且要全局限流 |
| APISIX、Kong | 中（要配置存储） | 管理接口 | 插件，多种后端 | 带门户的 API 产品；网关从“配置”变成“运维” |
| Caddy | 小 | 接口、文件 | 插件 | 小站点；Kubernetes 支持弱 |
| 云 API 网关或负载均衡 | 不占本机 | 控制台或接口 | 内建，全局 | 已经在某朵云上的客户：放在边缘前面可以，但不能替代生成的路由 |

| 问题 | 采用 | 不采用及原因 |
| --- | --- | --- |
| 令牌在哪里验证 | 每个服务里（本地公钥集合，很便宜），边缘只持有会话 | 只在边缘验证（转发认证、JWT 插件）：绕过边缘或单独部署组件时一切敞开，违反“每个组件都能单独运行” |
| 聚合层 | 只给移动端一个 | 每个入口一个、含 PC：多一层，每次组件改动都要传到它，换来的只是省下几个并行请求 |
| 路由的来源 | 由声明派生 | 手写网关配置：服务名带版本，版本一变，这份第二副本就静默失效 |

## 什么时候换

- **多个边缘实例，并且有一个必须跨实例成立的限额**（防滥用、合同约定的配额）：全局限流器，例如 Envoy Gateway 加它的限流服务，或在前面加云网关。
- **对外开放接口**：在边缘按外部应用的标识限流；配额留在服务里，按应用在数据库的计数窗口里计，不引入缓存服务器（决定 0201）。
- **客户统一用 nginx 或某个 Gateway API 控制器**：换成那个生成器。
- **客户集群的控制器给每份 Ingress 各建一个负载均衡器**（合并不了同一主机下各组件的 Ingress）：装配工具为这个主机生成一份合并的路由，条目不再各自对外。

## 怎样换

- **换网关产品**：Kubernetes 上改 Ingress 类与共享注解；Docker 上为新产品在装配工具中加一个标签生成器。各组件的声明与组件本身都不变；端到端检查必须对新边缘跑通。
- **全局限流器**：把限流服务加进基础资源，生成器的限流中间件指向它；路由的限额取值不变。
- 边缘的会话插件随身份适配组件发布，换边缘产品时要有对应产品的插件或旁挂进程（协议 20）。

## 替换时的检查

端到端检查对新边缘跑通：按路径段路由，相似前缀不串；超过请求体上限被拒；可伪造的头被剥掉；内部端点与 gRPC 端口从外部不可达；未登录取不到 `features`；改变状态的请求缺自定义请求头被拒；`TOKEN_STALE` 只重试一次，其他带请求体的失败不重试；绕过边缘直接访问组件，未带合格凭据仍被拒。

## 已知限制

- 限流按边缘实例计数：有两个实例时，在全局限流器出现之前，客户端能拿到两倍的额度。
- 族级前缀只容得下一个成员：同时装两个 IM 成员时，每个成员要声明自己的子前缀。
- Kubernetes 上，BrickKit 把共享注解写到每一份 Ingress 上，按路由不同的请求体上限或限额无法表达，直到平台提供按条目的注解。
- 生成的标签放在部署文件里；本地模式的部署文件整体取代它，重新生成后要刷新本地副本。
- 较旧的 Traefik 连不上较新的 Docker Engine：边缘的产品版本随引擎在代表部署实验中确定；Traefik 的管理面板只在开发环境开放。
