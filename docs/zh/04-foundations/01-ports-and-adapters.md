# 端口与适配器

一块基础设施什么时候算端口、它背后的实现怎么选、一致性套件怎么组织、SDK 及其契约怎么定版本、只有一个实现的端口怎么如实标注。要加端口、加适配器、加套件之前，或者要论证某样东西该不该可替换之前，先读这篇。

## 范围

本文写的是所有端口共用的规则。每个端口自己的契约、备选方案和更换步骤写在它自己的文档里，清单见[端口表](README.md#端口)。槽位族作为装配概念（每个变体一个组件，在组装项目时选）由 [0104](../02-decisions/01-architecture/0104-variants-become-slot-families.md) 决定；本文讲的是怎么证明这样一个族可以替换。语言中立的组件协议（不论用什么语言，每个组件都要实现它）另有一篇文档（计划中，02 号文件）；在这里它只是又一份带套件的契约。

## 选择

六边形架构的端口与适配器，只用在基础设施边界上。业务逻辑（订单状态机、补偿顺序）永远不是端口：错了就重写。基础设施和跨组件机制只设计一次，放在一份契约和一个一致性套件后面。

三条同时满足才算端口：

1. 它是基础设施，或者是跨组件共用的机制，不是业务。
2. 主流平台确实有不止一种合理实现，而且**今天就能说出**第二个实现的名字。
3. 换实现不改任何组件代码：只改 SDK 里的一个适配器、一个槽位族成员，或者项目配置。

这和 [09-ai-development.md](../01-conventions/09-ai-development.md#何时用设计模式) 里"说不出第二个实现就别抽象"是同一个判据，只是用在基础设施上：第二个实现已经说得出名字，抽象就值得。

端口背后的实现分三种：

| 种类 | 放在哪里 | 由什么选 | 例子 |
|---|---|---|---|
| **SDK 适配器** | 编译进每个官方 SDK，按 URL scheme 或某个配置值注册 | 一个共享配置值 | 事件总线、密钥来源、冷存储 |
| **槽位族成员** | 一个独立的组件，所有成员共用一份契约 | 项目装哪个成员（`brickkit add` / `remove`），加上共享变量 | 授权 provider、身份提供方、全局搜索 |
| **标准协议背后的产品** | 没有我们的代码：PostgreSQL 线协议、S3 API 或 OTLP 后面的一个官方镜像 | 共享配置里的地址 | 数据库引擎、对象存储、可观测性后端 |

每个端口都有四样东西：线协议层面的契约、一个默认实现、具名的备选、一个放在 `tools/be-acceptance/conformance/<套件>/` 下的套件。

**状态**：判据和套件的目录结构已定。多数套件已定但还没写；每个套件的状态见端口表。

## 端口契约

每个端口的文档在自己的**端口契约**一节里必须写清什么，以及每个适配器都要遵守的规则。

**端口契约写在线协议层面。** 组件可以用任何通过组件协议套件的语言来写，所以契约绝不是某一个 SDK 的函数签名。它要写明：

- 配置键；适配器按地址选时，还有 URL scheme（`nats://…`、`postgres://…`）；
- 线上格式：表结构、请求头或 metadata 键、消息字段、状态码、错误 reason；
- 能力清单，以及对每一项可选能力，没有它的适配器怎么做：答一个声明过的错误，或者走一个写明的降级路径，按能力逐项选定，绝不静默；
- 运维依赖的可观测信号（指标名与日志字段名），如果它们属于契约的话。

**运行期怎么选适配器。** 由一个共享地址键的 scheme 决定，比如事件总线的 `nats://…` 或 `postgres://…?schema=…`（这个键本身在 [12-event-bus.md](12-event-bus.md) 里定义）。键不存在时，SDK 回退到这个端口取代的旧键。组件从不 import、也从不点名某个适配器；适配器编译在每个官方 SDK 里，按 scheme 注册。在外壳里，每个进程一个适配器实例，每个成员一个句柄（[27-shells.md](27-shells.md)）。

**缺能力的适配器要大声失败。** 必需的能力缺了，它就拒绝启动，并点名是哪项能力；可选的能力缺了，它就答契约为这项能力声明的那个错误。静默地什么也不做是 bug：症状是某个功能对着默认适配器测试时"能用"，到了生产环境却悄悄什么也没做。

**槽位族的契约放在单独的仓库里**，绝不放在某个成员的仓库里：`contract-infra-authz`、`contract-infra-iam`。成员依赖契约，从不互相依赖；也没有任何组件依赖某个成员（[0104](../02-decisions/01-architecture/0104-variants-become-slot-families.md)）。

### 版本

- **线上契约只增不改**，与 [0302](../02-decisions/03-contracts-and-data/0302-contracts-are-additive-only.md) 同一条规则：一个请求头、字段、表列、reason 或 scheme 一旦发布，就绝不改名、改类型或挪作他用。必须改含义的字段，改成一个新字段。
- **官方 SDK 一起发布契约变更，用同一个版本号。** "SDK vX.Y"在 Go、Python、TypeScript 里意味着同样的线上行为，所以一个项目混用多种语言也不需要兼容性对照表。
- **同一个大版本内，SDK 对模块代码向后兼容。** 外壳用同一个 SDK 版本编译全部成员，同一门语言的所有组件和外壳都钉这同一个版本（计划中的门禁 `sdk-version-scan`），所以一个让某模块代码编不过的 SDK 小版本，会让托管它的每个外壳都编不过。一个 API 在某个小版本里标为弃用，在之后的小版本里才删，而且要等项目里已经没有组件再用它；把每个外壳都编译一遍就能证明这一点。
- **SDK 在每个组件 schema 里建的平台表**（outbox、inbox、任务租约、编号序列）按 expand/contract 演进：同一个成员单独运行时和在外壳里运行时，可能有一段时间用不同的 SDK 版本访问同一个 schema。平台 SQL 写明列名，从不 `SELECT *`。
- **套件随 `be-acceptance` 一起定版本。** SDK 的发布说明写明它通过的是哪个版本的套件。
- **组件协议在自己的仓库里定版本**，即计划新建的 `brickKit/be-protocol`：规范正文、schema、平台表的参考 DDL、语义向量和夹具契约都在里面，从 v1.0.0 起步。小版本只增加可选的面；要变成必须做到的行为，只能出大版本。`be-acceptance` 和各官方 SDK 钉同一个协议版本。

## 备选方案

| 做法 | 长处 | 短处 |
|---|---|---|
| **端口加一致性套件**（六边形：先定契约，再写每个实现都要跑的黑盒套件） | "可替换"变成一个测试结果；契约与语言无关；每个端口只有一个地方 | 每个适配器都要有一个套件，并且保持绿 |
| 不抽象：只有一个实现，直接用 | 代码最少；没有要保持同步的东西 | 以后要换就得改每个组件；第二个实现永远没被证明可行 |
| 通用的多后端抽象（ORM 方言、可移植的消息 API） | "白送"很多后端 | 最小公分母掩盖了每个后端自己的保证；边缘处会漏；ORM 已被 [0103](../02-decisions/01-architecture/0103-locked-stack-per-language.md) 排除 |
| sidecar 运行时（Dapr 的 building blocks） | 换后端只改 YAML；天生支持多语言 | 每个组件、每次调用多一个进程、多一跳；在 brickKit 旁边多出一套自己的组件模型；外壳没法再是一个进程 |
| 在一个实现里加配置开关 | 不用多建组件 | 所有客户的变体挤在一份代码里；已被 [0104](../02-decisions/01-architecture/0104-variants-become-slot-families.md) 排除 |

## 为什么选它

- **基础设施要一次做对；业务逻辑可以重写。** 正是这种不对称，端口只存在于业务层之下。
- **套件才让"可替换"成为事实。** 没有套件，第二个实现只是一句声明；有了套件，它就是 CI 里对每个适配器跑出来的测试结果。
- **组件可以用任何语言写**，所以契约必须落在线协议上。SDK 是它的一个实现，而不是它的定义。
- **对 AI 友好。** 每个端口一篇文档、一份契约、一个套件：要改事件总线的 AI 读这三样就够了，不用读每个组件。

## 为什么不选其他

- **不抽象**过不了我们自己的判据：端口表里每个端口的第二个实现都说得出名字、也确实有人要（小型安装要 PostgreSQL 队列，已经在用 Keycloak 的客户要 Keycloak）。
- **通用抽象层**恰好放弃了组件依赖的那些保证：事务级的角色切换、`SKIP LOCKED`、JetStream 的确认语义。而且 ORM 已被 0103 排除。
- **Dapr** 让每次调用变成两跳，每个组件多一个进程，也没法合并进外壳；它还和 brickKit 在组装期已经做的事重复。
- **配置开关**正是 0104 拒绝的做法：一份代码里装着每个客户的变体。

## 什么时候换

下面是改变"有哪些端口"的触发条件，不是更换某个端口背后实现的条件（那些写在各端口自己的文档里）：

- **升为端口**：第二个实现变得说得出名字，并且有客户或测试环境需要它时。先写契约和套件，再写第二个适配器。
- **降为非端口**：它的几种实现在实践中收敛到一个、也没人需要别的时（[0104](../02-decisions/01-architecture/0104-variants-become-slot-families.md) 的"何时重新讨论"）。套件保留下来当回归测试，标签改为"单适配器端口"。
- **SDK 适配器改为槽位族**：当这个实现需要自己的进程、自己的发布节奏或自己的数据库时，就像授权 provider 那样。

## 怎么换

更换任何一个端口背后的实现：

1. 读那个端口的**怎么换**一节：它会说明这次更换是改一个配置值、换一个槽位族成员，还是换一个基础设施产品。
2. 对目标跑那个端口的套件。套件红了就停。
3. 在 `config/vars.yaml` 里把共享值改一次（只针对某个环境时，改部署文件的 `vars:`）。槽位族就用 `brickkit remove` / `brickkit add` 换成员，并更新共享地址变量（[04-configuration.md](../01-conventions/04-configuration.md#依赖地址)）。
4. 组件代码不动。如果不得不动，说明端口的契约不完整：去补契约，而不是改组件。

新加一个适配器：

1. 在每个官方 SDK 里都写一份，否则在端口表里写明哪些语言有它。Python 里缺这个适配器，Python 组件就只能用默认的。
2. 注册它的 scheme 或配置值；把它加进套件的 CI 矩阵。
3. 先看到套件对一个故意写坏的假适配器跑红，再相信它的绿。
4. 把它写进端口的文档（**备选方案**、**怎么换**）和端口表。

## 一致性测试

目录结构：`tools/be-acceptance/conformance/<套件>/`，每个端口一个文件夹，用端口的短名命名（`db`、`store`、`bus`、`jobs`、`rpc`、`userapi`、`authz`、`iam` 等）；组件协议套件是 `conformance/component/`。非正式简称 `dbconf`、`authzconf`、`iamconf`、`compconf` 分别指 `conformance/db`、`conformance/authz`、`conformance/iam`、`conformance/component`。共享语义的向量（金额、时间、编号、请求指纹等）不是套件：它们放在计划新建的 `brickKit/be-protocol` 仓库的 `vectors/` 里，各套件和每个 SDK 的单元测试都从那里读。

每个套件最多三层：

| 层 | 内容 | 对什么跑 |
|---|---|---|
| **向量** | 取自 be-protocol `vectors/` 的 JSON 黄金用例：输入与期望结果。每个官方 SDK 读同一批文件，必须算出相同结果 | 各 SDK 自己的测试运行器 |
| **适配器黑盒** | 每个适配器对应的真实基础设施，所有适配器跑同一批用例 | 一个用完即弃的实例（`testcontainers`），或 `make up` 起的那个实例 |
| **组件黑盒** | 一个运行中的容器，只走它对外的端口；不看语言 | `brickkit build` 产出的镜像 |

规则：

- 没有声明某项能力的适配器，要测它声明的错误或降级路径。跳过这一项的套件是坏的。
- 新套件先对一个坏掉的假实现见一次红，它的绿才算数（[06-testing.md](../01-conventions/06-testing.md#红绿节奏与铁律)）。
- 套件找不到可测的东西时要失败，绝不悄悄跳过。静默跳过会连续几个月显示为绿，却什么也没验证。
- 组件协议套件（`conformance/component`）是新语言组件的门槛：通过它，组件才能进入项目并单独运行。

## 已知限制

- **单适配器端口如实标注**：后台任务、用户 API、缓存。它们的价值在于一套语义加一个套件，不在于能换。暗示它们能换的文档是错的。
- **只在一个家族内可替换。** 数据库端口指的是 PostgreSQL 方言族；离开这个家族，就要移植每个组件的 repo 层（[03-database.md](03-database.md#已知限制)）。
- **适配器按语言各写一份。** 某个适配器还没在每个官方 SDK 里写出来之前，缺它的那门语言的组件只能用默认的。
- **一个外壳只合并同一种语言的成员**，而且只限于有官方 SDK 和外壳启动器的语言。其他语言的组件单独运行。
- **多数套件还没写**；某个套件存在之前，那个端口表里的备选方案只是设计上留了位置，还没有被证明。
