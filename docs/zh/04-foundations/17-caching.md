# 缓存

数据在哪些地方离读取方比离属主的表更近，以及为什么项目不跑缓存服务器。读者是准备加缓存、加快照、加 Redis 的人，或者想知道某个值为什么晚了几秒的人。

## 范围

所有"读的那一刻不问数据属主"就能作答的做法：

- 某个成员进程内的缓存（展示用名称、查找表）；
- 每个进程都持有的权限 bundle 和身份公钥集（JWKS）；
- 别的组件数据的快照：存成读取方自己 schema 里的表，由事件刷新；
- 每个组件在自己 schema 里维护的授权投影（`besdk_authz_acl`，见 [20-authorization-provider.md](20-authorization-provider.md)）；
- 报表用的汇总表。

不在本文：网关上的 HTTP 缓存（计划中的 `18-edge.md`）、浏览器缓存、PostgreSQL 自己的缓冲区。

## 选择

**没有缓存服务器。缓存只活在一个成员的进程里，经 SDK 创建，有容量上限、TTL、并发回源只回源一次（single flight）、指标和由事件触发的失效。** 凡是要在副本之间共享、或者要扛过重启的，都是组件自己 schema 里的一张表，不是缓存。

项目里的每一类需求，以及它落在哪里：

| 需求 | 存在哪 | 怎么失效 | 要不要共享缓存 |
|---|---|---|---|
| 权限 bundle | 进程内存，每进程一份（外壳里也是一份） | 每 15 秒带 `ETag` 的条件 GET，外加 `infra.authz.changed.v1` 的 poke | 不要 |
| JWKS | 进程内存 | token 带了没见过的 `kid` 时重新拉取，限频 | 不要 |
| 主数据快照（客户、产品） | 读取方 schema 里的表 | 属主发的事件 | 不要 |
| 授权投影 | 组件 schema 里的 `besdk_authz_acl` | 拉取 changefeed，外加 poke | 不要 |
| `BatchGet` 拿到的展示用名称 | 可选的进程内缓存，TTL 30 秒 | 属主的事件，或 TTL 到期 | 不要 |
| 限流 | 边缘层（计划中的 `18-edge.md`）；应用级配额用 PostgreSQL 计数窗口 | 窗口结束 | 单机不要；多个网关实例时限额按实例平摊 |
| 会话 | 无状态 JWT；refresh token 存在 iam 的 PostgreSQL | 轮换 | 不要 |
| 幂等键 | `besdk_idempotency` 表 | 保留期 | 不要 |
| 分布式锁 | 行锁、事务级 advisory 锁、任务租约（[10-local-transactions.md](10-local-transactions.md)、[19-background-jobs.md](19-background-jobs.md)） | 事务结束、租约到期 | 不要 |
| 第三方 access token（钉钉） | 组件 schema 里的一行，加进程内互斥；跨副本刷新时加一把事务级 advisory 锁 | 到期 | 不要 |
| 热点读、报表 | 汇总表 | 事件或定时任务 | 不要 |

**状态**：bundle、JWKS、快照和汇总表已在用，就是这样做的。SDK 缓存帮手、它的指标、全局 map 门禁和一致性套件已定（随 3.0.0 统一升级落地）；在那之前，确实需要进程内缓存的组件按模块自己写一个有上限的，绝不用包级 map。

## 端口契约

缓存是一个只有一个适配器（进程内）的端口。契约是每个 SDK 都要实现的行为，与语言无关：

- **身份**：一个缓存有一个在本组件内唯一的名字、一个最大条目数、一个 TTL。三者必填；不允许无上限的缓存。
- **操作**：get、set、delete、flush。get 遇到缺失或过期的条目时调用加载函数；同一个缺失键上的并发 get 只调一次加载函数，共享结果（single flight）。加载出错时把错误返回给每个等待者，错误不进缓存。
- **淘汰**：超过条目数按最近最少使用（LRU）淘汰；TTL 从 set 那一刻算起。
- **失效**：缓存可以绑定一个事件 subject；每收到一条事件，就删掉该事件聚合 id 对应的条目（绑定声明要求时，清空整个缓存）。失效是尽力而为的，过期程度的上限是 TTL。
- **隔离**：每个成员一个实例。外壳里两个成员各有一个同名缓存，看到的是两个不同的缓存。缓存绝不放在包级变量或全局变量里。
- **指标**（Prometheus，每条序列都带 `component` 标签，见 [23-observability.md](23-observability.md)）：`be_cache_hits_total{name}`、`be_cache_misses_total{name}`、`be_cache_evictions_total{name}`、`be_cache_entries{name}`。
- **绝不跨请求缓存**的：授权决策。本地权限判定、远程 `Check` 的回答、资源级 `_authz/check` 的回答，最多只在当前请求内记住。缓存的决策在撤销以后还会继续放行，而省下的只是一次内存查找。

## 备选方案

| | 进程内 LRU（选用） | Valkey / Redis | Memcached | PostgreSQL unlogged 表 | PostgreSQL 普通表 + `LISTEN`/`NOTIFY` |
|---|---|---|---|---|---|
| 新增要运维的服务 | 无 | 一个有状态服务 | 一个服务 | 无 | 无 |
| 副本之间共享 | 否 | 是 | 是 | 是 | 是 |
| 扛过重启 | 否 | 可选 | 否 | 否（崩溃后被清空） | 是 |
| 失效 | 事件或 poke，TTL | TTL、pub/sub | TTL | 清扫 | `NOTIFY` |
| 外壳里 | 按成员创建即安全 | 键要加成员前缀 | 键要加成员前缀 | 靠 schema 隔离 | 靠 schema 隔离 |
| 一次读的代价 | 内存查找 | 一次网络往返 | 一次网络往返 | 一次查询 | 一次查询 |

## 为什么选它

- 客户在一台资源有限的机器上部署；每多一个基础服务，就多一样要安装、备份、加固、监控的东西（[0201](../02-decisions/02-permissions/0201-no-redis.md)）。
- 逐项过一遍上面的表，没有一项需要进程之间共享的缓存：每一项都已经在 PostgreSQL 或进程内存里有了着落。
- 决策缓存是最容易出错的缓存：撤销了的共享或角色，在条目过期前照样有效。决策不缓存，这一整类问题就没有了。
- 按成员创建的进程内缓存天然合并安全：外壳的行为和成员单跑完全一样。

## 为什么不选其他

- **Valkey / Redis**：换来的是副本之间的共享，而眼下没有任何需求要它；代价是一个有状态服务、每次读一次网络往返，外加一个分布式失效问题。外壳里每个键还得加成员前缀才能合并安全。
- **Memcached**：代价和 Redis 一样，保证更少。
- **PostgreSQL unlogged 表**：崩溃后行全部丢失，还要一个清扫任务；读它的代价和直接读属主自己的表差不多。
- **`LISTEN`/`NOTIFY`**：每个监听者都要一条长期占用的会话级连接，transaction 模式的连接池给不了（[03-database.md](03-database.md)）；经 NATS 的 poke 已经在做这件事。

## 什么时候换

[0201](../02-decisions/02-permissions/0201-no-redis.md) 的重议条件必须同时成立：有一个实测的负载，PostgreSQL 加进程内内存确实撑不住，数字写了下来，而且涉及的不止一个组件。另外加一条触发条件：多副本部署下，业务判定某一项读在副本缓存之间的不一致窗口（最多一个 TTL）不可接受。

## 怎么换

1. 先改写 0201；决策优先于本文。
2. 在每个官方 SDK 里，在同一份缓存契约后面加一个 Valkey 适配器。组件代码一行不动：组件只看得见缓存契约。
3. 在 `config/vars.yaml` 加一个共享键 `CACHE_URL`；它的 scheme（`redis://`）选择适配器，没有这个键就仍用进程内适配器。
4. 每个键加上成员的组件 ID 和缓存名作前缀，外壳里的成员互不干扰。
5. 对新适配器跑缓存一致性套件；它必须通过和进程内适配器相同的用例。

## 一致性测试

套件 `tools/be-acceptance/conformance/cache/`（已定），对每个官方 SDK 跑（布局见 [01-ports-and-adapters.md](01-ports-and-adapters.md)）：

- 超过条目数时，淘汰最近最少使用的条目；
- TTL 到期后重新调用加载函数，同一个键的并发未命中只调一次；
- 绑定的事件到达后，下一次读调用加载函数；
- 外壳里，两个成员的同名缓存看不到对方的条目；
- 加载出错时每个等待者都收到错误，错误不被缓存。

门禁 `module-global-cache-scan`（已定）：模块代码里用包级 map 或并发 map 当缓存时告警；先对一个故意违规的样例跑红一次，才信它（[06-testing.md](../01-conventions/06-testing.md#门禁与横切检查)）。

## 已知限制

- 多副本时，两个副本对同一个读的回答最多会相差一个 TTL。
- 外壳里，每个成员的缓存内存分开计算，但操作系统不强制；成员的条目上限就是它的预算。
- 每次重启后缓存都是空的；部署后的头几个请求要付回源的代价。
- 展示用名称最多可能晚 30 秒；必须精确的数据，从属主读或者从快照表读。
