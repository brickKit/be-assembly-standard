# 共享、委托与只读扮演

本页说清楚“让别人看”“替我办”“按我的视角排查”各自的授权来源、责任、范围、到期与撤销。读取、动作与字段继续使用[安全 01](01-authorization-evaluation.md)，身份取证使用[安全 02](02-trusted-identity-and-attributes.md)，并发节点与输出使用[安全 03](03-authorization-acceptance-and-revocation.md)，管理上限使用[安全 04](04-authorization-administration-and-appointments.md)；本页补的是来源与派生的规则。

默认小公司可以只启用单资源的只读共享与单层委托；有需要的客户再启用关系继承或有限的再委托，不以模型的名称假定这些能力已经交付。业务 agent 只预留位置，不实现。

## 方案选择

| 路线 | 判断 |
| --- | --- |
| **采用**：共用完整授予与时间结构，按来源类型区分生命周期 | 普通的机构授予、业务关系、依赖个人资格的委托各自可以解释，沿用已有的求值、身份与收紧机制 |
| 所有来源都复制成接收人的普通角色或附加 ID | 丢失动作、范围、字段、当前资格与责任绑定；满足不了完整授予与代理上限 |
| 所有授予都随授予操作人的资格消失 | 对个人委托合理；对合法的机构授予与正常的管理员交接违背 D36，会无故中断业务 |

## 来源类型与责任

| 来源类型 | 执行主体与权威 | 有效性依据 |
| --- | --- | --- |
| 普通资源共享 | 接收人以自己的身份读取；授权组件保存人工授权，业务属主提供资源与共享治理的事实 | 资源的治理边界、接收资格、明确的授予与期限；授出者是历史操作人，默认不是永久的个人委托来源 |
| 组件拥有的团队、成员、层级关系 | 接收人自己；关系事实归对应的业务组件，授权组件只保存受控的视图 | 当前的关系实例与层级，及其明确的读取或业务动作契约；不允许管理员伪改来源关系 |
| 个人临时查看或代办 | 实际操作者自己，保留被代表主体与来源的申请或委托 | 明确的个人来源、它当前的资格、创建上限、目的与期限；不套用普通机构授予的“卸任保留” |
| 休假审批代理 | 代理人自己，记录代谁履职；业务流程属主拥有任务与替代规则 | 委托人当前完整的审批资格、受托人必要的执行资格、任务与内容、本人自审的控制 |
| 只读扮演 | 实际支持人员与被查看主体分别记录；身份组件验证与签发身份，授权组件验证许可 | 真实操作者的扮演资格、被查看人当前的读取权限、会话上限与只读 profile |
| 服务代理用户调用 | 用户仍是被代表主体，另外验证直接服务 | 安全 02 的用户证据与服务方法许可；技术转发不自动变成业务委托 |
| 已接受业务的持久后续 | 受限的服务主体；原发起人只是历史责任信息 | 已建立的业务 B 的限定过程与当前的必需控制；不按个人代办令牌长期运行 |

个人来源与机构治理来源必须显式登记；不能从 `granted_by` 的名字、接口路径或有没有 `act` 来猜。治理上限被撤销或收紧、对象跨法人迁移、接收人失去资格、安全冻结，仍会影响普通共享；不是“历史操作人卸任后什么都不变”。

## 普通共享的授出与退出

- **授出资格**：普通资源共享先要求明确的共享管理资格与机构资源治理上限。能读不自动能分享；持有临时查看或委托读取，也不自动获得持久共享权。标准共享只授出声明资源的读取，不新增确认、取消、付款、关账等动作。
- **授予的绑定**：候选授予绑定资源类型与稳定 ID、接收主体或受控的组、法人等治理范围、允许的读取操作、显式字段、条件、有效期与来源修订。创建时用安全 04 的完整包含证明核对机构可分享的上限，不从授出者可读字段的全集隐式复制。这项治理权限本身必须由合格的管理者确认；不能把个人的短期阅读权包装成可以长期授出的机构边界。
- **属主与授权组件的分工**：业务属主声明哪些资源与字段可以分享、怎样验证对象存在与当前的治理边界；授权组件验证已认证属主的证明、用户身份或管理资格与当前上限，在受保护的生效点写入授予、修订与必要的审计。单纯的 `be-caller` 与客户端自报的负责人不作来源证明。跨属主的证明、水位与收紧沿用安全 01–03，不用“先本地成功、再等消息最终同步”冒充共享已完整生效。
- **读取段**：接收人的普通角色不必原本覆盖这条记录，但有效的共享必须产生明确、满足安全 01 字段与范围规则的读取段，以及声明的 `view_key` 资格。字段限制不改变结果集合的完整性义务；共享不能顺便开放任意父对象、伙伴的银行资料、附件、搜索或报表字段。
- **不默认带导出与再分享**：页面、附件访问、导出与公开链接各有声明的操作与目的。资源允许的普通查看可以包含受控的附件展示，但不能由“共享订单”推出原始文件的直接永久 URL。具体的渠道与字段映射在资源契约中声明。
- **授出人变化**：正常更换授出操作人或管理员，不自动撤销机构共享；管理责任按安全 04 接管，来源历史保留。对象的负责人改变后是否保持共享，按预先登记的治理规则处理；变化跨越绑定的法人、共享政策、资源类型或字段含义时，先保护受影响的授权，再复核或迁移，不让旧 ID 的授予无条件跟到新域。资源的删除、合并与墓碑按[跨组件引用的协议](../07-references.md)，不能让 ID 复用把访问权交给新对象。
- **撤回**：由有权管理该资源或授权域的人执行；接收人可以放弃自己的那份共享；不删掉另一条独立的合法授权。关闭、到期、撤销与停用都留据；普通读取的失效窗口与严格出口分别按安全 03 声明。结束后的新共享使用新的授权实例，不通过修改旧期限复活旧会话。

## 团队、组与层级继承

- **组**：共享给组时，先验证组的来源、资格与成员的完整性；成员加入或退出由组的属主处理，不能凭身份组件的外部组名自动扩权。动态组声明允许的成员变化语义、法人边界与字段规则；不支持组来源的完整性时，只允许共享给直接的主体，不以缺少成员信息代表全集。
- **父子与团队关系**：只按声明的契约动态派生完整段。每条路径保留父授权的身份、关系实例与版本、范围、字段与资格限制，并核对当前子资源的治理边界；不把父授权复制给每个孩子、失去撤回的联系。关系成环、过深、图被截断或缺边的事实，属于无法证明，不返回假的完整集合。
- **撤销与移动**：撤销一条父授权或成员关系，关闭相关的派生路径；另一条独立的合法路径可以继续。对象移出父层级后，旧路径不再授权；移入不支持或跨法人的新父级时，不自动继承。逐记录的字段只从当前合法的路径取并集，不能借另一个对象或分支的明文字段。
- **属主的边界**：资源属主拥有团队关系，不意味着它可以绕过用户资格与业务控制。关系声明可以承接特定的业务动作，但普通的人工共享仍只读；两者使用不同、明确的来源能力。完整查询与冷热、投影的水位继续满足安全 01、03。

## 个人委托的创建上限与使用求值

- **保存的内容**：根被代表主体、真实的受托主体及其必要资格、来源资格实例与修订、目的、工单或任务、明确的动作、资源、范围、条件与字段、创建时的完整上限、时间窗、授权链与撤销状态。请求人与合法的确认者按委托类型声明；独立确认不能通过另一个已关联的账号规避。
- **创建**：要有专门的委托资格，且每个拟委托的完整段包含于当时来源合法的完整许可与可委托的 profile。受托人可以没有原来的同名业务角色，但必须有该动作要求的实际执行资格；不能把职业资格、合法签署的任职或法定限制一并从委托人复制过去。不能委托的动作明确拒绝，不删掉检查后用系统身份执行。
- **使用时求交**：使用时重新取证来源当前的完整许可，把每份完整的来源段与创建上限、各条有效的委托边、资源范围与字段限制、本模式的 profile 相与，再按安全 01 产生合法的派生段。来源许可只在自己合法的分支内求并集；不能把甲的范围与乙的字段或额度拆开拼接。逐维求交见[安全 07](07-finite-expressions-containment-and-queries.md#求交委托和扮演的派生段)。
- **两头都管**：创建上限防止委托人后来扩权、让旧委托自动扩大；与当前许可求交，防止后来缩权、留下旧的宽许可。角色新增权限、改任职或组织边界等扩权修订，不自动更新上限，要重新确认；明确声明的动态资源集合可以覆盖它契约内的新记录，但不等于自动换到新法人、新岗位或解释不同的范围。
- **不与受托人自己的许可合并**：请求明确选择是自己履职，还是某一份代办依据，业务属主核对它与任务相容。所选的委托失败时，不悄悄用自己的另一任职或服务身份兜底；需要自己的合法动作时，走独立、明确的自有权限请求，不把结果记到失败委托的审计里。
- **最小读取单独声明**：委托动作所需的最小读取，单独声明为受限的完整段，分别被来源当前的读取资格与创建或委托的字段上限覆盖；审批资格本身不自动开放 view 或成本明文。缺少合法的最小读取、无法形成完整的业务能力时，拒绝启用相应的代理路径，不用系统 BatchGet 绕过。
- **默认不可委托**：授权管理、身份绑定与凭据变更、创建持久共享、创建新的委托、紧急提权，不从普通代办中默认获得。其他不可委托的动作按资源与业务 profile 登记；复杂客户确实需要受控扩展时，单独设计确认与验收。

## 休假审批与业务责任

- 代理委托只覆盖明确的流程职责或节点、业务操作、范围与时间，不复制委托人的全部角色。实际操作者、被代表主体、委托人所用的任职、受托人实际的履职证据分别记录；需要指定合法签署身份的动作，声明是否允许代办、受托人必须具备什么，不能只选一个别人的任职 ID。
- **本人自审**检查适用的责任主体、已关联的账号、实际的代理人、被代表主体，以及业务要求的受益或申请关系。代理人不能审批自己或委托人发起的单据来规避 D10；多级代办也不隐去参与的责任，无法证明分离就保护，不能把未知当成不同的人。
- **待办改派不创造权限**：流程属主按 D38 的绑定规则与当前资格处理任务（[协议 09](../09-approval-and-workflow.md)）。原处理人失去资格或委托结束后，未处理的任务回到仍合格的原职责，或重新解析合法的接任者；没有合法路径就暂停转人工，不盲目退回已离职的用户。旧任务的结果按任务与内容修订、执行依据处理，迟到的回执不覆盖新任务的状态。
- 代审批在相应的 A、B 节点检查当前的来源、受托资格、本人自审与内容或审批依据。委托撤销与已合法接受的动作按安全 03 分档裁决；需要“生效点仍合法”的管理或特定签署，采用同事务的 A、B 或提交屏障，不能笼统宣称所有旧接受立即取消。

## 再委托与多级链

- **基础 profile**：默认只允许一条个人委托边，再委托关闭。普通的代理请求不能把获得的权限变成永久的角色、共享或另一个委托；简单客户没有这项能力，也不影响机构的分级管理。
- **层数怎么算**：最大层数只计算有业务授权含义的委托边，不按 HTTP 服务的跳数或 JWT 历史 actor 的数量计。普通的技术转发或受众收窄不新增业务委托；改变合法的受托主体或下放业务权时，必须形成相应的受控边，不能伪称“只是转发”来避开再委托的检查。
- **有限再委托**：复杂客户启用时，父边必须显式允许；profile 声明最大边数、允许的类型与动作、来源完整性的能力；每次新增边独立确认，子边的资源、字段、条件与期限只能收窄。禁止自环、跨部署、责任主体绕道回到自己；不能把一串同名但不同的账号当作无环的证明。
- **链的求值**：从受信的根资格与链上的授权记录验证每一条边，终点取全部相关期限的最小值，当前来源与治理的收紧逐边应用。链的批准不让中间的受托人获得别人的职业资格；任何必要的边或事实未知、到期或被撤销时，该路径不贡献许可，其他独立完整的路径分别判断。
- **链来自授权记录**：不从 JWT 嵌套 `act` 的历史 actor 声明推出资格。[RFC 8693 §4.1](https://www.rfc-editor.org/rfc/rfc8693.html#section-4.1) 的历史 actor 只作历史表达；本项目额外的逐边上限来自权威的委托记录，绑定 ID 与修订并验证，不把历史 JSON 当完整的授权图。

## 只读扮演与会话隔离

生产环境可以声明支持只读扮演，用于受控地按用户视角排查问题：要有专门的扮演资格、明确的目标、原因或工单与短期会话，不允许业务写入。真实的支持人员与被查看主体在每条访问与审计中都保留；被查看者收到开始的通知。

- **读到什么**：只读的结果是被查看主体当前完整的读取许可，与本次授权的目标、资源、字段与 profile 上限的交集。真实操作者的超级用户或更宽的业务权限不与目标许可并集，也不能通过系统身份读取额外的字段。支持人员没有目标的业务角色时，可以凭合法的扮演资格进入受限模式，但不获得持久的角色。
- **副作用 profile**：所有实际的路由与用例都声明副作用类型。只读扮演拒绝 PATCH、确认、取消、管理，更要拒绝用 GET、GraphQL resolver、附件预签名、导出作业或订阅启动隐蔽的变更。必要的会话与访问审计、查看通知可以按协议产生，但不能让“通知”“渲染”成为发送付款、发布业务指令或对外打印的入口。敏感导出、原始文件下载与外部投递，默认不属于扮演的只读 profile。
- **会话**：起始上限 15 分钟（待评审的起始参数），没有刷新令牌，不通过刷新或换目标延长；续用就重新申请、重新取证。扮演会话与操作者的普通会话隔离；切换或退出时撤销对应的扮演会话，前端清除它私有的缓存、订阅与文件引用；旧的授权游标不跨模式复用。已显示的数据不能追回，后续的输出继续按安全 03 保护。
- **变化与模式**：被查看者被关闭、暂停或权限变化，按当前事实与安全 03 的风险节点和窗口生效；历史副本不保持目标旧视角的权限。身份变化与服务端请求使用相同的模式标识，不能只改前端的标签；开发用的全权扮演不能作为生产的默认分支。

## 服务、agent 与紧急访问的边界

- **服务代理**：先证明服务与用户；委托记录还限定服务或客户端、受众、目标与用途；`kind=svc` 不免除代理资格、当前上限或受众的检查。后台的用户导出、通知中的链接与推送、订阅，按执行与交付的节点重新验证；已建立的 B 的持久后续按安全 03 的业务过程规则执行，不携带长期的个人令牌。
- **agent**：仍是预留，不实现令牌交换或自动审批。将来允许时，它的工作负载身份、受信的用户委托、工具与动作许可、目的与确认节点都要声明；模型输出、提示词或工具名不能充当授权；没有完整的能力时拒绝，不能映射成服务或管理员来避开检查。
- **临时提权与紧急访问**不是普通代办：由安全 04 的合格管理路径授出受限、可撤销、带期限的机构许可，保留申请、独立确认、通知与复核，默认不允许自批。应急登录与恢复必须独立于已失效的认证路径，并明确备用身份与安全状态的取得机制；不开放无认证的后门或全权角色，也不默认“先用后审”（合同事先约定的紧急访问见[安全 08](08-state-and-change-protocol.md)）。
- **公开或外部访客链接**不是普通共享。将来启用时，需要独立、不可猜的凭据，接收身份或持有者的语义，资源、操作与字段，期限、用途、撤销，入口与频率控制的声明；不能把登录用户的共享变成任何持有 URL 的人都可见。现在只保留能力边界，不宣称已实现链接分享或 agent。

## 状态、续期与撤销的影响

| 阶段或变化 | 行为 |
| --- | --- |
| 申请、预览 | 记录目标、目的、候选边界与时间，不产生有效的读取或代办能力 |
| 确认、激活 | 在受保护的管理生效点重新验证资格、范围与字段、来源修订，持久保存来源与独立的授权实例；未知结果按幂等键查询 |
| 生效、到期 | 左闭右开；每次求值保留时间；缓存与输出的终点不晚于必要资格的终点；作业只是通知与整理 |
| 续期、扩权 | 新的候选与合格的确认；不通过修改旧实例的期限或上限恢复旧会话；新记录包含旧记录时，旧记录在同一个生效点以“被替代”结束（[安全 08](08-state-and-change-protocol.md#通用生命周期)），两者明确关联 |
| 改目标 | 先收紧：结束或收窄旧记录（立即生效）；再为新目标申请新记录，经确认与生效点；新记录生效之前，旧目标上已经没有访问（安全 08 的变更方向） |
| 上游个人缩权或失效 | 相关的个人委托路径按当前求交或保护，再可靠地更新派生视图；不等消息最终到齐才做安全裁决 |
| 普通的机构操作人卸任 | 不自动撤销合法的机构资源共享，按安全 04 接管；治理边界与接收资格仍动态检查 |
| 撤销一条路径 | 关闭该授权或委托边，处置缓存、会话与未接受的任务；其他独立合法的路径不一律删除 |
| 内容、归属或治理的修订 | 资源的最低安全水位与当前范围一起验证；不能借旧的分享关系读取不相容的新内容 |
| 恢复、成员切换 | 保留主体、授权实例、来源类型与修订、链与终态；用新的恢复代次核对安全状态；不复活旧会话，不只复制角色名 |

- 共享与委托的创建、扩大权限，需要可靠、受保护的生效证据；结束路径还维护影响依赖的索引，覆盖链边、组与父关系、会话、未接受的任务与输出。索引帮助快速收紧，不代替完整求值：索引有缺口时，关闭有关的域并对账，不能以“没有找到下游”证明无人受影响。
- 撤销分别报告安全 03 的“关闭新接受”“关闭旧提交”“保护出口完成”三种状态；不把通知成功、事件已发或撤下 JWT 密钥当作全部结束。已接受的动作、已提交的事实与已交付的副本按原协议处理，不写“撤销一律回滚全部”。

## 通知、审计与期限 profile

- **通知**：只读扮演的开始通知、授权的申请与决定、委托结束与重要异常，都有可靠的意图记录与受控的重试。通知不放用户令牌、敏感明文或长期的下载能力；站内通知与外部渠道的投递状态分开。“被查看者被通知”不能只在发送失败的日志里算完成：profile 声明站内可见的落点、投递预算、无法完成时的保护；没有合格方案时，不启用该扮演路径。
- **审计**：记录来源类型与实例、真实、被代表与批准的主体、合法的责任绑定、上限、资源与内容修订、请求模式、接受、提交与撤销的节点与结果。长期保存由[协议 03](../03-audit-durability.md)承担。
- **期限 profile**：每种来源声明最大期限、续期与确认规则、能否再下放、动作与字段的 profile、来源的健康与失效窗口、并发、数量、深度与查询预算、输出方式；缺必要参数或提供方能力，阻止启用。机构共享允许明确的“无固定终点”政策时，仍保留资格、治理与复核的控制，不把“没有日期”解释成秘密字段或跨域的永久访问。
- **期限数值**：除只读扮演的 15 分钟起始上限外，不直接采用知识库中 2 小时、8 小时、31 天等样例作为所有客户的期限。审批代理按声明的假期或职责时间窗受限，起止按业务日历换算为 UTC。共享、委托与扮演在通用生命周期中的参数、通知落点与影响闭包见[安全 08](08-state-and-change-protocol.md#共享委托与扮演的参数)，编码与 profile 见[安全 09](09a-encoding-and-records.md)。

| SD10 | 代理人、委托人或已绑定的其他账号发起被审的单据 | 按责任规则防本人自审；合法的他人单据正例成立 |
| SD11 | 只委托审批，没有合法的最小 view 或字段；系统 BatchGet 可读 | 不借系统读取绕过，须完整声明可读的代理业务路径 |

| SD17 | 扮演开始通知发送失败，必要的站内落点不可用 | 按 profile 可靠重试或保护，不把日志记了失败当作已通知 |
| SD18 | `kind=svc`，或未启用的 agent 请求带管理员 actor | 不跳过服务或委托的认证，不把 agent 降级为服务身份 |
| SD19 | 委托到期或撤销，与 A、B、任务重派、迟到的结果竞争 | 按安全 03 分档与业务职责裁决，不延长旧资格，不自动回滚事实 |
| SD20 | 撤销前的旧备份、提供方切换、索引漏边或证据失联 | 恢复时核对来源类型与链、水位、代次；缺完整性先保护，不复活旧令牌 |
| SD21 | 共享被复制成公开 URL；撤权后使用旧的下载能力 | 默认不允许匿名分享；URL 按真实的窗口或代理能力（安全 03）验证 |
| SD22 | 临时提权自批；应急只靠已失效的身份组件或默认全权的后门 | 不绕过安全 04 的管理与恢复边界；没有合格的能力不启用 |

## 依据与独立判断

知识库的委托与临时访问、完整授予与责任章节提供中立参考。本项目按 D36 区分机构授予与个人委托，不把知识库“个人来源随时失效”的规则一概套到机构共享；当前的风险时序按安全 03，不直接承诺“每次请求都检查”就等于提交时有效。

[RFC 9700 §2.3](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.3)用于核对令牌的用途、受众与最小权限，[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)用于核对每个入口的保护。来源类型、共享治理与派生上限是本项目的语义，标准的令牌交换或日志字段不替本项目证明业务授权正确。

## 已知风险与待定

- 各来源的默认期限参数、通知落点与投递预算，在共同能力 profile 中确定（安全 08、09）；没有合格的通知方案时，只读扮演不启用。
- 不可委托动作的清单随资源与业务 profile 登记。
- 公开访客链接与业务 agent 只保留能力边界，启用前单独设计与验收。
