# 扩展字段

客户常需要在标准实体上多记几项信息：客户的行业分类、产品的内部编码、订单的项目号。按定制的顺序（[工程规范的可配置与可定制](../01-conventions/01-engineering.md#可配置与可定制)），这类需求先用扩展字段满足，不需要 Fork。本页回答：

1. 哪些实体可以扩展，扩展值存在哪里，由谁校验与授权？
2. 字段改名、删除、改类型时，已有的值怎样不被误读？
3. 扩展字段怎样贯穿接口、事件、导入导出、报表、冷数据？
4. 扩展字段能做什么、不能做什么？

依据的决定：D32（有限业务设置）。本页是设计；什么时候实现由重建计划排期，组件在实现之前于自己的 `BRICKKIT.md` 写明还没有。

## 方案比较

| 路线 | 判断 |
| --- | --- |
| **采用**：实体表上一个 JSON 列，键为稳定的字段 ID；字段定义由属主组件管理；受限字段自动登记权限键 | 不改表结构即可增删字段；改名、删除、重建同名字段都不会错读旧值；属主统一校验与授权 |
| 属性-值表（EAV） | 灵活，但查询与排序要多表连接，类型校验分散，记录多时性能差 |
| 客户直接给实体表加列 | 查询最快，但每次增删都是数据库迁移，与标准版的升级冲突，等于变相 Fork |
| JSON 列但按字段名作键 | 简单，但改名会丢值，删除后重建同名字段会把旧值当成新字段的值（参考模型的坏变体） |

## 可扩展的实体与属主

- 实体的资源定义（[安全 09a](security/09a-encoding-and-records.md#定义资源维度操作与字段)）声明 `extensible: true` 与配额，才允许扩展。主数据（业务伙伴、产品、员工）与主要的单据头（订单、账单）通常可以扩展；流水与账务明细（出入库流水、分录）默认不可以扩展，因为它们是不可变的事实，扩展需求应放在来源单据上。
- 扩展值由实体的属主组件保存、校验、授权，与实体本身在同一个事务中写入。其他组件把扩展值当作不透明的数据，只有在声明了需要时才读取。

## 字段定义

字段定义是属主组件中的一条版本化记录，由客户授权的管理员通过管理界面维护（与 D32 的有限业务设置同样的权限、校验、审计与生效规则）。

| 属性 | 约束 |
| --- | --- |
| 字段 ID | 系统生成，永不复用；扩展值以它为键 |
| 键名 | `x_` 开头的小写下划线名，同一实体内对生效中的字段唯一；标准字段永不使用 `x_` 前缀，所以标准版升级不会撞名 |
| 显示名 | 多语言文本 |
| 类型 | 文本（最大长度）、整数、十进制（精度与小数位）、金额（引用同一实体上的币种字段）、日期、时刻、布尔、选项（选项有稳定的 ID）、引用（按[协议 07](07-references.md) 声明为历史引用或资格引用） |
| 基数 | 单值或多值（多值有数量上限） |
| 必填 | 只对生效后新建或修改的记录要求，不使已有的记录变为无效 |
| 缺省值 | 可选 |
| 校验 | 长度、范围、受限的格式模式；不支持任意脚本 |
| 字段类别 | 普通或受限（安全 09a 的 `FieldDefinition`）；受限字段在授权目录中自动登记客户命名空间的读、写权限键 `x.<实体>.<字段 ID>.read` 与 `x.<实体>.<字段 ID>.write` |
| 查询用途 | 可筛选、可排序；每个实体可以开启的数量受配额限制 |
| 状态 | 生效中、已弃用、已删除（见下表） |

| 当前状态 | 事件 | 结果状态 | 动作 |
| --- | --- | --- | --- |
| （无） | 管理员新建 | 生效中 | 生成新的字段 ID；受限字段登记权限键；需要索引的由工作项建立 |
| 生效中 | 修改键名、显示名，放宽约束 | 生效中（新版本） | 值以字段 ID 为键，不受影响 |
| 生效中 | 收紧约束 | 生效中（新版本） | 只对之后的写入生效；已有不符合的值保留，并在报表中标出 |
| 生效中 | 弃用 | 已弃用 | 不再接受新值，已有的值可读 |
| 已弃用 | 删除 | 已删除 | 保留期后由工作项清理值；字段 ID 不复用 |
| 已删除 | 任何事件 | 已删除 | 不复活；再建同名字段得到新的字段 ID |

## 演进规则

| 变化 | 规则 |
| --- | --- |
| 改键名或显示名 | 直接修改定义；值以字段 ID 为键，不受影响 |
| 加长文本长度、放宽范围 | 直接修改 |
| 收紧约束（缩短长度、缩小范围） | 只对之后的写入生效；已有不符合的值保留，并在报表中标出 |
| 改类型 | 不允许原地修改：新建字段，由迁移工作项（[协议 01](01-background-work.md)）转换已有的值，弃用旧字段；转换失败的值列入清单待人工处理 |
| 删除 | 先弃用；保留期后由工作项清理值；字段 ID 不复用 |
| 删除后再建同名字段 | 得到新的字段 ID；旧值不会出现在新字段下 |

## 扩展字段的边界

- **不参与核心业务规则**：计价、库存、过账、信用额度、审批路由的标准逻辑不读扩展字段。需要基于扩展数据的业务逻辑，用扩展组件（订阅核心事件、拥有自己的数据）或 Fork。
- **不是授权维度**：数据范围的维度由产品在资源定义中声明（[安全 07](security/07-finite-expressions-containment-and-queries.md)），客户不能把扩展字段变成授权维度；受限的扩展字段只在“字段可读写”的层面受控。
- **不能改变核心字段的含义或必填性。**

## 贯穿各出口

| 出口 | 规则 |
| --- | --- |
| 接口 | 读写时扩展值放在 `ext` 对象中，以键名呈现；响应附字段定义的版本；按字段资格逐行掩码（安全 07 的命中位图规则同样适用） |
| 事件 | 实体的状态事件包含扩展值与定义版本；消费者只投影自己声明需要的扩展字段（[协议 02](02-projections.md)） |
| 导入导出 | 模板包含扩展字段；导入按定义校验，逐行报告失败 |
| 报表与分析 | 分析侧取得字段定义与版本，按字段资格过滤 |
| 冷数据与归档 | 扩展值随记录归档；归档清单记录字段定义的快照，解冻时按快照解释 |
| 搜索 | 声明为可筛选的字段进入搜索投影 |
| 审计 | 变更记录以字段 ID 记录，展示时取当时的定义 |

## 存储与索引

- 实体表上一个 JSON 列，键为字段 ID；属主在写入时按定义校验类型与约束。
- 可筛选的字段使用 JSON 包含查询的通用索引；可排序的字段按需建立表达式索引，数量受配额限制。索引的建立与删除由属主的工作项执行，不在请求中进行。
- 数据库方言的差异由 SDK 的数据访问层处理，扩展字段协议本身不依赖某一种数据库的私有语法。

## 配额起始值

| 配额 | 起始值 |
| --- | --- |
| 每个实体的扩展字段数 | 50 |
| 每个实体可排序的扩展字段数 | 5 |
| 单条记录的扩展数据大小 | 16 KiB |
| 多值字段的值数 | 20 |

## 参考模型

[扩展字段模型](../../../tools/be-acceptance/models/20-extension-fields.py)（种子 20261013，3,000 次运行）：管理员随机新建、改名、删除、改类型、删除后重建同名字段，同时持续写入记录。按字段 ID 存储时，值只在写入时的字段下被读出、类型始终符合、改名不丢值；按字段名存储（错读与丢值）与原地改类型（类型不符）两个坏变体都被发现。模型不是 SDK 或数据库的运行结果。

## 独立预期

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| EX01 | 字段改名 | 已有的值仍可读 |
| EX02 | 删除字段后新建同名字段 | 新字段的 ID 不同，旧值不出现 |
| EX03 | 文本字段改为整数 | 不允许原地修改；新建字段并迁移，失败的值列清单 |
| EX04 | 新增必填的扩展字段 | 已有的记录不变为无效；新建与修改时要求填写 |
| EX05 | 受限的扩展字段 | 自动登记读写权限键；无权限者读到掩码、不能写 |
| EX06 | 用扩展字段影响价格计算 | 标准逻辑不读；需要扩展组件或 Fork |
| EX07 | 把扩展字段设为数据范围的维度 | 不允许 |
| EX08 | 标准版升级新增同名的标准字段 | 标准字段不用 `x_` 前缀，不撞名 |
| EX09 | 导入含扩展字段的数据 | 按定义校验，逐行报告失败 |
| EX10 | 归档记录解冻 | 按归档时的定义快照解释扩展值 |
| EX11 | 超过配额新建字段或排序索引 | 拒绝并提示配额 |
| EX12 | 流水或分录请求扩展 | 默认不可以扩展；需求放在来源单据 |
| EX13 | 订阅方没有声明需要某扩展字段 | 它的投影不包含该字段 |
| EX14 | 定义变更 | 有版本与审计；受 D32 的管理权限约束 |

## 已知风险与待定

- 各实体是否可以扩展、配额多少，随组件设计逐个声明。
- 管理界面的形态与前端的通用渲染方式，随前端设计确定（[协议 20](20-frontend.md)）。
- 选项类字段的选项增删与多语言、跨法人是否共享定义，在第一版实现前确定。
- 以上预期尚未在 SDK 或数据库上运行。
