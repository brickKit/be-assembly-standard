# 交易与库存

库存是物理库存变动的唯一写入者；销售与采购通过库存契约请求变动，不自己维护余额。合同管长期约定与周期出账，订单管一次交易（D70）。

## erp/sales

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有对外销售的客户；实物与服务共用订单基础（D44） |
| 必需依赖 | `mdm/partner`、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：实物订单必需，只有服务订单时可以不装；`erp/credit`：缺时无信用控制（装配时确认）；`erp/tax`：缺时报价的税额为人工录入；`crm/opportunity`（上游，只经事件）：商机发布“请求报价”，销售生成带商机参考的报价草稿，缺时报价照常手工创建；`erp/finance`：款到发货策略在放行交货前认领订单的预收额度（或采用预收发票形态），缺时该策略不能启用；`crm/customer`（上游，只经事件）：负责人变化，只用于显示与建订单时负责人的默认值；订单与报价的负责人是销售自己拥有的字段，按负责人限定的数据范围（“销售只看自己的订单”）用这个字段，不用 CRM 的关系投影；`erp/contract`：订单引用合同的价格与框架额度，缺时只用价格表；物流承运成员（`integration/carrier-*`）：缺时运单号人工录入；`erp/billing`（下游）：缺时不能出账；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）（D11）；电商平台成员（下游，`integration/shop-*` 转换平台订单）：缺时没有平台订单入口 |
| 范围 | 当前重建 |
| 设计 | 重建中（实验第 7 步）：统一语言、拥有的数据、不变量、命令与查询、事件、依赖、实现状态与验证故事在组件仓库的 [docs/design.md](../../../components/erp/sales/docs/design.md)；细则在 [docs/flows/confirmation.md](../../../components/erp/sales/docs/flows/confirmation.md)（确认过程）、[docs/rules/pricing.md](../../../components/erp/sales/docs/rules/pricing.md)（单价与金额）、[docs/flows/delivery-and-billing.md](../../../components/erp/sales/docs/flows/delivery-and-billing.md)（交货与可出账台账）；用法、部署与配置在组件做好后的 `BRICKKIT.md` |

## erp/contract

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有长期客户合同、框架协议或订阅（周期收费）业务的客户；只做一次性销售的不需要 |
| 统一语言 | 合同与版本；框架协议（价格与数量承诺，客户侧与供应商侧）；订阅；周期出账计划；续约；终止；框架额度 |
| 拥有的数据 | 客户合同与供应商框架协议及其版本、价格与额度承诺、订阅与周期计划、对出账的来源额度（每期可出账金额）、续约与终止记录 |
| 不变量 | 生效后的修改以新版本表达，已出账的周期不受影响；每个周期的可出账额度只产生一次，由本组件裁决，同一来源不被重复认领（协议 05）；终止后不再产生新周期 |
| 命令与查询 | 合同的维护、提交审批、生效、变更、续约、终止；周期计划的生成（定时槽位，协议 01）；来源认领（出账的请求，协议 05）；额度与执行查询 |
| 事件 | 合同状态事件；周期到期（来源额度变化，增量事实）；续约与终止 |
| 必需依赖 | `mdm/partner`、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | 电子签渠道（`integration/esign-*`）：缺时线下签署后上传；`infra/attachment`：缺时不能保存合同文本；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理；`erp/billing`（下游，向本组件认领）：缺时只记录到期，不出账；`erp/sales`（下游，订单引用合同的价格与框架额度）：缺时合同只用于订阅与周期出账 |
| 替换与 Fork | 周期与计费规则（按月、按年、预付或后付）是替换点；行业合同模型可 Fork |
| 部署 | 低负载、周期批量；适合外壳 |
| 适用协议 | 01（周期生成）、02、05、07、08、09、10（电子签）、13、14、16（期初合同）、安全 01–09 |
| 范围 | 远期（新身份，D70） |
| 验证故事 | 停机两天后补生成的周期不重复出账；合同变更后，已出账的周期不变、新周期按新版本；终止后不再产生周期；两人同时为同一周期出账只成功一张 |

## erp/purchase

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有采购业务的客户 |
| 统一语言 | 采购申请；采购订单（可带项目参考）；预付；到货与验收（服务验收）；收货请求；收货计价依据；采购退货；三单匹配的依据；直运（远期） |
| 拥有的数据 | 采购申请、采购订单、修订、到货通知、服务验收记录、退货单、对应付匹配的来源依据（已到货、已验收数量与金额） |
| 不变量 | 收货数量由库存的入库事实确认，采购只记录进度；同一采购明细的已验收数量不超过订单数量加允许的超收比例 |
| 命令与查询 | 申请与订单的维护；审批；预付申请（请财务形成预付未清项）；发起收货（请求库存入库，流水带收货行参考；装了复杂仓储时发布收货请求）；服务验收；采购退货（请求库存出库，引用原入库流水）；匹配依据查询（供应商票据匹配，D50；带订单行的预算分支身份；期末供财务查询已验收未开票的明细）；供应商价格表、询价与比价；供应商返利（结算经财务的供应商贷项） |
| 事件 | 订单状态事件；收货请求（带订单行参考，供仓储）；验收事实；收货计价依据（键是收货行参考，在发起收货或订单审批时发布，带单价与币种，供成本）；采购退货（供仓储与成本；均为增量事实） |
| 必需依赖 | `mdm/partner`（供应商角色）、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：库存物资采购必需；只有服务采购时可以不装；`erp/contract`：采购订单引用供应商框架协议的价格与额度，缺时只用价格表；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）；`erp/finance`（下游，向本组件查询匹配依据）：供应商票据匹配在财务应付内部，缺时没有应付；`erp/costing`（下游，消费收货计价依据）：缺时收货不参与计价；`erp/tax`：采购订单的税额，缺时人工录入；`erp/budget`：请购与订单的预算占用（协议 04 的分支），缺时不受预算控制；预付申请同样经 `erp/finance`，缺时预付只能线下处理；`erp/inventory`（远期，只经事件：寄售的所有权转移）；`erp/sales`（远期，只经事件：直运请求）；`prj/project`（下游，只经事件）：带项目参考的采购归集到项目 |
| 替换与 Fork | 采购策略（比价、配额）是替换点 |
| 部署 | 前台为主；适合外壳 |
| 适用协议 | 01、02、05（应付匹配依据）、07、08、09、13、14、16、安全 01–09 |
| 范围 | 当前重建（D63） |
| 验证故事 | 收货回调丢失时按库存的入库事实补齐进度；超收超过比例被拒；服务采购按验收形成匹配依据 |

## erp/intercompany

| 项 | 内容 |
| --- | --- |
| 何时需要 | 多法人集团中法人之间互相买卖的客户；单法人不需要 |
| 统一语言 | 关联方（对应法人的伙伴）；公司间规则；对开单据（甲的销售对应乙的采购）；内部往来对账；转移价格 |
| 拥有的数据 | 公司间规则（哪些法人之间、自动或经确认、价格依据）、对开记录（来源单据与生成单据的对应）、内部往来对账结果与差异 |
| 不变量 | 每张来源单据至多生成一张对开单据（按来源事实 ID 去重）；对开单据经属主的接口生成，本组件不写它们的数据；来源的修订与取消传给对开单据，已执行部分按属主的规则处理；对账差异只报告，不自动调账 |
| 命令与查询 | 规则维护；对开（自动或经确认）；对账运行；差异查询与处置 |
| 事件 | 对开完成或失败；对账差异 |
| 必需依赖 | `erp/sales`（来源单据）、`erp/purchase`（对开采购单）、`mdm/partner`（关联方）、`mdm/org`、身份、授权 |
| 可选依赖与缺件 | `erp/finance`：内部往来的账面余额，缺时只核对单据层面 |
| 替换与 Fork | 转移价格与对开规则是替换点 |
| 部署 | 低负载、事件驱动；适合外壳 |
| 适用协议 | 01、02、05、07、13、14、安全 01–09 |
| 范围 | 远期（新身份，D72） |
| 验证故事 | 甲的订单确认事件重复到达只生成一张乙的采购单；乙的采购不可用时对开进入重试并可见；甲取消订单，乙的对开单按采购的规则取消或转人工；期末甲的内部应收与乙的内部应付不一致时列出差异 |

## erp/planning

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要补货建议（再订货点、安全库存）或物料需求计划的客户；只做服务或手工补货的不需要 |
| 统一语言 | 补货规则（再订货点、安全库存、最高最低库存）；需求（销售订单、预测、生产用料）；供给（在库、在途采购、在制工单）；计划运行；建议（采购、生产、调拨）；下达 |
| 拥有的数据 | 补货规则、需求预测、计划运行记录与建议、建议的下达记录 |
| 不变量 | 只产生建议，不直接改变库存、采购或生产；建议由人确认后经属主的接口下达（采购申请、生产工单、调拨），每条建议至多下达一次；计划运行基于声明的数据截至时点，并在结果中标明 |
| 命令与查询 | 补货规则与预测维护；计划运行（手动或定时槽位，协议 01）；建议查询、确认与下达 |
| 事件 | 计划运行完成；建议下达 |
| 必需依赖 | `erp/inventory`（在库与预占）、`mdm/product`、`mdm/org`、身份、授权 |
| 可选依赖与缺件 | `erp/sales`：需求来源，缺时只按预测与再订货点；`erp/purchase`：在途供给与采购建议的下达，缺时采购建议只能人工处理；`erp/manufacturing`：BOM 展开、在制供给与生产建议的下达，缺时只做采购件与调拨的补货 |
| 替换与 Fork | 计划算法（再订货点、MRP、排产）是替换点（D27），整体可替换 |
| 部署 | 计划运行批量较重，后台预算单独；按负载单跑 |
| 适用协议 | 01、02、13、14、16 |
| 范围 | 远期（新身份，D71；承接原在制造中的 MRP） |
| 验证故事 | 低于再订货点生成一条采购建议，确认下达后只生成一张采购申请；重复运行不重复下达；BOM 修改后的新运行按新版本展开 |

## erp/warehouse

| 项 | 内容 |
| --- | --- |
| 何时需要 | 仓库作业复杂（波次、拣货路线、复核、打包）的客户；简单出入库不需要 |
| 统一语言 | 作业单；波次；拣货任务；复核；打包；任务推进状态 |
| 拥有的数据 | 作业单、波次、任务与推进状态、对库存提交的引用 |
| 不变量 | 不保存可独立扣减的余额；任务完成与库存提交分别定义，以库存的提交结果为准；库存已提交但应答丢失时查询恢复，不重复扣减 |
| 命令与查询 | 生成波次；分派与执行任务；复核；打包；取消任务 |
| 事件 | 作业与任务状态 |
| 必需依赖 | `erp/inventory`、`mdm/product`、身份、授权 |
| 可选依赖与缺件 | `erp/sales`（上游，只经事件）：订阅交货请求与退货状态生成出库与退货入库作业；`erp/purchase`（上游，只经事件）：订阅收货请求与采购退货生成入库与退货出库作业；现场打印代理（标签）：缺时不打印标签；物流承运成员（`integration/carrier-*`）：缺时运单号人工录入 |
| 替换与 Fork | 整体可替换为另一仓储实现；拣货策略是替换点 |
| 部署 | 仓库现场的终端访问；单跑或外壳 |
| 适用协议 | 01、02、04（与库存的协调）、10（标签打印）、13、20（仓库终端入口） |
| 范围 | 远期（新身份，D45） |
| 验证故事 | 拣货完成提交库存时超时，查询后恢复，不重复扣减；任务取消与预占到期并发 |
