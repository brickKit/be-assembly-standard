  3. `BRICKKIT_SERVED_MEMBERS`——逗号分隔版本化服务名，字典序；**零成员时是显式空字符串，不是变量缺失**（这条细节直接影响 Task 0.3 的实现，不能只判断"变量存在与否"）。

  6. **多版本共存**：同一个外壳收编同一组件的两个不同版本——**已确认支持**，brickKit 自己有单测（`TestResolveGroupsTwoVersionsOfSameComponentUnderOneShell`），唯一约束是端口不能撞。同一个 `(id, version)` 不能同时独立部署又被 `servedBy`——文档说是"重复声明"这条通用规则的推论，但**没有直接定位到对应代码**，需要我们自己真机确认。**两个不同外壳各自收编同一组件的不同版本**——brickKit 自己完全没有测试或文档覆盖这个场景，是真正的未知领域，我们是第一个要去踩的。
  7. `local: true` 的字段语义、K8s 下的拒绝逻辑、代码路径，`servedBy` 落地前后**完全没变**（已用 `git show` 核对具体 commit 的 diff，不是只读文档）。
