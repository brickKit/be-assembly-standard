## 1. 边界

**归我：**

- **展示与交互**：视图渲染、表单交互逻辑（联动显隐、正则校验、防抖节流、本地草稿）。
- **按装配与权限动态注册路由与菜单**：`features ∩ permissions`（§3.3）。
- **两端的页面**：PC（AntDV + vxe-table）与移动端（wot-design-uni），**共享 token 不共享组件**（§2.2）。
- **登录回调与 token 交换的前端那一半**：拿 Casdoor 回调 → 调适配层换应用 token → 存起来 → 静默刷新（§3.4）。

**不归我：**

| 什么 | 归谁 | 为什么 |
|---|---|---|
| **任何核心商业逻辑** | 后端组件 | §8.4 铁律：价格计算、库存防超卖、信用额度校验**严禁放前端**。要实时试算就调后端的 `DryRun` 接口（§8.4） |
| 权限的**判定** | 后端 `be-sdk` | §14.1.8：**前端判定从来不是安全边界**，它只决定"要不要显示"。后端仍然会 403 |
| 数据聚合 | `infra-bff-mobile` | 复杂页面走 BFF 一个查询；简单页面直接调网关 |
| 打印渲染 | `infra-print` | 我拿到 PDF 字节流负责展示/下载 |
| 认证本身 | Casdoor | 账密/微信/QQ/Google 全在它的登录页（`infra-iam-casdoor` §1.1） |

**`data_scopes: none`**（§14.2.2 要求显式写）——前端无数据库。

### 1.1 阶段三具体做哪些页面（范围已定，不做完整 CRUD）

阶段三的目标是**把附录 E 那条链路跑通**，不是把 62 个组件的页面做完。所以：

| 页面 | 对应组件 | 为什么这一档必须有 |
|---|---|---|
| 商机列表 + 详情（**标记赢单**按钮） | `crm-opportunity` | 链路的起点 |
| 销售订单列表 + 详情（确认 / 发货 / **打印送货单**） | `erp-sales` | 链路的主干 + `infra-print` 的入口 |
| **待办列表 + 待办详情（同意 / 驳回）** | `infra-workflow` | 链路里"审批"那一环，**也是移动端的主场景** |
| 通知中心（站内信 + 通道偏好） | `infra-notification` | 链路里"钉钉通知"的另一半（站内信）与偏好设置 |
| **角色管理 + 给人授角色** | `infra-authz` | §14.3 明确列在阶段三。**没有它就没法验权限判定**——所有接口标真实权限键之后，得有地方把角色发下去 |
| 客户 / 产品 列表 + 详情（只读为主） | `mdm-*` | 建单要选客户和产品 |
| 库存查询、应收查询（只读） | `erp-inventory` / `erp-finance` | 验证链路结果，**只读，不做出入库/手工凭证界面** |

⚠️ **移动端只做待办与通知两块**（审批 + 消息），不做建单——移动端建 ERP 单据是伪需求（§12.6.1.1：
移动端的形态是卡片列表/扫码/两个审批按钮）。

## 2. 拥有的数据

**无数据库。** 前端的"状态"分三层，归属见设计书 §12.6.8：

| 层 | 存哪 | 例子 |
|---|---|---|
| **装配期配置** | 构建产物 / 环境注入 | 主色、logo、水印、灰度——**不归用户**（决策 114） |
| **用户偏好（跟人走）** | 后端（`infra-*` 的用户偏好接口） | **只有四项**：收藏的组件、亮/暗、密度、语言 |
| **纯本地** | `localStorage` | 表格列宽/列序、未提交草稿 |

⚠️ **决策 114 明确拒绝的**：布局模式切换器、三十项偏好。**多一个偏好项 = 62 个组件的页面多一种组合要测。**

### 2.1 ⭐ `packages/design-tokens` 必须在写第一个页面之前定死

**这是整套前端设计里唯一有时间压力的一条**（决策 114 原文）：

- 亮/暗与密度都要**运行时切**，所以 tokens 必须是**运行时可写的 CSS 变量**，不能是编译进 bundle 的 TS 常量；
- 晚定的代价不是"改一个文件"，是**改每一个已经写好的页面**。

⚠️ **阶段三 Task 12 的第一步必须是它，不是任何页面。**

### 2.2 两端共享 token，不共享组件

| | PC | 移动端 |
|---|---|---|
| 组件库 | AntDV v4 + vxe-table | wot-design-uni |
| 我们的封装 | `packages/ui-kit-pc` | `packages/ui-kit-mobile` |
| 共享的 | **只有 `packages/design-tokens`**（纯数据、零框架 import） | 同左 |

⚠️ **两端用不同组件库是设计使然，不是妥协**（决策 111）：移动端是卡片/扫码/两个按钮，PC 是密集表格 +
多级联动长表单，**共用组件的收益接近零**。⚠️ **不许为了"统一"再抄一层跨端组件**。

⚠️ **第三方 UI 组件只许出现在两个 ui-kit 包里**（§12.6.3），业务页面一律用我们自己的组件名（`<BeTable>`
而不是 `<vxe-grid>`）。理由同 `be-sdk-*`：**换实现改一个文件，而不是改 40 个页面**——而 vxe-table 是
"默认选择、待核"（部分能力属商业版），这条尤其要紧。

## 3. 契约面

**对外：无 API。** 我是纯静态资源（Nginx 托管构建产物），**不提供任何接口**。

**我调用的**：

| 调谁 | 走什么 | 说明 |
|---|---|---|
| 各业务组件的 REST | **经网关** | 简单页面直接调 |
| `infra-bff-mobile` 的 GraphQL | 经网关 | 复杂聚合页面，一个查询喂满一屏 |
| `infra-iam-casdoor` | 经网关 | `/api/tenant/features`、换 token、刷新 |
| Casdoor 登录页 | **浏览器直连** | 标准 OIDC，不经过我们任何后端 |

⚠️ **我不在同步图里**（§6）：这些都是浏览器发起的 HTTP，不是组件间的服务调用。

### 3.3 ⭐ 路由与菜单：`features ∩ permissions`，两个都要判

```
可见路由 = features（这个环境装了没有）
         ∩ permissions（这个人能不能）
```

⚠️ **只判 features 不判 permissions 的症状是：菜单看得见、点进去整页 403**（导读第 20 条、§14.1.8）。
这是前端最容易犯的一个错，因为**开发时用的管理员账号两个都满足**，测不出来。

⚠️ **反过来也不行**：只判 permissions 不判 features，会在没装某组件的环境里显示一个永远 404 的菜单。

**数据来源**：`features` ← `/api/tenant/features`（`infra-iam-casdoor`）；`permissions` ← `/api/me/permissions`
（`infra-authz`）。两者都在登录后拉一次。

### 3.4 登录与静默刷新：前端要做的那一半

```
① 未登录访问 → 重定向到 Casdoor 登录页（账密 / 微信 / QQ / Google）
② Casdoor 回调带 code → 换 Casdoor 身份 token
③ 拿身份 token 调 infra-iam-casdoor 的 POST /api/iam/token → 拿到**应用 token** + refresh token
④ 之后所有请求带应用 token
⑤ 收到 401 且 WWW-Authenticate 带 error="token_stale" → 静默刷新 → 用新 token **重试原请求一次**
```

⚠️ **第 ⑤ 步只重试一次**（§14.1.6 原文："只重试一次，防死循环"）。这条是**必须实现的防线**，
不是优化——没有它，"刷新回来仍然不满足"的情形会变成用户侧的无限转圈。

⚠️ 第 ③ 步是阶段三新增的一步（`infra-iam-casdoor` §3.2），**旧版设计书附录 D 的时序图里没有它**，
那张图已经订正。

### 3.5 PC 骨架：AWS Console 式两级导航（§12.6.7，形态已钉死）

| 元素 | 说明 |
|---|---|
| 服务选择器 + 收藏栏 | 62 个组件不做左侧多级树（决策 113：每个客户装的组件不同，那棵树家家形状不同） |
| **服务内菜单强制扁平** | 与 AWS 不同的第一处必改 |
| **应用内标签页** | 与 AWS 不同的第二处必改——**ERP 一张未保存的出库单，浏览器一刷就没了**（决策 113） |
| ⌘K 全局搜索 | |
| **组织/法人切换器** | 替代 AWS 的 Region 切换器；给 `erp-finance` 的 `legal_entity` 数据权限维提供当前值（§14.2.2） |

⚠️ **业务页面一律从 `ui-kit-pc` 的页面级模板起手**（`BeListPage`/`BeDetailPage`/`BeFormPage`/`BeSettingsPage`），
**不许从空白 `<div>` 摆布局**——决策 113：AWS Console 最被诟病的就是视觉不统一，而**我们的病因一模一样：
62 个组件的页面由 AI 分批生成**。

## 4. 事件

**发布：** 无。**消费：** 无。

前端不接事件总线。实时性需求（如"待办来了要不要弹一下"）**本阶段用轮询**，不引入 WebSocket/SSE——
判据是 §11.4.1 的时间窗思路：审批待办的时效性要求是分钟级，轮询足够，而长连接会带来
"网关配置 + 断线重连 + 多标签页去重"三件事。记进 §9 第 3 条。

## 5. 依赖

**强依赖 / 弱依赖：均无。**

⚠️ **前端在 `component.yaml` 里不声明任何 `dependencies.components`**——它**只认网关**（§4.2 同步图的注释：
`FE --> GW`）。后端有没有装、装了哪些，通过运行时的 `/api/tenant/features` 得知（§3.3），不是靠平台的依赖解析。

**明确不依赖：**

| 谁 | 为什么不建依赖边 |
|---|---|
| 任何后端组件 | 见上。**建了依赖边反而会坏事**：平台会因为某个组件没装而阻断前端启动，而前端本该在任何装配组合下都能起来 |
| 数据库 / NATS | 前端无后端资源 |

## 6. 在同步图与三枢纽里的位置

**不在同步图里。** 设计书 §4.2 的图里我只有一条虚线 `FE -.->|只认| GW`。所有请求都是**浏览器发起的**，
不是组件间调用——所以我既不可能引入环，也与"CRM 与 ERP 零同步边"无关（**跨域数据在我这里聚合正是
§4.7"展示上推"指定的做法**）。

⚠️ **我与 `infra-bff-mobile` 都是"跨域聚合"的合法场所**，区别是：BFF 做**服务端**聚合（一个 GraphQL 查询），
我做**客户端**聚合（并发几个 REST 请求再拼）。简单页面用后者，复杂页面用前者。

## 7. 分区与归档策略

**不适用——无持久化数据（§2）。**

`localStorage` 里的表格列态与草稿是**每个浏览器各自的**，不同步、不备份、清了就没了。
⚠️ **不许把任何业务数据放进 `localStorage` 当缓存**——多标签页与多设备之间没有失效机制，
症状是"在另一台机器上改了，这台还显示旧的"。

**明确没有参考的**：Element Plus / Naive UI 等其他 Vue 组件库。**不是没查，是决策 111 已经锁定**——
再比较一次没有意义，且"为了更好看混第二个 UI 库"被明确拒绝（两个库的 token 体系对不齐，混得越多越不好看）。

**要避免它的什么：**

| 项目 | 它的做法 | 我们为什么不这么做 |
|---|---|---|
| vue-vben-admin 等 admin 模板 | 提供"布局模式切换器"和几十项偏好 | 决策 114：真实客户没人切，而它让 62 个组件的页面要在三种布局下各测一遍 |
| 多数 admin 模板 | 菜单来自后端的中心菜单表 | 决策 112/113：我们没有中心菜单表，菜单是 62 份 `assembly.yaml` **生成期聚合**的 |
| 常见做法 | 业务页面直接 import 第三方组件 | §12.6.3：换实现要改 40 个页面。一律走 `ui-kit-*` |
| 常见做法 | 前端自己算金额/折扣做"实时预览" | §8.4 铁律：调后端 `DryRun`。前端算的和后端算的迟早不一致，而**不一致的那一次一定发生在客户面前** |

**读完之后，这里有没有「多种实现都合理、只是适配客户不同」的分歧？**

**有，但它已经是槽位族本身，不需要新增。** `slot:frontend` 四个成员（`standard`/`advanced`/`{industry}`/`{customer}`）
正是"每一种都合理、只是客户不同"的形态：标准版、增强版、行业版、客户定制版。

**它也是全系统少数几个真正满足 §5.11 硬约束的位置**——**没有任何组件对前端建依赖边**（§5），
所以换成 `frontend-advanced` 真的只改 `brickkit.yaml` 一行。**这与阶段二那 9 条交易组件分歧的结论
形成正反对照**：前端能做 slot，恰恰因为它是 DAG 的叶子、没人依赖它（复盘 §4 第 5 条）。
