# 0012 多种合理实现并存，是新增槽位族的信号

## 决策

当成熟系统对同一功能给出真正不同的实现、而且每一种都适合某一类客户时（成本核算方法、拣货策略、审批路由），这个功能就成为一个槽位族：每种变体一个组件，契约完全相同，客户在组装时选一个。它不是某个组件里的配置开关。先设计并登记这个族，再实现任何成员；其他组件不得对族成员建依赖边。

## 理由

开关会把每个客户的变体塞进同一份代码里，为一个客户做的改动可能弄坏另一个客户。槽位族让每种变体各自独立，客户可以从最接近自己需要的那个成员 Fork。如果某一种实现明显优于其他，它就是默认实现，不需要建族。

## 挡下什么

- 在组件里写 `if costingMethod == "fifo"`
- "加一个设置，让客户自己选算法"
- 每来一个新客户就多一个取值的策略开关
- 反方向的错误：把普通设置做成族（单据编号规则就是一个配置键），或者把"主数据多几个字段"做成族（那是 Fork）
- 其他组件直接依赖某个族成员

## 何时重新讨论

实际使用中各变体收敛到同一种实现时——族随之收缩为这一个。
