# 0007 权限是纯并集，没有 Deny

## 决策

一个用户的权限，就是他所有角色权限的并集。没有 Deny 规则，也没有规则优先级。针对某一个人的例外，就是只有他一个成员的角色。

## 理由

纯并集下，"这个人为什么能做这件事"永远只有一个答案：授予它的那个角色。Kubernetes RBAC 不设 Deny 正是出于这个原因；先 Deny 后 Allow 的求值顺序，正是 AWS IAM 策略难以推理的根源。

## 挡下什么

- "销售部除了老王以外都能看"；"禁止实习生导出"
- 否定权限、黑名单、规则之间的优先级或顺序
- 在 `registry/permissions.tsv` 或 bundle 里加 Deny 列

要表达"除了 X 以外都可以"，就给这个用户一个不含 X 的角色。

## 何时重新讨论

某项合规要求只能表述为凌驾于所有授权之上的禁令，而且无论怎样拆分角色都表达不了时。
