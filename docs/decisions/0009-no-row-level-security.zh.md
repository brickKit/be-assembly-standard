# 0009 不用行级安全，不做共享引擎

## 决策

数据范围的条件写在每条查询的 SQL 里，以参数传入（`sqlc` 或手写 SQL）。不使用 PostgreSQL 行级安全（RLS），也没有通用的记录共享引擎。`org` 维度按物化路径 `dept_path` 的前缀匹配；没有任何组件保存组织树的副本。

## 理由

静态参数化 SQL 能表达本项目的所有维度，而且规则只在评审者会读的那一处。RLS 让规则多出第二个存放地，还带着一个静默陷阱：表的 owner 默认绕过 RLS，策略可能存在却什么都没过滤。通用共享引擎等于在造 Zanzibar，与单机部署不相称。

## 挡下什么

- "给这张表开 RLS"；`CREATE POLICY`
- 在每个组件里做一套"把这条记录分享给用户 X"的表和机制
- 为了解析"本部门及下级"而复制组织树，或在副本上做递归查询
- 给不属于任何部门的表（产品分类、计量单位）加 `dept_path` 列

## 何时重新讨论

出现一个真实的数据范围，无法写成静态参数化 SQL 时。
