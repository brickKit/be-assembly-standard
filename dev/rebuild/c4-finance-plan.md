阶段“按依赖顺序重建其余组件”的 C4（[components-plan.md](components-plan.md)），2026-11-10 维护者定先于 C3（收付款的事实要按本组件定义的会计事实契约发布，付款认领与核销在本组件）。照 C2 的做法（[c2-purchase-plan.md](c2-purchase-plan.md)）：先定首批范围与源头要补的能力，按改动的循环做，每一步先写红的测试，改坏检查，发布，真机格从空库到 L3。数据与改坏检查放 `c4-data/`。

- 仓库：`components/erp/finance` 已在 C0 重置（只有 README，旧代码在 `legacy/v2`）；注册表的端口与 schema 待核对。

## P0 的结果（2026-11-10，AI 定，待复核）

**首批做的**：

| 能力 | 怎样做 |
| --- | --- |
| 科目表、过账规则与科目映射、会计期间 | 按法人；过账规则键 → 借贷科目（来源不写科目，协议 05 的会计事实契约）；期间开、关（首批手工关，带“没有未过账事实”的检查） |
| 凭证 | 借贷平衡；凭证号按法人与期间连续（协议 14）；已关期间不能过账；手工凭证经审批（审批人不是制单人） |
| 会计事实契约（共享） | 财务定义、放在本组件的契约里（schema 与版本）；来源组件按它发布（各自的事件类型，形状相同），财务按装配清单订阅、按事实身份去重、按规则键与映射生成凭证；首批的来源是以后的成本、收付款，契约与接收先做好 |
| 应收形成 | 订阅出账的 `erp.invoice.issued.v1`：一个本地事务里形成应收未清项与凭证，发布“应收已形成”（协议 05 第 2 步） |
| 供应商票据与三单匹配 | 登记供应商票据（带采购订单行时向 `erp/purchase` 的 `MatchService.Basis` 取依据，容差内通过；没有订单的按审批）；形成应付与凭证；发布“票据单价确认”（给以后的成本） |
| 付款认领与到期未清项查询 | 认领、续期、确认、释放、冲回（协议 05 的认领模式与付款用法），只用可用余额；给收付款（C3）用，系统面 |
| 人工未清项 | 缺来源时登记应收应付（经审批） |
| 核销的接收方 | 按收付款以后发布的资金事实核销（锁内分配，发布“已核销”“应收结清”“应收减少”“应收重开”）；收付款在 C3 才有，首批先把核销的事务与事件做好、用替身驱动测试 |
| 查询 | 账簿、余额、未清项、账龄 |

**不在首批**（理由与触发）：

| 能力 | 理由 | 触发 |
| --- | --- | --- |
| 关账批次的协调（请求封存、已封存、迟到顺延） | 参与方（出账、收付款、成本）还没有封存接口 | 第一个参与方的封存做好时（C3 或 C5） |
| 预收与款到发货的放行台账、预收放行认领 | 销售的款到发货还没做 | 销售做款到发货时 |
| 预付申请、员工借款 | 采购的预付申请首批没做；报销不在当前重建 | 采购做预付申请时 |
| 外币重估、递延计划、收货未开票的期末暂估 | 期末步骤，依赖关账批次 | 关账批次做时 |
| 维度目录与成本中心 | 首批事实只带部门（`mdm/org` 的身份），财务校验部门即可 | 第一个带别的维度的来源 |
| 催款与对账单、法定财务报表、期初 | 依赖通知（C8）、报表数据集、协议 16 的迁移 | 各自的组件或上线迁移 |
| 资产购置确认、票据单价调整（折让与补差票） | 资产不在当前重建；补差票随成本 | 资产组件、C5 |

**源头要补的**：没有（见 P0b）。

**维护者定的**（2026-11-10）：种子用一套通用演示科目表（三个法人共用，标为演示）。

**起始值**（AI 定）：付款认领期限 7 天、收款差额容差 0（协议 05 的参数表）；三单匹配的容差协议没有给，起始 0（数量与单价都要相等），按法人声明，客户上线时按自己的政策调。
