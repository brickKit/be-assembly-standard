# C4：`erp/finance` 的子计划

阶段“按依赖顺序重建其余组件”的 C4（[components-plan.md](components-plan.md)），2026-11-10 维护者定先于 C3（收付款的事实要按本组件定义的会计事实契约发布，付款认领与核销在本组件）。照 C2 的做法（[c2-purchase-plan.md](c2-purchase-plan.md)）：先定首批范围与源头要补的能力，按改动的循环做，每一步先写红的测试，改坏检查，发布，真机格从空库到 L3。数据与改坏检查放 `c4-data/`。

## 依据与牵动

- 边界卡 `docs/zh/07-components/erp-finance.md#erpfinance`（范围：当前重建）；业务流程 `order-to-cash.md`（应收形成、核销、关账）、`procure-to-pay.md`（供应商票据与三单匹配、期末暂估、关账）；协议 05（会计事实契约、认领模式、核销、付款认领、预收与款到发货、预付与借款、期末暂估）、06（关账）、14（凭证号连续、金额）、16（期初）、02、03、07、11、13、15，安全 01–09；决定 D47–D51。
- 已重建、会给本组件事实的：`erp/billing`（已出账）、`erp/purchase`（匹配依据、验收事实）、`erp/inventory`（流水；成本另由 `erp/costing`）；下游：`erp/credit`（应收结清与重开）、`erp/sales`（预收放行认领）。
- 仓库：`components/erp/finance` 已在 C0 重置（只有 README，旧代码在 `legacy/v2`）；注册表的端口与 schema 待核对。
