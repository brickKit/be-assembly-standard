# 写屏障固定 search_path 的代价（粗测）

问题：写屏障的触发器函数加 `SET search_path FROM CURRENT`（修“别的会话带 schema 名写入时找不到 `be_tier_member`”）每行多花多少。

方法：`bench.sql`，be-postgres（PostgreSQL 16）里一张表 5 万行插入，触发器做与写屏障相同的成员查找；函数不固定与固定交替各跑 3 轮，另跑一轮不带触发器。电源模式 balanced（粗测，没有切性能模式）。原始输出 `out.txt`（`Time:` 行按 bench.sql 的顺序：插入的耗时是约 570–615 ms 的那几行与 120 ms 那一行）。

结果：不固定 573.978、570.534、589.600 ms；固定 602.808、608.407、613.994 ms；不带触发器 120.437 ms。固定多约 30 ms／5 万行（每行约 0.6 µs，写屏障本身每行约 9 µs，约 5%）。同组内波动约 3%，差别超出波动。

结论：采用（正确性需要）。T12 在性能模式下成对重测后交给知识库。
