## P0 的结果（草稿，2026-11-10，AI 定，待复核）

**首批做的**（线下登记为主，D47 的“受理、批准、执行、到账分别表达”照样分开）：

| 能力 | 怎样做 |
| --- | --- |
| 公司银行账户 | 按法人维护：开户行、账号（受限字段）、币种、状态 |
| 收款单 | 线下登记收款：法人、付款方（伙伴的客户角色或任意伙伴）、公司账户、金额与币种、到账日期、银行流水号；可带销售订单参考（带了的是预收，经 `erp/sales` 的订单读取核对）；发布收款事实（增量事实，财务以后核销） |
| 付款申请与执行 | 付款申请（收款方、金额、用途与参考号）→ 审批（协议 09，审批人不能是申请人）→ 线下执行登记（实付金额、银行流水号；部分付款）→ 已付；发布付款事实。没有财务时不认领未清项（缺件写法），财务在时改为先认领 |
| 资金调拨与科目收付 | 公司账户之间调拨、手续费与利息的收付，经审批；发布会计事实 |
| 银行对账（手工） | 导入对账单行（用户面），与已登记的收付款匹配；差错（单边、金额不符）登记与处理 |
| 事件 | 收付款单的完整状态事件；收付款事实、资金调拨与科目收付的会计事实：不可遗漏的增量事实（协议 05 的共同规则），系统面按身份读回 |

**不在首批**（理由与触发）：

| 能力 | 理由 | 触发 |
| --- | --- | --- |
| 付款认领与付款建议 | 未清项的属主是 `erp/finance` | C4 `erp/finance` |
| 经适配器的对外支付（对外命令、结果未知时查询而不重发、恢复后不盲目再付款） | 支付与银行适配器不在当前重建 | 第一个支付或银行适配器开工；那时边界卡的三个验证故事随它做 |
| 关账的封存与解封 | 关账由 `erp/finance` 协调 | C4 |
| 银行账户的期初余额与未达账项 | 协议 16 的数据迁移 | 客户上线迁移 |
| 统一待办 | `infra/workflow` | C7 |
