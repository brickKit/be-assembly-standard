# C7：`infra/workflow` 与 SDK 的流程内核的子计划

阶段“按依赖顺序重建其余组件”的第七个组件（[components-plan.md](components-plan.md) 的 C7）。维护者 2026-11-12 定：**连流程内核一起做**——先在 be-sdk-go 做协议 09 的流程内核（审批实例、按岗位分配处理人、以人为单位的职责分离、唯一决定、发布任务投影），把采购订单与付款申请的审批迁上去，再做统一待办，在格里跑通。数据与改坏检查放 `c7-data/`。

- 现在的状态（2026-11-12 读）：

## P0 的结果（草稿，2026-11-12，AI 定，待复核）

**首批做的**：

| 能力 | 怎样做 |
| --- | --- |
| 共享任务契约 | 属主 `infra/workflow`（同财务拥有共享的会计事实契约）：任务身份（流程管理方 + 任务 ID）、任务类型、单据引用（组件、类型、ID、单号）、摘要（只放发布方标明可公开的字段，见“不在首批”）、候选处理人（主体）、状态、截止、版本、法人；发布方在自己的流上发布，事件类型 `<发布方领域>.task.v1` 引用共享 schema |
| 流程内核（SDK） | 组件声明单据类型的流程（代码里的版本化定义：步骤、分配规则、步骤形式）；实例（单据引用、修订、依据摘要、流程版本、发起责任主体）与 `running → approved／rejected／withdrawn／superseded`；任务的待处理、已决定、`superseded`、`paused`；决定在一个本地事务里检查（任务待处理、处理人是候选、当前资格、职责分离以人为单位、修订未变、每任务至多一个决定、幂等键）；放行核对（`approved` 且修订与依据摘要相同） |
| 分配 | 岗位持有人（`mdm/org` 的岗位，`mdm/employee` 的任职与账号关联的投影：岗位 → 人 → 账号）与指定个人；解析时排除发起人（以人为单位）；投影不完整时等待；没有合法处理人时任务 `paused` 并告警 |
| 步骤形式 | 单人、任一（第一个同意完成，其余 `superseded`）；会签与法定人数见“不在首批” |
| 决定动作 | 内核在组件的用户面登记标准路由（同 SDK 的冷热分层路由那样由 SDK 登记）：同意、拒绝，带任务版本与幂等键；前端从待办直接发给所属组件 |
| 修订与取代 | 关键字段的新修订让实例 `superseded`、任务 `superseded`，按新修订启动新实例（采购订单的修订 PO06） |
| 迁移的业务 | 采购订单（PO03–PO06）、采购申请（PR02–PR03）、付款申请（PR03）、调拨与收付（BE02）：审批人改为流程定义的岗位持有人（采购：法人的采购负责人岗位；付款：财务负责人岗位，种子随 P6 定）；没有装员工组件时退回按账号比较（协议 09 第 4 条），风险照写 |
| 统一待办 | 部署配置列出“任务类型 → 发布方”（同财务的 `FINANCE_FACT_SOURCES`），只收选定发布方的投影，其余拒绝并记安全事件；按版本覆盖；我的待办（候选包含我、待处理）、已办（我决定过的、历史）；每个任务的所属组件与动作入口（由组件推出，不取投影里的地址）；所属组件的投影久未更新时标“可能不是最新” |

**不在首批**（理由与触发）：

| 能力 | 理由 | 触发 |
| --- | --- | --- |
| 会签、法定人数 | 两个业务的审批都是单步 | 第一个要会签的单据 |
| 关系分配（直接上级）、角色持有人 | 汇报关系的投影与业务角色另有依赖 | 第一个按上级审批的单据 |
| 重分配（组织事件驱动）与人工改派 | 先做 `paused` 与告警；重分配要订阅组织变化、按“任务 + 组织修订”幂等 | 首批之后的第一项（在 C14 之前） |
| 截止、提醒与升级 | 提醒经通知意图（`infra/notification`，C8） | C8 完成后 |
| 代理（安全 05） | 代理关系的来源未定 | 安全 05 的代理落地时 |
| 摘要字段按读者掩码（协议 13） | 首批摘要只放可公开的字段，不放受限字段 | 第一个需要在摘要里显示受限字段的任务类型 |
| 可选引擎与流程迁移（D23） | 没有客户要求 | 第一个需要复杂流程的客户 |
| 一次性动作令牌（IM 卡片） | 要 C10 的钉钉投递 | C10 |

**源头要补的**：`mdm/employee` 的岗位持有人能否经现有的投影或记录读取得到（任职的事件带岗位与人、账号关联带账号与人）——P1 查；缺的回源头补。

**要问维护者的**：范围的大方向已问（连内核一起做）。审批人改为按岗位（谁能批由“有权限的人”变成“岗位持有人”）是这个决定的一部分；具体哪个岗位批采购、哪个批付款由 P6 的种子定（AI 定，待复核）。
