# C5 P5 一致性考试的结果

- 考生：两个无头会话（默认模型、sonnet），只读 `components/erp/costing` 的文档与代码、`components/erp/purchase` 里与采购退货有关的部分，以及它们提到的 `docs/zh/`；题目 `questions.md`，参考答案 `answers.md`（出题时写）。
- 结果：默认模型 8/8 判“一致”，附两处说明；sonnet 4/8 一致，列了四处“不一致”。两份答案的事实都与参考答案相符，没有答错。

## 考生指出的与处理

| 指出的 | 谁 | 处理 |
| --- | --- | --- |
| 库存一直补不到的缺口：每个周期 `readGap` 再等时把 `waiting_since` 改成当时，恢复检查 `erp.costing.waiting`（等了超过一小时）永远报不出它 | sonnet | 真缺陷。`erp/costing` 3.0.1：等待的起点保留，本周期到期的时刻放进新列 `scope.wait_due`（迁移 0006，`nextPeriod`）；集成测试先红后绿（`sequence` 步：两个周期补取之后 `waiting_since` 不变） |
| IS02 写“先进先出下这几个单位算作已出库”，代码两种方法都把补平的单位记进层的已出库数量 | 两份 | 措辞窄于代码，移动平均下无影响；3.0.1 的设计改成两种方法都记 |
| RT01 与协议 05b 的 IC30 说拒绝时“提示按无原单的采购退货办理”，采购的错误信息没有这个提示 | sonnet | 采购首批没有无原单的退货，提示无处可指；3.0.1 的设计写明要等采购有无原单的退货 |
| `BRICKKIT.md` 的“否则成本事实等着不过账”把两种情形混在一起：没列出事实来源时财务根本不订阅 | sonnet | 3.0.1 的 `BRICKKIT.md` 分开写：没列出时只供查询、补上后从流里还保留的最早一条起收；映射缺规则时在财务等着 |
| 设计的 RT01 与实现状态还写着“采购随 P5 改” | 默认 | 3.0.1 改成 `erp/purchase` 3.0.4 起 |

## 没有采纳的

- 默认模型：采购在重放时仍向成本组件问一次可退数量（只是不比较），与“不再核对”措辞略有出入。问在幂等之前、事务之外，还不知道是不是重放；结果不用，行为与文档一致，不改。
