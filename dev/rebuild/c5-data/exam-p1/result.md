- 考生：两个无头会话（默认模型、sonnet），只读 `erp/costing` 的设计草稿与它提到的正式文档、上游组件（库存、采购、财务）的设计、`BRICKKIT.md` 与事件 schema，不读代码；题目 `questions.md`（10 题）。两份都答完，各列了“文档的空白与矛盾”（默认 18 条、sonnet 14 条）。计算题（移动平均乱序、先进先出与移动平均的调整分配）两份都按设计算对了。

## 处理（设计草稿 `5ccebb96` 之后的修订）

| 发现 | 谁指出 | 处理 |
| --- | --- | --- |
| 票据单价确认与冲回的事件没有日期，AD01 与 IC29 要票据日期 | 两份 | 源头补：财务两个事实加 `business_date`（契约加法，P0b 补），设计 LY04、AD01 写明 |
| 采购退货超过层在库：设计“不能拒绝”与协议 05b 的 IC30“拒绝”矛盾 | 两份 | 按协议：本组件系统面 `LayerService.ReturnLimit`，采购退货前问、超过就拒绝（采购随 P5 改）；异步带来的少量超出按 IS02 |
| 先进先出的“按数量加权的当前单价”与 IC24 对不上（在库 4 件应是 11 元，不是 11.6） | sonnet | LY03 改：层的单位按确认的先后分给票据，出库从层的前面取单位，每个单位有自己的单价；加权单价只给移动平均 |
| 新纪元从 1 起编（协议 05、库存的实现），设计写成“接上旧纪元的最后一号” | sonnet | VS04 重写：补完旧纪元，改用新纪元从 1 起；本组件比库存超前时停下（首批分不出 IC09 与 IC10）；新纪元里已计价的身份跳过 |
| `waiting_basis` 时 `process` 的格、等待从哪里起算、缺口后的入库等不等 | 两份 | 状态表补“没到忽略”；VS03、LY01 写明从进入状态起算、缺口后的流水都等 |
| 金额为 0 的角色、舍入尾差落哪、为 0 的出库发不发 | 两份 | AD01：为 0 的角色不写，尾差落差异；VS02：金额为 0 的事实一律不发 |
| 依据、票据匹配的键（`line_id`、`movement_id`）、参考的 `id` 是什么 | 默认 | LY01、LY03 写明 |
| 外币票据怎样折算 | sonnet | LY03：同 LY02 按票据日期取汇率快照 |
| 事实身份怎样推出、来源单据与单号 | 默认 | CF01：UUIDv5 由触发推出，来源是流水 |
| 晚装时收不到的依据、没有新流水的产品 | 两份 | LY02 与未决问题：订阅从流里保留的最早一条起，其余按政策价；期初成本层以后 |
| 库存加新的流水种类时谁先升级 | 默认 | VS02：先发能处理它的成本组件版本 |
| 冲回财务首批发不出来 | 两份 | LY04 写明：首批只用替身测 |
| 确认的先后以谁为准 | sonnet | 本组件收到的先后，记进未决问题 |

## 没有采纳的

- 由本组件顺延过账日期（默认第 18 条）：协议 05 的会计事实契约允许来源给出过账日期；本组件首批不封存，过账日期等于业务日期，落在已关闭月份由财务顺延（PD01），与收付款相同；本组件的顺延随关账批次的封存。
- 装配准入与可选依赖（默认第 10 条）：边界卡已写缺件时的降级，准入规则管的是“装了库存与财务就要装成本”，两者不冲突。
- 库存设计的“命令与查询”表缺 `Movements` 一行（默认第 12 条）：是库存文档的遗漏，随库存的下一个版本补。
