# erp/costing 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、状态、规则要点、命令与事件、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。

跨组件的规则在装配项目：存货成本（输入、计价序列、计算与缺口、暂估与调整、退货、输出与对账、期初）在协议 05b，会计事实契约与不可遗漏的增量事实在协议 05，关账与迟到在协议 06（首批不封存），单号、金额与纪元在协议 14，期初成本层在协议 16，数据范围在安全 07；决定 D45、D46、D50。端到端的位置见装配项目的业务流程“采购到付款”第 3、5 步与“订单到收款”的出库成本。首批范围是装配项目阶段计划 C5 的 P0 定的（AI 定，待复核）。

## 边界

存货的价值：按库存流水的计价序号计算每条入库与出库的成本，记下每个成本层的单价来自哪里，来源替换时出调整，把成本按会计事实发给财务过账。存货价值只有这一个权威（D46）：库存只管数量，财务不另算同一口径的成本。

| 不在这里 | 归谁 |
| --- | --- |
| 数量、流水、计价序号的分配 | `erp/inventory`（本组件按序号读它的流水，D45） |
| 收货计价依据（暂估单价） | `erp/purchase` |
| 供应商票据、三单匹配、票据单价确认 | `erp/finance`（D50） |
| 科目与凭证 | `erp/finance`（来源不写科目：成本事实带规则键与角色金额，财务按法人的映射出分录） |
| 报工、工时与工单 | `erp/manufacturing`（不在当前重建） |
| 产品、法人、币种与汇率 | `mdm/product`、`mdm/org`、`mdm/currency` |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 计价方法 | 法人的存货计价办法：移动平均（缺省）或先进先出；标准成本与定期盘存以后 | `policy.method`：`moving_average`、`fifo` |
| 计价范围 | 一起计价的流水：首批等于“产品 + 法人”（细分以后） | `scope`（法人、产品） |
| 计价序号 | 库存为“产品 + 法人”分配的连续序号，带纪元（`<恢复代次>.<时间线>`，协议 14）；本组件只按它的顺序计价 | `valuation_seq`（`epoch`、`seq`） |
| 计价进度 | 一个计价范围处理到第几号、在等什么、当前在库数量与价值 | `scope` 的 `epoch`、`next_seq`、状态 |
| 成本层 | 一条入库流水的数量与当前单价；记下单价的每个来源覆盖多少数量 | `cost_layer`、`layer_source` |
| 单价来源 | 政策价（待定价）< 收货计价依据（暂估）< 票据单价确认（最终），按优先级从低到高 | `layer_source.kind`：`policy`、`basis`、`invoice` |
| 待定价 | 入库时没有计价依据，按计价政策取了单价的层 | 层的来源 `policy` |
| 调整 | 来源替换带来的价值差额；按计价方法分成调库存价值的部分与计入销售成本差异的部分；作为新的成本事实发布，不改写原事实 | `adjustment` |
| 出库成本 | 一条出库流水按计价方法算出的成本 | `issue_cost` |
| 成本事实 | 本组件发给财务的会计事实，按财务的共享契约 `accounting_fact.v1` | 事件类型 `erp.costing.accounting_fact.v1` |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `policy` | 法人、计价方法、版本 | 不删除 |
| `scope` | 法人、产品、纪元、下一个要处理的序号、状态、在库数量、在库价值、等待开始的时刻、停下的原因 | 不删除 |
| `movement_in` | 收到还没处理的流水（按事实身份去重，按“范围 + 纪元 + 序号”唯一） | 处理后删除 |
| `valued_movement` | 每条已计价的流水：事实身份、范围、纪元与序号、种类、数量、业务日期、成本（入库是层的初始价值，出库与退货是取走的价值）、来源单据参考 | 不删除 |
| `cost_layer` | 入库流水的层：数量、已出库数量（含采购退货）、当前单价、最高来源、收货行参考 | 不删除 |
| `layer_source` | 层的单价来源：种类、来源身份（计价依据或票据单价确认的事实身份）、覆盖数量、单价、到达顺序、是否已撤掉 | 不删除；撤掉是新状态 |
| `issue_layer` | 先进先出下一条出库（或采购退货）从哪几层取了多少、按什么单价 | 不删除 |
| `basis` | 收到的收货计价依据与撤回（按收货行） | 不删除 |
| `costing_fact` | 本组件发布的成本事实，按身份读回；记下触发它的输入（流水、来源），同一触发只发一次 | 随账务 |

以后还有：标准成本、期初成本层、到岸成本分摊单、工单成本与差异、封存记录（关账）。

## 状态

每张表在代码里是同一张表（`core.Table`），单元测试逐格比较。

### 计价进度

一个计价范围（产品 + 法人）一份。

| 命令 | `running` | `waiting_gap` | `waiting_basis` | `stopped` |
| --- | --- | --- | --- | --- |
| 处理 `process` | 下一号已到时计价，否则有更后的号已到 → `waiting_gap` VS02 | 下一号到了 → `running` VS03 | 依据到了 → `running` LY01 | 忽略 VS05 |
| 缺口到期 `gap_due` | 忽略 VS03 | 允许：向库存补取 VS03 | 忽略 VS03 | 忽略 VS05 |
| 依据到期 `basis_due` | 忽略 LY01 | 忽略 LY01 | 按政策价入层 → `running` LY01 | 忽略 VS05 |
| 新纪元 `new_epoch` | 允许 VS04 | 允许 VS04 | 允许 VS04 | 忽略 VS05 |

### 成本层的单价来源

状态是层上优先级最高的有效来源。

| 命令 | `policy` | `basis` | `invoice` |
| --- | --- | --- | --- |
| 计价依据到达 `basis` | → `basis` LY02 | 忽略 LY02 | 允许：只记录 LY02 |
| 计价依据撤回 `withdraw` | 允许：只记录、告警 LY05 | 允许：只记录、告警 LY05 | 允许：只记录、告警 LY05 |
| 票据单价确认 `confirm` | → `invoice` LY03 | → `invoice` LY03 | 允许：作用于它匹配的数量 LY03 |
| 票据单价冲回 `reverse` | 忽略 LY04 | 忽略 LY04 | 允许：撤掉它的贡献 LY04 |

## 规则

### 计价政策

| 规则 | 内容 |
| --- | --- |
| PO01 | 每个法人一个计价方法：移动平均（缺省，没写过的法人就是它）或先进先出；按版本修改，审计。法人已经有计价过的流水时不能改（`POLICY_IN_USE`）：换方法要重估在库价值，不在首批 |

### 计价序列

| 规则 | 内容 |
| --- | --- |
| VS01 | 收到库存的流水（`erp.inventory_movement.recorded.v1`）：按事实身份去重；第一次见到的“产品 + 法人”建计价进度，纪元取这条流水的纪元，从序号 1 等起（成本组件比库存后装时，前面的流水由 VS03 补取）。流水先放进 `movement_in`，再排这个范围的处理工作项（同一范围同时只有一个在处理） |
| VS02 | 处理：按序号从小到大，一次处理一条，每条一个事务：写 `valued_movement`、改层与在库数量和价值、发布成本事实、`next_seq` 加一。种类 `receipt` 按 LY01 入层；`issue` 按 IS01 出库；`purchase_return` 按 RT01；不认识的种类（以后的调拨、调整、期初、销售退货）停下这个范围并告警（`stopped`，原因写种类），不跳过——跳过会让后面的成本都错 |
| VS03 | 缺口：下一号没到而更后的号已到，范围进入 `waiting_gap`，在最早那条到达后的“缺口等待”（`VALUATION_GAP_WAIT`，起始 5 分钟）排补取；到期时在事务外向库存补取（`StockService.Movements`：法人、产品、纪元、从 `next_seq` 起），补到的按 VS01 收下再处理；补不到（库存那边还没编号）就再等一个周期，每次都告警。缺口补齐之前不计算后面的出库成本 |
| VS04 | 纪元：只采用更大的纪元（协议 14 的比较）；更小的纪元的流水按身份去重后丢弃并告警。来了更大纪元 E′ 的流水时：先把旧纪元 E 补到底（从 `next_seq` 起补取，直到库存答没有更多），再读 E′ 的第一条（从序号 1 起补取）：它的序号正好接上 E 的最后一号时，范围改用 E′ 继续；否则（本组件处理过的序号在 E′ 里被重用，协议 05b 的 IC09、IC10）停下 `stopped` 并告警——按身份对齐、冲销丢失流水的成本不在首批 |
| VS05 | 停下的范围不再处理（新流水照样收下等着），恢复检查 `erp.costing.stopped_scopes` 报出它与原因；处置随原因：不认识的种类等本组件支持它的版本，纪元对不上等对齐能力（未决问题） |

### 成本层与单价来源

| 规则 | 内容 |
| --- | --- |
| LY01 | 入库（`receipt`）建一个层，数量是流水的数量。来源单据是采购收货（参考的种类 `purchase_receipt`）时按收货行（参考的 `line_id`）找计价依据：有就按它的单价，来源 `basis`；还没到，范围进入 `waiting_basis`，等“计价依据的等待”（`VALUATION_BASIS_WAIT`，起始 5 分钟；采购先发布依据再收货，通常不用等），到期按政策价入层、来源 `policy`（待定价），不再挡后面的流水。别的来源单据不等，直接按政策价。政策价：这个范围最近一层的当前单价；没有层时用当前移动平均单价；都没有是 0 并告警。发布入库的成本事实 `inventory_receipt`（`inventory` 借、`grni` 贷），金额 = 数量 × 单价，按币种的小数位舍入；金额为 0 不发布 |
| LY02 | 计价依据到达：按收货行登记；用到它的层当前是 `policy` 时，整层替换成依据的单价，按 AD01 出调整；当前是 `basis`（同一个依据）忽略；当前是 `invoice` 只记录（优先级低，不调整；IC14）。依据的币种不是法人本位币时，按依据的业务日期取 `mdm/currency` 的汇率快照折算（事务外取证） |
| LY03 | 票据单价确认（`erp.supplier_invoice.price_confirmed.v1`）：按其中每条匹配的入库流水与数量，把这些数量的单价替换成票据单价，按 AD01 出调整；一层分几张票据时各自只作用于自己匹配的数量，按数量加权得到层的当前单价，没开票的数量保留原来源（IC19）；记下到达顺序（先进先出的差异分配用，AD02）。匹配的流水还没计价时，确认先记下，层建好时按它入层（来源 `invoice`，不出调整） |
| LY04 | 票据单价冲回：撤掉那次确认的贡献，这些数量回到剩余来源里优先级最高的单价，按 AD01 出调整（IC20）；同一层后来再确认的照 LY03 |
| LY05 | 计价依据撤回（采购的收货失败）：依据标为撤回，不再用于新层；协议上没有流水用到它，所以已经用到它的层不改，只告警（说明两边对不上，要人查） |

### 调整

| 规则 | 内容 |
| --- | --- |
| AD01 | 调整 = （新单价 − 当前单价）× 替换的数量，按币种舍入；为 0 不发布。按 AD02 分成计入库存价值的部分与差异部分，发布一条成本事实：调高 `cost_adjustment_up`（`inventory`、`variance` 借，`grni` 贷），调低 `cost_adjustment_down`（反向）；`grni` 的金额是两部分之和。业务日期取触发它的输入的日期：计价依据的业务日期、票据的日期（IC29）；不改写原流水与原成本事实 |
| AD02 | 差异的去处，按计价方法：先进先出——层上已出库的数量（含采购退货）按票据确认到达的先后对应：先到的确认先对应已出库的数量，调整里对应已出库的部分进差异，其余调层的单价（IC24）；替换整层的依据，已出库的部分进差异。移动平均——计入库存的比例 = `min(调整时这个范围的在库数量, 替换的数量) ÷ 替换的数量`，摊入在库价值（平均单价随之变），其余进差异（IC25） |

### 出库与退货

| 规则 | 内容 |
| --- | --- |
| IS01 | 出库（`issue`）：移动平均按“出库数量 ÷ 在库数量 × 在库价值”取价值（舍入；取走全部在库时取走全部价值，不留舍入的尾差）；先进先出从最早的层起逐层取，每层按当前单价，记 `issue_layer`。发布出库的成本事实 `cost_of_sales`（`cost_of_sales` 借、`inventory` 贷），业务日期是流水的业务日期 |
| IS02 | 在库不够（成本组件比库存后装、期初成本层没导入，或数量与计价对不上）：够的部分照常；不够的部分按政策价（LY01）计，范围的在库数量可以变成负数，告警，恢复检查 `erp.costing.negative_stock` 报出；之后的入库先补平负数（按入库单价与原取价的差出调整，计入差异） |
| RT01 | 采购退货（`purchase_return`，带原入库流水 `origin_movement_id`）：按原入库层的当前单价（含替换之后的）出库，层的已出库数量加上退货数量；移动平均从在库价值里取走同样的价值。发布 `inventory_return`（`grni` 借、`inventory` 贷）。先进先出下退货数量超过原层仍在库的数量时，库存已经出了库，本组件不能拒绝：超出部分按 IS02 处理并告警（拒绝要在采购发起退货时查询本组件，未决问题） |
| RT02 | 销售退货不在首批：库存没有 `sales_return` 流水（按 VS02 停下）；`cost_of_sales_return` 规则键财务已经预备 |

### 成本事实

| 规则 | 内容 |
| --- | --- |
| CF01 | 成本事实按财务的共享契约 `accounting_fact.v1` 在流 `erp.costing` 上发布：来源是触发它的流水（入库、出库、退货）或层（调整，来源单据是票据或计价依据）；法人与币种（法人本位币，汇率为空）；业务日期与过账日期相同，落在财务已关闭的月份由财务顺延（PD01，本组件首批不封存）；伙伴：票据带来的调整是供应商，其余为空；分析维度：库存流水没有部门与项目，首批都为空。与计价写在同一个事务里（发件表与 `costing_fact`），按身份读回（`FactService.Read`）；同一个触发（流水的计价、某个来源的替换）唯一，重做不重发 |

拒绝的原因：法人已有计价的流水时改方法 `POLICY_IN_USE`；版本不对 `VERSION_CONFLICT`。

## 规则要点

- **只按计价序号计算**：乱序到达的流水先缓存，按序号处理，结果与到达顺序无关（IC01、IC07）；倒填的流水不触发对已处理出库的重算。
- **每条流水只计价一次**：`valued_movement` 按事实身份唯一，处理与发布在同一事务。
- **调整追加，不改写**：来源替换出新的成本事实，原事实不动（协议 05b）。
- **事务里不调用别的组件**：补取、汇率快照都在事务之前。
- **金额**：数量用基本单位；单价不舍入（`apd`），金额按币种小数位舍入；移动平均保存在库价值而不是平均单价，出清时不留尾差。

## 整套恢复之后

存在性与版本：计价政策（审计过的对象）。成本数据由流水推出，不另审计。

恢复后库存的纪元会变：按 VS04 接上；本组件自己恢复到比库存更早的点时，从 `next_seq` 起补取，照常追上。检查：`erp.costing.stopped_scopes`（停下的范围与原因）、`erp.costing.negative_stock`（在库为负的范围）、`erp.costing.waiting`（等了超过一个小时的缺口与依据）。

## 部署与替换

后台处理为主，适合外壳；写热点在 `scope` 行（一个范围同时只有一个处理者）。计价方法是替换点：改 `AD02`、`IS01` 所在的一个模块；整体可替换（协议 05b 的输入与会计事实契约不变即可）。

## 验证故事

1. 乱序到达的流水按序号处理，结果与顺序处理一致；缺口超过等待时向库存补取。
2. 暂估入库后收到票据，单价不同：在库部分调库存价值，已出库部分计成本差异，原事实不改。
3. 票据确认后冲回，回到计价依据的单价。

边界卡的“关账后的调整顺延”首批由财务的 PD01 顺延；本组件的封存随关账批次做。
