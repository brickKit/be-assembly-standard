# 第 9 步计划：其余运行形态的业务链（夜间无人值守）

> 2026-10-25 起草。用户当晚下令：电脑整夜到第二天上午开着、只开 VS Code，尽量减少变量，从头到尾测完、记下所有能得到的结果。依据：[实验计划](experiment-plan.md)的套件 A 与“步骤与检查点”第 9 步，[第 8 步计划](step8-plan.md)的格、数据与负载，[8-01](experiment-records/8-01-d-row-chain.md) 的结果与已知缺陷。

## 1. 要回答什么

同一套业务链（12 个组件、同一份基线数据、同一个混合负载）换成别的运行形态之后：

1. 业务结果是否仍与 D·S 完全相同；
2. 每种形态的 CPU 与内存开销：组件本身、形态带来的平台开销（Docker 守护进程、Podman 的 conmon 与 pasta、Kubernetes 的控制面与 kubelet、本机进程的 `go run` 包装），空库与有数据、空闲与负载；
3. 延迟有没有差别；
4. 起一格要多久（空库、带种子）。

用户最关心的是单跑（S 列）在本机、Docker、Podman、Kubernetes 四种形态的开销，所以每一行先测 S 列。

## 3. 已定的做法（AI 决定，供复核）

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 基础资源 | 每一行都用同一套 Docker 里的基础资源（PostgreSQL、NATS、RustFS、Casdoor），组件经宿主机端口连接（容器里 `host.docker.internal`、集群里 `host.minikube.internal`、本机进程 `localhost`） | 用户要求变量尽量少：基础资源不变，各行的差别只来自组件的运行形态；实验计划原定 P、K 两行的基础资源放在 Podman、集群里，改为以后的细分（套件 B 已有“集群外”一项） |
| 版本 | 与第 8 步相同的组件与外壳版本，不发新版本 | 与 D 行可比；授权重启的缺陷等全部测完再修 |
| 一格的流程 | 空库一段：起格（只做安装认领）、空闲 10 分钟、停；完整一段：起格（种子两遍、L3）、基线、独立预期与数据范围的场景、结果摘要（与 D·S 的 R8.1 比较）、空闲 10 分钟、预热 5 分钟、混合负载 7 次/秒测 15 分钟、停 | 正确性与性能共用一次起格与基线，一格约 1 小时；场景只多写几十条记录，相对 2 万张订单可以忽略，今晚的 D8-S 参照用同一流程，S 列严格可比 |
| 遍数 | 每格一遍 | D 行两遍相差在 6.5% 以内（8-01 的 5.5）；同一行的格之间差别小于 10% 的写“看不出差别” |
| 内存口径 | 采样加一种不含页缓存的读数：容器与 Pod 读 cgroup `memory.stat` 的 `anon`，本机进程读 PSS；仍保留原来的读数 | D 行发现 cgroup 读数大半是页缓存，比不了 |
| 平台开销 | Docker：dockerd、containerd、shim、docker-proxy（同 D 行）；Podman：conmon、pasta、netavark、aardvark-dns、rootlessport；Kubernetes：minikube 节点容器减去全部组件 Pod（控制面、kubelet、CNI、kube-proxy）；本机：`go run` 包装进程与看护的 `brickkit up` | 各形态自己多出来的开销 |
| 起格失败 | 种子遇到授权视图过期的 503（8-01 第 6 节的缺陷）时，等 70 秒再跑一次种子（种子可重复），记下重试 | 已知缺陷不该让一整格白跑；重试写进结果 |
| 防止休眠 | 整个运行包在 `systemd-inhibit`（休眠、空闲、合盖）里；电源模式全程 performance，每格开始记下 | 夜里不能停 |

| 5 | 时间够：LD·S、LP·S；最后再跑一次 D8-S 看一夜的漂移 | 各约 1 小时 |

合计约 12–13 小时。每一行的工具在上一行测量期间写好，等测量结束再冒烟，不在测量期间跑任何东西。

## 5. 夜里怎样运行

- 一个运行器按第 4 节的顺序跑完一行的全部格，每格每段写开始与结束；一格失败记下来、跳到下一格，不停下整轮。
- 监视每 30 秒检查一次：阶段结束、失败、电源模式变了时报，平时每 5 分钟一行。
- 每一行测完：整理表格、写进记录 `9-01`、提交并推送，再进下一行。
- **一行的工具卡住**（BrickKit 不支持、形态跑不通）超过约 1 小时：写下现象与复现，这一行留到白天，接着做下一行；BrickKit 的问题写进 `brickkit-feedback/`，不在组件里绕。
- **正确性不一致**：这一格的性能照测（数据也有用），记下差异，不修组件，早上汇报。
- 不改组件、不发版本、不动远端除了本仓库与 `be-acceptance` 的提交推送。

## 7. 请用户在离开前做的

- 电源接着、**不要合上盖子**（运行器会拦合盖休眠，但不保证所有机器都管用）；交流电下的空闲休眠已经是“不休眠”。
- 关掉 VS Code 以外的程序（浏览器、聊天、同步盘），不要在机器上做别的事。
- 保持 Claude Code 当前的权限模式：夜里要是有一个工具调用要你点同意，后面就停住了。
