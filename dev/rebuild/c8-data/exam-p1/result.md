# C8 P1 考设计的结果

考生：一个没参与写作的子代理（2026-11-12），12 题，答卷 `answer.md`。读的是线协议第 18 章草稿、第 17 章、通知组件的 `docs/design.md`、协议 10 的“通知”、统一待办的设计。

| # | 发现 | 改法（AI 定） |
| --- | --- | --- |
| 1 | 合并与撤回靠“按顺序到达”，消费者并发或重投时撤回会先于原意图处理，原意图写出后撤不回 | 合并键配**合并序号**（发送方保证递增，内核用任务版本）；认收方按“发送方 + 合并键”记最大序号，旧序号直接作废（P18.7、NT04、新表 `collapse`），不依赖顺序 |
| 2 | P18.10 写了第 17 章本版没有的转移（候选改变、转为 paused） | 只写建任务与 `paused` 重新解析两种 |
| 3 | 撤回意图的必填字段与到期没写 | 撤回意图只有合并键与序号，没有到期（P18.1、P18.6） |
| 4 | 候选超过 200 时整条意图被拒 | 上限 1000；内核超过时只发前 1000 个，其余在待办里看得到 |
| 5 | 岗位展开的日期与 P17.3 不一致 | 岗位收件人可带法人的业务日期，没给时用协调世界时的日期 |
| 6 | 验证故事 4 与 NT01 矛盾（没列出的发送方根本不被订阅） | 故事改为“列出的发送方冒充别人” |
| 7 | 没有 `mdm/employee` 与投影不完整分不开 | 可选依赖缺席（没有注入地址）立刻 `unresolvable`；不完整等到期 |
| 8 | 过期与无法展开的终态冲突、部分投递的终态没定 | 意图只有 `pending`/`done`/`superseded`；结果按收件人记（`written`、`preference_off`、`expired`、`unresolvable`） |
| 9、10 | 重试会不会重复写消息；同一主体经两个收件人怎样记 | `delivery` 以“意图 + 主体 + 渠道”唯一 |
| 11 | 协议 10 要求过期计数与告警 | NT12 |
| 12 | 协议 10 的字段表与第 18 章不齐；“法律通知”不在目录 | 目录加 `legal_notice`（必须送达）；协议 10 的表加合并键与序号；优先级写进第 18 章的“不在本版” |
| 13 | 标题取摘要的哪一部分、长度 | 摘要的标题，超过 200 个字符截断 |
| 14 | 清单的订阅写法与统一待办不一致 | 同统一待办：列已知发送方的前缀 |
| 15 | schema 文件还不存在 | P2 写（计划里本来就在 P2） |
| 16 | 到期晚于发生 schema 表达不了 | P18.1、P18.8 写明由认收方检查 |
| 17 | 意图 90 天后删，之后的撤回找不到消息 | 撤回按消息上的发送方与合并键找；`collapse` 保留 400 天 |
| 18 | 积压超过 24 小时，审批消息不再写 | 写进未决问题（协议 10 的参数，任务在待办里照常可见） |
| 19 | 链接依赖统一待办 | 写进未决问题（前端路径随协议 20） |
