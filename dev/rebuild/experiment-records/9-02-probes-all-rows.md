# 9-02 探针在四种运行形态：进程底价、外壳每个成员的代价、每一跳的通信

计划：[step9-plan.md](../step9-plan.md) 8.7。探针（`test/probe-*`，Go 与 Python 各几个变体）在 Docker（D）、Podman（P）、Kubernetes（K）、本机进程（L）四种形态下量三层：进程的底价（空闲）、外壳每多承载一个成员的代价、一条调用链上每一跳的通信。业务链的结果见 [9-01](9-01-other-rows-chain.md)。

**对比只在同一层、同一批里做**（用户 2026-10-28 定）：每一层的四种形态在同一批里挨着跑；不同批之间的读数不直接比。

## 1. 结论

- **进程本身的底价四种形态一样**（底价层，r94）：Go 探针常驻 32–36 MiB（cgroup 12–14 MiB），空闲 0.010 核；Python 探针约 100 MiB（cgroup 89–98 MiB），空闲 0.013–0.017 核。形态只改变平台：Kubernetes 1.6–2.6 GiB，Docker 0.53–0.57 GiB（同时服务基础资源），Podman 29 MiB，本机进程 44–70 MiB（`go run`、`uv run` 的包装）。
- **外壳每多承载一个成员的代价很小，四种形态一致**：Go 外壳每多一个成员常驻多 1.2–1.8 MiB，Python 外壳多 0.3–1.1 MiB；空闲 CPU 随成员数涨，Go 外壳 1、2、4 个成员是 0.010、0.015–0.018、0.024–0.032 核（每个成员自己的后台循环）。
- **每一跳的 CPU 四种形态看不出差别**（S 层，r95）：例如 Go 到 Go 的 echo-1k-grpc，每千次调用方 0.45–0.49 秒、被调方 0.34–0.36 秒；Python 到 Python 1.45–1.49 / 0.93–0.99 秒（L 行 1.13 / 0.84，见第 4 节）。延迟的 p50 也一样（Go 到 Go 0.26–0.27 毫秒）。
- **事件路径的延迟 L 行与 K 行高一些**（S 层）：Go 到 Go 的 relay p50 D 5.6、P 6.1、K 7.2、L 7.8 毫秒；L 行的进程经 `localhost` 连 NATS 与数据库走 Docker 的 `docker-proxy`（9-01 第 6 节）。同步调用不受影响。
- **同一进程里的一跳省多少**（H2 层，r94，同一格里比）：Go 到 Go 的 echo-1k-grpc 在同一外壳里每千次合计 0.63–0.74 秒，同一格里跨外壳的一跳（调用方加被调方）0.82–0.89 秒，少 17–25%。

## 4. 结果

### 4.1 底价层（r94）

| 进程 | D | P | K（Pod 的 cgroup） | L |
| --- | --- | --- | --- | --- |
| Go 探针，常驻 MiB / 空闲核 | 32.4 / 0.010 | 34.1 / 0.010 | 11.7 / 0.010 | 35.6 / 0.010 |
| Python 探针 | 101.8 / 0.016 | 102.1 / 0.017 | 89.0 / 0.017 | 99.6 / 0.013 |
| Go 外壳，1 / 2 / 4 个成员（MiB） | 33.9 / 35.1 / 38.7 | 36.0 / 37.4 / 40.4 | 12.4 / 14.0 / 17.3 | 37.5 / 39.2 / 42.8 |
| Go 外壳，空闲核 | 0.010 / 0.018 / 0.031 | 0.010 / 0.015 / 0.024 | 0.010 / 0.018 / 0.032 | 0.010 / 0.017 / 0.029 |
| Python 外壳，1 / 2 个成员（MiB） | 107.4 / 107.9 | 107.1 / 108.2 | 117.1 / 94.6 | 107.9 / 108.1 |
| 平台（2 个 Go 成员的格），MiB / 核 | 551 / 0.062 | 29 / 0.015 | 1977 / 0.083 | 70 / 0.000 |

- K 行只有 Pod 的 cgroup 读数（含页缓存），Python 外壳 1 个成员 117 MiB、2 个 95 MiB 是页缓存的起落，不是成员的代价。
- D 行的平台是 Docker（dockerd、containerd、shim、`docker-proxy`），同时服务基础资源；P 行 Podman 的平台只算 `conmon`、pasta 等，服务基础资源的 Docker 另计（表里未列）。
- 起格：底价格 D 10–18、P 4–21、K 15–29、L 5–20 秒。

### 4.2 S 层（r95）：每一跳

| Go → Go | echo-1k-grpc | 0.46 / 0.35，0.27 | 0.45 / 0.34，0.26 | 0.49 / 0.36，0.27 | 0.47 / 0.35，0.27 |
| Go → Go | write | 1.19 / 0.54，3.00 | 1.06 / 0.47，2.30 | 1.22 / 0.57，2.60 | 1.18 / 0.52，2.95 |
| Go → Go | relay | 1.27 / 1.52，5.57 | 1.19 / 1.44，6.14 | 1.40 / 1.65，7.16 | 1.32 / 1.54，7.78 |
| Go → Python | echo-1k-grpc | 0.51 / 0.92，0.77 | 0.51 / 0.98，0.80 | 0.53 / 0.95，0.78 | 0.49 / 0.82，0.72 |
| Python → Python | echo-1k-grpc | 1.46 / 0.93，1.34 | 1.45 / 0.99，1.39 | 1.49 / 0.96，1.34 | 1.13 / 0.84，1.19 |
| Python → Python | relay | 3.28 / 3.24，8.50 | 3.27 / 3.19，10.58 | 3.40 / 3.40，9.64 | 2.65 / 2.81，7.90 |

- 容器三种形态之间每一跳的 CPU 差在 10% 以内（看不出差别）。L 行的 Python 进程每跳的 CPU 少约 20%：它们是本机的 `uv run`，不在容器里；原因（解释器、cgroup 记账或别的）这一轮没有查。
- 全部 64 段（四格各 16 段）错误率 0。
- 资源（整格，MiB / 核）：组件 D 275 / 0.059、P 273 / 0.055、K 212 / 0.061、L 272 / 0.055；平台 D 556 / 0.073、P 54 / 0.026、K 1859 / 0.088、L 169 / 0.000。

### 4.3 H2 层（r94）：同一外壳里的一跳

| 跳 | 操作 | D | P | K | L |
| --- | --- | --- | --- | --- | --- |
| Go → Go（同一外壳） | echo-1k-grpc | 0.66，0.22 | 0.63，0.21 | 0.74，0.24 | 0.67，0.22 |
| Go → Go（跨外壳） | echo-1k-grpc | 0.50 / 0.35，0.27 | 0.49 / 0.35，0.27 | 0.53 / 0.36，0.27 | 0.48 / 0.34，0.27 |
| Python → Python（同一外壳） | echo-1k-grpc | 1.89，1.16 | 1.79，1.09 | 1.95，1.17 | 1.75，1.10 |
| Python → Python（同一外壳） | relay | 3.78，6.19 | 4.30，9.53 | 4.07，7.21 | 4.42，10.51 |

（同一外壳：调用方与被调方是同一进程，只有一个数。）

- 同一外壳里的一跳仍走真实的网络调用（项目的原则），所以省的只是两个进程各自的开销：Go 到 Go 合计 0.63–0.74 秒，同一格里跨外壳的一跳 0.82–0.89 秒，少 17–25%（D 22%、P 25%、K 17%、L 18%）；p50 少约 0.05 毫秒。Python 到 Python 在 H2 层只有同一外壳的一跳，跨进程的读数在 S 层（另一批），不在这里比。
- 资源（整格，MiB / 核）：组件 D 177 / 0.053、P 179 / 0.047、K 145 / 0.054、L 187 / 0.055；平台 D 590 / 0.070、P 45 / 0.026、K 2431 / 0.087、L 153 / 0.000；数据库连接峰值都是 17–18。

### 4.4 同一批里的 S 对 H2（只有 L 行）

r94 的 L9-probe-S 与 L9-probe-H2 在同一批里：组件 270 对 187 MiB（H2 少 31%），核数 0.055 对 0.055。其余三行的 S 对 H2 跨批（r95 对 r94），不在这里比；要这个对比时专门量一批。

## 5. 发现

- **探针变体的镜像装的是旧版本**：probe-go2、go3、go4 的 Dockerfile 以 `go install …/probes/go/v3@v<版本>` 安装探针，3.2.20 改了清单与代码的版本，没改 Dockerfile（仍是 v3.2.19），所以 3.2.20 的镜像跑的是 3.2.19 的探针、起来就不健康：r94 的 D9-probe-S、P9-probe-S（几秒内）与 K9-probe-S（等就绪 325 秒）起不来；从源码跑的 L 行与编进外壳的 H2 不受影响。修：探针 3.2.21，Dockerfile 装 v3.2.21；`make pin-check` 现在按 go.mod 的 `module` 行认模块，查 Dockerfile 安装的与外壳 go.mod 引用的探针模块（以前都查不到），测试在 `infra/scripts/tests/test_pin_check.py`。
- **本机进程的会话日志很大**：L 行两个通信格的 `local-session.log` 各 67–81 MiB（进程的输出），归档时压缩（gzip 后 7–9 MiB）。
