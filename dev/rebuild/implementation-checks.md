# 交实现核对的项

冻结时检查发现、按用户“只有底层逻辑的大问题才阻塞冻结”的标准算通过、交给实现阶段核对的项。实现到相应部分时逐项核对，结论写回对应的正式文档（不一致的先改文档）。

| 方面 | 项 |
| --- | --- |
| 数据库与运行时 | `current_db_epoch()` 的读法与权限、外壳共享池下 `SET LOCAL ROLE` 的行为（0-12：经事务模式代理、几个客户端共用一条后端连接时，`SET LOCAL ROLE` 与 `INHERIT FALSE` 的授予都按预期，事务外的 `SET` 会泄漏；SDK 自己的共享池还要在第 2 步测）；连接池代理与 pgx 的执行模式（0-12：pgx 默认的语句缓存要求 PgBouncer 开 `max_prepared_statements`，否则报“prepared statement already exists”；SDK 二选一：要求代理开启，或在配置为经代理时改用 `CacheDescribe`/`Exec`，结论写进数据库引擎一页）；编号事务限时在各 PostgreSQL 版本上的写法；安全记录属主的全局提交序号是热点行；TS 与 Python 能否读到计入挂起的时钟 |
| 规模与时长 | 对齐时全量重新取回（万到十万行）的耗时与探测量；新授权成员建立水位的时长；收紧路径多出的两段写延迟；外壳中可选边造成的启动等待 |
| 恢复与消息 | 整套恢复后带旧纪元位置的补发行与消费者的配合；JetStream 与 PostgreSQL 队列两个适配器在消费者库回退后的补发与持久消费者重置；RustFS 等对象存储对版本保留的支持；计划内切换使非幂等工作项转暂停的运维成本 |
| 卡片的细节 | 采购与报销带项目参考时需要同步查询项目，卡片写“只经事件”；可选的流程引擎向业务组件报完成是事件还是调用；现场打印的打印队列属主；伙伴卡没有列出营销同意；客户组合表里没有 `ana/bi`（随重建计划确定）；预算在没有财务时的维度来源 |
