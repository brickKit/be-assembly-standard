## 决定（定稿时）

| 问题 | 候选 | 决定 |
| --- | --- | --- |
| 审计的契约放哪 | 计划只列了授权与身份两个契约仓库；审计是被调方，按“被调方发布契约包” | **AI 决定**：放在 `infra-audit` 仓库的 `contract/` 子目录里单独发布（同探针的做法），不另建仓库 |
| 契约的线格式 | **已定（用户 2026-10-18 选 B，D76）**：信封用 protobuf，安全记录以规范 JSON 字节放在 `bytes` 字段里，按 JSON Schema 校验，摘要直接对收到的字节核对 | 已定 |
| Casdoor 能否提供账号的变更序号或管理事件 | 边界卡写明“待代表部署实验核实，核实前按外部来源声明” | **按外部来源声明（读源码，2026-10-18）：给不出可靠的变更序号**。操作记录表（`record`）有自增编号、经 API 的操作都会记，但记录是在请求处理之后另起协程异步写入：崩溃时可能丢，编号顺序也不保证与变更生效的顺序一致，另有“只记写操作”的设置；webhook 可配重试，但没有序号、不保证顺序。所以按外部来源声明，正确性靠定期的全量状态比较（账号的停用状态与更新时间），操作记录与 webhook 只用来更快发现。本步用最小复现确认（在控制台停用一个账号，看记录与 webhook），结论写进边界卡 |
| 边缘的会话缓存与失效推送 | 边界卡列入代表部署实验 | 不在本步（计划的“只实现到”没有它）；记进后续 |
| 外壳 | 计划：基础外壳 `be-go-infra` 承载身份、授权、审计与主数据 | 本步先单跑通过 L2，再在一格里进外壳跑剖面 |

## 风险

- **契约改动的连锁**：契约包一改，SDK、探针、外壳都要跟着升版本，和第 4 步的修复一样一路发下去；按依赖顺序发，每层测完再发下一层。
- **Casdoor 的行为未知**：变更序号或管理事件若不存在，授权的新鲜度只能按外部来源声明，安全 03 的相关保证要在边界卡写明降级。
- **授权是每个请求都读的**：视图核验的性能直接进每个请求，按“性能与可读性”的规矩，写完先量。

## 进度

- **T5.1 完成（2026-10-19，协议 3.0.0-alpha.16）**：两个组件服务端的义务按协议第 08 章的约定写进它们的契约（T5.2），协议只加调用方与被调方共用的规则与向量。
  - P8.11 补全安全 03 的接受表。之前两个 SDK 只比较恢复代次；现在还比较作答的成员实例，以及逐个依赖域的纪元与修订。整个回答判为回退时，持有的分片暂停使用；单个分片回退时停用，直到更高的恢复代次。向量 `view-accept`。
  - 核验回答加了 `instance` 字段（安全 09a）：只答“未变”的回答不带视图；从备份另建的环境内容相同、摘要也相同，光看视图里的修订认不出另一个实例。
  - P8.22 写明按已备份水位删除本地审计行的判断（同一纪元、祖先纪元与分叉点、丢失的分支、更晚的纪元）。向量 `audit-purge`；Go SDK 已有这套逻辑，Python 要按向量核对。
  - 身份一侧不加新规则：签发的令牌按现有的 P8.1 与向量 `jwt-verify` 核验。
- **T5.2 第一部分（2026-10-19，协议 3.0.0-alpha.17）**：
  - **安全记录的 JSON Schema**：从字段表生成。生成工具 `tools/be-acceptance/doc-checks/security-schemas.py` 读安全 09a 与协议第 08 章，产出写进 `be-protocol/schemas/security/`，`make gates` 核对二者一致。
  - **记录的线上形态**：线上的记录不带自己的摘要，摘要随信封传；字节不是规范形式的整条拒绝（09a）。
  - **09a 补了 `ComponentId` 类型**：组件 ID（`infra/authz`、`test/probe-go`）不符合 `Key` 的写法（没有 `/` 与 `-`），`owner_component`、`authority` 原来写成 `Key`，是错的。
  - **修了审计转运的缺陷**：两个 SDK 转运时从各列重新拼出记录，字节与算摘要时的不同（null、数据库的时刻格式、键序），审计组件核对不了摘要。改为写入时把规范字节存进行里（迁移 0009），转运原样发送（P8.20、P8.21）；SDK 在 T5.3 跟上。
  - **向量 `security-records`**：schema 接受与拒绝的样例记录，并给出规范字节与摘要。

  - **视图**：经 `ViewService` 取得，按记录打开（规范字节、摘要、生成的 schema）；回答按完整的 P8.11 接受，两个 SDK 都过了向量 `view-accept`。
