# C10 P1 设计考试的结果

考生：一个没参与写作的子代理（2026-11-13），只读文档与现有代码。答卷摘录 `answer.md`。全部条目由 AI 处理（AI 定，待复核）。

## 必须改（9 条，全部处理）

| # | 处理 |
| --- | --- |
| M1 令牌原文经意图事件流到发件表、消息系统、对象存储与死信 | 采用方案 B：所属组件签发**不是秘密的动作授权**；按钮上的一次性随机值由渠道成员生成、只存摘要、每次发送重新生成；动作事件带授权身份。秘密只在渠道成员与钉钉之间（线协议第 20 章开头、P20.5、P20.6；协议 10 的交互按钮） |
| M2 动作事件没有受众 | `Deliver` 带发送方与意图身份；动作事件带受众；受众不是自己的静默确认，不写安全审计（P20.1、P20.6、P20.7） |
| M3 事件路径上的授权把可重试的当成拒绝 | P20.8：在消费者的事务里决定，用本地视图与判断的截止时刻；可重试的结果（视图过期或无法证明、`QUALIFICATION_UNKNOWN`、数据库错误）不记在授权上、否认事件重投；最终的结果才记。SDK 的 Check 要区分（P3） |
| M4 管理员维护映射等于能冒充审批人 | P20.9 与渠道成员 ID10：绑定只由用户本人经钉钉的身份授权建立，管理员只能结束 |
| M5 通知组件的投递全在一个事务里、`pending` 被当成结果、被取代的意图留令牌 | NT13：外部投递单独一个作业，按行认领、事务外调用；`pending` 不是结果；NT04：取代时外部 `pending` 记 `superseded`；授权不是秘密，没有原文要清 |
| M6 第 13 章与 SDK 没有本地到期作废；结果未知都要 24 小时后人工 | 第 13 章 P13.14 本地放弃时刻：过了它不发、不查、不等人工，转 `failed`（`expired`）；渠道成员的命令带它（ID03）；随机值不在命令参数里，重发时现生成 |
| M7 回调答成功之后崩溃就丢了 | 存 `received` 与登记工作项同一个事务，提交之后才答成功；工作项以回调行幂等处理；停在 `received` 超过 5 分钟告警（ID06、ID07） |
| M8 外部调用拖住站内投递、没有退避 | NT13：外部投递作业按行认领，协议 10 的退避，同一渠道一轮里不可达就跳过其余行，持续 1 小时告警（NT12） |
| M9 偏好规则自相矛盾 | NT07、NT09：偏好按“类别 × 渠道”，必须送达的类别只有站内关不掉；`Route` 随 P4 加渠道参数 |
