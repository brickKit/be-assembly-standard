# C6 P1 考设计的结果

- 考生：两个无头会话（默认模型、sonnet），只读商机的设计、边界卡、A71、协议与 `erp/sales`、`mdm/partner` 的文档与事件 schema；题目 `questions.md`，参考答案 `answers.md`（出题时写）。
- 结果：两份 12 题的事实都与参考答案相符；两份都把“销售那边还没有承接”列为空白（预期：销售随 P2b 改）。

## 指出的与处理

| 指出的 | 谁 | 处理 |
| --- | --- | --- |
| 订单事件没有商机参考、报价事件没有请求身份、没有“拒绝请求报价”的事实、销售没有去重的记录 | 两份 | 设计的“依赖”列出销售 P2b 要补的三条（订阅与去重、草稿与拒绝的事实、报价与订单带商机身份与请求身份）；OP08 写明订单靠自己的商机参考，不经报价推 |
| 草稿没有税率，报价 schema 的税率必填；草稿的部门从哪来 | 两份 | 请求的产品作为草稿上的参考，由人补成明细再发出；部门留空（销售 P2b） |
| 重开与回退时手工概率丢失；重开后再赢单发不发事实 | 两份 | 回退用目标阶段的缺省；重开回到关闭前的阶段与概率（新列）；重开后再关闭照样发事实 |
| 推进能不能以 `won`、`lost` 为目标；修改能不能改阶段 | 两份 | 不能，只经赢单与输单；修改不改阶段 |
| 新建时指定别人为负责人绕过 `assign` | sonnet | 指定别人要另有 `crm.opportunity.assign` |
| 自动赢单的操作者 | 默认 | 本组件自己，不做授权检查，记 `system` |
| 漏斗的口径（终态、舍入、受限字段）；销售主管的范围 | 两份 | 六个阶段都列，赢单用赢单金额，加权按币种舍入，首批没有受限字段；主管授予法人内全部负责人 |
| 币种不同时赢单事实的币种；`quotation_accepted` 下订单又取消 | 两份 | 都是商机的币种；只记下，由人处理 |
| 请求停在 `requested` 没有出口；关闭时已发出的请求 | 两份 | 请求只是记录，不占东西；关闭不碰销售的报价（未决问题） |
| 边界卡与组件索引的依赖没跟上；“按客户的设置”的措辞 | 两份 | 边界卡加 `mdm/org`、`mdm/currency`，改成“部署方的设置”，组件索引重新生成 |
| 赢单后仍可改名称与预计成交日 | 两份 | 保留，写进未决问题（AI 定） |
| 客户之后被暂停商机不会发现 | sonnet | 写进 OP02：下次改客户时重新取资格，销售生成报价时由销售取 |

## 没有采纳的

- “跨步推进与边界卡的‘只按声明的顺序’有出入”：跨步不改变顺序，OP03 写明了。
- 恢复核对加“请求停在 `requested`、销售已有草稿”：销售的事件一到就补上，不另做核对（写进“整套恢复之后”）。
- 历史赢率要不要新表：属于 Fork 的替换实现，不在首批。
