# C11 P1 设计考试：答卷摘录与处理

考生：一个没参与写作的子代理（2026-11-13，只读文件，约 18 万 token、59 次工具调用、9 分钟），考 `components/infra/bff-mobile/docs/design.md` 的第一稿（组件仓库提交 `fb4fee1`）。下面是每条的发现（摘录）与处理；处理都是 AI 定、待复核。

## 必须改（12 条）

| # | 发现 | 处理 |
| --- | --- | --- |
| M1 | `GET /api/workflow/tasks/{id}` 要必填的 `component`（任务由“组件 + ID”确定），`task(id)` 与 `decideTask` 都没有 | `task(component, id)`；决定不再经本组件（M5） |
| M2 | 错误形状违反 P3.3：`extensions` 要原样放 `reason`、`domain`、`metadata`（缺的组件在 `metadata.dependency`），不另造 `code` | 照 P3.3：`extensions` 是 `{reason, domain, metadata, trace_id}`，可重试的另带 `retry_after`；本组件自己的原因 `PERSISTED_QUERY_NOT_FOUND` 在契约里声明 |
| M3 | 原因列表不全：`RESULT_UNKNOWN`（写超时）、`AUTHORIZATION_UNPROVABLE`（下游 401 改写）、`OUTBOUND_LIMIT`、`CIRCUIT_OPEN`、`DEADLINE_BUDGET_EXHAUSTED`、`CAPABILITY_UNSUPPORTED` | 读路径的原因写全；写路径不再有（M5） |
| M4 | 边缘对每个请求剥掉 `Authorization`、只给带会话 Cookie 的请求注入令牌：原生应用的令牌进不来；浏览器入口的 POST 要带 `BE-Request: 1`，轮询带 `BE-Polling: 1` | 首批只支持浏览器入口（移动 H5，含企业微信、钉钉的内置浏览器）；原生应用经边缘的做法记为未决（协议 20 与边缘的事）；客户端约定写进 BM01 与 `BRICKKIT.md` |
| M5 | 决定经本组件转发与协议 09、20、D68 的“前端直接发给任务所属组件”字面冲突；而且标准路由 `/be/flow/...` 在每个流程管理组件上路径相同，边缘按前缀分不出发给谁（PC 前端同样撞上） | **本组件只读**，移动端像 PC 一样经边缘直接把决定发给属主。**在源头补缺口**：线协议规定组件的公网前缀（组件定义声明，默认 `/api/<名字>`），用户面与 SDK 的标准路由（流程、冷热转层）都挂在它下面，SDK 启动时检查；跑流程内核的组件前缀必须是 `/api/<名字>`，统一待办由发布者的身份推出动作入口 `/api/<名字>/flow/tasks/{id}/decisions` |
| M6 | 列表下的可用量是 N+1 扇出，撞 SDK 每依赖 64 的并发上限 | 类型拆开：可用量只在产品详情的类型上（`product(id)` 返回 `ProductDetail`），列表的类型没有这个字段，结构上就不会扇出 |
| M7 | 代价怎样算不清：`limit` 是运行时变量，嵌套是加还是乘 | 嵌套字段的代价乘以父列表的 `limit`；启动时每个列表按上限 50 计；运行时变量里的 `limit` 超过 50 答 `REQUEST_INVALID`（`violations` 指出字段） |
| M8 | 一个变更操作里多个变更根字段等于编排写 | 没有变更了（M5） |
| M9 | `customers` 走 `GET /api/partner/partners`，没有按客户角色筛选，供应商、员工混进来 | 回源头补：`mdm/partner` 的列表加 `role`（`customer`、`supplier`）与 `legal_entity_id` 的筛选 |
| M10 | 依赖表把身份与授权成员列成必需依赖，与协议 19 不符 | 删掉，写“凭据与授权视图经配置引用取得，不是依赖” |
| M11 | SDK 的准入不判断调用者有没有入口的操作，要处理函数自己判断 | BM01 写明：资源 `infra.bff_mobile.entry`、维度 `{}`，处理函数先判断，不成立答 `PERMISSION_DENIED`（403，入口没有记录，不是“看不见答 404”的情形）；种子给移动端的账号；测试：没有授予时被拒、什么也不调 |
| M12 | 边界卡把被聚合的组件写成必需依赖、写“批量加载用 dataloader”，设计改成全部可选、首批不用 | 修订边界卡：被聚合的组件是可选依赖（按装配裁剪），批量加载按需（有按 id 补名称的字段时） |

## 建议改（18 条）
