# C3 P5 一致性考试的结果

- 考生：两个无头会话（默认模型、sonnet），只读 `components/erp/payment` 的文档与代码、它们提到的 `docs/zh/` 与 `erp/finance` 的契约；题目 `questions.md`，参考答案 `answers.md`（出题时写）。
- 结果：两份都是 8/8 判“一致”，答案的事实与参考答案相符；各列了几处“两边都没写”或要核实的地方。

## 考生指出的空白与处理

| 空白 | 谁指出 | 处理 |
| --- | --- | --- |
| 放行时前几行已确认、后一行认领失效：申请停在 `approved`，已确认的认领留在财务；后台失效只释放“其余”认领，被拒续期的那条（已确认的）不释放，应付一直被占着 | sonnet（默认模型推到一半） | 真缺陷。`erp/payment` 3.0.1：放行时认领失效即释放全部认领、退回草稿并答 `CLAIM_LOST`；失效释放全部认领（含触发的那条）；设计 PR04、PR08 随之改；测试先红后绿，改坏 2 处都被抓住（`c3-data/mut-p5/`） |
| 银行账户的审计可能带全账号（没核实 SDK） | 默认模型 | 核实了：SDK 只遮蔽审计变更的顶层字段，本组件把记录放在 `after` 下，全账号进了审计——真缺陷。3.0.1 审计写遮蔽后的账户（照 `mdm/employee` 不把受限字段放进审计记录的做法）；测试先红后绿，改坏被抓住 |
| 冲正事实沿用原汇率、业务日期取当天，设计没写 | 两份 | 设计 RC02、PR06 补写 |
| 协议 05 把调拨与科目收付写成“资金事实”，组件与财务都是会计事实 | 默认模型 | 协议 05 的表改成“会计事实”（开头一句本来就写“按会计事实契约直接过账”） |
| BE02、BE03 括号里的“转出账户”“转入账户”让人以为事实带账户 | sonnet | 删掉 |
| 续期“期限更短时在中点”只在模块说明里 | 默认模型 | 设计 PR08 补写 |

## 没有采纳的

- 默认模型说已满额的应付在付款建议里不出现、因此答 `OPEN_ITEM_NOT_PAYABLE` 而不是 `CLAIM_EXCEEDS_AVAILABLE`：属实且是想要的（可用为零的未清项本来就付不了），设计 PR02 已写“不在里面就拒绝”。
