# C3 P1 考设计的结果

- 考生：两个无头会话（默认模型、sonnet），只读 `erp/payment` 的设计与它提到的正式文档、`erp/finance` 的设计与 `BRICKKIT.md`，不读代码；题目 `questions.md`（8 题）。两份都答完，各列了“文档的空白与矛盾”（默认 12 条、sonnet 17 条）。

## 处理（设计 `c4dd85c` 之后的修订）

| 发现 | 谁指出 | 处理 |
| --- | --- | --- |
| 确认认领在付完之后登记时才做，违反协议 05 的“不可撤回的动作之前确认” | sonnet | 加“放行”（`release` → `ready`）：批准之后、人去银行之前确认认领；执行只登记已付 |
| 资金调拨：协议 05 是成对的两条事实、带同一调拨身份、在途记在途资金；设计与财务都是一条 `fund_transfer` | 两份 | 源头改：`erp/finance` 3.0.2 的规则目录换成 `fund_transfer_out`、`fund_transfer_in`（经 `in_transit`），集成测试先红后绿；收付款的调拨分转出与到账两步（`in_transit` 状态） |
| 从对账单行生成科目收付（协议 05 的 BL84）没有 | 两份 | 加 BR04 `create_entry`，过账时自动匹配回来源行 |
| 草稿时“不超过可用余额”没有接口能查 | 两份 | 草稿不核对，可用余额在提交的认领里由财务裁决（PR01） |
| “申请人”是新建人还是提交人 | sonnet | 提交人（PR02） |
| 实付怎样分到各行 | sonnet | 可以逐行给，不给按行的顺序（PR05） |
| 续期失败用户看不到、财务不可达怎么办 | 默认 | 续期被拒时工作项把申请退回草稿并写原因；不可达时重试（PR08） |
| 暂挂的到账查明付款方之后怎么办 | 两份 | 冲正后按付款方重新登记（RC02）；财务的暂挂事后分配以后 |
| 外币账户与财务只收本位币的应付对不上 | sonnet | 写明首批外币账户只用于外币到账与外币贷方余额的退款 |
| 没装员工组件时同一个人两个账号能自批，协议 09 要求告知客户 | 默认 | PR03 写明，部署前准备里告知 |
| 对账：没有流水号怎么去重、退回与冲正的单据怎么对、调拨按腿、补登记后是否再匹配 | 两份 | BR01、BR02 补写 |
| 冲正的规则键 | sonnet | 沿用原事实的（规则要点） |
| 登记错了的付款怎么更正 | sonnet | 与银行退回同用“退回”（PR06） |

## 没有采纳的

- 协议 05 的 BL79（一笔付款覆盖多张应付时只核销成功的几张）：那是适配器的逐条结果；线下一次付一笔，PR05 写明。
- 付款退回后“应付重开”的事件：财务没有给应付的下游，事件表不加。
