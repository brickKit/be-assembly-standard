以下按 8 题逐一回答。依据只来自文档，没读代码，也没改任何文件。简称：「支付设计」是 `components/erp/payment/docs/design.md`，「财务设计」是 `components/erp/finance/docs/design.md`，「协议 05」是 `docs/zh/06-protocols/05-billing-settlement-and-payment.md`。

## 1. 应付 1000 元，已被另一张申请认领 300 元；新建 800 元申请提交，会怎样？改成 700 元呢？

- **800 元：整张提交失败，申请留在草稿。**
  - 提交时，每行先在事务外向财务认领（支付设计「PR02」）。
  - 财务按「`pay_claimed + 本次 ≤ amount − settled`」裁决（财务设计「CL01」）。
  - 这里可用余额 = 1000 − 0 − 300 = 700，800 超过 700，所以拒绝，原因是 `CLAIM_EXCEEDS_AVAILABLE`（财务设计「付款认领」末尾「拒绝的原因」）。
  - PR02 写明：有一行被拒，已成功的行同时释放，申请留在草稿，并答财务的原因。
  - 协议 05 的 BL33 也有同样的预期：认领额度不足被拒，钱不会付两次。
- **700 元：认领成功，提交成功，申请变成 `submitted`。**
  - 依据：700 ≤ 700，满足 CL01。
  - PR02：全部认领成功才在一个事务里写下认领与期限。
  - 认领后可用余额为 0，`pay_claimed` 为 1000。
- 两种金额还要满足 PR01：行金额大于零，且不超过「登记时财务答的可用余额」。
  - 文档没说「登记时」具体指哪个动作，见末节。

## 2. 批准后放了 10 天才去银行付，认领会失效吗？失效后登记执行会怎样，该怎么办？

- **默认不会失效，因为后台会续期。**
  - 认领起始期限是 7 天，配置键 `CLAIM_PERIOD`（财务设计「CL01」；协议 05 参数表）。
  - `submitted`、`approved` 的申请，由支付组件的后台工作在期限前一小时续期（`Renew`），续期后按新期限再排（支付设计「PR07」）。
  - 续期从续期时起再算一个期限（CL01）。
- **续期失败才会失效。**
  - 续期只对未到期的待确认认领有效（CL03）。
  - 待确认的认领到期后，由财务的工作项置为 `expired`，并把认领中的数量退回可用余额（CL05）。
  - 支付设计 PR07：续期被拒（已到期）的会被记下，执行时答 `CLAIM_LOST`。
  - 文档没写续期失败的具体原因，例如组件停机、财务不可达。
- **失效后登记执行：被拒绝，答 `CLAIM_LOST`，申请保持 `approved`。**
  - PR04：执行前先逐行向财务 `Confirm`，有一行确认不了（已到期或被释放）就拒绝。
  - 已确认的认领不再到期（CL04、CL05）。
- **接下来：取消，再重新申请。**
  - PR04：「要取消后重新申请」。
  - 支付设计「未决问题」也写明：认领失效后不在执行时自动重新认领。
  - 取消时，`approved` 状态向财务释放认领（`Release`，幂等）（PR06）。
  - 财务那边已 `expired`/`released` 的认领，再释放返回成功（CL08）。
  - 重新申请要用新的认领身份（CL05、CL08：到期后要再付，用新身份重新认领）。
- 「整套恢复之后」一节：恢复后，`submitted`、`approved` 的申请逐条向财务读认领（`Get`），已到期或已释放的，执行时同样答 `CLAIM_LOST`。

## 3. 1000 元申请批准后银行只付出 600 元，怎样登记？财务的已核销、可用余额各是多少？剩下 400 元怎么办？

- **登记：** 执行（`execute`）时填实付金额 600、付款日期、银行流水号。
  - 依据：PR04，实付金额大于零且不超过申请金额，可以少于申请（术语表「执行」）。
  - 实付按行的顺序分到各行，每行不超过本次金额。
  - 同一事务里发布资金事实 `payment`，认领清单是「认领身份 → 分到的金额」，申请变成 `paid`。
- **财务这一侧：** 按 CL07，财务核销 600，认领正式化（600），剩下的 400 从 `pay_claimed` 退出、回到可用余额。
  - 已核销（`settled`）= 600。
  - 未清余额 = 1000 − 600 = 400。
  - 可用余额 = 400（假设这张应付只有这一张申请认领，且应付总额为 1000）。
  - 财务设计里的例子是「应付 1000，认领 600，实付 500」，数字不同，机制相同。协议 05 的 BL46 与本题情形一致：可用余额为 400。
- **剩下的 400 元：** 回到可用余额，可以再做一张新的付款申请去认领、再付。
  - 文档没有写「对同一张已 `paid` 的申请补付」的办法。支付申请是整张进入 `paid`，终态只有 `returned`，没有「部分已付」的状态。
  - 所以只能理解为另建一张申请（协议 05 的付款认领一节：「用户把一张应付拆成几笔付款，就是几个认领」）。
  - 文档没有明说「新申请」这个步骤，见末节。

## 4. 张三提交的申请，张三自己能批准吗？能登记执行吗？李四批准后，李四能登记执行吗？

- **张三批准：不能。** 批准人不能是申请人，拒绝 `APPROVER_IS_SUBMITTER`（支付设计 PR03；状态表「批准」一行）。
- **张三登记执行：不能。** 执行人不是申请人（PR04）。
  - 「未决问题」里同样写明：执行人不是申请人，按账号；执行人可以是批准人。
- **李四批准后，李四自己登记执行：可以。** 文档明确允许执行人是批准人，状态表和规则里没有「执行人不是批准人」的限制。
  - 状态表写「执行：认领都已确认时 → `paid`」。
  - 对此有一条标注：「AI 定，待复核」。
- **比较口径是账号，不是人。**
  - 支付设计 PR03：按账号，有员工组件和 C7 的业务确认 profile 之后才按人（协议 09 的 D10）。
  - 协议 09 写的是：以人为单位，没装员工组件时至少比较稳定的发起主体（账号），同一个人的多个账号无法识别，该风险在装配时告知客户。
- 权限：批准与驳回需要 `erp.payment.request.approve`；执行与退回需要 `.execute`；新建、修改、提交、取消需要 `.edit`。

## 5. 收到 500 元到账，不知道是谁付的：怎样登记？财务怎样处理？后来查明是客户 A 呢？

- **登记：** 用收款单登记，付款方留空。
  - RC01：「付款方（活跃的伙伴；不知道是谁时留空，财务记暂挂）」。
  - 其他必填项：法人、启用的账户、金额（大于零）与币种（等于账户币种）、到账日期、银行流水号（同账户内不重复）。
  - 同一事务发布资金事实 `receipt`，不带认领。
- **财务：**
  - 凭证：没有伙伴的到账，`bank` 借、`suspense` 贷，即「资金暂挂，不分配」（财务设计「ST02」）。
  - 核销：不自动分给任何单据（协议 05 核销表「资金暂挂」；BL12）。
  - 事实留作未分配。
  - 以上由财务设计 ST02 推出。文档没写暂挂在财务里是否有专门的未清项或查询。
- **后来查明是客户 A：文档没写。**
  - 支付设计的收款单状态只有 `received`、`reversed`，没有「补填付款方」命令，登记也不可修改。
  - 可行的做法只能是用冲正（RC02）冲回这笔错误登记，再用正确付款方重新登记。
  - 但冲正对「没有伙伴、已记暂挂」的到账怎么处理，文档没写。
- 协议 05 的放行台账里提到「事后分配到本订单的暂挂收款」，说明预期有「事后分配」。
  - 但财务设计和支付设计都没定义这个命令，ST03 只写「付款方未知的到账」留着，没有人工分配的动作。

## 6. 付款登记执行后，银行把钱整笔退回，怎样处理？财务那边会怎样？

- **收付款侧：** 对 `paid` 的申请做「退回」（`return`）。
  - 要写明原因，需要 `.execute` 权限。
  - 一个事务里发布冲正的资金事实（`reverses_fact_id` 指向付款事实，金额相同），申请变成 `returned`（PR05）。
  - `returned` 对其他命令都是拒绝，是终态。
  - 退回仅限整笔：「部分退回不在首批」。
- **财务侧：** ST05（财务设计）。
  - 凭证照原凭证借贷相反。
  - 原来的每条分配写一条反向分配（方向 `reverse`），原记录保留。
  - 未清项的已核销减回。
  - 正式化过的认领冲回（CL09）。
  - 被冲回的应收发布「应收重开」。
  - 对应付来说，应付重新可付（协议 05：「应付重新可付，`settled` 减少」；BL35）。
- 首批只接受整笔冲正。
  - 财务设计 ST05 的限制是：金额必须等于原事实，到账形成的贷方余额没被用过。
  - 不满足就告警，等人处理，并不报错。这条对付款的整笔退回不构成障碍。
- 冲正先于原事实到达时，财务先暂存，等原事实到达后先核销再冲回（ST05；协议 05 的 BL80）。
- 同一张应付要再付，需要新的申请和新的认领身份。这是我从 CL08、CL09 推出的，文档没有逐字写。

## 7. 从招行账户调 1 万元到工行账户、银行收 20 元手续费：各怎样登记？会不会针对伙伴的未清项？财务怎样知道记哪个科目？

- **登记：** 各用一张 `bank_entry`。
  - 调拨（`transfer`）：BE01 规定转出和转入两个账户，必须同一法人、同一币种、都启用、不同账户。金额 10000。
  - 手续费（`charge`）：只填一个账户（招行），金额 20。
  - 流程：新建（草稿）→ 提交 → 批准即过账。
  - 批准人不是制单人（按账号）（BE02）。
  - 权限是 `erp.payment.entry.edit`、`.approve`。
- **不针对伙伴的未清项。**
  - 支付设计「规则要点」：资金调拨与科目收付除外，它们直接过账。
  - 协议 05 的「不针对伙伴未清项的资金流」一节也是这样写的。
  - 它们发布的是会计事实 `accounting_fact.v1`，不是带认领的资金事实。
  - 财务设计 AF01 写明：首批不从会计事实形成未清项。
- **财务怎么知道记哪个科目：** 来源不写科目，只带规则键和角色金额，财务按「规则键 + 角色」找法人的科目映射出分录（财务设计「会计事实契约」，AF01）。
  - 调拨：规则键 `fund_transfer`，角色 `bank_in`、`bank_out`。
  - 手续费：规则键 `bank_charge`，角色 `expense`、`bank`。
  - 分析维度带公司账户（BE02）。
  - 规则目录在财务里，来源新增的规则键要先加进目录，法人再映射；没映射的角色会让事实等着，补上映射后过账（AF02）。
  - 首批目录已经预备了 `fund_transfer`、`bank_charge`、`bank_interest`（AF02）。
  - 协议 05 里「在途期间记入在途资金」「成对的两条资金事实」两处的说法与支付设计不一致，见末节。

## 8. 对账单上有一笔 300 元到账，系统里找不到收款单；系统里一张已付的申请对账单上没有；同一行被导入两次，各怎样处理？

- **对账单有 300 元到账，系统没有收款单：** 属于「单边差错（银行有、本组件没有）」，处理办法是补登记收款，再匹配（BR03）。
  - 具体步骤：补登记收款单（RC01），银行流水号对上就能自动匹配；之后在对账单行上手工匹配（BR02：同一账户、金额相等、那张单据没被别的行匹配）。
  - 补登记后匹配也是验证故事 4。
  - 如果这行其实是银行手续费一类，协议 05 提到「银行对账可以从对账单行生成科目收付（经审批）」，BL84 也是。
  - 但支付设计没有写「从对账单行生成」的命令，见末节。
  - 对账单行在未解决前是 `unmatched`；处理完要写明处理说明，标为 `resolved`（`resolve`），可以重新打开（BR03）。
- **系统有一张已付申请，对账单没有：** 属于「本组件有、银行没有」，要「查明后在单据上处理」（BR03）。
  - 具体怎么处理，BR03 没写。可用的手段有：`paid` 的申请可以退回（PR05，退回仅限银行把钱退回的情形），或在查明后补登记对账单行。
  - 账户的对账情况查询会列出「本组件这一侧没有被匹配的单据」。
  - 这一侧的差错没有对应的 `statement_line`，所以不能用 `resolve` 标记。文档没写它的处理说明记在哪里。
- **同一行被导入两次：** 同一账户、同一银行流水号的行不重复登记，重复的跳过，答复里列出（BR01）。
  - 前提是流水号相同。文档没写两行流水号不同或为空时怎么办，见末节。

## 文档的空白与矛盾

按重要程度排列：

1. **付款方未知的到账事后认定（第 5 题）。**
   - 协议 05 的放行台账提到「暂挂收款事后分配到本订单」，BL12 只写到「暂挂，不自动分配」。
   - 财务设计 ST03 只写了「到账按伙伴自动分配」，没有人工分配命令。
   - 收款单也没有「补填付款方」命令，只有登记和冲正。
   - 所以「后来查明是客户 A」没有明确做法。只能推测为冲正再重登记，但冲正暂挂到账的财务侧行为也没写。
   - 暂挂在财务里是不是未清项、怎么查询，也没写。

2. **调拨的资金事实形态：协议 05 与支付设计对不上。**
   - 协议 05：调拨是「成对的两条资金事实（转出、转入），带同一调拨身份；在途期间记入在途资金」。科目收付是「一条资金事实，带过账规则键」。
   - 支付设计和财务设计：调拨与科目收付都发布会计事实 `accounting_fact.v1`，调拨用 `fund_transfer` 一条事实，角色 `bank_in`/`bank_out`。
   - 「在途资金」在两个组件的设计里都没有出现。
   - 支付设计 BE02 说「批准即过账」，也没有区分转出与转入的时点。

3. **科目收付与对账单行的关联。**
   - 协议 05 与 BL84：对账单上的银行手续费，可以「从对账单行生成科目收付（经审批）」。
   - 支付设计的对账单行命令里没有这个动作，`bank_entry` 与 `statement_line` 之间也没有字段记录来源行。
   - BR03 对单边差错只说「补登记收款、付款或收付后再匹配」，没说能一键生成。

4. **部分付款后的剩余 400 元。**
   - 申请 `paid` 之后没有任何后续命令，状态也不能表达「部分已付」。
   - 文档没有明说剩余部分需要新建申请。
   - 协议 05 BL46 写「应付的可用余额为 400」，但谁、怎样去付这 400，要从「拆成几笔付款就是几个认领」自己推。

5. **职责分离的口径不一致。**
   - 支付设计、财务设计按账号比较（并写明等员工组件与 C7）。
   - 协议 09 要求按人比较，没员工组件时退化为账号。
   - 两者并不矛盾，但没装员工组件时，同一个人的第二个账号可以批准自己的申请。
   - 协议 09 要求「在装配时告知客户」，支付设计没有写这条告知。
   - 另外协议 09 写的是「处理人」不是「发起人」的职责分离，没提执行环节。
   - 支付设计「执行人可以是批准人」属于该组件自己的选择（AI 定，待复核）。

6. **提交与认领的边界。**
   - PR01：每行本次金额「不超过登记时财务答的可用余额」，这个检查发生在哪一步？是新建、修改，还是提交？
   - PR02 又说提交时才逐行认领。
   - 这两处的先后与重复检查没有写清。草稿阶段看到的可用余额，提交时可能已经变了。
   - 第 1 题的「800 元」按 PR02 理解，在提交时才被拒；若 PR01 的登记时也向财务询问，则可能在新建时就被拒，文档没写。

7. **续期失败的原因与恢复。**
   - PR07 只说续期被拒就记下，执行时答 `CLAIM_LOST`。
   - 没写申请上有没有可见的提示，用户要等到执行才知道失效。
   - 也没写后台续期工作项本身失败（组件停机、财务不可达）的处理。
   - 财务设计里续期被拒的条件只有「已到期」，没有写财务不可达的重试。

8. **银行退回只能整笔，银行部分退回无办法。**
   - PR05 与 ST05 都明说部分退回不在首批，财务设计 ST05 说「不满足的告警、等着人处理」。
   - 但「等着人处理」怎样处理，两份文档都没写，包括人用什么命令去处理。

9. **对账单重复判断只靠银行流水号。**
   - BR01 去重键是「同一账户、同一银行流水号」。
   - 流水号为空、或银行在不同行复用同一流水号时的做法没写。
   - 收款单的银行流水号同账户内唯一，付款申请的流水号在文档里没写是否唯一，也没写同一流水号被自动匹配到多张单据时的处理（BR01 只写「唯一的一个才匹配」）。

10. **上游契约字段的对应。**
    - 支付设计写发布的是「`fund_fact.v1`：到账（`receipt`，没有认领）、付款（`payment`）、退款（`refund`）」。
    - 财务设计契约表里种类是「到账、付款、退款、冲正」，并说冲正带被冲正的资金事实身份。
    - 两处用词略有不同，但没有矛盾。
    - 一个小的对不上之处：支付设计事件表写「冲正带被冲正的事实身份」，PR05 称字段为 `reverses_fact_id`；财务设计只写「被冲正的资金事实身份」，没给字段名。

11. **财务缺席时的行为。**
    - 支付设计「PR01」「PR02」写没装财务时「直接 `submitted`」，PR04 在没财务时是否仍要确认，没写。
    - 此时审批、退回、冲正没有财务可回写，BL35 这类的行为只在装了财务时才有意义。
    - 协议 05 与边界卡写「线下登记、人工核对」，没给出核对的办法。
