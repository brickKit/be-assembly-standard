# 参考答案（考前写）

1. 收货单保持 `receiving`，已收数量不变（已收只来自入库流水）；恢复作业按同一收货身份重发 `StockService.Receive`（库存按收货身份幂等，不会多收）；库存的流水事件（`ref_kind = purchase_receipt`）到达时按流水身份去重记进 `receipt_movement`、加已收，收货单的流水齐了就 `posted`。依据：design.md 的“收货、验收与退货”、PO07；库存设计的“采购收货”。
2. 拒绝，整笔拒绝：98 + 8 = 106 > 100 × 1.05 = 105（PO07；收货中的也算进去）。
3. 修订：只有已批准的订单能修订，新修订回到 `submitted` 要重新审批（PO06）；已收的不改，收货计价依据按发起收货时的单价，差额由财务的票据单价确认与成本调整处理（未决问题最后一条；协议 05b 的暂估与调整）。
4. 要审批时：批准被拒，批准人不能是提交人（按账号，PO04）；政策不要审批时，提交直接批准（PO03），审计照写。
5. 被拒：退货数量不超过该流水的净收货（PO09，采购先查），库存再核对一次（库存设计的“采购退货”：数量不超过原流水减它已退的，答 `RETURN_NOT_POSSIBLE`）。
6. 不能取消（PO11：已批准的只在没有收货、验收时）；要结束未收部分用“关闭”（PO10，没有收货中的收货才行，未收部分作废）；全部收足时自动完成（PO12）。
7. 服务行经验收：验收单记数量与金额、发布验收事实；财务经系统面 `MatchService.Basis` 按订单行读已验收的数量与金额（匹配依据），期末暂估同样按它（协议 05 的“收货未开票的期末暂估”）。
8. 收货计价依据：每个收货行一条，单价取订单行（不含税）、币种取订单，在发起收货时（建收货单的事务里）发布；它是不可遗漏的增量事实，事实身份是收货行身份，丢了按身份经 `FactService.Read` 补取（协议 05 的共同规则）；没到之前成本按政策价标“待定价”（协议 05b）。
