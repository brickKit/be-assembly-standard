# C2 P5 一致性考试的结果

- 考生：两个无头会话（默认模型、sonnet），只读 `components/erp/purchase` 的文档与代码与它们提到的 `docs/zh/`；题目 `questions.md`，参考答案 `answers.md`（出题时写）。
- 结果：两份都是 8/8，每题都判“一致”，与参考答案相符；没有答错。

## 考生指出的空白与处理

| 空白 | 谁指出 | 处理 |
| --- | --- | --- |
| 设计没写收货计价依据的单价按基本单位（只有契约与 `receipts` 的说明写了） | 两份 | `erp/purchase` 3.0.1 的设计“规则要点”补写 |
| 收货已失败之后库存的流水仍计入已收（`record` 的“入库事实优先”），设计没写 | 默认 | 3.0.1 的设计“按入库事实补齐”补写 |
| 撤回事实的身份是随机的：拿着计价依据、漏了撤回的消费方算不出该读哪个身份 | sonnet | 真缺口。3.0.1 把撤回的身份改成由计价依据身份推出（UUIDv5，命名空间写进契约 alpha.3），集成测试先红后绿 |

## 没有采纳的

- 默认模型提到“去重依赖库存的同步答复与事件的流水身份相同”：这是库存契约的承诺（`ReceiveResponse.movement_ids` 与事件的 `fact_id` 是同一条流水），不在采购里改。
