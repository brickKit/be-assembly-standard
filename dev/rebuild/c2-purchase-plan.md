# C2：`erp/purchase` 的子计划

阶段“按依赖顺序重建其余组件”的第二个组件（[components-plan.md](components-plan.md) 的 C2）。照 C1 的做法（[c1-employee-plan.md](c1-employee-plan.md)）：先定首批范围与源头要补的能力，按改动的循环做，每一步先写红的测试，改坏检查，发布，真机格从空库到 L3。数据与改坏检查放 `c2-data/`。

## 依据与牵动

- 边界卡 `docs/zh/07-components/erp-trade.md#erppurchase`；业务流程 `docs/zh/08-flows/procure-to-pay.md`；协议 01、02、05（应付匹配依据、预付）、05b（收货计价依据、退货）、07、08、09、13、14、16，安全 01–09。
- 源头现在做不到、要先补的（2026-11-10 读代码与设计）：
  - `mdm/partner`：只有客户角色；供应商角色在契约里、答“能力不支持”（设计第 128 行）。
  - `erp/inventory`：入库只有给种子与手工收货的用户面（`POST /api/inventory/receipts`）；采购退货出库（`purchase_return`，引用原入库流水）答“能力不支持”（设计第 23、143 行）。采购要一个经系统面、带收货行参考与幂等的收货入库，与引用原入库流水的退货出库。
  - `mdm/product`：按法人的可采购（`purchasable`）与资格查询已有。
- 下游还没有：`erp/finance`（应付、预付、匹配依据的查询方）、`erp/costing`（收货计价依据的消费方）、`infra/workflow`（审批待办）、`erp/tax`、`erp/budget`、`erp/contract`。按边界卡的“缺件”，首批里这些用到的地方照缺件的写法处理。

## P0 的结果（2026-11-10，AI 定，待复核）

**首批做的**（边界卡的统一语言与命令，按协议 05、05b 的衔接）：

| 能力 | 怎样做 |
| --- | --- |
| 采购申请 | 新建、修改、提交、批准或驳回、取消；批准后的申请行转成订单行（一行可以分几张订单，转过的数量不超过申请数量） |
| 采购订单与修订 | 抬头：法人、供应商（`mdm/partner` 的供应商角色在该法人启用）、币种、部门与负责人；行：产品（`mdm/product` 在该法人可采购）、数量与单位、单价、仓库（库存物资）、预计到货日、可选的项目参考。状态：草稿 → 待审批 → 已批准 → 部分收货 → 已收货 → 已关闭，以及取消；已批准的订单修改是新修订（数量不低于已收、价格变了要重新审批）；生命周期一张表（照 `erp/sales`） |
| 审批 | 组件页面里审批（没有 `infra/workflow` 时的缺件做法，协议 09）：操作 `erp.purchase.order.approve`，审批人不能是申请人本人（按账号；按自然人等 C7 的业务确认 profile 再看） |
| 收货入库 | 采购经库存的系统面发起入库（带收货行参考，按收货身份幂等）；收货数量以库存的入库事实为准：订阅库存的流水事件，按收货行参考补齐进度（回调丢失时补齐，验证故事）；超收比例按法人的采购政策（起始 0%），超出被拒 |
| 服务验收 | 服务与非库存物资的行按数量或金额验收，记验收事实，不入库 |
| 采购退货 | 退货单引用原订单行与原入库流水，经库存的系统面出库（`purchase_return`）；退货数量不超过该流水的净收货 |
| 事件 | 订单状态事件（全状态）；验收事实、收货计价依据（键是收货行参考，带单价与币种）、采购退货：都是不可遗漏的增量事实（协议 05 的共同规则：事实身份、按身份与序号范围查询） |
| 匹配依据查询 | 系统面：按订单行给已收、已验收的数量与金额（供 `erp/finance` 的三单匹配与期末暂估） |

**不在首批**（理由与触发）：

| 能力 | 理由 | 触发 |
| --- | --- | --- |
| 预付申请 | 预付申请是向 `erp/finance` 的命令，财务还没有；边界卡的缺件写法是线下处理 | C4 `erp/finance` |
| 供应商价格表、询价与比价、返利 | 首批价格在订单上录入；返利经财务的供应商贷项 | 客户要价格表，或 C4 之后 |
| 税额 | `erp/tax` 不在当前重建；订单金额不含税，进项税由财务按票据算（D49） | `erp/tax` 开工 |
| 预算占用 | `erp/budget` 不在当前重建 | `erp/budget` 开工 |
| 框架协议的价格与额度 | `erp/contract` 不在当前重建 | `erp/contract` 开工 |
| 复杂仓储的收货请求、直运、寄售 | 远期（D45 之后的仓储、销售的直运） | 对应组件开工 |
| 审批按自然人与统一待办 | 等 `infra/workflow`（C7）与业务确认 profile | C7 |

**源头补能力（P0b）**：`mdm/partner` 的供应商角色（照客户角色：每个伙伴、每个法人至多一个，开通、暂停、退役，资格查询 `eligible`/`not_opened`/…，供应商的付款条件与默认币种）；`erp/inventory` 的采购收货（系统面 `Receive`：收货行参考、产品、仓库、数量、批次或序列号，按收货身份幂等；入库流水带来源参考）与采购退货出库（系统面，引用原入库流水，类型 `purchase_return`，数量不超过该流水未退的部分）。两个组件各按改动的循环做（意图、考设计、契约、红的测试、实现、核对、发布），连锁照 C1。
