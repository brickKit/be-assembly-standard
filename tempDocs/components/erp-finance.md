# 财务与结算

> 边界卡，2026-10-13 候选。格式见[目录页](README.md)。财务拥有总账、应收应付台账、核销与期间；信用、存货成本、客户出账、收付款、税计算各是独立可选的组件（D03、D46、D48、D47、D49），向财务提供可靠事实，不维护第二份账簿权威。

## erp/finance

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要会计账簿、应收应付的所有 ERP 客户 |
| 统一语言 | 科目表；凭证与分录；应收与应付未清项；核销与冲正；会计期间与关账批次；供应商票据登记与匹配（D50）；期初 |
| 拥有的数据 | 科目表、凭证（每法人一个正式账簿，D51）、应收应付未清项、核销记录、期间状态与关账批次、供应商票据与匹配结果、编号序列 |
| 不变量 | 借贷平衡；凭证号按法人与期间连续（协议 14）；已关期间不能过账；核销在锁内完成，未清金额不为负（协议 05）；同一来源事实只入账一次（事实 ID 去重） |
| 命令与查询 | 过账（来自各来源的事实）；手工凭证；核销与冲正；关账批次（协议 06）；重开；供应商票据登记与匹配；账簿、余额、账龄查询 |
| 事件 | 凭证过账；应收结清与重开（供信用释放或恢复应收占用，协议 05）；期间状态 |
| 必需依赖 | `mdm/org`、`mdm/partner`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | 出账、收付款、成本、信用都是可选来源：缺时相应的事实不存在，由财务手工凭证或人工未清项处理，并在报表中注明 |
| 替换与 Fork | 需要多账簿或特殊会计准则的客户选择专项财务实现或 Fork（D51） |
| 部署 | 事务密集、期末批量；单跑或外壳按负载 |
| 适用协议 | 01、02、03、05、06、07、11、13、14、15、16（期初凭证与未清项）、安全 01–09 |
| 范围 | 当前重建范围 |
| 验证故事 | 同一收款被两次核销时只成功一次；关账期间迟到的成本调整顺延；期初应收控制科目等于未清项合计才激活 |

## erp/credit

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要对客户做信用控制的客户 |
| 统一语言 | 信用政策；额度（按伙伴、法人、币种）；信用占用（订单预占、应收占用）；超限判断 |
| 拥有的数据 | 政策、额度、占用分支（协议 04）、应收占用（由“已出账”增量事实建立、财务的“应收结清／重开”事实增减，协议 05） |
| 不变量 | 已用 = 订单占用 + 应收占用 ≤ 额度（超限按政策拒绝或转审批）；订单出账后订单占用转为应收占用在一个本地事务内完成（协议 05） |
| 命令与查询 | 预占、提交、消耗、释放（协议 04）；期初分支与期初应收占用（上线窗口，协议 16）；额度维护（需要业务确认）；可用额度查询 |
| 事件 | 占用状态；超限 |
| 必需依赖 | `mdm/partner`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/billing`：缺时没有“已出账”事实，订单占用不转换为应收占用，只按订单占用控制，并注明；`erp/finance`：缺时应收占用只增不减（没有结清事实），需要人工释放 |
| 替换与 Fork | 信用评分与审批规则是替换点；整体可替换 |
| 部署 | 低到中负载；适合外壳 |
| 适用协议 | 02、04、05、13、安全 01–09 |
| 范围 | 当前重建范围（新身份） |
| 验证故事 | 两张订单同时确认，只有额度内的一张成功；出账后占用转换不重复计算 |

## erp/costing

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要存货成本与销货成本的客户 |
| 统一语言 | 计价方法（移动平均、先进先出、标准成本）；成本层；暂估；成本调整；成本事实 |
| 拥有的数据 | 计价政策与标准成本、成本层、暂估与调整记录、成本处理进度（按序） |
| 不变量 | 按库存流水的事实 ID 与“产品 + 计价范围”序列的顺序处理，每条流水只计价一次；缺口时暂停后续并补齐（协议 05）；暂估与实际差异以调整事实表达 |
| 命令与查询 | 计价政策维护；成本重算（受控）；成本查询 |
| 事件 | 成本事实（供财务过账） |
| 必需依赖 | `erp/inventory`、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | 财务：缺时成本事实只供查询 |
| 替换与 Fork | 计价方法是替换点；整体可替换 |
| 部署 | 后台处理为主；期末批量 |
| 适用协议 | 01、02、05、06、13、14、安全 01–09 |
| 范围 | 当前重建范围（新身份，D46） |
| 验证故事 | 乱序到达的流水按序处理；暂估入库后收到票据形成调整；关账后的调整顺延 |

## erp/billing

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要向客户开具账单或商业发票的客户 |
| 统一语言 | 账单与明细；来源认领（协议 05）；补差；更正与红字；账单正式化 |
| 拥有的数据 | 账单、来源认领记录、更正与补差、账单的编号序列（按法定要求连续） |
| 不变量 | 认领由来源裁决，同一来源额度不被重复出账；正式化后不修改，更正以新单据表达；账单金额与税额依据可追溯 |
| 命令与查询 | 草拟账单（从来源）；正式化；更正与补差；账单查询 |
| 事件 | 账单正式化（供财务形成应收，供信用转换占用）；更正 |
| 必需依赖 | `mdm/partner`、`mdm/org`、`mdm/currency`、身份、授权，至少一个来源组件（销售或项目） |
| 可选依赖与缺件 | `erp/tax`：缺时税额由有权限的人录入并标为人工税额；`integration/einvoice-<地区>`：缺时不提交电子发票；打印：缺时不出 PDF |
| 替换与 Fork | 出账规则（周期出账、按里程碑）是替换点 |
| 部署 | 中负载、月末高峰；适合外壳 |
| 适用协议 | 01、02、05、07、10（电子开票）、13、14、16、安全 01–09 |
| 范围 | 当前重建范围（新身份，D48） |
| 验证故事 | 两人同时为同一订单出账，只有一张成功；正式化后更正生成红字；电子发票提交结果未知时先查询 |

## erp/payment

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要登记或执行收付款的客户（可以只用线下登记） |
| 统一语言 | 收款单与付款单；付款申请与执行；公司银行账户；外部交易结果；银行对账 |
| 拥有的数据 | 收付款单、付款申请与执行进度、公司银行账户资料、外部结果、对账结果与差错 |
| 不变量 | 受理、批准、通道接收、到账分别表达；付款执行有职责分离与审批（协议 09）；结果未知时不重复执行（协议 10） |
| 命令与查询 | 登记收款；提交付款申请；执行付款（经适配器）；对账；差错处理 |
| 事件 | 收付款事实（供财务核销）；付款状态 |
| 必需依赖 | `mdm/partner`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | 支付与银行适配器：缺时只能线下登记；`infra/workflow`：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09） |
| 替换与 Fork | 资金流程可 Fork；通道适配器可替换 |
| 部署 | 低到中负载；适合外壳 |
| 适用协议 | 01、02、05、09、10、13、14、15（外部事实进入证据存储）、安全 01–09 |
| 范围 | 当前重建范围，先做线下登记（新身份，D47） |
| 验证故事 | 付款超时后查询而不重发；银行对账发现漏收回调；恢复后不盲目再付款 |

## erp/tax

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要自动计算税额的客户 |
| 统一语言 | 税务主体与登记；税项；计税基础；税率与规则版本；计算结果（适用、不适用、未知） |
| 拥有的数据 | 税务主体与登记、规则与版本、计算记录 |
| 不变量 | “不适用”与“无法计算”分别表达；结果附规则版本与日期依据；不静默按零税额放行 |
| 命令与查询 | 计算（报价、订单、账单）；规则维护 |
| 事件 | 规则版本发布 |
| 必需依赖 | `mdm/org`、`mdm/partner`、`mdm/product`、身份、授权 |
| 可选依赖与缺件 | 外部税务服务适配器：按地区 |
| 替换与 Fork | 按地区的实现可替换；与电子开票分别选配（D49） |
| 部署 | 低负载、同步调用；适合外壳 |
| 适用协议 | 02、10（外部税务服务）、14 |
| 范围 | 远期（新身份） |
| 验证故事 | 规则变更后旧订单按原版本解释；未知结果阻止正式出账并提示 |
