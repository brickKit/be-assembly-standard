# 升级与维护窗口

规则见[协议 17 的维护窗口中的升级](../06-protocols/17-runtime-and-resources.md#维护窗口中的升级)、[协议 19](../06-protocols/19-config-secrets-registries-release.md) 与[协议 14 的结构迁移](../06-protocols/14-data-foundations.md#结构迁移与版本兼容)。

## 标准升级

| 步骤 | 做什么 | 完成的依据 |
| --- | --- | --- |
| 1. 准备 | 升级候选：目标基线、变化（功能、权限、数据、契约）、升级路径、验证证据、维护窗口与恢复办法；客户决定接受 | 客户的书面确认 |
| 2. 预告 | 通知受影响的业务与时间 | 通知记录 |
| 3. 核对产物 | 部署前核对产物摘要与签名、软件物料清单与清单一致；外壳由工具从基线生成 | 核对记录；不一致拒绝部署 |
| 4. 冻结 | 按备份与恢复手册的第 2 步停止入口与执行者 | 没有在途发送 |
| 5. 备份 | 完整备份并确认可读 | 备份记录 |
| 6. 迁移 | 执行结构迁移；数据库主版本升级或迁移、删库重建时推进部署恢复代次（协议 14）；组件启动检查持久设置与计时源 | 迁移日志；代次记录；组件进入就绪 |
| 7. 验证 | 真实业务验证：受保护的请求、事件、作业、对外命令（沙箱）各走一遍 | 验证清单 |
| 8. 开放 | 先查询后写入；核对组件报告的实际版本与配置摘要 | 实际版本记入基线 |
| 失败 | 开放之前失败：按备份与恢复手册的第 2–10 步处理，第 3 步恢复到升级前的备份（冻结、恢复、推进两种代次、重建消息流、补回维护窗口内的收紧、结束会话、外部对账，验证期间发出的事件不能留在消息流中）；开放之后：只向前修复 | 处置记录 |

## 配置变更

1. 提交完整的候选配置快照；校验失败则整个候选不生效。
2. 动态键原子替换；需要重新部署的键随部署生效。
3. 核对组件报告的实际配置摘要与目标一致；不一致按告警处理。

## 密钥轮换

| 类型 | 步骤 |
| --- | --- |
| 签名密钥 | 备用密钥已发布超过验证方的最长缓存时间（5 分钟）后切换签名；发布新的备用；旧公钥在旧令牌全部过期加缓存时间后移除 |
| 回调签名密钥 | 新旧并存 7 天后移除旧的 |
| 数据库密码 | 两个运行角色交替：建好新角色并分发，组件切到新连接，旧连接自然结束后停用旧角色 |
| 外部账户、对象存储凭据 | 先加后删；不支持并存时安排维护窗口 |
| 泄露 | 立即吊销（记入证据）；签名改用已分发的备用密钥，同时生成并发布新的备用；记录可用性影响 |

## 更换授权成员或身份成员

按安全 [10](../06-protocols/security/10-providers-and-member-switching.md#成员切换协议)、[11](../06-protocols/security/11-identity-member-switching.md) 的步骤，在维护窗口内进行。操作要点：

- 预检的缺口一项不留；身份切换要准备每个平台主体（含没有映射的）的状态记录、两个控制台的锁定、新签名公钥的预先发布、全部身份来源消费者的清单。
- 每一小步完成后核对守卫（排空为零、全量核对“不比旧成员宽”）才进入下一步；守卫不满足时按协议的回退步骤，不跳步。
- 身份切换从 6.2 到授权组件完成 6.5 实际停机（依赖身份来源的判断关闭），维护窗口按演练测得的时长安排；超过 `T_tight` 的部分，账号管理需要第二人确认（单管理员部署由部署所有者确认），部署所有者在场。
- 身份切换中，授权组件完成对齐之前不开放新成员的登录；只选（a）（b）登记方式时，开放前核对每个授权管理员都已领取登记码。
- 记录每个消费者完成重新对齐的时间；全部完成、旧成员签发的最后一个访问令牌过期、观察期（起始 1 天）内没有请求到达旧成员之后，才退役旧成员。

## 更换存储路线或对象存储后端

- 冷数据：按协议 11，把已发布的单元复制、校验、以新清单版本发布到新路线，宽限期与读取租约结束后释放旧路线。
- 对象存储：新后端先通过接口子集的一致性套件；按属主逐个复制并核对摘要；切换后旧后端在宽限期内只读；对账覆盖两边（协议 12）。
