# 前端技术栈

本页回答：前端用什么框架与组件库，页面怎样保持一致，移动端用什么构建、各种形态怎样登录；这些选择在终局设计下是否仍然成立，什么条件下改选。入口、页面模块、会话、显示规则与断网草稿的协议在[协议 20](../06-protocols/20-frontend.md)；按入口选择与替换的客户视角在[前端的选型说明](../00-overview/guides/frontend.md)。

项目原有五条前端决定（0401–0405：技术栈、第三方组件只在 ui-kit、两层导航、四项用户偏好、设计令牌为 CSS 变量）。现有代码不约束终局设计（D59），所以本页把它们逐条放到终局设计下重新审视：结论是沿用，并按终局设计调整菜单的来源、移动端各形态的登录方式与写法约定；原决定中挡下的做法与重新讨论的条件，在下文“沿用的约束”中原样承接。

## 结论

| 方面 | 选择 | 调整 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript，只用 Composition API 与 `<script setup lang="ts">` | 锁定大版本；`AGENTS.md` 写明版本与唯一写法；lint 禁止 Options API 等旧写法 |
| PC 组件库 | Ant Design Vue（表单、布局、反馈）+ vxe-table（表格）+ ECharts（图表） | 不变 |
| 移动端 | Uni-app + wot-design-uni；按需要出 H5、小程序或 App | 各形态的登录方式按下文的表，与协议 20 一致 |
| 组件隔离 | 第三方 UI 只出现在 `ui-kit-pc` 与 `ui-kit-mobile` 中，页面只用 ui-kit 暴露的组件（`<BeTable>` 等） | 不变 |
| 导航 | PC 两层导航：服务选择器（按领域分组的组件）+ 组件内的扁平菜单 + 应用内标签页 + 命令面板 + 法人切换；四种页面模板 | 菜单与服务选择器的来源改为页面模块的声明（见下文），不再由后端组件的 `assembly.yaml` 汇总 |
| 用户偏好 | 收藏的组件、亮暗色、密度、语言，外加本地保存的表格列状态；品牌是部署配置 | 不变 |
| 设计令牌 | 运行时 CSS 变量，同时驱动 AntDV 与 vxe-table 的主题 | 不变 |

## 逐条复核

| 原决定 | 与终局设计的关系 | 结论 |
| --- | --- | --- |
| 0401 技术栈 | 入口按 D17 分别选择与替换，标准入口用什么技术不约束客户 Fork 或行业入口；PC 与移动是两种产品，不共享组件，只共享令牌，与“按入口”的设计一致 | 沿用 |
| 0402 第三方组件只在 ui-kit | 与后端“只经 SDK”同一思路；更换表格引擎只改一个包，页面不动；这对 AI 生成页面尤其重要（页面不会混入第三方组件的写法） | 沿用 |
| 0403 两层导航 | 原理由是“每个客户装的组件不同，多级树形状各不相同”，在按客户基线构建入口（D34）下仍然成立；但菜单的来源从后端 `assembly.yaml` 汇总改为页面模块声明（协议 20） | 沿用，改菜单来源 |
| 0404 四项用户偏好 | 与终局设计无冲突；偏好不需要后端服务（列状态只在本地） | 沿用 |
| 0405 CSS 变量令牌 | 亮暗与密度在运行时切换；客户 Fork 改品牌只改令牌 | 沿用 |

## 沿用的约束

原决定中“挡下什么”与“何时重新讨论”全部承接，迁移时随决定记录保留：

| 原决定 | 挡下的做法 | 何时重新讨论 |
| --- | --- | --- |
| 0401 技术栈 | React、Next.js 等非 Vue 框架；用 Element Plus、Naive UI、Vuetify 等替代 Ant Design Vue（当前大版本 v4）；“PC 与移动统一一套组件库”；在 ECharts 之外再引入第二个图表库 | 某个锁定的库停止维护，或页面需要的 vxe-table 能力被证实只在商业版提供：在 `<BeTable>` 背后替换表格引擎，页面不动 |
| 0402 第三方组件只在 ui-kit | 页面里直接引入第三方组件（`<vxe-grid>` 也不例外）；“这个页面用 X 库更好看”；在单个页面覆盖第三方组件的样式；没有记录的封装逃生口。例外通道：只有 Ant Design Vue 缺失的能力（甘特图、审批流设计器、富文本、代码编辑器、大屏看板）才可以引入其他 UI 库，必须包在 ui-kit 里并记录在 `ui-kit-pc/README.md` | 页面直接引入第三方组件这一点永不重新讨论；能力缺口清单只在 Ant Design Vue 确实做不到时增加 |
| 0403 两层导航 | 左侧多级树形菜单；组件内可折叠或嵌套的菜单；去掉应用内标签页（未保存的表单在浏览器刷新时会丢失）；把 vue-vben-admin、antdv-pro 等 admin 模板作为依赖（可以读它们的代码，不安装）；中心化、手工维护的菜单表；从空白 `<div>` 开始手工排版页面。骨架：服务选择器（按领域分组、可搜索、最近访问、可加星标）、收藏栏、每个组件 3–5 个页面的扁平菜单、跨组件的应用内标签页、⌘K 命令面板、组织与法人切换器；隐藏组件只是方便，不是安全措施 | 某个组件的页面多到扁平菜单放不下时：先拆分组件，而不是加深菜单 |
| 0404 四项用户偏好 | 让用户选布局（侧边栏、顶栏、混合）；每个用户自选主题色或 logo；照抄 admin 模板的设置面板（圆角、动画、页脚、面包屑开关）；只为存偏好新建后端服务或仓库。四项是收藏的组件、亮色／暗色／跟随系统、密度、语言，外加只存本地的表格列状态；收藏与语言存身份适配组件的用户资料，亮暗与密度存本地；主色、logo、产品名、水印与灰度模式是部署配置 | 多个真实客户都要求同一个额外偏好项时 |
| 0405 CSS 变量令牌 | 令牌导出成 TS／JS 常量或只在构建期解析的 Sass 变量；在页面里硬编码颜色或尺寸；每个 UI 库各一套互不相通的主题 | 永不重新讨论 |

## 方案比较

**框架**：

| 方案 | 判断 |
| --- | --- |
| **采用**：Vue 3 + TypeScript | 业务表单的双向绑定直接；PC 与移动（Uni-app）同一框架；Vue 生态有成熟的 ERP 表格（vxe-table）与企业组件库（AntDV）；生成的模板结构简单，便于评审 |
| React + TypeScript | 资料与组件最多，类型约束更自然，是没有既有约束时的常见默认；但移动端要换 Taro 或 React Native，PC 的密集表格要另选（AG Grid 等），项目已有的 Vue 页面规范与决定都要重写。改选条件：需要的关键组件只在 React 上成熟，或团队转向 React |
| Angular、Svelte 等 | 生态或团队熟悉度不足以抵消改变的代价 |

**表格**：

| 方案 | 判断 |
| --- | --- |
| **采用**：vxe-table（包在 `<BeTable>` 后面） | 虚拟滚动、合并单元格、可编辑表格、树表与大数据量在开源版中可用，适合 ERP 的密集列表 |
| AntDV 自带的表格 | 简单列表够用，大数据量与可编辑场景不足 |
| AG Grid | 功能最全，但部分企业功能需要商业许可；React 生态更成熟 |

改选条件：页面需要的某项能力被证实只在 vxe-table 的商业版中提供，或它停止维护——在 `<BeTable>` 背后替换引擎，页面不动。依赖某项表格能力之前，先对照免费版逐项核对：虚拟滚动、冻结列、可键盘连续录入的可编辑单元格、树表格、Excel 导入导出、分组与透视、甘特图；结论记在 `ui-kit-pc` 的说明中。可编辑单元格、虚拟滚动、冻结列三项中任一项需要付费，就换引擎；候选引擎也按同一份清单核对。

**移动端**：

| 方案 | 判断 |
| --- | --- |
| **采用**：Uni-app（Vue） | 同一套 Vue 代码出 H5（浏览器、企业微信与钉钉内的页面）、小程序与 App；与 PC 同一框架 |
| Capacitor 包装 H5 | 网页已完成、只需上架与少量设备能力时简单；不出小程序 |
| React Native、Flutter | 原生体验更好，但换语言或框架，与 PC 不共用写法 |
| 原生开发 | 深度使用系统能力时才值得 |

改选条件：外勤场景需要大量原生能力（离线采集、复杂硬件），或某个渠道（例如鸿蒙原生）成为必需。

## 移动端各形态的登录

Uni-app 出的不同形态，在会话模型里属于不同类型（协议 20 的登录与会话）：

| 形态 | 会话类型 | 方式 |
| --- | --- | --- |
| H5（浏览器，企业微信与钉钉内置浏览器） | 浏览器入口 | 服务端会话：身份适配组件持有会话，浏览器只有 `HttpOnly` Cookie，边缘注入短期令牌（D61）；企业微信与钉钉的免登用它们的授权码换平台会话 |
| App（Android、iOS） | 原生应用 | 系统浏览器中的授权码 + PKCE；令牌存于系统安全存储；刷新令牌每次更换 |
| 小程序 | 平台应用 | 平台登录凭证经身份适配组件换取应用会话；凭证存平台提供的存储，按原生应用的刷新规则；需要小程序时专项设计并验收 |

## 菜单与导航的来源

- **页面模块声明菜单**：每个页面模块声明菜单项、路由、所需的权限键，以及它所属的组件与领域（用于服务选择器的分组）。入口构建时按客户基线组合选中的页面模块，菜单随之确定（协议 20）。
- **后端组件不再声明菜单**：后端组件的 `assembly.yaml` 不再有 `menus`；装配工具中按组件汇总菜单的功能退役。原因：页面属于入口，同一个后端组件在 PC、移动与终端入口上的页面不同，菜单应当跟着页面走；客户 Fork 某个入口时，菜单随 Fork 一起改，不需要改后端组件。
- **运行时**按 `features`（部署启用了什么）与 `permissions`（这个用户能做什么）过滤显示。

## 写法约定

锁定版本、只用一种写法、lint 强制：

- `package.json` 写精确版本（不用 `^`、`~`、`latest`），锁文件进仓库；必须配套的组合（vxe-table 与 vxe-pc-ui）连同版本记在 `ui-kit-pc` 的说明中。Vue、AntDV、vxe-table、Uni-app、wot-design-uni 的大版本升级是单独的任务，用官方迁移工具一次迁完。
- 只用 Composition API 与 `<script setup lang="ts">`；`eslint-plugin-vue` 的 `vue/component-api-style` 禁止 Options API；`vue-tsc` 严格模式。
- 页面从 ui-kit 的四种页面模板（列表、详情、表单、设置）开始；页面里不硬编码颜色、尺寸与间距。
- 只为 AntDV 缺的能力混入别的库（甘特图、审批流设计器、富文本、代码编辑器、大屏可视化），每混一个在 `ui-kit-pc` 的说明中记一行：哪个能力、为什么 AntDV 不行、许可证；绝不为好看混入：两个库的令牌体系对不齐。
- 表格一律经 `<BeTable>`；直接用表格引擎接口的逃生口逐个记在 `ui-kit-pc` 的说明中，这份清单的长度就是将来换引擎要改的地方。
- 可编辑单元格在 vxe-table 的编辑插槽里用 AntDV 的控件，一次注册成全局渲染器。
- **前端与后端的分工**：金额计算、扣减库存、核心状态迁移都在后端；前端只管表单交互（校验、字段显隐联动、防抖节流、防丢失的本地草稿）。依赖后端规则的实时估算，防抖调用后端的试算或校验接口，绝不在前端重写后端的公式；不手写请求，一律用从契约生成的客户端与类型。
- 日期范围选择器的默认值与列表的默认范围一致（未关闭，或最近 N 天内创建，[协议 11 的列表与导出](../06-protocols/11-tiering.md)），不会无意中扫全表，也不会把仍未关闭的旧单据排除在外。

**主题与视觉**：

- PC 端主题只有一个源头：AntDV 的 seed token 是源，`ui-kit-pc` 在启动时由它派生 vxe-table 的变量；亮暗与密度在同一个函数里一起切换 AntDV 与 vxe-table。没接起来的话什么都不报错，只是每张表格都像贴进页面的。
- 视觉方向是克制专业：只改 seed token 的主色，其余跟随 AntDV 的派生；紧凑密度用紧凑算法，行高由 ui-kit 统一给；小圆角、克制阴影，不拿卡片包裹一切；系统字体栈，不下载也不内嵌字体（离线部署）；表格无斑马纹、只留横线、悬停高亮，固定表头、冻结列、虚拟滚动是默认。在本项目里“好看”就是“一致”：毁掉分批生成的页面观感的，是这一页间距 16、下一页 20。
- 入口仓库的 `AGENTS.md` 写明版本、唯一写法与一个标准页面的例子（[AI 导航与信息定位](../01-conventions/05-ai-navigation.md)）。

## 已知风险与待定

- vxe-table 开源版与商业版的能力边界随版本变化，按页面需求在实施时核对。
- 小程序的登录与会话在需要时专项设计；企业微信与钉钉内 H5 的免登流程随身份成员的设计确定。
- 入口仓库与共享包（ui-kit、设计令牌、接口客户端）的划分随重建计划确定。
- 以上选择尚未在终局设计的入口上实现；原有的 Vue 页面只作参考。
