# 验证映射与正式文档迁移

本页回答：

1. 每个覆盖要求（C01–C44）由哪些设计文档、独立预期、参考模型与将来的测试来证明？
2. 独立预期怎样变成测试，怎样防止“写了预期却没有测试”？
3. 冻结报告包含什么？
4. 冻结之后，设计稿怎样迁成正式文档，旧文档怎样归档而不留下现行引用？

依据：[测试与验证](../01-conventions/02-testing-and-validation.md)、[文档规则](../01-conventions/03-documentation.md)、[AI 导航与信息定位](../01-conventions/05-ai-navigation.md)、[路线](../00-overview/06-roadmap.md)；D59（现有代码不约束设计）、D67（开发完成前正式文档只写中文）。

## 从预期到测试

- 每条独立预期在实现阶段至少对应一个测试；测试名或测试前的注释带预期编号（例如 `AP06`），工具从中生成“预期 → 测试”的对照表（[AI 导航的追踪链](../01-conventions/05-ai-navigation.md)）。
- **覆盖报告**列出每个前缀的预期与对应测试，没有测试的预期列为缺口；发版前缺口为零，或在对应文档写明不适用的理由。
- 参考模型的每个坏变体对应一个负例测试。
- 跨组件的预期（DT、L3）在业务链测试中验证，不以组件的单元测试代替。
- 预期本身被发现有误时，先修改设计文档，再改测试；不为了让测试通过而修改预期。

## 设计稿的状态

| 当前状态 | 事件 | 守卫条件 | 结果状态 |
| --- | --- | --- | --- |
| 候选 | 整理为终稿，经对照与反例审查，发现全部处理 | — | 终稿 |
| 终稿 | 组件分配的多轮复查与最后一轮整体复查没有阻塞问题；冻结报告写成 | — | 待确认 |
| 待确认 | 用户确认冻结报告（含逐条复核 AI 选择） | — | 可冻结 |
| 待确认 | 用户要求修改 | — | 终稿（修改后重新审查受影响的部分） |
| 可冻结 | 迁移完成，收尾检查通过 | 用户确认 | 已迁移（设计稿与开发区归档） |
| 任一 | 实现或实验发现设计错误 | — | 受影响的文档回到终稿，先改文档再改实现 |

## 冻结报告

整体复查结束时写冻结报告，至少包含：

| 部分 | 内容 |
| --- | --- |
| 范围 | 冻结的文档清单与版本（提交） |
| 复查记录 | 每轮复查的范围、发现、处理；最后一轮没有阻塞问题 |
| 覆盖 | C01–C44 每项的设计依据与验证映射（本页）；仍为“未执行”的证据；检查 33、34、链接检查与全部模型的运行结果 |
| 用户决定 | 用户裁定的决定（D01 起）；AI 自行做出的设计选择清单，供用户逐条确认 |
| 已知限制 | 依赖实验的取值、正式交付前的承诺、远期组件 |
| 下一步 | 代表部署实验的计划要点；重建计划（复用、改名归档、新建的仓库清单），经用户确认后才执行 |

## 正式文档迁移

### 目标结构

开发完成之前，正式文档只写中文（D67），按语言目录留出多语言的位置（[文档规则的语言](../01-conventions/03-documentation.md#语言)）。冻结后的内容按读者与用途放置：

| 正式位置 | 来自 |
| --- | --- |
| 根 `AGENTS.md` | 按 D67 用中文重写：入口路由、约定一行摘要、易错点、组件表；指向下列文档（[AI 导航](../01-conventions/05-ai-navigation.md)） |
| `docs/zh/00-overview/` | 设计稿 `00-overview/`：项目主体、领域与边界、组件全景与选择关系、变更与退出、路线、选型说明 |
| `docs/zh/01-conventions/` | 设计稿 `01-conventions/`：工程规范、测试与验证、文档规则、图与表、AI 导航、验收矩阵 |
| `docs/zh/02-decisions/` | 决定台账（D01 起）改写为决定记录；原有决定逐条承接或标为被取代 |
| `docs/zh/03-seed-data.md` | 保留，随新组件更新 |
| `docs/zh/04-foundations/` | 设计稿 `04-foundations/`：每个底层选择一篇 |
| `docs/zh/05-operations/` | 运维手册：备份与恢复、升级与维护窗口、观测与告警、客户上线 |
| `docs/zh/06-protocols/` | 设计稿 `06-protocols/`：安全 01–11 与协议 01–21 的完整设计（含理由、独立预期与参考模型说明） |
| `docs/zh/07-components/` | 系统层的组件全景与边界卡；组件仓库中的文档按边界卡展开 |
| `be-protocol` 仓库 | 从安全与协议中抽出的组件必须遵守的规则（必须、应当、内部），按协议 18 的章节；语义向量 |
| `be-acceptance` 仓库 | 验收矩阵（PA、DT、ST）、一致性套件的检查、参考模型与文档检查脚本 |
| 各组件仓库的 `BRICKKIT.md`、`AGENTS.md`、`docs/design.md` | 边界卡与组件内的设计（重建组件时写入） |
| `registry/` | 组件身份、端口、schema、资源类型、权限键等（协议 19 的注册表规则） |

### 步骤

1. **承接表**：列出现行 `docs/`、根 `AGENTS.md`、工具说明中的每一节，写明在新正文中的去处，或被什么取代、为什么不再需要。没有去处的内容不能归档。
2. **从开发区提取**：开发区的台账、复查记录与证据中仍承载有效结论的内容（决定、证据摘要）迁入正文或决定记录；正文不链接开发区。
3. **写正文**：以设计稿为来源，按目标结构放置；去掉设计稿中只对设计过程有意义的说明；术语按系统层术语表。
4. **归档**：旧 `docs/`（包括现行的英文正文）与 `tempDocs/` 整体移入归档目录；归档之间可以互相引用，现行内容不引用归档（`make docs-boundary` 检查，现行引用归档即失败）。
5. **更新入口与工具**：根 `AGENTS.md`、组件说明、`registry/`、`make` 目标与检查脚本（镜像检查在只有中文时不启用）；本机路径与知识库路径不出现在正文中。
6. **收尾检查**：链接、边界、预期编号（检查 33）、必需依赖无环与组合闭包（检查 34）、表格结构；搜索现行内容对归档、旧路径、`tempDocs` 的引用，应为零。

### 不做的事

- 不保留新旧两套并行的现行规则；切换是整体替换。
- 不把旧代码的行为写成兼容要求（D59）。
- 不在用户确认冻结前迁移。

| VM10 | 增加第二种语言后，两种语言的章节不对应 | 镜像检查失败 |
| VM11 | 正文链接到开发区或本机路径 | 不允许；收尾检查失败 |
| VM12 | 新组件身份未在注册表登记就进入组件表 | 不允许 |
| VM13 | 整理时某份草稿的预期编号没有带到终稿 | 编号检查失败（被整理掉的草稿中的编号必须全部出现在终稿） |
| VM14 | 只有中文时运行镜像检查 | 不要求镜像，检查不启用 |
