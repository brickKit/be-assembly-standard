# 完整授予与统一授权求值

本页回答：一份授权怎样把动作、资源范围、条件与字段绑在一起；同一条记录在列表、详情、动作与字段上的结果怎样保持一致；哪些不确定的情况必须保护。它是[权限与安全](README.md)的求值规格，不另维护产品选择或用户决定。

默认按小公司落地，长期保留标准、静态、关系图、策略引擎的适配路线。所有实现先遵守共同的求值语义，再比较部署与性能；没有统一的规模计划，不因此缩小安全保证。服务凭据（[安全 02](02-trusted-identity-and-attributes.md)）、接受与撤销（[安全 03](03-authorization-acceptance-and-revocation.md)）、授权管理（[安全 04](04-authorization-administration-and-appointments.md)）、委托链（[安全 05](05-sharing-delegation-and-impersonation.md)）、身份映射与迁移是本页的输入前提，各自有专门的规格；本页的求值公式不替它们成立。它们都使用本页的段与集合语义，不另建一套更宽的求值。

## 依据与方案选择

| 已定要求 | 本页保持的结果 |
| --- | --- |
| D09：日常汇总完整授予，关键动作选择任职 | 一份授予的范围、条件、字段一起判定；需要任职的动作只使用相容的绑定 |
| D10：默认防本人自审 | 业务强约束作用于最终动作，额外的角色、共享或任职不能绕过 |
| D07、D08：能力分档与按风险的新鲜度 | 方案缺能力时不能静默扩大或缩小查询；不满足所需新鲜度时保护 |
| 普通授予与管理员交接 | 管理员正常卸任不自动撤销他合法发出的普通授予；来源与资格绑定分别判断 |
| 普通角色升级须确认 | 模板新增的权限不能自动改变客户实际的授予；求值消费明确的版本 |
| 不提供管理员可配置的 Deny | 允许的授予取合法并集，必需控制单独检查，不增加负权限的优先级 |

| 路线 | 优点 | 代价与判断 |
| --- | --- | --- |
| **采用**：完整授予的有限中间表示，统一产生单对象、查询与字段结果 | 不绑定提供方；配对关系可以核对，可以下推到查询，便于三种语言与 AI 局部验证 | 要限定表达式、保留来源与能力元数据；不能只缓存一个全局最宽的范围 |
| 全部远程逐对象 Check | 单对象决策集中，复杂关系容易接入 | 列表完整性、分页、字段与故障预算仍需协议；适合作为声明过的图分支，不能成为所有查询的默认过滤方式 |
| 按维度、等级、字段分别汇总 | 数据结构与调用形状较简单 | 丢失授予的配对；已有法人与仓库交叉授权的反例，不能满足本项目的目标 |

共同中间表示是行为模型，不规定所有提供方的内部表相同，也不强制把任意策略语言翻译成 SQL。成员可以采用等价的“完整候选集合加检查”路径，但必须证明完整性、字段与预算；做不到时，拒绝启用对应的能力。

## 可信输入与资源声明

一次求值使用同一个上下文 `C`：部署、实际主体、被代表主体、有效任职与委托上限、已接受的授权版本、资源事实的版本、求值时刻、操作种类与所需的新鲜度。输入来自已验证的身份与有权威来源的属性，不来自用户自报的角色、`be-caller` 名称或任意 JSON 属性；取证与调用模式见[安全 02](02-trusted-identity-and-attributes.md)。

| 输入 | 必须声明 |
| --- | --- |
| 资源类型 | 由哪个组件拥有、`view_key`、记录身份与法人、组织等维度、每个属性的类型与来源 |
| 操作 | 已注册的权限键；用途是读取、动作还是字段；是否需要选择任职；有没有输出内容，输出用哪个读取权限键 |
| 字段集 | 已注册的字段读写键到列或派生字段的映射；普通字段白名单、不可输出的秘密、能否被搜索与过滤 |
| 资源事实 | 存在性、当前的范围属性、必要的条件属性与修订；已知的 null 与未取得的属性分别表达 |
| 授予集合 | 版本、来源与绑定、完整段；图或关系的结果还要有完整性与适用类型、动作的证据 |

权限键来自注册表，资源与字段的声明属于对应的组件版本。本页中的 `view`、`approve`、`cost`、法人甲与乙、仓库一与二都是模型标签，不分配正式的 ID、权限键或数据库列。

## 完整授予的最小结构

把一份角色任职授予、直接授予或有效的资源关系展开为求值段 `g`。一个段绑定一个操作；同一角色有多个操作或条件组时，产生多个有共同来源的段，不能做范围值的笛卡尔积。

| 成员 | 含义与校验 |
| --- | --- |
| `grant_id`、`source_ref` | 稳定的授予与来源身份，追踪到客户实际角色的版本、任职或资源授予；不只是角色名 |
| `subject`、`binding` | 适用的主体与任职或其他资格的绑定；直接授予也必须有明确的资格与有效性 |
| `resource_type`、`operation` | 已声明的类型与权限键；未知的键不被当作全权或未来的通配 |
| `scope` | 同一段的全部范围约束；显式全范围、明确的空集合、具体值、相对主体的范围分别表达 |
| `conditions` | 本操作的有限类型条件；金额比较带币种或单位语义，不比较浮点数或裸字符串 |
| `read_fields`、`write_fields` | 该操作在该段可以读取、写入的字段集，保留字段键与来源；缺省的敏感字段集合为空 |
| `valid_from`、`valid_until`、资格状态 | 时间窗左闭右开；撤销或失效的绑定不参与；到期不依靠清理任务才失效 |

授权管理保存更丰富的审核、交接与生命周期记录；求值段只是经过校验的执行视图，不能成为第二份授权管理的权威。

普通字段也通过资源的白名单进入输出。新加的字段没有声明分类或权限时，声明校验失败，不能因为它不在敏感字段表里就默认输出。系统秘密从不因超级用户或字段许可变成可输出的数据。

人工共享只给读取，不自行授出确认、取消、关账等业务动作；字段的扩展必须在允许分享的资源与字段清单内明确表示，不自动继承分享者的全部字段许可。组件拥有的团队等关系，按已声明的关系契约产生段，不能用关系的名称伪造业务动作。来源、治理与派生限制见[安全 05](05-sharing-delegation-and-impersonation.md)。

委托与扮演产生的段，必须已经结合合法的来源链、当前上游的资格、期限与各级上限。普通共享、普通管理员发出的授予、用户代办不共用同一种失效规则。本页只消费这种受限的视图：把原授予复制给代办人，不是合格的输入。多个提供方的结果不在调用方按 OR 拼接。

## 范围与条件的有限表达

第一版支持下列语义原语；线协议的字段名、能力版本与预算由[安全 09](../../../security/09-encoding-and-profiles.md)确定，原子、规范化与查询编译见[安全 07](../../../security/07-finite-expressions-containment-and-queries.md)。

| 原语 | 语义与边界 |
| --- | --- |
| 明确的全集、空集、ID 集合 | 全集只对已声明的资源与作用范围生效；空集不匹配；不同的法人与仓库集合仍在同一段内相与 |
| 本人、指定组织、组织子树 | 使用可信的主体与资源属性；空部门不匹配组织分支；子树按路径段的边界判断，不按任意字符串前缀 |
| 属性等值、集合包含 | 属性的类型与允许的来源预先声明；未知值不是通配；已知的 null 默认不匹配这些正向比较 |
| 十进制的上下界 | 写明边界是否闭合、币种或统一的计量依据；舍入与精度遵守共享语义 |
| 有效期、操作环境 | 求值时刻固定在 `C` 中；环境属性的来源可以验证；不能在每行求值时任意读取变化的外部环境 |

一个段内是有限的合取，多个完整段是析取。需要 `owner OR org` 时，展开成两个都保留原有法人、仓库、条件与字段的完整段：例如 `法人甲 AND 仓库一 AND (本人 OR 甲部门)`，不能展开成缺少法人或仓库的分支。

原始 SQL、任意代码、任意属性名与提供方私有的表达式不进入共同表示。标准表达满足不了的客户需求，明确地增加能力、适配或 Fork，不靠忽略条件处理。未知的操作符或不支持的表达，使候选的策略或查询计划不可用；不替换合格的策略，也不丢掉该分支后冒充完整的查询。

## 读取、动作与字段的求值公式

令 `Match(C,K,r,g)` 表示段 g 的主体、资格或任职、类型、操作 K、时间窗、全部范围与全部条件同时成立。段内必须保持绑定。

```text
Entitled(C,K,r) = OR over g: Match(C,K,r,g)
Visible(C,r) = Entitled(C, resource.view_key, r)
PermissionAllowed(C,K,r) = Visible(C,r) AND Entitled(C,K,r)

Readable(C,K,r,f) = Visible(C,r)
                   AND OR over g: (Match(C,K,r,g) AND f IN g.read_fields)

Writable(C,K,r,f) = PermissionAllowed(C,K,r)
                   AND Readable(C, resource.view_key, r, f)
                   AND OR over g: (Match(C,K,r,g) AND f IN g.write_fields)
```

`PermissionAllowed` 只回答资源上的授权资格，不证明单据此刻可以执行、审批依据有效或动作已被接受。`Executable` 还要检查业务约束与相应接受节点的证据；接口与前端不能把它们混成一个“成功”状态。

- **写需要读**：普通的资源字段编辑同时要求可读与本动作的写许可，所以不可读的字段不能经普通的 PATCH 修改。设置密码等专用命令的秘密输入另有明确的输入契约，不读取旧秘密，也不因此默认开放盲写字段。读与写是两道各自完整的检查，不从任何读字段的授予推出写权。
- **响应用自己的读取操作**：读取响应用该读取操作 K 的字段结果；动作响应声明自己的读取操作，不能因为有审批或执行权，就输出原本不可读的成本字段。动作可以不返回单据正文；返回正文时，重新验证声明的读取动作。导出用独立的导出操作段及其字段集合，不直接复用页面已显示的列，也不调用系统身份取全量。
- **字段许可只从覆盖当前记录的段汇总**：只汇总覆盖当前 r、且满足当前 K 条件的段。g1 在甲法人的明文许可，不能让 g2 在乙法人的读取得到明文；两个都合法覆盖同一行、同一操作的段，可以并集各自明确的字段。

## 三种列表的集合

| 查询类型 | 应返回的完整集合 |
| --- | --- |
| 通常的读取列表 | 请求的筛选条件 AND `Visible(C,r)`；单对象读取使用同一个 `view_key` |
| 特殊读取或导出列表 K | 请求的筛选条件 AND `PermissionAllowed(C,K,r)`；用同一 K 的单对象读取资格与字段输出核对 |
| 可执行动作的筛选 K | 请求的筛选条件 AND `Executable(C,K,r)`；同时包含可见、动作授权与声明的业务约束 |

普通列表可以另外返回逐行的动作状态；它仍是可读记录的列表，不承诺每一行都可以审批。某个动作的条件无法完整下推、或在预算内无法完整求值时，可以保留普通列表并把该动作状态记为未知，或明示不支持该动作的筛选；不能把“候选可审批”当作已经满足 `Executable` 的集合。

所以不是“任意 K 的列表都等于可见集合”：可见性与操作资格各有确切的集合；同一用途、同一 `C`、同一数据集合下，列表与单对象必须一致。动作返回 404 还是 403，与读取授权一样按存在性保护统一解释。

## 查询下推、分页与敏感字段

查询与单对象使用同一个段模型。关系型适配把每个段生成参数化的谓词，再完整地 OR；所有分支先授权，再排序、分页。不同提供方的内部 SQL 可以不同，结果集合与字段义务必须一致；SQL 不拼接用户字符串。

多个分支可以优化成 UNION，但重叠的记录按稳定的身份去重，字段按全部合法匹配的段判断，之后统一排序、分页与聚合；不能先各取一页再截断，也不能让去重随机选一个较宽或较窄的字段版本。

图分支要有覆盖完整集合的协议。ListObjects 的截断、超时、缺少某部分关系，不能当作空集合或完整集合。“取候选再权威检查”只能在最终分页之前构成完整集合；成本过高时，使用有边界的异步查询或拒绝本次查询，不放宽保护。

排序、过滤、搜索、分组、聚合与关联展示，都声明所用的字段与派生依赖。标准路径：先确定不依赖这些受限字段条件的可见候选范围；再证明调用者对范围内所用的字段有相应的读取资格；最后执行相关的筛选或排序。已经独立证明可用的普通筛选可以先缩小范围。资格可以通过有限的包含关系证明，证明不了就拒绝该查询用法。空结果不免除查询字段的权限检查：不能先运行敏感筛选、再用“返回空集”说明合法，也不能让敏感条件筛掉不可读字段的记录后循环证明权限。

混合字段权限的列表仍然可读，逐行掩码；不能为了让某个成本排序可用，就静默删掉不可读成本的行。另外声明的公开统计或受控的跨范围指标，是独立的资源与读取契约，不套用明细授权后随意扩大聚合。

游标绑定计划摘要（[安全 07 的分页与游标](../../../security/07-finite-expressions-containment-and-queries.md#分页与游标)：该主体在该资源类型上的规范化段集合、筛选、排序与资源定义的版本）；后续页重新验证当前的资格。版本或授权时间窗改变时，不能证明同一个安全集合继续成立，就要求重新查询；不能沿着旧游标保持撤销前的权限。接受与撤销的时间规则见[安全 03](03-authorization-acceptance-and-revocation.md)。

## 创建、修改与业务强约束

- **修改**：现存记录先用权威的旧事实判断可见与动作资格，普通修改还检查请求中每个字段的写许可。任一待修改字段检查失败时整条命令拒绝，不静默丢弃用户想改的字段；批量是整批还是逐项成功，由业务契约明确。
- **改变资格的修改**：修改法人、负责人、组织、共享关系或金额等可能改变资格的内容，必须声明专门的动作或新旧值守卫。候选的新状态重新校验所有相关的范围与条件：不能把符合上限的旧金额改到上限之外，也不能靠改负责人或法人取得另一个范围的数据。计算出的金额、单位与来源属性先由业务规则确定，不能只检查用户提交的数值。
- **创建**：标准创建使用校验后的候选资源事实，要求该范围的创建资格与创建后的读取资格；还没有 ID 时，也能校验法人、组织等维度。确实需要“创建后不向操作者公开内容”的专门业务，声明独立的接口、输入与最小回执，不从本公式推出通用的盲写能力。
- **业务强约束**：期间锁、冻结、不能自审、审批修订、执行许可与库存不变量，由业务属主在最终的提交或执行节点检查。列表里的 `_access` 或 `PermissionAllowed` 是体验与资格结果，不代替并发提交的保护。

## 不确定、缺能力与解释

已知事实确实不匹配，按读取或动作的规则拒绝。缺少可信的输入、不能满足新鲜度、提供方故障或查询集合不完整，属于“无法证明”，不伪装成“没有数据”。内部区分“明确拒绝”与“无法决策”；对外复用协议批准的保护错误，具体的原因在线契约中登记，不临时发明生产错误键。

局部未知的分支不贡献许可；已有独立完整的授予能证明某个单对象的许可时，只采用它已证明的字段。列表中未知的分支可能改变成员集合时，整体标为不可完成，不能只返回可证明的部分。部署受众、身份、所需的当前资格等全局输入不合格时，不再用局部的授予放行。

解释记下实际主体与履职身份、资源类型与修订、K、授权版本、匹配的段与字段来源、必要的限制与求值时间。对无权的记录，解释不暴露它的金额、负责人等属性；更多解释路径的能力缺失，不能改变基本的允许或拒绝结论。审计的可靠保存见[协议 03](../../../protocols/03-audit-durability.md)。

## 独立预期

理论向量；同一上下文同时比较读取与动作、字段、完整列表，另配合法的正例。

| 编号 | 反例或正常场景 | 固定预期 |
| --- | --- | --- |
| AE01 | 授予甲配法人甲、仓库一，授予乙配法人乙、仓库二 | 原配对可读；甲与二、乙与一不因分别取集合而可读 |
| AE02 | 甲范围可审批，乙范围只读 | 乙可读不可审批，甲范围内合法的他人记录可审批 |
| AE03 | 甲可审批 100 以内，乙可审批 50 以内；乙范围的金额 75 | 乙拒绝，不能借甲的上限；声明为闭区间时，边界值分别核对 |
| AE04 | 甲可读成本，乙只可读普通字段 | 乙的成本为 null 且列在 `_masked`；甲的明文不扩散到乙 |
| AE05 | K 的范围覆盖 r，`view_key` 不覆盖 r | `Visible`、`PermissionAllowed` 都否；K 的特殊读取列表与动作集合都不含 r |
| AE06 | `view_key` 可读，审批授权不匹配 | 普通列表含 r，审批集合不含 r；读取列表不被动作条件缩小 |
| AE07 | 两份有效授予都覆盖同一行与读取动作，各有不同的字段 | 只并集两份合法的字段；另一行或另一动作的字段不参与 |
| AE08 | 有页面读取、无导出操作；另有同范围但字段较窄的导出许可 | 前者拒绝导出；后者只导出它完整段允许的字段 |
| AE09 | 空部门、明确空的仓库集合、已知 null、未知的必要属性 | 不扩为全集；未知的必要属性按无法证明处理，不返回假的空集合 |
| AE10 | 授予内 `owner OR org`，另有法人与仓库条件 | 两个 OR 分支都保留其他限制；不能经 org 绕过法人 |
| AE11 | 关键动作选择甲任职，却引用乙任职的授予；任职刚失效 | 不能借用乙的授予；资格变化按适用的新鲜度与接受协议保护 |
| AE12 | 自己发起的单据，同时持有多个审批角色或共享许可 | 本人自审的约束仍然阻止；合法的他人单据正例成立 |
| AE13 | 两个查询 OR 分支都含同一条记录，权限页已满且字段策略不同 | 只出现一次，合法字段并集后统一分页，不漏下一条 |
| AE14 | 部分行的成本不可读，请求按成本排序、筛选或查看派生的毛利 | 不能证明整个查询的字段资格时，拒绝该查询用法；普通的掩码列表仍可用 |
| AE15 | 旧金额 50 合法，请求改成超出本动作范围的 150；改法人或负责人 | 候选新状态或专门的转移守卫拒绝，原记录不变 |
| AE16 | 提供方截断、未知表达、图分支超时，当前页仍有本地的行 | 不能伪称列表完整或无权的数据为零；独立已证明的单对象许可另行判断 |
| AE17 | 当前游标之后撤权或授予到期 | 不继续用旧授权，按安全规则重查或中止；不承诺旧分页永远完整 |

## 依据

知识库关于组合公式、兼任与字段的专题提供中立参考；本项目保持无管理员 Deny、组件属主与可替换，并采用更严格的列表用途区分。最小权限、每次请求都授权与安全失败的原则参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)；[PostgreSQL 行安全文档](https://www.postgresql.org/docs/18/ddl-rowsecurity.html)对旧行的使用资格与新行检查的区分，用来校验修改的边界。本方案在组件与 SDK 中实施，不启用行级安全（RLS）。

## 已知风险与待定

- 正式的 schema、逐记录的字段与查询 API、动作元数据与跨语言向量，随安全 06、09 的契约与 SDK 确定；以上预期是理论向量，尚未在 SDK 或数据库上执行。
- 对外的保护错误中“无法决策”的具体原因键，在线契约中登记。
