# 存货成本

存货成本组件（`erp/costing`）拥有成本子账，是存货价值的唯一权威（D46）。本页定义成本怎样在消息乱序、补发票、迟到流水的情况下算对：输入来自哪里、按什么顺序计算、暂估与票据单价怎样调整、生产成本与到岸成本、输出与对账、期初，以及没有安装成本组件时怎样。出账、核销与付款，以及成本组件依赖的共同规则（不可遗漏的增量事实、会计事实契约、供应商票据发布的事实），见[协议 05](05-billing-settlement-and-costing.md)。

依据的决定：D45（库存核心拥有物理变动）、D46（成本归成本组件，价值只有一个权威）、D50（应付匹配在财务）。各组件的职责与方案比较见[财务与结算的选型说明](../00-overview/guides/finance-and-settlement.md)。

成本组件发给财务的成本事实按[协议 05 的会计事实契约](05-billing-settlement-and-costing.md#会计事实契约)发布，按[协议 05 的共同规则](05-billing-settlement-and-costing.md#共同规则不可遗漏的增量事实)去重、补取与处理纪元变化；它代理库存与制造参加关账（[协议 06](06-period-close.md)）。


## 输入

| 输入 | 产生方 | 键 | 用途 |
| --- | --- | --- | --- |
| 出入库流水 | `erp/inventory` | 事实身份；计价序号；来源单据参考（收货行、退货单、工单） | 计价的主序列 |
| 收货计价依据 | `erp/purchase` | 收货行参考（采购订单行或到货行）；一行分几次收货时几条流水共用 | 暂估单价（税前）、币种与口径；采购在发起收货时、或订单审批时发布 |
| 票据单价确认及其冲回 | `erp/finance` | 收货行参考 | 最终单价 |
| 费用票据确认 | `erp/finance` | 票据身份 | 到岸成本的费用金额 |
| 报工、工时与工单完工 | `erp/manufacturing` | 事实身份；制造的事实序号 | 工单成本；领料与完工入库本身是库存流水 |
| 工作中心成本费率 | `erp/manufacturing`（工作中心的属性） | 工作中心与生效期间 | 工时与机时计入工单成本 |

## 计价序列

- 库存固定按“产品 + 法人”为每条流水分配**计价序号**（一条连续的序列），与成本组件是否安装、计价范围怎样声明无关。成本组件的计价范围只能等于或细于法人；细分时按过滤得到子序列，顺序不变。
- 同一法人内不同库位的流水共用这一条序列，先后由库存的提交顺序确定。按库位分序列时，同一计价范围内库位甲的入库与库位乙的出库的先后没有定义，移动平均的结果会随处理的交错而变，所以不按库位分序列。
- 范围内的调拨不改变计价，在同一序列内记为一笔（或成对的两笔连续序号）；跨计价范围的调拨在两条序列各记一笔，按出方的成本转入。
- 货主不是本企业的库存（供应商寄售、客户所有，[领域与边界](../00-overview/02-domains-and-boundaries.md)的货主维度）不进入计价。
- 每条流水另带库存范围的**库存流水序号**，供成本组件代理库存参加关账（[协议 06](06-period-close.md)）。两个序号在不同的编号事务中分配，同一产品的两条流水在两条序列中的先后可以不同：计价只按计价序号，关账的覆盖只按库存流水序号。

## 计算与缺口

成本组件按每个“产品 + 法人”（或它过滤得到的计价范围子序列）的计价序号顺序计算。乱序到达的流水先缓存，等前面的序号到齐再处理；缺口超过等待期限（参数表“计价序号的缺口等待”）时，按序号向库存补取，补齐之前不计算后续出库的成本。按到达顺序直接计算，移动平均等方法的结果会随消息顺序而变（参考模型的“按到达顺序计算”坏变体）。

## 暂估与调整

收货时按收货计价依据的单价入账，标为暂估。单价来源按**成本层**记录：每条入库流水是一个成本层，记下它的数量、当前单价，以及当前单价来自哪个来源、覆盖多少数量。来源有三种，按优先级从低到高：

| 来源 | 什么时候用 |
| --- | --- |
| 政策价（待定价） | 流水到达时计价依据还没到，等待（参数表“计价依据的等待”）后按计价政策取单价（标准成本或最近的采购价），标为“待定价”，不阻塞后续出库的计算 |
| 收货计价依据 | 正常的暂估 |
| 票据单价确认 | 最终价；带匹配到的入库流水与数量 |

替换的规则，按行序第一条命中：

| 到达的输入 | 处理 |
| --- | --- |
| 优先级高于该层当前来源的输入 | 替换它覆盖的数量的单价，调整 = （新单价 − 当前单价）× 数量 |
| 与当前来源同一优先级、同一来源单据的新修订（计价依据修订、票据重开） | 替换旧修订，按差额调整 |
| 票据单价确认，与当前来源同为票据、来自另一张票据（分批开票） | 只作用于它匹配到的数量；一层分几张票据时按数量加权，未开票的数量保留原来源 |
| 某来源被冲回（票据冲回、计价依据撤回） | 撤掉它的贡献，该数量回到剩余来源中优先级最高的单价，按差额调整 |
| 优先级低于当前来源的输入 | 只记录，不调整 |

- 调整一律带被替代的来源，作为新的成本事实发布，不改写原流水与原成本事实。
- 差异的去处按成本层计算：该层仍在库的数量调整库存价值；该层已经出库的数量，按成本政策计入当期销售成本差异。
- 迟到的倒填流水（业务日期早于已处理的流水）：成本只按计价序号计算，倒填的流水不触发对已处理出库的重算，只影响它自己的成本事实归属哪个期间：该期间尚未被成本组件封存时计入该期间；已封存或已关闭时，按[协议 06](06-period-close.md) 的迟到规则顺延到下一个开放期间（成本组件的迟到政策只能是顺延）。改写历史（重算并替换）与追加调整层是两种成熟的做法；标准实现采用“追加调整”，不改写已发布的成本事实。

## 到岸成本（远期）

成本组件拥有“到岸成本分摊单”，把一张费用（运费、关税、保险）按声明的方法（数量、金额、重量）分摊到若干入库流水，生成成本调整事实；费用金额来自“费用票据确认”。

## 生产成本

工单成本、在制品与差异由成本组件计算（价值只有一个权威，D46）：领料流水计入工单，报工与工时按工作中心成本费率计入，完工入库按工单成本或标准成本入库，差异作为调整事实；制造只提供数量、工时与费率。委外加工（远期）的材料存放在供应商处，用库存的货主与库位维度表达。

## 输出与对账

每条出库的成本事实与每次调整事实，带稳定身份，按会计事实契约发给财务过账；分析维度（项目、部门、成本中心）从流水的来源单据继承。财务以这些事实为存货与销售成本的唯一依据，不另算同一口径的成本（D46）。成本组件与财务按期间对账：成本子账余额与总账存货科目一致；不一致时报告差异并告警，不自动改写任何一方。

## 期初

- 期初库存以库存的“期初”流水进入，期初成本层由成本组件导入（[协议 16](16-go-live-and-import.md)）。成本组件把期初流水与期初成本层按（仓库、产品、批次）对应，不为期初流水产生成本事实：期初的存货金额只由期初凭证进入总账。
- 上线时已收货未开票的货，财务以期初的“收货待票”子账按采购订单行承接暂估应付；新系统中票据匹配时冲回它，单价差异由财务直接计入差异科目，不进成本调整（这批货没有收货流水），也不发布“票据单价确认”。
- 期初的账单（原账单的来源认领）只作为更正与红字的引用，不发布“已出账”：应收由期初应收未清项承接，信用的期初占用由期初应收事实建立。

## 成本组件未安装

需要存货成本的能力（例如按实际成本过账）不能启用；不返回虚构的成本（D46）。装配准入检查：同时含库存与财务的客户基线必须含成本组件（[选择方式与关系的组合准入规则](../00-overview/04-selection.md#组合准入规则)）；只要期末结果的小客户选成本组件的定期盘存策略（期末按盘点结存倒算销货成本）。定期盘存策略下没有逐笔出库成本：退货按该期间的平均成本冲回，成本子账与总账的对账在期末盘点之后进行。只有不装财务的组合（只做服务，或库存只管数量）可以不装成本组件。

## 寄售、直运与委外（远期）

现在只预留形状：

- **寄售**：货主为供应商的库存不进入计价；消耗时所有权转移，由库存发布所有权转移事实，采购据此生成票据匹配的依据。
- **直运**：没有入库流水；票据匹配的依据是“供应商发货确认”，销货成本由财务按票据过账。
- **委外**：委外采购单由采购拥有，材料用库存的货主与库位维度表达；制造对采购的依赖随委外设计确定。

## 独立预期

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| IC01 | 出库流水乱序到达成本组件 | 按序号处理；结果与顺序处理一致 |
| IC02 | 流水序号缺口超过等待期限 | 按序号向库存补取，缺口补齐前不计算后续出库成本 |
| IC03 | 收货按暂估入账，票据单价不同 | 在库部分调库存价值，已出库部分计成本差异；原事实不改写 |
| IC04 | 期间已关闭后到达的倒填流水 | 按协议 06 计入下一开放期间 |
| IC05 | 成本组件未安装，启用按实际成本过账 | 装配拒绝；不返回虚构成本 |
| IC06 | 成本子账与总账存货科目不一致 | 对账报告差异，告警，不自动改写任何一方 |
| IC07 | 同一法人内两个库位的入库与出库交错到达 | 按库存分配的同一条计价序号处理，结果唯一 |
| IC08 | 跨法人调拨（或跨细分的计价范围） | 两条序列（或子序列）各记一笔，转入成本取出方的成本 |
| IC09 | 库存库异步切换，成本组件已处理的两条出库流水在新纪元中不存在，新纪元的流水重用了它们的序号 | 成本组件只采用更大的纪元，按序号范围对账重新对齐；丢失的流水列入损失范围并冲销据此算出的成本，不把新流水当作已处理 |
| IC10 | 库存库异步切换，一条流水的事实已复制、只是编号丢失，在新纪元重新编号 | 按事实身份去重，不当作丢失，不冲销 |
| IC11 | 销售退货入库 | 成本按原出库的成本冲回，不按当前平均成本 |
| IC12 | 入库流水到达成本组件时收货计价依据还没到 | 等待后按政策取单价并标待定价；计价依据到达后按“新单价 − 当前单价”生成调整 |
| IC13 | 一张运费票据分摊到三条入库 | 成本组件按声明的方法生成三条调整事实 |
| IC14 | 收货按政策价 8 标为待定价；票据单价 10 先确认，计价依据 10 后到 | 票据确认时调整 +2；计价依据优先级低于票据，只记录，不再调整；存货单价为 10 |
| IC15 | 仓库里有供应商寄售的货 | 寄售货不进入计价；消耗时由所有权转移事实生成采购的匹配依据 |
| IC16 | 一条采购订单行分三次收货 | 三条入库流水按收货行参考共用同一条计价依据，不各自等待 |
| IC17 | 期间 P 已被成本组件封存、尚未关闭时，到达一条业务日期属于 P 的倒填出库 | 按协议 06 的迟到规则顺延到下一个开放期间，不在 P 内重算 |
| IC18 | 期初库存激活后，成本组件收到期初流水 | 与期初成本层按（仓库、产品、批次）对应，不产生成本事实；总账存货只由期初凭证进入 |
| IC19 | 同一收货行两张票据分别确认 6 件 12 元、4 件 11 元 | 两张票据按各自匹配的数量替换单价；不把第二张只记录 |
| IC20 | 票据确认 12 元后冲回，重开 11 元 | 冲回撤掉 12 元的贡献，回到计价依据的单价；重开的 11 元再替换 |

## 参考模型

[出账、核销与成本模型](../../work/checks/17-billing-settlement-costing.py)的成本子模型（种子 20261013，2,000 次运行）：乱序到达的流水按计价序号处理后，移动平均成本与按顺序处理一致；坏变体“按到达顺序计算”被发现。模型不是 SDK、数据库或真实账务规则的运行结果。

**模型没有覆盖的条款**：成本子模型只建了一条计价序列，相当于“产品 + 法人”下只有一个库位，没有建出同一计价范围内多库位共用序列与跨计价范围的调拨（IC07、IC08）、纪元变化后的对齐（IC09、IC10）、单价来源的成本层与替换规则（IC14、IC19、IC20）与寄售排除（IC15），靠实现测试。

## 依据与独立判断

Business Central（数量分录与价值分录分开、价值再过入总账）与 Odoo（库存估值与财务估值分别表达）支持“数量、成本、总账各有权威、保持关联”的分工。按计价序号计算、成本层记录单价来源与追加调整是项目的协议设计，正确性依靠模型与后续的实测。

## 已知风险与待定

- 成本方法的选择（移动平均、先进先出、标准成本、定期盘存）属于成本组件的实现与替换（D27、D46）；本页只规定输入、顺序、调整与输出的协议。
- 寄售、直运、委外与维修（客户所有的货进库维修，退货单的“维修”类型或现场服务）的完整流程随这些能力的设计确定。
- 在制品的期末入账时点、标准成本变更的重估与存货减值，尚未设计，随成本组件的设计补齐。
- 以上预期尚未在 SDK、数据库或真实账务上运行。
