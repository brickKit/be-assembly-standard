# 权限验收矩阵与反例

本页列出授权必须证明的 39 项结果（PA01–PA39）：每项是一个场景与必须断言的结果，用来区分正确与错误的实现。它们是理论验收规格，实例化时绑定具体的契约版本、接口、错误映射与运行命令。

## 目的与使用范围

共同语义以[权限设计](../../06-protocols/security/README.md)为准，本矩阵将已定方向落实为可区分正确与错误实现的场景。认证、授权、业务约束、投影与出口的责任分别检查，不能只验证 provider 返回允许／拒绝。矩阵不重新裁定权限模型、管理员 Deny、默认 MQ 或数据库行级安全。

具体的权限模型、成员与切换关系见[授权选型](../../00-overview/guides/authorization.md)。实例化时绑定实际的成员、SDK 与契约版本，标准、静态、关系图、策略引擎成员各按所选能力验证；只有模型名称、产品支持 Check 或替身的自测，不能作为成员已通过的证明。

这些用例是产品机制与客户组合的验收基线，不是客户正式角色模板。客户配置还需按实际需求核对授权范围；测试数据、演示种子和生产初始化互相分清。需要某能力的组合不能因实现未支持而将对应场景标为不适用。

## 最小反例数据

| 对象 | 样例定义 | 要制造的反例 |
| --- | --- | --- |
| 法人与组织 | 法人甲／乙各有两个部门，另有无部门人员 | 法人与部门混淆，空部门被误当组织根 |
| 多任职主体 | 同一主体在甲一有读取／审批及成本明文，在乙一只有读取且成本受限；另有明确授予管理权的管理员 | 将甲一的审批／字段权限与乙一的范围拼成超出授权的访问 |
| 单据 | 两个法人／不同部门各有已存在单据；包含自己发起、其他人发起、关键修订、冻结及已执行状态 | 不用“查不到 ID”伪装范围校验，形成状态与职责分离的正反对照 |
| 字段与条件 | 成本为样例敏感字段，金额上限为样例 `100.00`；提供上限以下、等于上限和超过上限的记录 | 边界比较、字段与范围错配、过滤／导出的旁路泄露 |
| 授予与任务 | 有效／到期／撤销授予、旧任职／有效兼任、待审批与已达业务授权节点的任务 | 将组织变化、普通授权、委托、任务执行混为同一生命周期 |
| 数据副本与运行 | 相同逻辑记录在声明的在线／投影／冷层；两个实例、缓存与后台作业可独立暂停／恢复 | 暖缓存、滞后副本、恢复与实例差异导致越权 |

以上名称与金额仅是测试标签，不分配正式组件 ID、权限键、端口、币种或生产角色。正式用例需明确主体／任职、权限点、资源属性、字段策略和当前修订的具体表示。另准备有权的正例，防止“全部拒绝”也通过矩阵。

涉及撤权、任职变更、到期和同步的预期，按所选操作的风险、确认点与声明的新鲜度窗口实例化；不要求未声明的同瞬间全副本生效，也不能以最终生效掩盖窗口越界。不同入口确实使用不同权限点或附加业务条件时分别说明，集合对照使用同一读取动作和条件。

时间节点与风险分档见[接受与撤销](../../06-protocols/security/03-authorization-acceptance-and-revocation.md)。PA26–PA30、PA32、PA36 实例化时结合 AT01–AT64，分别断言关闭新接受与关闭旧提交，不把 Check 成功、许可或部分屏障回执当作已完成。

PA13–PA18 的管理、任职与模板升级，结合[管理与任职 AM01–AM20](../../06-protocols/security/04-authorization-administration-and-appointments.md)实例化，保持完整上限、目标影响与生效点的检查；正常卸任与机构上限收紧分别断言。

共享、代办与只读扮演的场景结合[共享与委托 SD01–SD22](../../06-protocols/security/05-sharing-delegation-and-impersonation.md)，特别检查来源类型、创建时与当前的完整上限、任务责任、有限链、隐蔽副作用与通知落点。

实例化所有场景时对照[共同结构与能力 SC01–SC24](../../06-protocols/security/06-security-contracts-and-capabilities.md)：区分身份、事实、求值、接受与业务回执，核对实际资源、动作与出口的完整能力路径及新旧版本；接口表或可解析的 schema 不代替 SDK 与真实依赖的证据。

PA29 与 PA34 的成员能力与切换部分，结合[成员能力与切换 PV01–PV31](../../06-protocols/security/10-providers-and-member-switching.md#独立预期)实例化。

PA13–PA18、PA21、PA32 与 PA37–PA39 的管理、任职、扮演、恢复与确认部分，结合[状态与变更协议 CP01–CP95](../../06-protocols/security/08-state-and-change-protocol.md#独立预期)实例化。

PA04–PA11、PA13–PA15 与 PA35 的范围、字段与授出部分，结合[有限表达 FX01–FX24](../../06-protocols/security/07-finite-expressions-containment-and-queries.md#独立预期)实例化；其参考模型只在 SQLite 上核对算法与编译模板，不计作 SDK 或 PA 场景通过。

## 身份、入口与完整授予

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA01 | 无凭证、错误类型／受众／issuer、过期或失效凭证访问受保护动作；各配合法正例 | 非法凭证不取得业务访问；合法身份仍须独立授权。状态／错误按固定契约检查 |
| PA02 | 新增业务入口漏声明权限，或绕过页面直接请求接口 | 门禁能识别声明遗漏；直接请求不能依靠菜单隐藏或边缘登录获得放行 |
| PA03 | 有读取无审批，或有功能权限但资源在范围外；替换为真实存在的外部 ID | 无副作用且无受限内容；不能仅在 ID 不存在时拒绝 |
| PA04 | 兼任主体审批乙一单据，另有甲一的审批授予 | 不得将甲一审批权与乙一读取范围拼接；甲一合法他人单据按条件可审批 |
| PA05 | 一份授予上限 `100.00`、另一份只读范围不同；尝试拼上限、范围和字段 | 操作、范围、条件、字段来自完整有效授予；声明允许等于上限的样例中，等于和超出分别得到预期结果 |
| PA06 | 无部门主体使用组织范围授予，另有独立本人范围授予；关键履职动作未选择任职 | 空部门不能展开到全组织，本人范围按自身授权处理；关键动作按声明选择合法任职并留依据 |

## 查询、字段与数据出口

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA07 | 同一读取动作／权限点、主体／授权修订／数据快照与条件下，分页遍历列表并逐条检查对象 | 列表完整集合与同条件的单对象可读集合相符；不同入口的附加条件另列，排序／游标／跨层行为按声明覆盖，不能用并发数据变化解释固定样例差异 |
| PA08 | 对范围外数据请求计数、合计、排行、下拉联想、搜索或报表 | 除明确授权的跨范围指标外，结果／筛选项不泄露受限事实；每个已启用通道分别断言内容 |
| PA09 | 兼任主体读取甲一与乙一记录，先读取甲一成本明文再读取乙一 | 字段按覆盖当前记录与操作的完整授予判定，甲一字段许可不带到乙一；返回字段／值与规定掩码相符 |
| PA10 | 写入不可写字段，或借不可读字段过滤／排序／搜索、错误信息和通知推断内容 | 不改变受限字段，不从这些旁路泄露。具体拒绝／裁剪形状先由契约明确，不依据当前实现临时放宽 |
| PA11 | 无导出权、只有部分范围／字段、不同范围批量混合与分页导出 | 无导出权不能导出；文件头、每行和值符合当前授权。混合批量的整批／逐项结果按声明固定，未授权项无业务副作用 |
| PA12 | 两个不同范围主体交替命中缓存；导出生成期间或领取前撤权；订阅收件人调岗／停用 | 缓存不跨范围／字段授权泄漏；执行及交付按当前授权重验，旧文件／链接与订阅按声明失效处理 |

## 授权管理、任职与升级

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA13 | 只有业务使用权的人授予别人；管理员没有该业务使用权但具备明确管理权 | 使用权不产生授出权；合法管理动作按其独立上限判定，不要求管理员先持有全部业务权 |
| PA14 | 下级管理员越对象／权限／范围／条件／字段上限授予，包含给自己或其他账号 | 所有管理路径受同一上限约束，实际授权结果不越界；合法上限内正例成立 |
| PA15 | 修改角色内容、授出管理权或批量变更间接扩大权限 | 校验实际影响的人员和授予，不只检查管理入口；无法证明合法的变更不生效 |
| PA16 | 某任职失效但其他兼任仍有效，新任职建议尚未确认；变更事件重复／乱序 | 旧任职关联授予撤销，其他授予按各自条件保留；新建议未经合格管理者确认不生效 |
| PA17 | 原管理员正常卸任，另测试被授予人任职失效或委托人撤权 | 合法普通授予不因授予操作人卸任自动消失，管理由合法接任／上级接管；任职及委托的失效规则不被交接规则绕过 |
| PA18 | 升级增加普通角色权限，审核期间管理资格／角色内容变更，重复确认 | 新键不自动进入普通角色；确认时复核上限和变更依据。系统角色按各自规则验证，不能与普通模板共用错误预期 |

## 审批与业务控制

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA19 | 自己发起的单据，通过兼任、代理或已关联的其他账号申请审批；另有他人合法单据 | 本人自审限制按声明的业务责任主体成立；换角色／账号不绕过。主体映射来源与其他人正例明确，不能用姓名／邮箱推断 |
| PA20 | 允许授予下的冻结／期间锁／已执行单据；切到明确无人工审批流程 | 独立业务约束仍生效，无人工审批不跳过必要校验／审计；不为此新增管理员可配置 Deny |
| PA21 | 生产环境已授权的只读扮演，尝试写操作或超出被查看主体范围 | 只读边界及共同授权成立，保留真实执行者／被查看者审计与既有通知要求；无权扮演和合法读取分别测试 |
| PA22 | 审批中或通过未执行时关键内容修订，与旧同意／执行结果竞争 | 旧审批不能放行受影响的新内容；普通原单修订、严格变更与已执行更正各按声明处理，历史依据保留 |
| PA23 | 在途流程遇到新流程版、处理人失资格、合法接任／无人替代 | 原流程相关版本继续，当前权限与职责分离不冻结；合法交接可继续，无替代则暂停转人工，接任不自动取得授权 |
| PA24 | 审批截止与提交竞争，单据或预占更早到期，恢复后过期提醒重投 | 普通截止不伪造人工结论，业务到期不被审批等待延长；提醒／转交不能绕过处理资格，已执行事实不被盲目取消 |

## 服务、任务与授权新鲜度

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA25 | 用户请求经 BFF／跨组件调用，尝试用服务身份替代用户读取范围 | 下游保持受约束的调用身份与授权，不因为走后台或同一外壳获得全量数据；实际链路和响应内容可关联 |
| PA26 | 已达明确业务授权节点的后续任务，原发起人离职；另有仅接收／草稿任务 | 合格受限服务主体可继续既定业务后续，但当前取消／冻结／修订控制有效；未到节点不能借系统身份继续执行 |
| PA27 | 撤销或到期后，暂停权限投影同步并向多个实例发起高风险操作 | 按明确确认点与严格新鲜度要求拒绝／暂缓；不能在无法证明有效授权时继续放行，不虚构零延迟保证 |
| PA28 | 低风险读取在声明窗口内／外使用旧策略，再测试修订倒退、冷启动与本地策略缺失 | 只在明确允许范围与时效内使用旧策略，越界保护；缺失／无效／不能证明新鲜度不默认允许。窗口数值待规格与实验确定 |
| PA29 | 授权 provider 超时／故障、切换或缺少启用业务所需能力 | 没有静默降级或放宽控制；替换检查覆盖能力、授权状态与主体映射，不用“接口仍返回布尔值”证明语义等价 |
| PA30 | 附件父记录无权／撤权、冷层记录和分析投影、停用后的历史查阅 | 各已启用层保留当前授权和关联；临时下载能力的窗口与严格访问分别验，不假设已签出 URL 随应用撤权逐个即时失效 |

## 证据、恢复与替换

| 编号 | 场景与变化 | 必须断言的结果 |
| --- | --- | --- |
| PA31 | 必需敏感读／导出、拒绝与代操作审计记录失败或积压；普通低风险读作对照 | 按声明可靠采集／保护，事件身份和依据可追溯；不以采样日志代替必要审计，不把普通读取全部扩为长期审计 |
| PA32 | 备份恢复到撤权之前，另有之后的撤销／安全事件记录；查询审计和解释接口 | 服务恢复前核对后续安全状态；审计／解释本身受权限与脱敏控制，不能因恢复旧策略泄露资料 |
| PA33 | 同一授权状态与样例在三种 SDK、单跑／外壳和多实例间对照 | 共同契约下允许／拒绝、范围／字段、错误与任务身份相符；每格绑定精确版本，未运行不能记成通过 |
| PA34 | 切换授权／身份实现或客户 Fork，迁移角色名相同但范围／条件／修订／关系不同 | 核对真实授权语义、缺失能力与状态迁移，失败可恢复；仅搬同名角色或在主干通过不证明客户组合兼容 |
| PA35 | 定向坏变体：去掉范围、将多授予拆开汇总、删除职责分离、忽略有效期、复用其他主体缓存 | 对应场景应在预期断言处失败；正确样例通过。空套件、全部拒绝、重复期望由被测实现生成都不能作证明 |
| PA36 | 权限查验与查询并行负载、失效更新集中到来、外壳成员争用与恢复 | 记录声明新鲜度的实测上界、错误／暂缓、尾延迟、资源及恢复；性能好不能抵消越权，轻量与完整方案分别验 |
| PA37 | 最后一名可用的授权管理员在员工组件被正常办理离职，或在身份组件被正常停用；另有两名管理员并发互相撤销 | 来源事实照常生效，办理时提示；授权组件应用事件后进入待恢复，管理结构的放宽（管理员恢复除外）被驳回，收紧照常；并发互相撤销被最后管理员不变量串行化，后提交者被驳回 |
| PA38 | 建立或变更账号与员工的关联；申请人用关联到同一员工的另一账号确认；单管理员部署 | 关联是受保护操作，确认记录由授权组件保存，没有确认不生效；同一员工的账号视为同一人，不能自我确认；单管理员时由部署所有者确认 |
| PA39 | 单人公司发起关账或重开等业务确认；另有受保护的安全操作 | 业务确认按业务确认 profile，可以由发起人显式确认并留审计，不需要部署所有者确认；受保护的安全操作仍需独立确认人或部署所有者确认 |

## 一条可执行记录的必填项

每项实例化为：矩阵编号 → 规则与能力档 → 精确协议／provider／SDK／组件／外壳版本 → 入口及权限键 → 样例与独立预期 → 数据／授权修订及时间边界 → 变化／故障注入 → 请求／内容／副作用／审计断言 → 命令与环境 → 实际结果与限制。正例、反例和当前期望分别保留，不能用当前实现的输出反推预期。

错误码、批量结果形状和字段裁剪若仍未确定，先补协议再实现用例。共享快照条件、可控时钟与变化确认点要能复现；未声明时间预算的用例不能只以“最终拒绝”签发新鲜度通过结论。

## 验证阶段与退出条件

| 阶段 | 做什么 | 不能据此声称 |
| --- | --- | --- |
| 设计审查 | 样例与规则逐项核对，寻找反例，明确适用范围和待补协议 | SDK／业务／部署已经安全 |
| 协议与 SDK 验收 | 固定向量及黑盒对所选语言／profile 实际运行，检查坏变体 | 真实数据库查询和全部业务入口已经受控 |
| 组件与跨层验收 | 真实数据、调用、文件／导出、任务、并发和故障断言 | 未测过的存储／授权／客户 Fork 组合也通过 |
| 部署与交付验收 | 声明的拓扑与引擎、精确客户组合，验授权等价及资源边界 | 一格代表所有规模和未来货架 |

机制相同的通道可以复用用例结构，但每个已启用实际出口仍要断言；缺少未来组件的场景保留排期，当前范围只证明已实现的代表样板。完整报告区分适用并通过、失败、待实现、未执行、不适用及限制；部分 profile 不能冒充完整合规。

审查的出口是：范围与预期可以核对、协议缺口有去处、执行记录的格式明确；运行合格还需要真实证据。

方法参考：[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)要求按业务需要定义授权、检查每个请求并验证配置／实现。本项目按已定组件与安全语义建立矩阵，不从推荐模型推导必须采用某个产品，也不将默认拒绝误写成管理员任意配置 Deny。
