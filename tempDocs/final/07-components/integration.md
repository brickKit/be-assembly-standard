# 外部渠道与集成

物流承运与电商平台为远期集成族；门店收银与客户、供应商门户登记为评估，单独设计后再定（D73）。所有适配器遵守[协议 10](../06-protocols/10-external-integration.md)：对外命令、结果未知、回调验证、能力声明、对账、凭据；它们不决定业务结论。同一族的成员按能力声明多选并存或按范围选择。

## IM 渠道：integration/im-dingtalk、im-wechat-work、im-feishu、im-slack、im-teams

| 项 | 内容 |
| --- | --- |
| 何时需要 | 客户使用相应的协作工具，希望在其中收到通知或处理待办 |
| 统一语言 | 渠道账号映射；消息；交互动作；投递结果 |
| 拥有的数据 | 人与渠道账号的映射、投递命令与结果、回调原始报文 |
| 不变量 | 交互按钮带任务所属组件签发的一次性动作令牌（绑定任务、处理人与版本）；回调验证后在本适配器自己的事件主题上发布，由所属组件核对发布者与令牌后执行，渠道不调用业务组件、不记录决定（D68）；不能确认送达时不写“已送达” |
| 命令与查询 | 投递（来自通知）；回调接收；账号映射同步 |
| 事件 | 投递结果 |
| 必需依赖 | `infra/notification`、身份 |
| 可选依赖与缺件 | `mdm/employee`（只经事件）：订阅员工与账号的事件维护渠道账号映射的投影，不同步调用员工组件（D68），缺时由管理员手工映射；任务所属组件（下游，订阅本适配器的交互动作主题）：缺时按钮只能跳转到系统中处理 |
| 替换与 Fork | 成员多选并存；不同渠道的扩展能力不同，前端识别差异 |
| 部署 | 低负载；适合外壳 |
| 范围 | 钉钉在当前重建范围；其余远期 |
| 验证故事 | 在 IM 中点同意，所属组件核对动作令牌后按协议 09 检查；令牌已用或任务版本已变时被拒；渠道回调伪造被丢弃 |

## 邮件与短信：integration/email、integration/sms

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要邮件或短信通知的客户 |
| 其余各项 | 与 IM 渠道相同的投递职责；邮件另有退信与投诉回调 |
| 范围 | 远期 |

## 支付：integration/payment-stripe、payment-paypal、payment-alipay、payment-wechat-pay

| 项 | 内容 |
| --- | --- |
| 何时需要 | 在线收款或付款的客户 |
| 统一语言 | 支付命令；外部交易；结果未知；退款；对账文件 |
| 拥有的数据 | 对外命令、回调原始报文、对账材料 |
| 不变量 | 回调只是线索，资金结果经查询或声明为权威的签名终态确认；终态不倒退；不重复执行 |
| 命令与查询 | 收款、付款、退款、查询；回调接收；对账 |
| 事件 | 命令终态（供 `erp/payment`） |
| 必需依赖 | 身份 |
| 可选依赖与缺件 | `erp/payment`（下游，调用本适配器发起支付、订阅结果）：缺时不使用 |
| 替换与 Fork | 成员多选并存；替换时在途命令在原适配器完成（协议 10） |
| 部署 | 低负载；回调入口外部可达或只查询模式 |
| 范围 | 远期 |
| 验证故事 | 应答丢失后查询确认，不重复收款；伪造的支付成功回调被丢弃 |

## 银行：integration/bank-<格式>

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要银行对账单导入或付款文件的客户 |
| 统一语言 | 对账单（例如 ISO 20022 camt.053）；付款文件（例如 pain.001）；银行回单 |
| 拥有的数据 | 文件、解析结果、提交与回单记录 |
| 不变量 | 同一对账单不重复导入；付款文件提交结果未知时不重新生成新的付款 |
| 命令与查询 | 导入对账单；生成与提交付款文件；查询状态 |
| 事件 | 银行流水（供 `erp/payment` 对账） |
| 必需依赖 | 身份 |
| 可选依赖与缺件 | `erp/payment`（下游，调用本适配器发起付款与对账、订阅结果）：缺时不使用 |
| 范围 | 远期（新身份族） |
| 验证故事 | 重复导入同一对账单被识别；付款文件银行未确认时人工核对 |

## 电子签：integration/esign-docusign、esign-pandadoc、esign-esign

| 项 | 内容 |
| --- | --- |
| 何时需要 | 合同（`erp/contract`）与单据需要电子签署的客户 |
| 统一语言 | 签署请求；签署方；签署完成；签署文件 |

| 范围 | 远期 |
| 验证故事 | 签署回调丢失，查询发现已完成；签署完成后业务仍按审批状态决定 |

## 电子开票：integration/einvoice-<地区>

| 项 | 内容 |
| --- | --- |
| 何时需要 | 所在地区要求合规电子发票的客户 |
| 统一语言 | 票据格式；签名；提交；外部接受或拒绝；更正 |
| 拥有的数据 | 提交命令、外部响应、提交的票据文件引用 |
| 不变量 | 已生成、已提交、外部已接受分别表达；结果未知时先查询（D49） |
| 必需依赖 | 身份 |
| 可选依赖与缺件 | `erp/billing`（下游，调用本适配器提交电子发票、订阅结果）：缺时不使用；税额依据随账单提交，本适配器不调用税组件 |
| 替换与 Fork | 按地区选择；与税计算分别选配 |
| 范围 | 远期（新身份族）；实施前查当地官方要求 |
| 验证故事 | 提交超时后查询外部状态；外部拒绝后账单保持未合规状态并提示 |

## 交换：integration/edi

| 项 | 内容 |
| --- | --- |
| 何时需要 | 与客户或供应商以 EDI 交换订单、发货通知、发票的客户 |
| 统一语言 | 报文；交换伙伴；确认 |
| 拥有的数据 | 收发报文、映射、确认状态 |
| 不变量 | 入站报文按业务键幂等转为业务命令；出站结果未知时先查询或等确认 |
| 必需依赖 | 身份、授权 |
| 可选依赖与缺件 | `erp/sales`（入站订单经销售的外部来源建单命令幂等转换）、`erp/purchase`（出站采购单、入站发货通知），按报文类型启用，装配准入要求至少有一个（安全 09） |
| 范围 | 远期 |
| 验证故事 | 重复的入站订单报文只建一张订单 |

## 物流承运：integration/carrier-<承运商>

| 项 | 内容 |
| --- | --- |
| 何时需要 | 发货要对接快递或物流公司（面单、运单号、跟踪）的客户 |
| 统一语言 | 运单；面单；运单号；揽收；物流轨迹；签收 |
| 拥有的数据 | 对外命令（下单、取消）、运单号与面单引用（文件经附件或打印）、轨迹原始报文 |
| 不变量 | 下单结果未知时先查询，不重复下单（协议 10）；轨迹与签收只是外部事实，交货与收入确认由业务组件按自己的规则判断 |
| 命令与查询 | 下单与取消；面单获取；轨迹查询；回调接收 |
| 事件 | 运单状态（揽收、在途、签收、异常） |
| 必需依赖 | 身份 |
| 可选依赖与缺件 | `infra/print` 或现场打印代理：缺时面单只能下载；发起的业务组件（下游，`erp/sales` 的交货或 `erp/warehouse` 的打包调用本组件、订阅运单状态） |
| 替换与 Fork | 成员多选并存，按承运商与线路路由 |
| 部署 | 低负载；回调入口外部可达或只查询模式 |
| 范围 | 远期（新身份族，D73） |
| 验证故事 | 下单应答丢失后查询确认，不生成两个运单号；伪造的签收回调被丢弃 |

## 电商平台：integration/shop-<平台>

| 项 | 内容 |
| --- | --- |
| 何时需要 | 在电商平台（例如淘宝、Shopify）开店、订单要进入 ERP 的客户 |
| 统一语言 | 店铺；平台订单；平台商品与产品映射；可售量同步；售后 |
| 拥有的数据 | 店铺与凭据引用、平台商品与产品的映射、平台订单原始报文与转换记录、同步状态 |
| 不变量 | 平台订单按平台订单号幂等转为销售订单，重复拉取或回调不重复建单；可售量同步只推送库存给出的值，不在平台侧扣减权威库存；平台退款与售后转为业务命令，由属主判断 |
| 命令与查询 | 订单拉取与回调接收；转换与重试；可售量推送；映射维护 |
| 事件 | 转换完成或失败 |
| 必需依赖 | `erp/sales`、`mdm/product`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：可售量来源，缺时不同步库存；物流承运成员：缺时发货信息人工回填平台 |
| 替换与 Fork | 成员多选并存，每个平台一个成员 |
| 部署 | 订单高峰（大促）时负载突增；按负载单跑 |
| 范围 | 远期（新身份族，D73） |
| 验证故事 | 同一平台订单拉取两次只建一张销售订单；转换失败的订单可见并可重试；平台退款不自动冲销已出账的账单 |
