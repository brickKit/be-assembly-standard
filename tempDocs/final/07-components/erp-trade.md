# 交易与库存

库存是物理库存变动的唯一写入者；销售与采购通过库存契约请求变动，不自己维护余额。

## erp/sales

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有对外销售的客户；实物与服务共用订单基础（D44） |
| 统一语言 | 报价；销售订单与明细（实物或服务）；修订；价格表与定价规则；订单确认过程；交货请求；销售退货 |
| 拥有的数据 | 报价、订单、修订历史、价格表与定价规则、确认过程的持久状态（协议 04）、交货请求与执行进度、退货单、对出账的来源额度（可出账数量与金额） |
| 不变量 | 订单的确认只有一个过程实例；已确认订单的修订按协议 04 调整各分支，增加的部分不足则修订不生效；可出账额度只由销售裁决，同一来源不被重复认领（协议 05）；已执行的明细只能修订未执行部分 |
| 命令与查询 | 报价与订单的维护；提交审批；确认（启动预占过程）；取消；修订；发起交货；登记服务完成；来源认领（出账的请求，协议 05）；订单与执行进度查询 |
| 事件 | 订单状态事件；确认完成与失败；交货请求；服务完成；来源额度变化（增量事实） |
| 必需依赖 | `mdm/partner`、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：实物订单必需，只有服务订单时可以不装；`erp/credit`：缺时无信用控制（装配时确认）；`erp/billing`（下游）：缺时不能出账；`erp/tax`：缺时报价的税额为人工录入；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）（D11）；`crm/opportunity`：赢单生成报价，缺时不受影响 |
| 替换与 Fork | 定价规则是明确的替换点（D27）；行业销售模型可 Fork |
| 部署 | 交易中心之一，前台为主；外壳或单跑按负载 |
| 适用协议 | 01、02、04、05、07、08、09、10（电子签等对外动作经适配器）、13、14、16、安全 01–09 |
| 范围 | 当前重建 |
| 验证故事 | 订单确认同时预占库存与信用，一方失败则全部释放；确认中取消，迟到的预占被拒；批准后修改数量走修订重审，待发货明细暂停；部分发货后修订只改未执行部分；服务订单不请求库存 |

## erp/purchase

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有采购业务的客户 |
| 统一语言 | 采购申请；采购订单；到货与验收（服务验收）；采购退货；三单匹配的依据 |
| 拥有的数据 | 采购申请、采购订单、修订、到货通知、服务验收记录、退货单、对应付匹配的来源依据（已到货、已验收数量与金额） |
| 不变量 | 收货数量由库存的入库事实确认，采购只记录进度；同一采购明细的已验收数量不超过订单数量加允许的超收比例 |
| 命令与查询 | 申请与订单的维护；审批；发起收货（请求库存入库）；服务验收；退货；匹配依据查询（供应商票据匹配，D50） |
| 事件 | 订单状态事件；验收事实（增量事实） |
| 必需依赖 | `mdm/partner`（供应商角色）、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：库存物资采购必需；只有服务采购时可以不装；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）；`erp/finance`（下游，向本组件查询匹配依据）：供应商票据匹配在财务应付内部，缺时没有应付；`erp/costing`（下游）：缺时收货的暂估单价不参与计价 |
| 替换与 Fork | 采购策略（比价、配额）是替换点 |
| 部署 | 前台为主；适合外壳 |
| 适用协议 | 01、02、05（应付匹配依据）、07、08、09、13、14、16、安全 01–09 |
| 范围 | 当前重建（D63） |
| 验证故事 | 收货回调丢失时按库存的入库事实补齐进度；超收超过比例被拒；服务采购按验收形成匹配依据 |

## erp/inventory

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有实物库存的客户 |
| 统一语言 | 仓库与库位；库存维度（产品、仓库、库位、批次、序列号、库存状态）；流水（入库、出库、调拨、调整、期初）；余额；预占（分支，协议 04）；盘点 |
| 拥有的数据 | 仓库与库位、流水（唯一写入者）、余额、预占分支与墓碑、批次与序列号的存在与状态、盘点单 |
| 不变量 | 可用量 = 在库 − 已预占 ≥ 0（不超卖）；流水不可修改，更正以反向流水表达；每条流水有稳定事实 ID，并带两个连续序号：参与方序号（关账用，协议 06）与“产品 + 法人”的计价序号（成本用，协议 05，与成本组件是否安装无关）；已关账期间不再写入（迟到的按协议 06 顺延） |
| 命令与查询 | 预占、提交、消耗、释放（协议 04）；入库、出库、调拨、调整（调整需审批或权限）；期初流水与已确认期初订单的期初分支（上线窗口，协议 16）；余额与可用量查询；流水查询 |
| 事件 | 流水（不可遗漏的增量事实，供成本与财务）；余额状态事件（可覆盖）；预占分支状态 |
| 必需依赖 | `mdm/product`、`mdm/org`、身份、授权 |
| 可选依赖与缺件 | `erp/warehouse`（下游，经库存契约执行作业）：缺时由简单操作直接出入库；`erp/costing`（下游）：缺时流水照常带计价序号，只是没有成本计算 |
| 替换与 Fork | 不可整体替换为另一套余额权威；分配与出库策略（先进先出、按批次到期）是替换点 |
| 部署 | 写热点（余额行）；需要时单跑并单独分配数据库资源（协议 17 的热点处理） |
| 适用协议 | 01、02、04、05、06、11（流水可转层）、13、14、16、17、安全 01–09 |
| 范围 | 当前重建 |
| 验证故事 | 并发预占不超卖；预占的应答丢失后重试只占一次；已关账期间的迟到出库顺延到下一期；序列号产品出库必须指定序列号 |

## erp/warehouse

| 项 | 内容 |
| --- | --- |
| 何时需要 | 仓库作业复杂（波次、拣货路线、复核、打包）的客户；简单出入库不需要 |
| 统一语言 | 作业单；波次；拣货任务；复核；打包；任务推进状态 |
| 拥有的数据 | 作业单、波次、任务与推进状态、对库存提交的引用 |
| 不变量 | 不保存可独立扣减的余额；任务完成与库存提交分别定义，以库存的提交结果为准；库存已提交但应答丢失时查询恢复，不重复扣减 |
| 命令与查询 | 生成波次；分派与执行任务；复核；打包；取消任务 |
| 事件 | 作业与任务状态 |
| 必需依赖 | `erp/inventory`、`mdm/product`、身份、授权 |
| 可选依赖与缺件 | 现场打印代理（标签）：缺时不打印标签 |
| 替换与 Fork | 整体可替换为另一仓储实现；拣货策略是替换点 |
| 部署 | 仓库现场的终端访问；单跑或外壳 |
| 适用协议 | 01、02、04（与库存的协调）、10（标签打印）、13、20（仓库终端入口） |
| 范围 | 远期（新身份，D45） |
| 验证故事 | 拣货完成提交库存时超时，查询后恢复，不重复扣减；任务取消与预占到期并发 |
