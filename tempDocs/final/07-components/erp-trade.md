# 交易与库存

库存是物理库存变动的唯一写入者；销售与采购通过库存契约请求变动，不自己维护余额。合同管长期约定与周期出账，订单管一次交易（D70）。

## erp/sales

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有对外销售的客户；实物与服务共用订单基础（D44） |
| 统一语言 | 报价；销售订单与明细（实物或服务）；修订；价格表与定价规则；订单确认过程；交货请求；销售退货单（退货、折让、换货、取消；含退货授权）；可贷记台账与原订单行的贷记汇总；待处理退回量；款到发货；直运（远期：明细由采购为供应商生成采购单，不经库存）；寄售（远期：库存的货主维度） |
| 拥有的数据 | 报价、订单（含订单负责人）、修订历史、价格表与定价规则、确认过程的持久状态（协议 04）、交货请求与执行进度、退货单、对出账的来源额度（可出账数量与金额）与退货的可贷记台账（协议 05） |
| 不变量 | 订单的确认只有一个过程实例；已确认订单的修订按协议 04 调整各分支，增加的部分不足则修订不生效；可出账额度只由销售裁决，同一来源不被重复认领；同一原订单行的贷记汇总分两维：数量维（只算退货）与金额维（退货与折让）各自的认领中加已贷记不超过已出账（协议 05）；已执行的明细只能修订未执行部分 |
| 命令与查询 | 报价与订单的维护（报价可带商机参考）；提交审批；确认（启动预占过程）；取消；修订；发起交货（简单流程调用库存出库并带分支身份；款到发货时先向财务认领并确认放行额度，再提交放行，提交后正式化；失败或取消时释放；未发运部分关闭，以及退回量使可出账额度减少时，向财务冲回；进入可贷记的由财务在红字时冲回；先换后退的补发超出已收到的退回时另行放行认领，到期未退回转为销售，赊销订单以换货单身份建立信用分支，协议 05）；未完成订单的期初导入（各个量、期初已交付）与期初放行台账命令（协议 16）；登记服务完成；退货的登记与批准（退货授权，可带工单参考）、发起退货入库、折让、换货、已开票未发货部分的取消；来源认领与可贷记额度认领（出账的请求，协议 05）；订单完成或关闭时释放剩余的预占与信用分支；订单与执行进度查询 |
| 事件 | 报价与订单状态事件（带商机参考）；确认完成与失败；交货请求；服务完成；退货状态；来源额度与可贷记额度变化（增量事实） |
| 必需依赖 | `mdm/partner`、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：实物订单必需，只有服务订单时可以不装；`erp/credit`：缺时无信用控制（装配时确认）；`erp/tax`：缺时报价的税额为人工录入；`crm/opportunity`（上游，只经事件）：商机发布“请求报价”，销售生成带商机参考的报价草稿，缺时报价照常手工创建；`erp/finance`：款到发货策略在放行交货前认领订单的预收额度（或采用预收发票形态），缺时该策略不能启用；`crm/customer`（上游，只经事件）：负责人变化，只用于显示与建订单时负责人的默认值；订单与报价的负责人是销售自己拥有的字段，按负责人限定的数据范围（“销售只看自己的订单”）用这个字段，不用 CRM 的关系投影；`erp/contract`：订单引用合同的价格与框架额度，缺时只用价格表；物流承运成员（`integration/carrier-*`）：缺时运单号人工录入；`erp/billing`（下游）：缺时不能出账；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）（D11）；电商平台成员（下游，`integration/shop-*` 转换平台订单）：缺时没有平台订单入口 |
| 替换与 Fork | 定价规则是明确的替换点（D27）；行业销售模型可 Fork |
| 部署 | 交易中心之一，前台为主；外壳或单跑按负载 |
| 适用协议 | 01、02、04、05、07、08、09、10（电子签等对外动作经适配器）、13、14、16、安全 01–09 |
| 范围 | 当前重建 |
| 验证故事 | 订单确认同时预占库存与信用，一方失败则全部释放；确认中取消，迟到的预占被拒；批准后修改数量走修订重审，待发货明细暂停；部分发货后修订只改未执行部分；服务订单不请求库存 |

## erp/purchase

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有采购业务的客户 |
| 统一语言 | 采购申请；采购订单（可带项目参考）；预付；到货与验收（服务验收）；收货请求；收货计价依据；采购退货；三单匹配的依据；直运（远期） |
| 拥有的数据 | 采购申请、采购订单、修订、到货通知、服务验收记录、退货单、对应付匹配的来源依据（已到货、已验收数量与金额） |
| 不变量 | 收货数量由库存的入库事实确认，采购只记录进度；同一采购明细的已验收数量不超过订单数量加允许的超收比例 |
| 命令与查询 | 申请与订单的维护；审批；预付申请（请财务形成预付未清项）；发起收货（请求库存入库，流水带收货行参考；装了复杂仓储时发布收货请求）；服务验收；采购退货（请求库存出库，引用原入库流水）；匹配依据查询（供应商票据匹配，D50；带订单行的预算分支身份；期末供财务查询已验收未开票的明细）；供应商价格表、询价与比价；供应商返利（结算经财务的供应商贷项） |
| 事件 | 订单状态事件；收货请求（带订单行参考，供仓储）；验收事实；收货计价依据（键是收货行参考，在发起收货或订单审批时发布，带单价与币种，供成本）；采购退货（供仓储与成本；均为增量事实） |
| 必需依赖 | `mdm/partner`（供应商角色）、`mdm/product`、`mdm/org`、`mdm/currency`、身份、授权 |
| 可选依赖与缺件 | `erp/inventory`：库存物资采购必需；只有服务采购时可以不装；`infra/workflow`（下游）：缺时人工审批照常，任务在本组件页面中处理，没有统一待办入口（协议 09）；`erp/finance`（下游，向本组件查询匹配依据）：供应商票据匹配在财务应付内部，缺时没有应付；`erp/costing`（下游，消费收货计价依据）：缺时收货不参与计价；`erp/tax`：采购订单的税额，缺时人工录入；`erp/budget`：请购与订单的预算占用（协议 04 的分支），缺时不受预算控制；预付申请同样经 `erp/finance`，缺时预付只能线下处理；`erp/inventory`（远期，只经事件：寄售的所有权转移）；`erp/sales`（远期，只经事件：直运请求）；`prj/project`（下游，只经事件）：带项目参考的采购归集到项目 |
| 替换与 Fork | 采购策略（比价、配额）是替换点 |
| 部署 | 前台为主；适合外壳 |
| 适用协议 | 01、02、05（应付匹配依据）、07、08、09、13、14、16、安全 01–09 |
| 范围 | 当前重建（D63） |
| 验证故事 | 收货回调丢失时按库存的入库事实补齐进度；超收超过比例被拒；服务采购按验收形成匹配依据 |

## erp/inventory

| 项 | 内容 |
| --- | --- |
| 何时需要 | 有实物库存的客户 |
| 统一语言 | 仓库与库位；库存维度（产品、仓库、库位、批次、序列号、库存状态、货主）；流水（入库、出库、调拨、调整、期初、销售退货、采购退货）；余额；预占（分支，协议 04）；盘点 |
| 拥有的数据 | 仓库与库位、流水（唯一写入者）、余额、预占分支与墓碑、批次与序列号的存在与状态、盘点单 |
| 不变量 | 可用量 = 在库 − 已预占 ≥ 0（不超卖）；流水不可修改，更正以反向流水表达；每条流水有稳定事实 ID，并带两个连续序号：库存流水序号（成本组件按它补取；关账封存前成本组件请求高点，库存写标记行并锁内编号后返回，协议 06）与“产品 + 法人”的计价序号（成本用，协议 05b，与成本组件是否安装无关）；倒填流水的限制是库存自己的业务规则，会计上的迟到由成本组件顺延（协议 06） |
| 命令与查询 | 预占分支的预占、确认、取消、查询、消耗、调整（协议 04）；库存流水序号的高点读取（写标记行并锁内编号，标记行不是流水，成本组件跳过它）与按序号补取（协议 06）；入库、出库、调拨、调整（调整需审批或权限）；期初流水与已确认期初订单的期初分支（上线窗口，协议 16）；余额与可用量查询；流水查询 |
| 事件 | 流水（不可遗漏的增量事实，供成本；库存与财务之间没有事件）；余额状态事件（可覆盖）；预占分支状态 |
| 必需依赖 | `mdm/product`、`mdm/org`、身份、授权 |
| 可选依赖与缺件 | `erp/warehouse`（下游，经库存契约执行作业）：缺时由简单操作直接出入库；`infra/workflow`（下游）：调整的审批，缺时在本组件页面中处理；`erp/costing`（下游）：缺时流水照常带计价序号，只是没有成本计算 |
| 替换与 Fork | 不可整体替换为另一套余额权威；分配与出库策略（先进先出、按批次到期）是替换点 |
| 部署 | 写热点（余额行）；需要时单跑并单独分配数据库资源（协议 17 的热点处理） |
| 适用协议 | 01、02、04、05（退货入库）、05b（计价序号）、11（流水可转层）、13、14、16、17、安全 01–09；不是关账参与方（成本组件代理，协议 06） |
| 范围 | 当前重建 |
| 验证故事 | 并发预占不超卖；预占的应答丢失后重试只占一次；已关账期间的迟到出库顺延到下一期；序列号产品出库必须指定序列号 |

## erp/planning

| 项 | 内容 |
| --- | --- |
| 何时需要 | 需要补货建议（再订货点、安全库存）或物料需求计划的客户；只做服务或手工补货的不需要 |
| 统一语言 | 补货规则（再订货点、安全库存、最高最低库存）；需求（销售订单、预测、生产用料）；供给（在库、在途采购、在制工单）；计划运行；建议（采购、生产、调拨）；下达 |
| 拥有的数据 | 补货规则、需求预测、计划运行记录与建议、建议的下达记录 |
| 不变量 | 只产生建议，不直接改变库存、采购或生产；建议由人确认后经属主的接口下达（采购申请、生产工单、调拨），每条建议至多下达一次；计划运行基于声明的数据截至时点，并在结果中标明 |
| 命令与查询 | 补货规则与预测维护；计划运行（手动或定时槽位，协议 01）；建议查询、确认与下达 |
| 事件 | 计划运行完成；建议下达 |
| 必需依赖 | `erp/inventory`（在库与预占）、`mdm/product`、`mdm/org`、身份、授权 |
| 可选依赖与缺件 | `erp/sales`：需求来源，缺时只按预测与再订货点；`erp/purchase`：在途供给与采购建议的下达，缺时采购建议只能人工处理；`erp/manufacturing`：BOM 展开、在制供给与生产建议的下达，缺时只做采购件与调拨的补货 |
| 替换与 Fork | 计划算法（再订货点、MRP、排产）是替换点（D27），整体可替换 |
| 部署 | 计划运行批量较重，后台预算单独；按负载单跑 |
| 适用协议 | 01、02、13、14、16 |
| 范围 | 远期（新身份，D71；承接原在制造中的 MRP） |
| 验证故事 | 低于再订货点生成一条采购建议，确认下达后只生成一张采购申请；重复运行不重复下达；BOM 修改后的新运行按新版本展开 |
