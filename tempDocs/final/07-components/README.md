# 组件边界卡

每个组件一张边界卡，写它拥有什么、保证什么、依赖什么、缺件时怎样。组件的身份、范围与选择关系见[组件货架](../00-overview/03-catalog.md)与[选择方式、关系与客户组合](../00-overview/04-selection.md)；确定边界的方法与五项检查见[领域与组件边界](../00-overview/02-domains-and-boundaries.md)。重建组件时，边界卡写进各组件仓库的 `BRICKKIT.md`。

## 卡片的行

| 行 | 写什么 |
| --- | --- |
| 何时需要 | 客户什么情况下会单独选它，什么情况下永远不需要 |
| 统一语言 | 本组件内的关键术语及其含义 |
| 拥有的数据 | 本组件是唯一写入者的数据 |
| 不变量 | 必须在本组件一次本地事务内成立的规则 |
| 安全来源与恢复 | 只出现在安全记录的属主与授权的内部来源上（组织、员工、身份、授权）：水位来源的职责、证据、高可用与恢复 |
| 命令与查询 | 对外提供的主要动作与读取 |
| 事件 | 发布的状态事件与增量事实 |
| 必需依赖 | 缺了就不能运行的组件；“身份”指任一身份成员（`infra/iam-*`），“授权”指 `infra/authz` |
| 可选依赖与缺件 | 缺了时的明确行为 |
| 替换与 Fork | 谁可以接替它，定制的入口 |
| 部署 | 负载特点，单跑或外壳的倾向 |
| 适用协议 | 本组件必须遵守的协议与安全文档 |
| 范围 | 当前重建、远期、留位或评估；退役身份的去向 |
| 验证故事 | 用来检查边界的成功与失败故事 |

“必需依赖”指运行与业务成立所需；组件之间的调用一律经契约，事件消费经投影（协议 02），引用经协议 07。主数据被所有人读取、自己不调用业务组件；库存是物理库存变动的唯一写入者；财务主要接收命令与事件。

## 检查

[检查 34](../../work/checks/34-dependency-closure.py) 读取本目录的卡片与[客户组合](../00-overview/04-selection.md#客户组合与闭包)，核对：必需依赖无环（BrickKit 拒绝必需依赖成环）；每个必需依赖都有卡片；每个组合列出了自己组件的全部传递必需依赖；每个组合恰好一个身份成员，并包含授权与审计。
