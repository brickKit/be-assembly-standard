# 数据、事务与恢复的验收反例

> 状态：2026-10-13 理论验收规格，DT01–DT30 均未执行。编号仅为用例索引，不分配 API、权限键或生产参数。

## 怎样使用

依据[数据与生命周期](../04-data-and-lifecycle.md)、[事务与消息](../05-transactions-and-messaging.md)和[权限语义](../02-security-and-permissions.md)，先固定独立预期，再绑定真实协议／SDK／组件／适配器版本。故障与并发应可控制地发生在指定提交点，配正常正例；只启动成功、最终不崩溃或全拒绝不算通过。

## 数据定位、转层与当前授权

| 编号 | 场景／反例 | 必须证明 |
| --- | --- | --- |
| DT01 | 不同月份写入相同业务唯一 ID／单号；改变时间后重试同一操作 | 不能因分区键不同重复生效，真正的唯一性与业务写入同事务 |
| DT02 | 导入旧记录、财务期间分区、订单与明细 ID 时间不同 | 按稳定身份准确定位所有层，不单凭 UUID 时间；已冷但缺对象不是不存在 |
| DT03 | 同月仍有未完订单／未决作业，其他记录均终态 | 不整块搬走或删除活跃记录；所选聚合和关联完整 |
| DT04 | 封存检查与迟到更新／追加／任务提交竞争 | 一个共同裁决决定结果；复制集合稳定，迟到事实进入明确更正路径 |
| DT05 | 在复制、校验、发布、摘分区、清理每步杀进程 | 源或已验证目标始终可用，恢复后不丢记录、不双计、不跳过校验 |
| DT06 | null 与文本 `\N`；字段包含分隔字符；时区／十进制／二进制变化 | 不同逻辑内容有无歧义编码，同一逻辑内容跨语言摘要一致 |
| DT07 | 归档工作者租约到期后继续发布；新工作者已接管 | 旧代次不能改目录或清理新版本，重复导出不覆盖已发布内容 |
| DT08 | 读游标期间发布新清单，热冷有重叠数据，旧读仍使用源 | 快照／重试语义明确，无遗漏／重复；源清理尊重有效读取引用 |
| DT09 | 同一范围跨层排序／聚合／导出，读取适配器超时或截断 | 完整结果或明确未完成／不支持，不能默默少行或报零 |
| DT10 | 冷记录责任交接、撤权、字段收紧；游标或导出已创建 | 当前授权按规定节点生效，历史快照不永久保留旧许可；结果领取重验 |
| DT11 | 删除审批后新增保全，擦除时对象和备份仍有副本 | 共同控制点裁决，保全不被旧检查绕过；回执如实列已完成与未完成副本 |
| DT12 | 旧结构解冻到删列／加默认字段后的新结构，再封存 | 原始内容与转换结果分别可验证，不用改变后的摘要冒充原始摘要，解冻不重开业务 |

## 本地事务与跨组件业务

| 编号 | 场景／反例 | 必须证明 |
| --- | --- | --- |
| DT13 | 两请求抢最后库存／信用额度，反向顺序多明细，新增行竞争 | 不超用、无半截提交；行数、约束／锁与完整事务重试覆盖真实并发 |
| DT14 | 两人修改／审批／执行同修订，DB 提交成功但响应丢失 | 旧依据不执行新内容，状态转换只有一次；同一操作查询可恢复，无新命令副作用 |
| DT15 | 预占成功响应丢失；取消先到、迟到预占；释放与确认竞争 | 原分支可查询，重复无害，取消墓碑阻止复活，共同状态裁决 |
| DT16 | 库存确认占用，信用到期；协调者在确认订单前重启 | 订单不报已确认，已占部分按声明补偿／恢复，不凭空消失或重复占用 |
| DT17 | 订单确认后旧暂存 TTL 到期；单据取消／修订与执行交错 | 暂存计时不能释放已确认占用；执行修订和许可有效，不能复用旧请求 |
| DT18 | 两个工作者执行付款，旧租约者晚返回；首次外部结果未知 | 固定业务执行身份、防重复或明确人工核对；不能换通道盲试，不以 fencing 推导外部已停止 |
| DT19 | 两次部分出账并发，来源同期开取消／修改额度 | 一个权威资格／额度裁决，正式出账不超额、不重复、不用旧依据 |
| DT20 | 同一笔资金核销到多张单据，部分退款／冲正与核销并发 | 金额／币种、余额和分配记录同边界保证，资金／会计事实可对账 |
| DT21 | 关账检查后迟到数量／成本／账务，批次部分失败或进程重启 | 来源截止及处理完整覆盖，期间屏障阻止漏账；迟到／重开明确，失败不报已关闭 |
| DT22 | 正式连续编号事务回滚、重复过账与更正 | 编号与凭证一同提交，已签发号保留，sequence 空洞不能伪装连续性 |

## 运输、去重与恢复

| 编号 | 场景／反例 | 必须证明 |
| --- | --- | --- |
| DT23 | v12 先于 v11；同修订多事实；订阅只接部分事件 | 完整状态与增量模式分开，必需事实不被最大游标跳过；顺序缺口正确解释和补齐 |
| DT24 | 请求缓存／游标清理后，旧过账／付款事实由死信或恢复重投 | 长期业务唯一性仍挡重复，不因固定 30 天等短期缓存过期重新执行 |
| DT25 | broker 保留／容量窗口耗尽，MaxDeliver 次数用完，消费者长期离线 | 能发现缺口并从合格权威补齐／暂停；最后失败进入可恢复死信，不等不存在的下一投递 |
| DT26 | 新增订阅／分析投影，当前 List 已无旧删除和调整事实 | 声明的快照增量交接／历史来源完整，不能用当前列表证明全部历史重建 |
| DT27 | PG 队列有多个订阅及同订阅多个副本，订阅停用／新增 | 广播与竞争不同，每个必需订阅按身份处理；清理和 bootstrap 有明确范围 |
| DT28 | 恢复旧 DB，broker 进度已前进；另一格恢复旧 Inbox 并重投 | 缺失事实可定位补齐、旧副作用不重做；业务对账后才恢复受影响服务 |
| DT29 | 备份之后已付款／发货、撤权／销毁或发生安全事件 | 外部结果和后续安全控制被核对，缺证据时暂停，不盲目重放或恢复旧访问 |
| DT30 | 前台交易并行冷读／报表／作业，外壳成员占满总池或存储 | 总预算、背压与保留能力有效，资源及尾延迟实测；更慢的方案仍守同一正确性 |

## 证据与冻结门槛

每项记录独立业务预期、输入及各层版本／水位、调用身份、合法正例、提交／竞争点、故障方式、数据库／响应／外部结果／审计断言、真实命令、环境与结果。预期不能由被测实现生成。限时、保留窗口和维护预算先由规格声明，不边跑边放宽。

理论审查先把每条如何成立、如何失败写清；实现后分别在所选语言、运输／存储、单跑／外壳／多副本代表组合执行。一个适配器通过不证明另一个通过，一套业务组合不证明未来完整货架的吞吐。与[权限矩阵](authorization-matrix.md)共用安全预期，不另建立较宽权限。
