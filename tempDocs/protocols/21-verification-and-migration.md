## 从预期到测试

- 每条独立预期在实现阶段至少对应一个测试；测试名或标注带预期编号（例如 `AP06`）。
- **覆盖报告**列出每个前缀的预期与对应测试，没有测试的预期列为缺口；缺口要么补测试，要么写明不适用的理由。
- 参考模型的每个坏变体对应一个负例测试。
- 跨组件的预期（DT、L3）在业务链测试中验证，不以组件的单元测试代替。
- 预期本身被发现有误时，先修改设计文档（文档状态回到候选），再改测试；不为了让测试通过而修改预期。

## 正式文档迁移

### 目标结构

正式文档以英文为准，中文镜像（项目约定）。冻结后的内容按读者与用途放置：

| 正式位置 | 来自 |
| --- | --- |
| 根 `AGENTS.md` 与中文版 | 重写：组件表、约定一行摘要、易错点；指向下列文档 |
| `docs/en/00-overview/`（新） | 项目主体、选择关系图、货架与边界卡的客户视角 |
| `docs/en/01-conventions/` | 工程规范、测试与验证体系、文档规则（重写） |
| `docs/en/02-decisions/` | D01–D65 改写为决定记录；旧决定逐条承接或标为被取代 |
| `docs/en/03-seed-data.md` | 保留，随新组件更新 |
| `docs/en/04-foundations/` | 底层基线与各选型专篇（每个底层选择一篇） |
| `docs/en/05-operations/`（新） | 恢复（协议 15）、升级与维护窗口（协议 17、19）、观测与告警（协议 17）、客户上线（协议 16）的操作手册 |
| `docs/en/06-protocols/`（新） | 安全 01–10 与协议 01–21 的完整设计（含理由与独立预期） |
| `be-protocol` 仓库 | 从安全与协议中抽出的组件必须遵守的规则（必须、应当、内部），按协议 18 的章节；语义向量 |
| `be-acceptance` 仓库 | 验收矩阵（PA、DT、ST）与一致性套件的检查 |
| 各组件仓库的 `BRICKKIT.md` 与 `AGENTS.md` | 边界卡（重建组件时写入） |
| `registry/` | 新增与退役的组件身份、端口、schema（协议 19 的注册表规则） |

### 步骤

1. **承接表**：列出现行 `docs/`、根 `AGENTS.md`、工具说明中的每一节，写明在新正文中的去处，或被什么取代、为什么不再需要。没有去处的内容不能归档。
2. **从工作记录提取**：`tempDocs/work/` 与 `rounds/` 中仍承载有效结论的内容（决定、证据摘要）迁入正文或决定记录；正文不链接工作记录。
3. **写英文正文**：以冻结的中文稿为来源；术语按统一语言表。
4. **写中文镜像**：与英文逐节对应（`make docs-mirror`）；语义对照由另一会话复核。
5. **归档**：旧 `docs` 与 `tempDocs` 整体移入归档目录；归档之间可以互相引用，现行内容不引用归档（`make docs-boundary` 检查，现行引用归档即失败）。
6. **更新入口与工具**：根 `AGENTS.md`、组件说明、`registry/`、`make` 目标与检查脚本；本机路径与知识库路径不出现在正文中。
7. **收尾检查**：链接、镜像、边界、预期编号（检查 33）、必需依赖无环与组合闭包（检查 34）、表格结构；搜索现行内容对归档、旧路径、`tempDocs` 的引用，应为零。

### 不做的事

- 不保留新旧两套并行的现行规则；切换是整体替换。
- 不把旧代码的行为写成兼容要求（D59）。
- 不在用户确认冻结前迁移。
