# 数据基础

> 状态：2026-10-13 数据协议第十四份候选，尚未冻结。承接 C12（数据库适配）、C17（时间、日历、法人）、C18（金额、数量、汇率、单位）、C19（ID、单号、分页、过滤）、C21（迁移与版本兼容），以及 D05（法人资料与组织同一组件，会计期间归财务）、D15（发生时归属与当前责任）、D51（每法人一个正式账簿）、D58（每客户精确基线）与[数据与生命周期](../04-data-and-lifecycle.md)的数据库一节；按 D59 从零设计。现行 `docs/en/04-foundations/` 的身份、时间、金额与结构演进文档只作参考，其中多数选择在本页被保留，差异处单独说明。

## 本页解决什么

每个组件都要建表、生成身份、编号、处理日期与金额、分页列表、升级结构。这些规则若各组件自己决定，组件之间与三种语言之间就会不一致。本页给出共同规则：

1. 数据库怎样使用：结构、角色、事务、超时、连接池。
2. 记录身份、单号与唯一性。
3. 时刻、业务日期、时区、日历与期间。
4. 金额、数量、汇率、单位与舍入。
5. 列表的游标、排序与筛选。
6. 结构迁移与版本之间的兼容。

## 数据库

| 方面 | 规则 |
| --- | --- |
| 标准数据库 | PostgreSQL；支持的主版本随客户基线声明（D58）。跨方言不是标准能力，按专项路线评估 |
| 结构 | 每个组件一个 schema；多个组件可以共用实例或数据库，也可以分开（数据正文的分离形态表），不跨 schema 读写 |
| 角色 | 每个组件两类角色：属主角色（只供迁移）与运行角色（只有业务所需权限）；运行角色可以有两个交替使用的实例，用于不停机的密码轮换（[协议 19](19-config-secrets-registries-release.md#密钥)）；凭据是密钥引用。属主角色的凭据在服务容器中可见（迁移与服务由同一镜像执行，已接受的平台限制），运行时代码不得使用属主角色。外壳中的成员各用自己的角色 |
| 事务入口 | 只经 SDK 的事务入口：在事务内以 `SET LOCAL` 设定角色与 `search_path`，事务结束即失效；不在连接级设置任何会话状态 |
| 隔离级别 | 默认 READ COMMITTED，配合行锁、条件更新与唯一约束保证不变量；需要 SERIALIZABLE 的事务单独声明 |
| 重试 | 只对序列化失败与死锁重试，且整笔事务重做；事务内不做网络调用 |
| 超时 | 每笔事务有语句超时、锁等待超时与事务内空闲超时；数值由组件声明，SDK 给缺省值 |
| 连接池 | 单独运行时，每个组件用自己的运行登录角色与自己的池。外壳中，同一数据库目标的成员共享外壳的一个池：池用外壳级的登录角色连接，成员的运行角色保持可登录（单独运行时直接使用），同时授予外壳登录角色，外壳每个事务用 `SET LOCAL ROLE` 切到所属成员的角色；角色定义因此与部署形态无关，单跑与外壳互换不需要改角色属性；成员各自的预算按协议 17 合并。这是资源与连接的合并，不是成员之间的安全隔离。外壳登录角色的密码轮换同样用两个交替的登录角色（协议 19）。不同数据库目标的成员各用一个池 |
| 时区 | 数据库会话时区固定为 UTC；业务 SQL 不向数据库询问“今天” |
| 跨组件 | 没有跨库外键与跨组件事务；其他组件的数据经契约、事件或数据集（协议 13）取得 |

## 身份与唯一性

- **记录身份**：UUIDv7，由组件经 SDK 在插入前生成；不使用数据库缺省值。身份永不复用，删除与销毁后留下墓碑（[协议 07](07-references.md)）。
- **对其他组件记录的引用**：不透明字符串，没有外键；引用的类别与生命周期按协议 07 声明。
- **分区键**是表上的显式列（业务日期、期间或创建时刻），不从身份中推出。现行设计用 UUIDv7 中的时间推出分区，但导入的旧记录、父子记录不同时间、按会计期间分区时，这个推导不成立（数据正文的分区一节）。
- **分区表上的全局唯一**：分区表的唯一约束必须包含分区键，所以需要按身份定位或全局唯一的分区表，配一张不分区的**身份登记表**（身份 → 分区键与归档单元），登记与业务写入同事务；它同时是协议 11 的定位索引。追加量极大、只按时间范围读取的流水表可以声明不登记，代价是按身份读取要先给出时间范围。
- **标准代码表**（币种、单位、国家）以标准代码作为主键。
- **严格单调的计数**（例如发布序号）用自增整数，只在组件内部使用，不出现在契约中。

## 单号

单号是给人看的编号（销售订单号、凭证号、发票号），与记录身份分开。

| 声明项 | 说明 |
| --- | --- |
| 序列范围 | 法人、序列代码，以及按期间或会计年度重新开始 |
| 连续性 | 连续（不允许缺号）或允许缺号 |
| 分配时点 | 签发或过账时；草稿没有正式单号 |
| 格式 | 配置项；新格式只用于新单号 |

- **连续序列**：在签发或过账的同一事务中锁定序列行、加一并写入单据，提交时一起生效；事务回滚则编号也回滚，不留缺号。用数据库序列或在草稿时预先分配都会留下缺号（参考模型的两个坏变体）。会计凭证按法人、按期间连续；需要连续的发票等单据按其法规声明的序列与年度连续。
- **作废不收回编号**：已签发的单据作废后保留编号与作废状态；更正以新的单据（例如红字或更正发票）表达。
- **吞吐**：连续序列在同一法人、同一序列上串行；超过它的吞吐时，业务选择允许缺号的序列，或把编号点移到期末批量编号。这是业务决定，记在组件的设计中。
- **允许缺号的序列**：可以在事务外分配；唯一性由唯一约束保证；编号永不重复使用。
- **导入的历史单号**在序列中登记，新编号从声明的起点之后开始（协议 16）。

## 时间、日历与期间

| 概念 | 表示 |
| --- | --- |
| 时刻 | `timestamptz`，契约中为 UTC 的 RFC 3339 |
| 业务日期 | `date`，契约中为 `YYYY-MM-DD`；不随时区换算 |
| 法人的时区 | IANA 时区名，建立法人时必须指定，没有隐含缺省值；“今天”由 SDK 按法人时区计算后作为参数传入 |
| 会计年度与期间 | 归财务（D05）：按法人的年度起始月与期间模式生成期间行（起止日期）；13 期或 4-4-5 模式作为期间模式扩展 |
| 工作日历 | 归组织组件（法人与地点的工作日与节假日）；审批截止（[协议 09](09-approval-and-workflow.md)）、交期等按它计算，日历有版本 |
| 定时任务 | 按法人时区与本地日期确定槽位，夏令时按[协议 01](01-background-work.md)处理 |

- 事件携带单据的业务日期；消费者按业务日期记账，不按处理事件的时刻。
- 显示：业务日期原样显示；时刻默认按法人时区显示并标明时区，用户偏好只改变显示。
- 法人更换时区是数据变化：之后计算的业务日期使用新时区，已有单据的日期不变。
- 发生时的组织与当前组织分别保存（D15）。

## 金额、数量、汇率与单位

| 方面 | 规则 |
| --- | --- |
| 表示 | 契约中为十进制字符串；数据库为定标 `NUMERIC`；内存中为十进制类型；任何环节不经过浮点 |
| 列的精度 | 金额 `NUMERIC(19,4)`；单价与成本 `NUMERIC(19,6)`；数量 `NUMERIC(19,6)`；汇率 `NUMERIC(19,10)`；比率 `NUMERIC(9,6)`；单位换算系数 `NUMERIC(24,12)`。列的小数位是容量，实际精度由币种或单位决定 |
| 币种 | 金额总是带币种（ISO 4217）；每个法人有记账本位币 |
| 舍入 | 只在 SDK 中进行，按币种的最小单位与声明的舍入方式（缺省四舍五入远离零，可选银行家舍入，可配置现金舍入单位）；三种语言共用向量 |
| 分摊 | 总额按权重分摊到多行时用最大余数法，各部分之和恰好等于总额；每行独立舍入会产生尾差（参考模型的坏变体） |
| 税额 | 由税计算能力按行或按单据舍入，声明哪一种（D49）；同一单据上的各方按同一声明 |
| 汇率 | 外币单据快照汇率、汇率日期与汇率类型；账簿同时记录交易币与本位币金额；汇率由币种与汇率主数据提供（属主组件随全货架边界卡确定） |
| 单位 | 单位分类各有基本单位；产品专属换算优先于通用换算；数量按单位的舍入规则；单位可带 UN/ECE 代码 |

## 列表：游标、排序与筛选

- **只用游标分页**，不用偏移量：偏移量在翻页期间有插入或删除时会重复或漏掉行（参考模型的坏变体）。
- **稳定排序**：排序键之后总是追加记录身份作为最后的比较键；没有它，相同排序值的行在页边界处会漏掉或重复（参考模型的坏变体）。
- **游标内容**：最后一行的排序键值与身份、筛选条件的摘要、目录版本（涉及冷数据时，[协议 11](11-tiering.md#列表与导出)）；筛选条件改变时游标失效。授权按[安全 07 的分页与游标](../security/07-finite-expressions-containment-and-queries.md#分页与游标)：游标绑定计划摘要（该主体在该资源类型上的规范化段集合与资源定义版本），每页按当前授权重新编译，摘要变化时要求重新查询，不沿旧游标继续。
- **页大小**有上限；总数是可选的，可以是估计值并明确标明。
- **可筛选、可排序的字段**由资源定义声明；对受限字段的筛选与排序，只有用户能读该字段时才允许（[安全 07](../security/07-finite-expressions-containment-and-queries.md)），否则筛选本身会泄露值。
- 翻页期间排序键被修改的行，可能出现两次或不出现；这是游标分页的已知语义，需要严格快照时使用导出（协议 13）。

## 结构迁移与版本兼容

| 方面 | 规则 |
| --- | --- |
| 迁移文件 | 纯 SQL；每种语言一个迁移工具；状态表在组件自己的 schema |
| 执行 | 由组件镜像在服务启动前执行，可重复执行；SDK 提供锁等待上限与阻塞者报告 |
| 禁止的语句 | 角色、授权、schema 的创建与修改，`SET`，写死的 schema 或角色名；由检查工具拒绝 |
| 演进方式 | 扩展与收缩：扩展（加列、加表、加索引）随时可发；收缩（删列、改约束）只在使用旧结构的版本全部退出后发 |
| 退出的判断 | 依据客户的精确基线与实际部署（D58），由发布检查确认，不凭“应该已经升级” |
| 大量回填 | 作为可续跑的工作项（协议 01），不放在迁移中；回填完成前，读取兼容两种形态 |
| 回退 | 生产只向前；应用回退到上一版本可行，因为上一版本能在扩展后的结构上运行；数据错误按恢复协议（协议 15）处理 |
| 升级路径 | 每个版本声明可以从哪些版本升级；跨多个版本的升级按顺序执行中间的迁移 |
| 持久状态的格式 | 工作项、审批实例、事件、清单等持久格式带版本；新版本能读旧版本，在途实例按协议 01、09、11 的规则继续 |
| 契约 | 同一主版本内只追加；破坏性变化发新主版本，与旧版本并存到调用方全部迁走 |

终局设计从第一次正式发布开始执行这些规则；发布前的开发版本可以重建数据库（D59），不需要迁移历史。

## 参考模型

[数据基础模型](../work/checks/26-data-foundations.py)（种子 20261013，每部分 3,000 次运行）：

| 部分 | 检查 | 结果 | 坏变体（全部被发现） |
| --- | --- | --- | --- |
| 连续编号 | 并发过账、部分回滚、草稿删除后，已提交单据的编号恰为 1..n | 成立 | 事务外取序列号；草稿时预先分配 |
| 游标分页 | 翻页期间插入、修改排序键、删除，始终存在且排序键未变的行恰好出现一次 | 成立 | 偏移量分页；无身份作为最后比较键 |
| 分摊 | 按权重分摊并按最小单位舍入后，各部分之和等于总额 | 成立 | 每行独立舍入 |

模型不是 SDK 或数据库的运行结果。

**模型没有覆盖的条款**：数据库使用规则（外壳共享池的登录角色与事务内切换、`SET LOCAL`、超时）不在模型中，靠一致性套件与实现测试。

## 独立预期

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| DF01 | 组件在连接上设置 `search_path` 而不用 `SET LOCAL` | 检查工具拒绝；只经 SDK 事务入口 |
| DF02 | 两个外壳成员连接不同数据库 | 各用自己的池，不共享 |
| DF03 | 事务中发生序列化失败 | 整笔事务重做；事务内没有网络调用 |
| DF04 | 导入 2019 年的历史订单到按业务日期分区的表 | 按业务日期列落入正确分区，不按身份时间 |
| DF05 | 分区表上按身份读取 | 经身份登记表定位 |
| DF06 | 两个分区中出现同一单号 | 不可能；唯一性由登记或唯一约束保证 |
| DF07 | 凭证过账事务回滚 | 编号随之回滚，不留缺号 |
| DF08 | 删除一张草稿 | 不影响编号（草稿没有正式编号） |
| DF09 | 作废已签发的发票 | 编号保留并标为作废；更正以新单据表达 |
| DF10 | 修改单号格式 | 只影响新单号 |
| DF11 | 新建法人未指定时区 | 拒绝 |
| DF12 | 法人在西班牙，时刻 23:30 UTC 的单据 | 业务日期按 Europe/Madrid 计算 |
| DF13 | 法人更换时区 | 已有单据日期不变 |
| DF14 | 事件晚到 | 按事件携带的业务日期记账 |
| DF15 | 金额经过三种语言的往返 | 字符串与舍入结果完全一致 |
| DF16 | 100.00 按 1:1:1 分摊 | 33.34、33.33、33.33，合计 100.00 |
| DF17 | 三位小数币种的金额 | 按该币种的最小单位舍入 |
| DF18 | 外币单据 | 快照汇率、日期与类型；账簿记两种币种 |
| DF19 | 产品专属单位换算与通用换算冲突 | 产品专属优先 |
| DF20 | 翻页期间插入新行 | 已存在的行不重复、不遗漏 |
| DF21 | 筛选条件改变后使用旧游标 | 游标失效 |
| DF22 | 按无权读取的受限字段排序 | 拒绝 |
| DF23 | 删除一列，而客户基线中仍有旧版本在运行 | 收缩迁移不能发布 |
| DF24 | 从版本 1 直接升级到版本 3 | 按顺序执行版本 2 与 3 的迁移 |

## 仍未解决与下一步

- 币种与汇率主数据、工作日历的组件归属，随全货架边界卡确定。
- 各国单号的法定要求（例如发票序列与年度），随税务与电子开票的地区设计确定。
- 13 期与 4-4-5 期间模式的具体生成规则，随财务组件设计确定。
- 超大表的结构变更（扩展与收缩不够用时）的工具，按需要评估。
- 三语言的十进制与单号向量，随 SDK 共同契约（协议 18）统一。

C12、C17、C18、C19、C21 有了协议与模型；未运行 SDK 或数据库验收，不标关闭。
