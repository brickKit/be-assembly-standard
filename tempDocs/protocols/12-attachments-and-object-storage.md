# 附件与对象存储

> 状态：2026-10-13 数据协议第十二份候选，尚未冻结。承接 C24、I04，以及 D53（标准物理访问走 SDK 存储适配器，不增加纯转发组件）与[附件、物理对象与存储访问的选择](../replacements/files-and-attachments.md)中“待补齐的对象与权限协议”；按 D59 从零设计。

## 本页解决什么

1. 哪些组件拥有对象存储里的哪些对象？桶、前缀与凭据怎样划分？
2. 上传、扫描、下载怎样保证“扫描通过的”就是“被下载的”那份内容？
3. 附件的读权限从哪里来？已签出的下载链接在撤权后多久失效？
4. 解除引用、删除、保全、对象与元数据的不一致，怎样处理？

## 方案比较

| 路线 | 判断 |
| --- | --- |
| 推荐：客户端经预签名地址上传到暂存键；附件组件确认时把内容复制到不可覆盖的最终键并记录摘要；扫描与下载只针对最终键；下载前向父记录的属主取得授权，短期链接或受控下载 | 扫描结果与内容绑定；预签名地址在确认后仍可用也改不了最终内容；撤权的暴露窗口有上界 |
| 直接把客户端上传的键当作最终对象 | 预签名地址在有效期内可以再次写入，同一个键在扫描后被替换（参考模型的“扫描并提供暂存键”坏变体） |
| 所有字节经附件组件转发 | 每次访问都可检查授权，但大文件占用组件的连接与内存；只在严格的敏感类别使用 |
| 统一存储门面组件 | D53 未采用；集中凭据，但多一层网络与故障点 |

## 对象的属主与凭据

| 对象 | 属主组件 | 说明 |
| --- | --- | --- |
| 业务附件 | 附件组件（`infra/attachment`） | 元数据、处理状态与引用；读权限来自父记录 |
| 正式单据的渲染结果 | 附件组件（作为该单据的附件） | 由业务组件请求保存，记录模板版本与数据摘要（[协议 10](10-external-integration.md#打印与渲染)） |
| 导出文件 | 发起导出的组件 | 短期保留；只有发起人按当前授权可领取（D29） |
| 事件的大载荷 | 发布事件的组件 | 事件中只带引用；保留不短于事件流的保留期 |
| 冷数据 | 数据的属主组件 | 按[协议 11](11-tiering.md) |

- 每个属主组件有自己的桶或前缀，以及只能访问它的凭据；凭据是密钥引用，由装配时的初始化（与数据库初始化同一类工作）创建。共用一个存储服务不等于共用访问权。
- 组件经 SDK 的存储端口访问对象存储（D53）；三种语言的适配器提供同样的语义：对象身份、条件写入、摘要校验、预签名、错误分类。
- 所用的对象存储接口子集由一致性套件验证（认证与签名、预签名、长度限制、元数据、服务端复制、列举、错误、版本）；标称“兼容 S3”不直接等于本项目的用法兼容。

## 附件记录

| 字段 | 说明 |
| --- | --- |
| 附件 ID | 附件组件生成 |
| 父记录 | 属主组件、资源类型、记录 ID；附件归属一个父记录，不跨父记录共享 |
| 类别 | 例如合同、发票原件、产品图片；类别决定大小上限、允许的类型、敏感级别与保留类别 |
| 最终键与摘要 | 最终对象的键与 SHA-256；键包含附件 ID 与内容版本，写入后不覆盖 |
| 大小与类型 | 由服务端检测，不信任客户端声明 |
| 状态 | `uploading`、`finalizing`、`pending_scan`、`available`、`quarantined`、`rejected`、`detached`、`purged` |
| 扫描结果 | 结果、引擎与签名版本、被扫描内容的摘要 |
| 上传者与时间 | 上传者不因上传而永久可见；读权限仍来自父记录 |
| 保全与保留 | 与协议 11 相同的保全记录与保留类别 |

## 上传

1. **创建上传会话**：调用者对父记录有“添加附件”的权限；附件组件写入 `uploading` 记录，生成暂存键与预签名上传地址（限定长度、类型，支持时附带摘要校验头），有效期短。大文件用分段上传。
2. **客户端直传**到暂存键。
3. **确认**：附件组件在本地事务中把记录转为 `finalizing` 并预留最终键；然后**先**把暂存对象以服务端复制写到最终键（使用条件写入，键已存在则失败），**再**读取最终对象计算摘要与大小、检测类型、检查类别限制——检查的对象就是今后提供下载的对象，客户端在确认期间覆盖暂存对象也改变不了它；再在本地事务中记录摘要并转为 `pending_scan`。任何检查失败转为 `rejected`。
4. 暂存对象在会话到期后由清理工作删除。预签名上传地址在确认之后仍然有效到期满，但它只能写暂存键，不能改变最终对象。

## 扫描与派生物

- 扫描工作读取最终键，先核对内容摘要等于记录的摘要，再扫描；结果与该摘要一起记录。干净转为 `available`；发现威胁转为 `quarantined`；扫描出错或类型不支持不算干净，保持 `pending_scan` 并重试，超过时限告警，由有权限的人决定。
- 生产环境默认开启扫描，开发环境默认关闭；关闭时附件直接可用，并在记录中标明“未扫描”。
- 替换附件的内容是新的内容版本：新的最终键、新的摘要、重新扫描；旧版本按保留规则保留。原地覆盖同一个键并沿用旧的扫描结果，会让未扫描的内容被下载（参考模型的坏变体）。
- 预览、缩略图等派生物以源内容的摘要为键，源内容变化时重新生成。

## 下载与授权

1. 调用者请求下载附件；附件组件向父记录的属主取得授权结论：调用者能否读取该父记录，以及能否读取这类附件（附件类别可作为父资源的字段，按[安全 07](../security/07-finite-expressions-containment-and-queries.md) 的字段资格判断）。授权结论按[安全 03 的有界本地授权](../security/03-authorization-acceptance-and-revocation.md#默认路径有界本地授权)使用。
2. 只有 `available` 的附件可以下载。
3. 普通类别：签发预签名下载地址，有效期短；撤权后，已签出的链接最多在一个有效期内仍可使用，这是声明的暴露窗口。没有有效期的链接会让撤权失去意义（参考模型的坏变体）。
4. 严格的敏感类别：不签发预签名地址，由附件组件按每次请求检查授权后转发字节；续传的每个片段同样检查。
5. 下载记录按[协议 03](03-audit-durability.md)：敏感类别的下载进入审计。

## 解除引用、删除与保全

| 动作 | 结果 |
| --- | --- |
| 从父记录移除附件 | `detached`；在宽限期内可以恢复 |
| 父记录被删除或作废 | 附件按父记录属主发布的事件转为 `detached` |
| 宽限期后清除 | 在一个事务中检查没有生效的保全、保留已到期，转为 `purged`，再删除对象 |
| 父记录被销毁或擦除（[协议 07](07-references.md#销毁与擦除)） | 按擦除涉及的类别清除附件；保全中的推迟并告警 |
| 保全 | 期间不能清除；保全检查在清除的决定事务中进行 |

附件记录与对象存储不能共同提交，所以每一步都先写记录、再动对象，并由对账补齐：

| 对账发现 | 处理 |
| --- | --- |
| 对象存在，没有任何记录指向它 | 孤儿；超过验证窗口且没有未结束的上传会话时删除 |
| 记录为 `available`，对象缺失 | 故障；转为不可用并告警，不报告为“不存在” |
| 记录为 `purged`，对象仍在 | 继续删除 |
| 记录为 `finalizing` 超过时限 | 重做确认或转为 `rejected` |

清理按记录判断，不按对象的年龄判断：只看年龄会删掉仍被引用的对象（参考模型的坏变体）。

## 备份与恢复

对象存储的备份或版本保留与数据库备份对齐：恢复后，附件记录指向的最终键都必须存在；清除记录晚于恢复点的，重新执行清除。具体流程在恢复协议（协议 15）中统一。

## 存储后端的更换

更换对象存储后端时：新后端先通过接口子集的一致性套件；按属主逐个复制对象并核对摘要；切换路由后，旧后端在宽限期内只读；对账覆盖新旧两边。预签名链接因后端变化失效，客户端重新请求即可。

## 参考模型

[附件模型](../work/checks/24-attachments.py)（种子 20261013，3,000 次运行）：上传、确认、扫描、替换、签发链接、下载、撤权、清理、保全、解除引用与清除随机交错；预签名上传地址在确认后仍可写暂存键。

| 检查 | 结果 |
| --- | --- |
| 下载得到的内容总是扫描为干净的那份 | 成立 |
| 可用的附件总有对象 | 成立 |
| 保全中的附件从不被清除 | 成立 |
| 撤权后的下载不晚于撤权时刻加链接有效期 | 成立 |

5 个坏变体全部被发现：扫描并提供暂存键、原地替换内容并沿用旧扫描结果、按年龄清理对象、清除时忽略保全、链接没有有效期。原地替换的变体首轮未发现：撤权在多数运行中发生得太早，之后不再签发链接，下载几乎没有发生；调低撤权频率、提高下载频率后被发现。模型不是 SDK、对象存储或附件组件的运行结果。

2026-10-14 按独立复查（IR20）扩展：确认步骤改为先复制到最终键、再读取最终对象；模型加入关闭扫描的部署（约三成运行）与“下载内容等于确认时记录的摘要”检查，新增“先读暂存、后复制”坏变体，被发现。

## 独立预期

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| FA01 | 组件甲用自己的凭据读组件乙的桶 | 拒绝 |
| FA02 | 确认后，客户端用仍有效的预签名地址再次上传 | 只改变暂存对象；最终对象与扫描结果不变 |
| FA03 | 客户端声明的类型与实际内容不符 | 按检测到的类型检查类别限制 |
| FA04 | 扫描出错 | 不可下载；重试并告警 |
| FA05 | 开发环境关闭扫描 | 附件可用，并标明未扫描 |
| FA06 | 替换附件内容 | 新的内容版本，重新扫描；旧版本按保留规则保留 |
| FA07 | 上传者失去父记录的读权限 | 不能再下载自己上传的附件 |
| FA08 | 撤权后，已签出的下载链接 | 最多在一个有效期内仍可用 |
| FA09 | 敏感类别附件 | 受控下载，每次请求检查授权 |
| FA10 | 父记录被作废 | 附件转为解除引用，宽限期后清除 |
| FA11 | 清除时有保全 | 不清除 |
| FA12 | 对象存在但没有记录 | 验证窗口后且无未结束会话时删除 |
| FA13 | 记录可用但对象缺失 | 不可用并告警，不报告“不存在” |
| FA14 | 确认中途崩溃 | 超时后重做确认或拒绝 |
| FA15 | 正式发票的渲染结果 | 作为发票的附件保存，记录模板版本与数据摘要 |
| FA16 | 导出文件由他人领取 | 拒绝；只有发起人按当前授权领取 |
| FA17 | 事件引用的大载荷 | 保留不短于事件流的保留期 |
| FA18 | 从备份恢复后 | 记录指向的对象都存在；晚于恢复点的清除重新执行 |
| FA19 | 更换对象存储后端 | 一致性套件通过后复制、核对、切换，旧后端宽限期只读 |
| FA20 | 父记录因个人信息擦除被销毁 | 清除相应类别的附件；保全中推迟并告警 |
| FA21 | 确认期间客户端覆盖暂存对象 | 最终对象是复制时的内容，摘要、大小与类型按最终对象计算，一致；关闭扫描的部署也不受影响 |
