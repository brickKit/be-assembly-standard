# 完整授予与统一授权求值

> 状态：2026-10-13 第一份授权求值候选规格，尚未冻结。承接已定目标，提出技术结构；不修改当前族契约、SDK 或生产运行规则。

## 本次设计的目的与边界

默认按小公司落地，长期保留标准／静态／关系图／策略引擎的适配路线。所有实现先遵守共同求值语义，再比较部署和性能；用户没有统一规模计划，不因此重新提问或缩小安全保证。

本页回答：一份授权怎样绑定动作、资源范围、条件和字段；同一记录的列表、详情、动作及字段怎样一致；哪些不确定情况必须保护。它是[权限主体](../02-security-and-permissions.md)的执行规格候选，不另维护产品选择或用户决定。

本次优先处理 I18 的完整授予／字段绑定和 I28 的 List／Can 谓词适用域。服务凭据、接受／撤销屏障、授权管理全状态、委托链、身份映射与迁移随后分别收敛；它们作为本页的输入前置条件，不能因求值公式确定就标为已解决。

## 已定依据与方案选择

| 已定要求 | 本页保持的结果 |
| --- | --- |
| D09：日常完整授予汇总，关键动作选择任职 | 一份授予的范围、条件、字段一起判定；需要任职的动作只使用相容绑定 |
| D10：默认防本人自审 | 业务强约束作用于最终动作，额外角色、共享或任职不能绕过 |
| D07／D08：能力分档与风险新鲜度 | 方案缺能力不能静默扩大／缩小查询；不满足所需新鲜度时保护 |
| 普通授予与管理员交接 | 正常管理员卸任不自动撤销其合法普通授予；来源与资格绑定分别判断 |
| 普通角色升级须确认 | 模板新增权限不能自动改变客户实际授予；求值消费明确版本 |
| 不提供管理员可配置 Deny | 允许授予取合法并集，必需控制单独检查，不增加负权限优先级 |

方案比较：

| 路线 | 优点 | 代价与判断 |
| --- | --- | --- |
| 推荐：完整授予的有限中间表示，统一产生单对象、查询和字段结果 | 不绑定 provider；配对关系可核对，可下推查询，便于三语言和 AI 局部验证 | 要限定表达式、保留来源和能力元数据；不能只缓存一个全局最宽范围 |
| 全部远程逐对象 Check | 单对象决策集中，复杂关系容易接入 | 列表完整性、分页、字段和故障预算仍需协议；适合作为声明过的图分支，不能成为所有查询的默认过滤方式 |
| 按维度／等级／字段分别汇总 | 数据结构和调用形状较简单 | 丢失授予配对；已存在法人／仓库交叉授权反例，不能满足本项目目标 |

共同中间表示是行为模型，不规定所有 provider 的内部表相同，不强制把任意策略语言全部翻译成 SQL。成员可采用等价的完整候选集合／检查路径，但须证明完整性、字段和预算；无法做到时拒绝对应能力启用。

## 可信输入与资源声明

一次求值使用同一上下文 `C`：部署／实际主体／被代表主体、有效任职与委托上限、已接受的授权版本、资源事实版本、求值时刻、操作种类及所需新鲜度。输入来自已验证身份和有权威来源的属性，不来自用户自报角色、`be-caller` 名称或任意 JSON 属性；取证与调用模式见[可信身份候选规格](02-trusted-identity-and-attributes.md)。

| 输入 | 必须声明 |
| --- | --- |
| 资源类型 | 由哪个组件拥有、`view_key`、记录身份与法人／组织等维度、每个属性的类型与来源 |
| 操作 | 已注册权限键、读取／动作／字段用途、是否需选择任职、是否有输出内容及其读取权限键 |
| 字段集 | 已注册字段读／写键到列／派生字段的映射，普通字段白名单、不可输出秘密、是否允许被搜索／过滤 |
| 资源事实 | 存在性、当前范围属性、必要条件属性及修订；已知 null 与未取得属性分别表达 |
| 授予集合 | 版本、来源与绑定、完整段；图／关系结果还须有完整性及适用类型／动作证据 |

权限键继续来自注册表，资源／字段声明属于对应组件版本。本页中的 `view`、`approve`、`cost`、法人甲／乙和仓库一／二都是模型标签，不新分配正式 ID、权限键或数据库列。

## 完整授予的最小结构

将一份角色任职授予、直接授予或有效资源关系展开为求值段 `g`。一个段绑定一个操作；同一角色有多操作／条件组时产生多个有共同来源的段，不能做范围值的笛卡尔积。

| 成员 | 含义与校验 |
| --- | --- |
| `grant_id`／`source_ref` | 稳定授予／来源身份，追踪到客户实际角色版本、任职或资源授予；不是仅有角色名 |
| `subject`／`binding` | 适用主体与任职／其他资格绑定；直接授予也必须有明确资格与有效性 |
| `resource_type`／`operation` | 已声明类型与权限键；未知键不被当作全权或未来通配 |
| `scope` | 同一段的全部范围约束；显式全范围、明确空集合、具体值和主体相对范围分别表达 |
| `conditions` | 本操作的有限类型条件；金额比较含币种／单位语义，不比较浮点或裸字符串 |
| `read_fields`／`write_fields` | 该操作在该段可读取／写入的字段集，保留字段键与来源；缺省敏感字段集合为空 |
| `valid_from`／`valid_until`／资格状态 | 时间窗为左闭右开，撤销／失效绑定不参与；到期不依靠清理任务才失效 |

授予管理保存更丰富的审核、交接与生命周期记录；求值段只是经过校验的执行视图，不能成为第二份授权管理权威。

普通字段也通过资源白名单进入输出。添加字段未声明分类／权限时，声明校验失败，不能因为它不在敏感字段表就默认输出。系统秘密从不因 superuser 或字段许可变成可输出数据。

人工共享继续承接普通共享只给读取、不自行授出确认／取消／关账等业务动作的边界；字段扩展必须在允许分享的资源／字段清单内明确表示，不自动继承分享者的所有字段许可。组件拥有的团队等关系按已声明关系契约产生段，不能用关系名称伪造业务动作。来源、治理与派生限制见[第五份生命周期候选](05-sharing-delegation-and-impersonation.md)。

委托／扮演产生的段必须已经结合合法来源链、当前上游资格、期限和各级上限；普通共享、普通管理员发出的授予与用户代办不共用同一种失效规则。本页只消费这种受限视图，委托协议尚未完成时不能把原授予复制给代办人就视为输入合格。多 provider 不在调用方按 OR 拼接。

## 范围与条件的有限表达

第一版推荐支持如下语义原语；实际线协议的字段名、能力版本与预算在 schema 阶段确定。

| 原语 | 语义与边界 |
| --- | --- |
| 明确全集／空集／ID 集合 | 全集只对已声明资源和作用范围生效；空集不匹配；不同法人和仓库集合仍在同一段内相与 |
| 本人／指定组织／组织子树 | 使用可信主体／资源属性；空部门不匹配组织分支，子树按路径段边界，不按任意字符串前缀 |
| 属性等值／集合包含 | 属性类型和允许来源预先声明；未知值不是通配，已知 null 默认不匹配这些正向比较 |
| 十进制上下界 | 含边界是否闭合、币种或统一计量依据；舍入和精度遵守共享语义 |
| 有效期／操作环境 | 求值时刻固定于 C，环境属性来源可验证；不能在每行求值时任意读取变化的外部环境 |

一个段内是有限合取，多个完整段是析取。需要 `owner OR org` 时展开成两个保留原法人／仓库／条件／字段的完整段；例如 `法人甲 AND 仓库一 AND (本人 OR 甲部门)`，不能展开成缺少法人／仓库的分支。

禁止原始 SQL、任意代码、任意属性名和 provider 私有表达式直接进入共同表示。标准表达仍不能满足的客户需求，明确增能力／适配／Fork，不靠忽略条件处理。未知操作符或不支持表达使候选策略／查询计划不可用，不替换合格策略，也不丢掉该分支后冒充完整查询。

## 读取、动作与字段的求值公式

令 `Match(C,K,r,g)` 表示 g 的主体、资格／任职、类型、操作 K、时间窗、全部范围和全部条件同时成立。段内必须保持绑定。

```text
Entitled(C,K,r) = OR over g: Match(C,K,r,g)
Visible(C,r) = Entitled(C, resource.view_key, r)
PermissionAllowed(C,K,r) = Visible(C,r) AND Entitled(C,K,r)

Readable(C,K,r,f) = Visible(C,r)
                   AND OR over g: (Match(C,K,r,g) AND f IN g.read_fields)

Writable(C,K,r,f) = PermissionAllowed(C,K,r)
                   AND Readable(C, resource.view_key, r, f)
                   AND OR over g: (Match(C,K,r,g) AND f IN g.write_fields)
```

`PermissionAllowed` 只回答资源上的授权资格，不证明单据此刻可执行、审批依据有效或动作已接受。`Executable` 还必须检查业务约束和相应接受节点的证据；接口和前端不能将它们混为一个成功状态。

普通资源字段编辑同时要求可读与本动作的写许可，承接“不可读字段不经普通 PATCH 修改”的保护。密码设置等专用命令的秘密输入另有明确输入契约，不读取旧秘密，不以此默认开放盲写字段。读取与写入是两道各自完整的检查，不从任一读字段授予推导写权。

读取响应使用该读取操作 K 的字段结果；动作响应声明自己的读取操作，不能因具有审批／执行权就输出原本不可读的成本字段。动作可不返回单据正文；返回正文时重验声明读取动作。导出也使用独立导出操作段及其字段集合，不直接复用页面已显示的列或调用系统身份取全量。

字段许可只从覆盖当前 r 且满足当前 K 条件的段汇总。g1 在甲法人的明文许可不能给 g2 在乙法人的读取解密；两个均合法覆盖同一行／操作的段则可并集其明确字段。

## 三种列表的严格集合契约

| 查询类型 | 应返回的完整集合 |
| --- | --- |
| 通常读取列表 | 请求筛选条件 AND `Visible(C,r)`；单对象读取使用同一 view_key |
| 特殊读取／导出列表 K | 请求筛选条件 AND `PermissionAllowed(C,K,r)`；以同 K 的单对象读取资格和字段输出核对 |
| 可执行动作筛选 K | 请求筛选条件 AND `Executable(C,K,r)`；同时包含可见、动作授权及声明的业务约束 |

普通列表可另外返回逐行动作状态；它仍是可读记录列表，不承诺每行可审批。若某动作条件无法完整下推或预算内完整求值，可以保留普通列表并把该动作状态记为未知，或明示不支持该动作筛选；不能将“候选可审批”当作已经满足 Executable 的集合。

由此修正 I28：不再宣称“任意 K 的列表都等于 Can.visible”。可见性与操作资格有各自确切集合；同一用途、同一 C、同一数据集合下必须一致。动作返回 404／403 与读取授权按[权限主体](../02-security-and-permissions.md)的存在性保护统一解释。

## 查询下推、分页和敏感字段

查询与单对象使用同一段模型。关系型适配把每段生成参数化谓词，再完整 OR；所有分支先授权再排序／分页。不同 provider 的内部 SQL 可以不同，结果集合和字段义务必须一致，SQL 本身不接受用户字符串拼接。

多分支可以优化为 UNION，但重叠记录按稳定身份去重，字段按全部合法匹配段判断，之后统一排序、分页与聚合；不能先各取一页再截断，也不能让去重随机选择一个较宽或较窄字段版本。

图分支要有覆盖完整集合的协议。ListObjects 的截断、超时、缺少某部分关系不能当作空集合或完整集合。取候选再权威检查只能在最终分页前构成完整集合；若成本过高，使用有边界的异步查询或拒绝本次查询，不放宽保护。

排序、过滤、搜索、分组、聚合和关联展示都声明所用字段及派生依赖。标准路径先确定不依赖这些受限字段条件的可见候选范围，再证明调用者对范围内所用字段具有相应读取资格，最后执行相关筛选或排序；已独立证明可用的普通筛选可以缩小该范围。资格可通过有限包含关系证明，不能证明就拒绝该查询操作。空结果不免除查询字段权限检查，不能先运行敏感筛选再靠返回空集说明合法，也不能让敏感条件筛掉不可读字段的记录后循环证明权限。

混合字段权限的列表仍可读取并逐行掩码；不能为了使某个成本排序可用而静默删掉不可读成本的行。另声明的公开统计或受控跨范围指标是独立资源／读取契约，不套用明细授权后随意扩大聚合。

游标绑定筛选、排序、数据视图和授权上下文标识；后续页须重验当前资格。版本或授权时间窗改变时，若不能证明同一安全集合继续成立，就要求重新查询；不能沿旧游标保持撤销前权限。严格接受／撤销的时间协议仍须下一专题定义。

## 创建、修改与业务强约束

现存记录先以权威旧事实判断可见／动作资格，普通修改还检查请求中每个字段的写许可。任一待修改字段检查失败时整条命令拒绝，不静默丢弃用户试图改的字段；批量的整批／逐项事务行为由业务契约明确。

修改法人、负责人、组织、共享关系或金额等可能改变资格的内容，必须声明专门动作或新旧值守卫。候选新状态重新校验所有相关范围和条件；不能把符合上限的旧金额改到上限外，也不能靠改 owner／法人获得另一范围的数据。计算出的金额、单位和来源属性先由业务规则确定，不能只查用户提交的数值。

标准创建使用校验后的候选资源事实，要求该范围的创建资格及创建后读取资格；尚无 ID 时仍能校验法人、组织等维度。确需创建后不向操作者公开内容的专门业务，声明独立接口、输入与最小回执，不从本公式推导通用盲写能力。

期间锁、冻结、不能自审、审批修订、执行许可和库存不变量由业务属主在最终提交／执行节点检查。列表里的 `_access` 或 PermissionAllowed 是体验与资格结果，不替代并发提交保护。

## 不确定、缺能力与解释

已知事实确实不匹配，按读取／动作规则拒绝；缺失可信输入、不能满足新鲜度、provider 故障或查询集合不完整属于无法证明，不伪装成“没有数据”。内部区分明确拒绝与无法决策，对外复用协议批准的保护错误，具体 reason 在线契约阶段登记，不能临时发明生产错误键。

局部未知分支不贡献许可；已有独立完整授予可以证明某个单对象许可时，只采用其已证明的字段。列表若未知分支可能改变成员集合，必须整体标不可完成，不能只返回可证明的部分。部署受众、身份、所需当前资格等全局输入不合格时，不继续用局部授予放行。

解释留下实际主体／履职身份、资源类型／修订、K、授权版本、匹配段及字段来源、必要限制与求值时间。无权记录的解释不暴露其金额、负责人等属性；更多解释路径的能力缺失不能改变基本允许／拒绝结论。审计可靠保存另由 I29 对应协议处理。

下表为理论向量要求，未在 SDK／数据库执行。相同上下文同时比较读取／动作、字段和完整列表，另配合法正例。

| 编号 | 反例或正常场景 | 固定预期 |

| AE08 | 有页面读取，无导出操作；另有同范围且字段较窄的导出许可 | 前者拒绝导出，后者仅导出其完整段允许的字段 |
| AE09 | 空部门、明确空仓库集合、已知 null、未知必要属性 | 不扩为全集；未知必要属性按无法证明处理，不返回假空集合 |
| AE10 | 授予内 owner OR org，另有法人／仓库条件 | 两个 OR 分支均保留其他限制；不能通过 org 绕过法人 |
| AE11 | 关键动作选择甲任职，却引用乙任职授予；任职刚失效 | 不能借用乙授予；资格变化按适用新鲜度／接受协议保护 |
| AE12 | 自己发起的单据，同时持有多个审批角色或共享许可 | 当前适用本人自审约束仍阻止；合法他人单据正例成立 |
| AE13 | 两个查询 OR 分支都含同一记录，权限页满且字段策略不同 | 只出现一次，合法字段并集后统一分页，不漏下一条 |
| AE14 | 部分行成本不可读，请求按成本排序／筛选或看衍生毛利 | 不能证明全查询字段资格时拒绝该查询用法；普通掩码列表仍可用 |
| AE15 | 旧金额 50 合法，请求改成超出本动作范围的 150；改法人／owner | 候选新状态／专门转移守卫拒绝，原记录不变 |
| AE16 | provider 截断、未知表达、图分支超时，当前页仍有本地行 | 不能伪称完整列表或无权数据为零；独立单对象已证许可另判断 |
| AE17 | 当前游标之后撤权或授予到期 | 不继续旧授权，按安全重查／中止处理，不承诺旧分页永远完整 |

本页提出可核对的求值模型，不将 I18／I28 标为闭环：还要审查上述候选规则，确定有限表达的 schema、逐记录字段／查询 API、动作元数据、向量与版本迁移。旧 `authz/2` 的维度并集和字段规则含义变化，须显式处理新主版本或候选版本重建，不能以新增 JSON 字段名掩盖破坏性语义变化。

服务主体与属性来源已有[第二份候选规格](02-trusted-identity-and-attributes.md)，授权接受／撤销已有[时间候选规格](03-authorization-acceptance-and-revocation.md)，管理／任职已有[第四份候选](04-authorization-administration-and-appointments.md)，均仍需审查和运行验收。下一件工作与尚缺细节见[接续清单](../work/04-next-steps.md)。它们均使用本页的段与集合语义，不另建一套更宽求值。
