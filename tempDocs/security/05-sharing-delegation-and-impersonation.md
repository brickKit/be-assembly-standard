# 共享、委托与只读扮演生命周期

> 状态：2026-10-13 第五份安全候选规格，尚未冻结。承接前四份规格、D09／D10／D36 及只读扮演 A5 方向；不修改当前协议、权限数据、SDK 或 IAM，不实现预留的 agent 分支。

## 目的与方案选择

本页补清楚“让别人看／替我办／按我的视角排查”各自的授权来源、责任、范围、到期与撤销。默认小公司可只启用单资源只读共享和单层委托；有需要的客户启用关系继承或有限再委托，不以模型名称假定这些能力已经交付。

| 路线 | 判断 |
| --- | --- |
| 推荐：共用完整授予与时间结构，按来源类型区分生命周期 | 普通机构授予、业务关系和依赖个人资格的委托各自可解释，沿用既有求值／身份／收紧机制 |
| 所有来源都复制成接收人的普通角色／ExtraIDs | 丢失动作、范围、字段、当前资格与责任绑定；不能满足完整授予和代理上限 |
| 所有授予都随授予操作人资格消失 | 对个人委托合理，对合法机构授予和正常管理员交接违背 D36，会无故中断业务 |

本页补的是来源与派生规则。读取／动作／字段继续使用[完整授予规格](01-authorization-evaluation.md)，身份取证使用[可信身份规格](02-trusted-identity-and-attributes.md)，并发节点与输出使用[时间规格](03-authorization-acceptance-and-revocation.md)，管理上限使用[管理／任职规格](04-authorization-administration-and-appointments.md)。

## 来源类型与责任

| 来源类型 | 执行主体与权威 | 有效性依据 |
| --- | --- | --- |
| 普通资源共享 | 接收人以自己身份读取；Authz 保存人工授权，业务属主提供资源／共享治理事实 | 资源治理边界、接收资格、明确授予及期限；授出者是历史操作人，不默认是永久个人委托源 |
| 组件拥有的团队／成员／层级关系 | 接收人自己；关系事实归对应业务组件，Authz 仅保存受控视图 | 当前关系实例、层级及其明确读取／业务动作契约，不允许管理员伪改来源关系 |
| 个人临时查看／代办 | 实际操作者自己，保留被代表主体及来源申请／委托 | 明确个人来源、其当前资格、创建上限、目的和期限；不套用普通机构授予的卸任保留 |
| 休假审批代理 | 代理人自己，记录代谁履职；业务流程属主拥有任务和替代规则 | 委托人当前完整审批资格、受托人必要执行资格、任务／内容和本人自审控制 |
| 只读扮演 | 实际支持人员与被查看主体分别记录；IAM 验证／签发身份，Authz 验证许可 | 真实操作者的扮演资格、被查看人当前读取权限、会话上限及只读 profile |
| 服务代理用户调用 | 用户仍是被代表主体，另验证直接服务 | 第二份规格的用户证据和服务方法许可；技术转发不自动变成业务委托 |
| 已接受业务的持久后续 | 受限服务主体，原发起人仅为历史责任信息 | 已建立业务 B 的限定过程和当前必需控制，不按个人代办 token 长期运行 |

个人来源和机构治理来源必须显式登记；不能从 `granted_by` 名字、接口路径或有无 `act` 猜测。治理上限被撤销／收紧、对象跨法人迁移、接收人失资格和安全冻结仍会影响普通共享；不是“历史操作人卸任后什么都不变”。

## 普通共享的授出与退出

普通资源共享先要求明确的共享管理资格和机构资源治理上限；能读不自动能分享，持有临时查看／委托读取也不自动获得持久共享权。标准共享只授出声明资源的读取，不新增确认、取消、付款、关账等动作。

候选授予绑定资源类型／稳定 ID、接收主体或受控组、法人等治理范围、允许读取操作、显式字段、条件、有效期及来源修订。创建时用第四份完整包含证明核对机构可分享上限，不从授出者可读字段全集隐式复制。该治理权限本身必须由合格管理者确认；不能把个人短期阅读权包装成可长期授出的机构边界。

业务属主声明哪些资源／字段可分享、如何验证对象存在与当前治理边界；Authz 验证已认证属主证明、用户身份／管理资格及当前上限，在受保护生效点写授予、修订和必要审计。单纯 `be-caller` 和客户端自报 owner 不作来源证明。跨属主证明、水位与收紧沿用前三份，不用“先本地成功后等消息最终同步”冒充共享已完整生效。

接收人的普通角色不必原本覆盖这条记录，但有效共享必须产生明确、满足第一份字段／范围规则的读取段和声明的 `view_key` 资格。字段限制不改变结果集合的完整性义务；共享不得顺便开放任意父对象、伙伴银行资料、附件、搜索或报表字段。

普通共享不是默认带导出、下载或再次分享。页面、附件访问、导出和公开链接各有声明操作与目的：资源允许的普通查看可以包含受控附件展示，但不能由“共享订单”推导原始文件的直接永久 URL。具体渠道及字段映射在资源契约声明。

正常更换授出操作人／管理员不自动撤销机构共享，管理责任按第四份接管，来源历史保留。对象负责人改变是否保持共享，按预登记治理规则处理；变化跨越绑定法人、共享政策、资源类型或字段含义时，先保护受影响授权，再复核／迁移，不让旧 ID 授予无条件跟随到新域。资源删除／合并／墓碑承接跨组件引用协议，不能让 ID 复用把访问权给新对象。

撤回由有权管理该资源／授权域的人执行，接收人可放弃自己对应共享；不删掉另一条独立合法授权。关闭、到期、撤销和停用留据，普通读取失效窗口和严格出口分别按第三份声明。结束后的新共享使用新授权实例，不修改旧期限复活旧会话。

## 团队、组与层级继承

共享给组时先验证组来源、资格与成员完整性；成员加入／退出由组属主处理，不能凭 IAM 外部组名自动扩权。动态组须声明允许的成员变化语义、法人边界和字段规则；未支持组来源完整性时只允许直接主体共享，不以缺成员信息代表全集。

父子资源或团队关系只按声明契约动态派生完整段。每条路径保留父授权身份、关系实例／版本、范围、字段和资格限制，并核对当前子资源的治理边界；不复制父授权给每个孩子后失去撤回联系。关系环、超深、图截断或缺边事实属于无法证明，不返回假完整集合。

撤销一条父授权／成员关系关闭相关派生路径；另一条独立合法路径可继续。对象移出父层级后，旧路径不再授权；移入不支持或跨法人的新父级时不自动继承。逐记录字段只从当前合法路径取并集，不能借另一个对象或分支的明文字段。

资源属主拥有团队关系，不意味着它可以绕过用户资格和业务控制。关系声明可以承接特定业务动作，但普通人工共享仍只读；两者使用不同、明确的来源能力。完整查询及冷热／投影水位继续满足第一／第三份规格。

## 个人委托的创建上限与使用求值

个人委托保存根被代表主体、真实受托主体及其必要资格、来源资格实例／修订、目的／工单／任务、明确动作、资源／范围／条件／字段、创建时的完整上限、时间窗、授权链及撤销状态。请求人和合法确认者按该委托类型声明；独立确认不通过另一个已关联账号规避。

创建须有专门委托资格，且每个拟委托完整段包含于当时来源的合法完整许可和可委托 profile。受托人可以没有原来的同名业务角色，但须有该动作要求的实际执行资格；不能把职业资格、合法签署任职或法定限制一并从委托人复制过去。不能委托的动作明确拒绝，不删除检查后以系统身份执行。

使用时重新取证来源当前完整许可，将每份完整来源段与创建上限、各有效委托边、资源范围／字段限制及本模式 profile 相与，再按第一份规则产生合法派生段。来源许可只在自己的合法分支内求并集；不能把甲范围和乙字段／额度拆开拼接。

创建上限防止委托人后来扩权让旧委托自动扩大；当前许可求交防止后来缩权留下旧宽许可。角色新增权限、改任职／组织边界等扩权修订不自动更新上限，要重新确认；明确声明的动态资源集合可覆盖其契约内新记录，不等于自动换到新法人／岗位或解释不同的范围。

委托模式不与受托人自己的更宽许可合并。请求明确选择自己履职或某份代办依据，业务属主核对与任务相容；所选委托失败时，不悄悄用自己的另一任职或服务身份兜底。需要自己的合法动作时，走独立、明确的自有权限请求，不把结果归到失败委托的审计记录。

委托动作所需最小读取单独声明为受限完整段，分别被来源当前读取资格和创建／委托字段上限覆盖；审批资格本身不自动开放 view 或成本明文。缺合法最小读取无法形成完整业务能力时拒绝启用相应代理路径，而不是用系统 BatchGet 绕过。

授权管理、身份绑定／凭据变更、创建持久共享、创建新委托和紧急提权不从普通代办默认获得。其他不可委托动作按资源与业务 profile 登记，复杂客户确需受控扩展时单独设计确认与验收，不在本稿新增生产权限键名单。

## 休假审批与业务责任

代理委托只覆盖明确的流程职责／节点、业务操作、范围和时间；不复制委托人的全部角色。实际操作者、被代表主体、委托人所用任职和受托人的实际履职证据分别记录；需要指定合法签署身份的动作必须声明是否允许代办及受托人必须具备什么，不能只选一个别人的任职 ID。

本人自审检查适用责任主体、已关联账号、实际代理人、被代表主体以及业务要求的受益／申请关系。代理人不能审批自己或委托人发起、以此规避 D10 的单据；多级代办也不隐去参与责任，无法证明分离则保护，不能把未知当不同人。

待办改派不创造权限。流程属主按 D38 的绑定规则与当前资格处理任务；原处理人失资格或委托结束后，未处理任务返回仍合格原职责或重新解析合法接任者，无合法路径则暂停转人工，不盲目退回已离职用户。旧任务结果按任务／内容修订和执行依据处理，迟到回执不覆盖新任务状态。

代审批在相应 A／B 节点检查当前来源、受托资格、本人自审及内容／审批依据。委托撤销与已合法接受动作按第三份分档裁决；需要生效点仍合法的管理或特定签署采用同事务 A／B 或提交屏障，不能笼统宣称所有旧接受即时取消。

## 再委托与多级链

基础 profile 默认只允许一个个人委托边，再委托关闭。普通代理请求不得把获得的权限变成永久角色、共享或另一个委托；简单客户没有这项能力也不影响机构分级管理。

最大层数只计算有业务授权含义的委托边，不按 HTTP 服务跳数或 JWT 历史 actor 数量计数。普通技术转发／受众收窄不新增业务委托；改变合法受托主体或下放业务权时，必须形成相应受控边，不能伪称转发避开再委托检查。

复杂客户要启用有限再委托，父边必须显式允许，profile 声明最大边数、允许类型／动作和来源完整性能力；每次新增边独立确认，子边资源／字段／条件／期限只可收窄。禁止自环、跨部署和责任主体绕道回到自己；不能把一串同名但不同账号当作无环证明。

求值从受信根资格和链上授权记录验证每条边，终点取全部相关期限最小值，当前来源和治理收紧限制逐边应用。链的批准不让中间受托人获得别人的职业资格；任何必要边／事实未知、到期或撤销时，该路径不能贡献许可，其他独立完整路径分别判断。

链条属于应用授权记录，不从 JWT 嵌套 `act` 的历史 actor 声明推导资格。RFC 8693 的历史 actor 只作历史表达；本项目额外的逐边上限来自有权威的委托记录，须绑定 ID／修订并验证，不把历史 JSON 当完整授权图。[RFC 8693 §4.1](https://www.rfc-editor.org/rfc/rfc8693.html#section-4.1)

## 只读扮演与会话隔离

承接 A5：生产可声明支持只读扮演，用于受控排查用户视角；必须有专门扮演资格、明确目标／原因／工单和短期会话，不允许业务写入。真实支持人员和被查看主体在每条访问／审计中保留，被查看者获得开始通知。

只读结果为被查看主体当前完整读取许可，与本次授权的目标／资源／字段／profile 上限的交集。真实操作者的 superuser 或更宽业务权限不与目标许可并集，也不能通过系统身份读取额外字段；若支持人员不具备目标业务角色，可凭合法扮演资格进入受限模式，仍不获得持久角色。

所有实际路由和用例声明副作用类型。只读扮演拒绝 PATCH／确认／取消／管理，更拒绝用 GET、GraphQL resolver、附件预签名、导出作业或订阅启动隐蔽变更。必要会话／访问审计与查看通知允许按协议产生，但不能让“通知／渲染”成为发送付款、发布业务指令或对外打印的入口。敏感导出、原始文件下载和外部投递不默认属于扮演只读 profile。

推荐保留旧 A5 的 15 分钟会话上限作为待审起始参数，无刷新令牌，不通过刷新或换目标延长；续用重新申请并重新取证。新会话与操作者普通会话隔离，切换／退出撤销对应扮演会话，前端清除其私有缓存、订阅和文件引用；旧授权游标不跨模式复用。已显示的数据不能追回，后续输出继续按第三份保护。

被查看者关闭、暂停或权限变化按当前事实及第三份的风险节点／窗口生效，历史副本不保持目标旧视角权限。身份改变和服务端请求使用相同模式标识，不能只改前端标签；开发用全权扮演不能作为生产默认分支。

## 服务、agent 与紧急访问边界

服务代理先证明服务与用户，委托记录还限定服务／客户端、受众、目标和用途；`kind=svc` 不免除代理资格、当前上限或受众检查。后台用户导出、通知中的链接／推送与订阅按执行／交付节点重验；已建立 B 的持久后续则按第三份业务过程规则执行，不携带长期个人 token。

agent 仍是预留，不实现令牌交换或自动审批。未来允许时，其工作负载身份、受信用户委托、工具／动作许可、目的和确认节点都须声明，模型输出／提示词／工具名字不能充当授权；没有完整能力时拒绝，不能映射成服务或管理员以避开检查。

临时角色提权与紧急访问不是普通代办：由第四份合格管理路径授出受限、可撤销、带期限的机构许可，保留申请／独立确认和通知／复核，默认不允许自批。应急登录／恢复必须独立于失效认证路径，并明确备用身份与安全状态取得机制；不在本页开放无认证后门、全权角色或默认先用后审。

公开／外部访客链接不是普通共享。若未来启用，需独立不可猜凭据、接收身份或持有者语义、资源／操作／字段、期限、用途、撤销及入口／频控声明；不能把登录用户共享转成任何持有 URL 的人可见。本稿只保留能力边界，不宣称已实现链接分享或 agent。

## 状态、续期与撤销影响

| 阶段／变化 | 候选行为 |
| --- | --- |
| 申请／预览 | 记录目标、目的、候选边界和时间，不产生有效读取／代办能力 |
| 确认／激活 | 受保护管理生效点重验资格、范围／字段和来源修订，持久化来源及独立授权实例，未知结果按幂等键查询 |
| 生效／到期 | 左闭右开、每次求值保留时间，缓存及输出终点不能晚于必要资格终点，作业只是通知／整理 |
| 续期／扩权／改目标 | 新候选和合格确认，不改旧实例的期限／上限来恢复旧会话；旧记录与新实例明确关联 |
| 上游个人缩权／失效 | 相关个人委托路径当前求交／保护，再可靠更新派生视图；不等消息最终到齐才进行安全裁决 |
| 普通机构操作人卸任 | 不自动撤销合法机构资源共享，第四份接管；治理边界及接收资格仍动态检查 |
| 撤销一条路径 | 关闭该授权／委托边，处置缓存、会话和未接受任务；其他独立合法路径不一律删除 |
| 内容／归属／治理修订 | 资源最低安全水位与当前范围一起验证；不能借旧分享关系读取不相容的新内容 |
| 恢复／成员切换 | 保留主体、授权实例、源类型／修订、链和终态，使用新恢复代次核对安全状态，不复活旧会话或仅复制角色名 |

共享／委托创建和扩大权限需要可靠、受保护的生效证据；结束路径还维护影响依赖索引，覆盖链边、组／父关系、会话、未接受任务和输出。索引帮助快速收紧，不替代完整求值：索引缺口时关闭有关域并对账，不能以“没有找到下游”证明无人受影响。

撤销分别报告第三份的关闭新接受、关闭旧提交及保护出口完成状态，不把通知成功、事件已发或撤下 JWT 钥匙当作全部结束。已接受动作、已提交事实和已交付副本按原协议处理，不写“撤销一律回滚全部”。

## 通知、审计与期限 profile

只读扮演开始通知、授权申请／决定、委托结束和重要异常有可靠意图记录与受控重试。通知不放用户 token、敏感明文或长期下载能力；站内通知与外部渠道投递状态分开。A5 的“被查看者被通知”不能只在发送失败日志里算完成：profile 声明站内可见落点、投递预算和不能完成时的保护，尚无合格方案时不启用该扮演路径。

必要审计记录源类型／实例、真实／被代表／批准主体、合法责任绑定、上限／资源／内容修订、请求模式、接受／提交／撤销节点与结果。审计长期保存继续由 I29 处理，不能因本页列了字段就称可靠闭环。

每种来源声明最大期限、续期／确认规则、是否可再下放、动作／字段 profile、来源健康／失效窗口、并发／数量／深度／查询预算及输出方式；缺必要参数或 provider 能力阻止启用。机构共享允许明确的无固定终点政策时，仍保留资格、治理与复核控制，不将“无日期”解释成秘密字段或跨域永久访问。

除 A5 的已有 15 分钟起始上限，本稿不直接采用知识库的 2／8 小时、31 天等样例作为所有客户的期限。审批代理按声明假期／职责时间窗受限，起止按业务日历转为 UTC；具体默认参数在共同能力 profile 阶段确定，不重新询问统一业务规模。

## 依据与独立判断

知识库委托／临时访问、完整授予及责任章节提供中立参考。本项目按 D36 区分机构授予和个人委托，不把知识库的个人来源随时失效规则一概套到机构共享；当前风险时序按第三份，不直接承诺每请求检查就是提交时有效。

[RFC 9700 §2.3](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.3)用于核对令牌用途／受众和最小权限，[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)用于核对每入口保护。来源类型、共享治理和派生上限是项目候选语义，标准的令牌交换或日志字段不替本项目证明业务授权正确。
