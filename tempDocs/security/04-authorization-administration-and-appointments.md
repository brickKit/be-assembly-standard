# 授权管理上限与任职生命周期

> 状态：2026-10-13 第四份安全候选规格，尚未冻结。承接 D06–D10、D35–D37 和前三份安全规格；本页定义管理行为，不修改正式契约、SDK 或客户授权数据。

## 目的与已定约束

默认小公司可以集中管理，集团可启用受限分级管理。两者使用同一完整授予和管理上限语义；分级不是扮演，也不要求管理员先拥有全部被管理业务操作权。

| 已定要求 | 本页保持的结果 |
| --- | --- |
| 完整授予配对 | 管理者每份授出资格也保持对象、动作、范围、条件和字段绑定，不能分别取最宽再组合 |
| 管理与使用分开 | 业务许可不推导管理权；管理上限本身也不授予业务数据访问 |
| 新任职授予人工确认 | 任职事实、权限建议和生效授予分开，预审核计划仍在生效时重验 |
| 普通管理员正常卸任 | 结束其管理资格，合法普通授予按自身绑定继续；代办仍依赖相应上游资格 |
| 普通角色升级经客户确认 | 模板发布不自动扩展客户实际角色或已绑定授予 |
| 共同安全与必需控制 | 上限收紧、角色退役、本人自审和其他必需控制不能被旧角色或兼任绕过，不引入管理员可配置 Deny |

求值见[第一份规格](01-authorization-evaluation.md)，主体／属性取证见[第二份](02-trusted-identity-and-attributes.md)，管理提交与收紧见[时间规格](03-authorization-acceptance-and-revocation.md)。本页只补管理对象、包含关系和生命周期，不另写业务许可公式。

## 方案比较与推荐结构

| 方案 | 判断 |
| --- | --- |
| 推荐：明确管理职责单元、持有资格与有限完整上限；客户角色版本和授予显式绑定 | 易于说明“谁管理哪部分、能授出什么”；卸任、收紧与普通授予可分别处理，适合集中和分级 |
| 管理者只能授出其本人业务许可 | 结构较少，但违反管理／使用分开的目标，迫使管理员获得不需要的业务数据和动作权限 |
| 任意策略语言间自动证明上限 | 表达广，但不能保证可判定、预算或跨实现一致；仅有限可证明表达进入标准路径，其余明确适配或交合格上级处理 |

管理职责单元是机构授权边界，不是一个永久管理员账号。它有稳定身份、管辖范围、上限与治理来源；管理者通过有效管理资格持有它。管理者退出与职责单元撤销分开，不把某个人的任职期限当作所有下级治理关系的寿命。

| 对象 | 最少记录与责任 |
| --- | --- |
| 管理职责单元 | 稳定 ID／修订、所管法人／组织／人员／授权对象、允许管理动作、可授出的完整上限段、有效期及治理父来源 |
| 管理持有资格 | 实际主体、职责单元、所需任职／其他资格及有效期；由合格管理路径确认，不从职务名自动推导 |
| 客户实际角色版本 | 稳定角色 ID、不可变内容修订、操作／字段／条件模板、来源和退役状态；不能只存“销售经理”名称 |
| 普通业务授予 | 稳定授予 ID／修订、受授主体、实际角色内容版本或明确直接操作、范围／条件／字段、资格绑定和有效期 |
| 管理／角色变更计划 | 明确目标及候选状态、影响清单、各绑定修订、所用上限证明、确认人、有效期、幂等键及处置记录 |
| 来源与接管记录 | 谁在什么资格及上限下授出、归哪个治理单元管理、实际变更依据和后续接管；不覆盖原授予来源 |

这些对象是候选行为模型，不登记新权限键或组件 ID。作用域支持集中管理员的显式全范围，但只对声明部署／资源成立；不把空值、未知组织或未安装能力当作全权。

## 授出包含关系与完整见证

一次新增／扩大授予先检查管理者当前身份、管理动作及目标对象资格，再把候选角色和授予展开为第一份规格的完整段。每个候选段须在一份合法完整管理上限段内得到包含证明；多个上限可通过显式拆成不同候选段配合，不按维度、金额或字段独立取并集。

| 比较项 | 标准路径的证明要求 |
| --- | --- |
| 管理目标 | 候选主体、任职、角色／授予与被影响治理域均属于许可目标集合；人员在本部门不意味着其全部跨法人权限都归本部门管理员 |
| 操作 | 每个候选操作属于该上限的明确可授出集合；未知、退役或未来键不借通配生效 |
| 范围 | 候选资源集合包含于上限资源集合，法人／仓库等配对保持；全集、空集、ID 集合和组织子树分别校验 |
| 条件 | 候选段成立必然使相应上限条件成立；金额同币种／单位比较，区间边界一致；不能把两个范围的额度拼成一个更大上限 |
| 字段 | 候选读／写字段各自包含于对应上限字段集，派生依赖和普通字段分类也合格；写权仍遵守第一份读写组合 |
| 时间与资格 | 候选有效期、任职／其他业务资格及要求不超过治理许可；未来生效先登记待确认，不提前可用 |
| 再下放管理 | 管理职责的再下放必须有独立许可、目标和深度上限，不能从普通授予动作或业务角色内容推导 |

包含证明支持有限集合包含、明确组织路径段／子树包含、相容类型的区间收窄、条件合取加强和字段集合包含；多个 OR 分支先展开成完整段再逐段证明。不是任意布尔／策略语言的通用蕴含求解器。无法证明、来源缺失或超预算时拒绝／转合格上级，不能删去难证明的条件后通过。

例如管理资格甲只可授“法人甲／仓库一／审批 ≤100”，资格乙只可授“法人乙／仓库二／审批 ≤50”，不能据此授出“甲／二”或“乙 ≤100”。合法原配对可以分别形成两份授予。

`self`、任职相对组织等表达按候选受授主体和绑定事实展开，不把管理者自己的本人／部门表达复制后误当包含。无法证明未来绑定变化仍在上限内时，绑定该资格修订，变化后按下文失效／复核；不能因语法字符串相同就判相等。

上限只提供最大可授出集合，仍需要明确管理动作才能执行；它不提供业务使用权。这与 [AWS permissions boundary 对最大权限和实际授予的区分](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_boundaries.html)相近，但本项目不照搬 AWS 的资源策略或 Deny 合并算法。

普通授予的业务有效期受机构治理上限及受授资格约束，不以授予操作人的任职终点裁剪；管理者仅在本次操作生效时必须合格。个人卸任后的普通授予因而能按 D36 继续，而机构上限撤销／收紧仍执行后文影响闭包。

## 不同管理动作的检查

| 动作 | 需要检查的实际影响 |
| --- | --- |
| 新增／扩大普通授予 | 目标资格和每个候选完整段的授出包含证明，不能只看角色名 |
| 收回／缩小授予 | 专门回收权和被影响授权域，不要求回收者同时有权重新授出旧的宽许可；也不能借管理一个人员撤掉其不归自己管的跨域授予 |
| 修改角色内容 | 该角色版本和所有目标授予的实际变化；不能只因有“编辑角色”入口就影响未获管辖的成员 |
| 绑定／替换角色版本 | 每份绑定都按候选新内容重新证明，发布角色修订不替代绑定确认 |
| 下放管理权 | 管理父来源、可管理动作、目标、上限、期限与深度；禁止环和自己绕道扩大同一管理资格 |
| 管理员交接 | 交接权、接任者有效资格、职责单元和边界；接任是新管理资格确认，不是继承卸任者登录凭据 |
| 管理上限收紧／治理单元撤销 | 对新管理及已发授权的依赖闭包、收紧与停用处置；不同于正常卸任 |

回收只作用于有权管理的授权域。一个宽授予跨越多个管辖域时，仅能执行有完整影响证明的分段收窄，或者由覆盖整体的上级处理；不通过删掉整个授予间接撤销另一法人合法权限。

管理者给自己或已关联其他账号配置业务权限，同样不能超过其明确授出上限；业务资格或修改角色不能成为扩大管理上限的入口。小公司的合法集中配置不默认要求第二名员工。需要独立确认的管理扩权、紧急访问等由受保护操作清单声明；不能自己绕过该清单，缺合格确认者转上级／受控部署恢复，不临时取消要求。

管理变更是高风险动作。推荐管理状态和接受裁决由 Authz 同属主持有，在同一守卫事务完成 A／B，重验当前管理持有资格、治理上限、目标修订及影响计划后提交；不能使用旧的管理 Check 更新授权。若所选实现不能将管理生效纳入同一保护事务，须具备等价 B 档管理提交屏障，否则不启用该管理能力。普通业务的 A 在先可限定继续，不能被用于让已失去资格的管理员稍后发布未生效授权计划。跨属主资格变化先执行第三份收紧协议，异步批次也在各生效点重验。

## 角色模板、客户角色与版本升级

标准模板、客户实际角色、任职建议、有效授予是四种对象。模板升级只生成差异和候选，不改客户实际角色。客户角色新修订默认不自动替换已绑定修订，明确的确认计划选择哪些绑定采用新内容，防止同名角色被就地扩权。

已发布权限键不改名或复用，权限含义变更仍审兼容与迁移。新增功能安装后可能需要客户做一次权限配置才能使用，交付界面与说明应明确这一状态，不能为避免配置而自动扩权。

| 差异 | 处理 |
| --- | --- |
| 新操作／新字段、范围或条件放宽 | 展示实际扩权，合格管理者确认并证明影响对象的上限后生效 |
| 客户主动收窄 | 记录修订，执行收紧协议并更新明确目标绑定，保留旧证据 |
| 权限退役／必需控制／安全修复 | 执行受保护升级规则，旧角色修订不能继续启用已退役键或绕过当前控制；具体兼容与受影响动作按升级契约处理 |
| 相同键含义变化、资源类型或字段解释变化 | 按语义破坏性变更审查，不冒充仅模板新增字段；冻结前确定迁移版本 |
| 客户自定义角色／Fork | 保留实际内容和来源，比较具体差异；不按名字强行覆盖 |

角色不默认任意继承；复用权限组也必须展开并绑定具体版本。未来启用继承时，声明无环、深度、实际内容展开和变更影响能力，不能借继承让未确认权限自动进入旧角色。

系统角色保护、最后一个管理员保护和专用 superuser 对已注册未退役键的特殊补齐继续承接 D37，另有受保护规则；普通角色不能冒充它们。生产默认无人持有 superuser，秘密不可输出和必需业务控制仍不能绕过。演示 seed 角色不直接作为正式客户模板。

## 变更计划与批量生效

计划保存不可变候选、目标全集／完整枚举证据、角色／授予／任职／治理修订、影响与包含证明、确认身份、终点和幂等键。预览和确认均受管理数据访问控制，只展示必要权限事实，不因管理员能管理角色而展示所有业务敏感值。

提交时重验目标和当前资格／上限，预览通过不是永久许可。原依赖修订变化时暂停失效部分并重新计算剩余候选，由合格人员确认；不能自动采纳变宽的新上限、角色内容或已转部门的目标。减少影响的变化也必须有可证明的相容规则，不凭直觉忽略。

小计划可声明整批本地原子提交；大计划采用有界批次，明确每份已生效、被拒、待处理和终止结果。每批绑定相同候选语义并重验当前证明；不得部分生效后返回“整批未执行”。取消仅停止未生效部分，已生效部分需新收紧／回收计划，不能盲目回滚他人后续修改。

新增人员、角色使用者或授权域不自动进入审核过的计划；对动态成员集合采用固定全集或可证明的截止水位。重复确认和重试不再授一次，不延长有效期；未知结果按第三份许可／业务事实查询恢复。

## 任职事实与授予生命周期

员工与账号可非一一对应，任职使用不可复用的资格实例和明确修订。任职结束后重新任职是新资格实例，不让旧任职授予复活。改法人／部门／岗位、资格条件等安全含义变化，默认结束旧资格绑定并创建新资格／候选授权；显示名等不影响资格的修改另有明确字段分类。

| 变化 | 默认处理 |
| --- | --- |
| 任职尚未生效 | 权限建议可准备；未满足时间及确认条件不能产生有效授予 |
| 新任职或安全含义变化 | 员工属主提交事实，生成候选建议；合格管理者确认后授出，不把维护岗位等同于授权 |
| 原任职结束／到期 | 关闭该资格的新接受和读取证据；撤销关联授予与管理持有资格，时间保证按第三份，不等待定时清理 |
| 仍有其他兼任 | 其他合法完整授予分别保留，不能按账号全量删权；需要所选任职的动作不借另一任职混用 |
| 独立直接授予 | 标明依据与复核政策，不因任职变化一律删除或永久保留；必要事实不清时暂停其未证明部分 |
| 一个法人离任／全部离职 | 员工属主声明失效范围，处理对应资格；账号是否停用由 IAM 生命周期政策和受控绑定决定，不把单个任职结束推成全账号删除 |
| 重新入职／账号重新启用 | 重新验证当前资格及明确确认，不恢复旧资格实例、已撤销授予或旧管理持有关系 |

授权保存受授主体、账号／员工及资格绑定的受信关系和修订，跨账号撤销按这些绑定展开；不能靠姓名／邮箱或只找“最近登录账号”处理。关系、员工和组织版本各自有域，不比较裸版本大小来忽略冲突。

建议状态为待确认、有效、受控暂停、到期／已撤销等执行视图，理由与生命周期分别记录；具体线状态机在 schema 阶段冻结。恢复失效资格不能改旧记录的有效期，让旧审计事实消失。

跨组件变化使用第三份“先收紧，后属主完成；先完整正向事实，后放开”的协议。重复／乱序事件按资格实例和修订幂等收敛，完整回填不能被局部同版本阻塞，承接 I30；同步停止时不能以投影最后一行仍 active 继续新接受。

预先审核的调岗计划仍绑定明确新资格、模板／客户角色版本、受授人员、范围和生效时点，实际生效前重验。审查后计划或管理资格改变时，未生效部分暂停重审；旧任职终点不会因等待新授权而延长。

## 管理员交接、再下放与上限收紧

正常卸任终止个人的管理持有资格，机构职责单元和合法普通授予保留。接任者通过独立合法确认获得该职责，原来源不改名。无合格接任时由已声明上级接管管理；无上级时进入受控恢复，普通合法业务授予继续按自身资格和必需控制判断，不凭空新建管理员。

机构治理父来源与个人代办来源分开。允许再下放时，子职责上限必须包含于有效父职责的完整上限，子管理者有自己的有效资格；父管理员正常卸任不自动终止合法机构边界。父职责被撤销／收紧则影响子治理能力，不能以已交接为由保留越界下放；子职责无环和最大深度属于装配／治理 profile 的显式约束。

上限收紧先关闭相关管理路径并建立影响闭包，按第三份裁决协议对已发授予的越界部分保护。可完整证明的收窄生成新修订并留据；无法证明部分边界时暂停该受影响授予，转合格上级复核。不能只限制未来授出却让已发越界业务许可无限留存，也不能把所有授予一律永久删除。

安全事件、发现原授予越权、组织撤销和治理单元废止不套用正常卸任规则。分别声明需要冻结的账号／服务／管理／业务域、恢复资格和对既有接受／已执行事实的处置；通常管理上限变化不等同于代办人上游个人权限变化，完整代办协议由下一专题定义。

## 最后管理员、恢复与业务交接

普通管理变更不得使部署无合格、可用的受保护管理资格：在同一裁决域检查当前账号状态、资格期限、治理边界和声明的认证／恢复条件，不能只数某个角色表有几行。权限回收、角色修改、任职结束与账号停用的受控路径共同检查这一不变量。

安全强制停用、已发生的外部账号失效不能为保留“最后管理员”而继续开放受侵身份；这些场景关闭相关资格并转明确的部署恢复流程。该保护不是阻止必要安全处置，也不自动授出 superuser；bootstrap、紧急恢复与当前管理数据的恢复代次承接第二／第三份规格，操作与结果留据。

审批任务／业务责任交接独立于授权交接，按 D38 的绑定职责规则解析合法接任者，不能因被任命管理员就批准他人的单据。已作出的审批事实和业务归属保留，当前资格仍按适用节点检查；无合法候选暂停转人工，不自动通过或提前授予新权。

## 独立验收预期与剩余出口

| 编号 | 场景 | 固定预期 |

| AM01 | 有业务使用权，无授出权；有管理权但无对应业务使用权 | 前者不能授出，后者可在合法上限内管理，不因此读取业务敏感值 |
| AM02 | 两份管理资格分属甲一／乙二，额度分别 100／50 | 原配对可分别授出，交叉范围／借额度拒绝 |

| AM06 | 给自己其他账号、角色塞入管理动作或越级下放 | 不扩展自己的管理资格，受保护独立确认和治理链有效 |
| AM07 | 在管辖域回收旧宽许可，但无权重新授出同样许可 | 合格回收可执行，不错误要求旧授出能力；不撤另一域合法部分 |
| AM08 | 预览后管理资格撤销、目标调岗、模板／上限改变 | 生效点重验，失效候选不借旧审核提交 |
| AM09 | 模板升级新增键／字段，客户角色同名 | 默认不自动扩权，合法确认的明确绑定才采用新内容 |
| AM10 | 旧角色包含退役键／安全缺陷规则，或冒充系统角色 | 当前必需控制和退役规则生效，特殊角色不可伪装 |
| AM11 | 新任职、未来任职、预审核计划到生效点 | 完整事实与合格确认前不生效，时点重验不延长旧任职 |
| AM12 | 原任职失效仍有其他兼任，直接授予依据不同 | 只撤相关绑定，其他合法段保留；直接授予按依据复核 |
| AM13 | 同员工多账号、单法人离任、全部离职／重新入职 | 按受信绑定和声明范围处理，不漏其他账号，不复活旧资格授予 |
| AM14 | 管理员正常卸任、接任为空、子职责仍合法 | 管理资格终止，普通授予与机构边界不因个人退出自动失效；上级或恢复路径接管 |
| AM15 | 治理父职责／上限收紧，越界子职责和已发授予 | 先保护影响域，合法收窄或复核；不能仅限制未来授出 |
| AM16 | 批量部分成功、重复确认、取消与迟到回执 | 明确逐项状态，幂等不重授；已生效不假报回滚，未知先查询 |
| AM17 | 删除最后管理员与并发任职结束；安全强制停用 | 普通操作保护管理可用性，安全停用不维持受侵身份，转受控恢复 |
| AM18 | 事件乱序／局部同版本、同步失联和恢复旧备份 | 资格实例／完整修订收敛，缺证明保护，新代次不恢复旧授予 |

| AM20 | provider／Fork 更换，仅搬同名角色或管理员 | 搬完整授予、版本、治理和资格绑定，不能用同名掩盖差异 |

## 依据与独立判断

知识库完整授予／兼任、任职、委托和授权架构提供中立参考；本项目的管理员正常卸任、受限分级管理和客户角色确认以 D35–D37 为准，不把普通机构授予等同于依赖个人当前权限的委托。

[Kubernetes RBAC 的角色创建／绑定限制](https://kubernetes.io/docs/reference/access-authn-authz/rbac/#restrictions-on-role-creation-or-update)提醒角色编辑也可能造成间接扩权，本项目独立采用完整管理上限，并不要求管理者拥有全部被授业务权。[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)用于核对每入口检查和最小访问原则；这些来源不证明本项目的包含算法或状态协议已通过验收。
