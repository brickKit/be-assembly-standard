# 共同安全结构、接口与能力兼容

> 状态：2026-10-13 第六份安全候选规格，尚未冻结。收敛前五份的共同记录、调用责任和兼容要求；不是已发布的 proto／OpenAPI、能力注册表或实施计划，不修改 SDK、正式契约、部署与权限数据。

## 目的与共同方案

默认小公司开发，按客户需要选择配置、专项组件及部署；共同结构从开始就保留有限扩展和替换的边界，不要求基础成员实现全部扩展，也不承诺无限规模。这里解决“组件具体交换什么、谁能证明、怎样识别能力不足”，不重新选择权限产品。

| 路线 | 取舍 |
| --- | --- |
| 推荐：类型明确的共同记录与接口，能力按语义／限制／责任声明 | 同一业务要求可以核对不同 provider，SDK 与属主各自承担执行义务；增加显式验证与版本维护成本 |
| 各成员只返回 allow／deny，调用方自行补来源、字段和时间 | 无法表达未知、完整集合、限定接受及撤销完成，业务组件容易各写一套 |
| 全部成员暴露相同数据库结构和策略语言 | 表面统一，实际绑死实现，精简成员被迫承担不用的图／策略能力，不采用 |

共同记录是有限的语义边界，可以由不同内部实现提供等价证明。请求不会把任意策略代码送进业务组件，业务也不按 provider 名称写分支。一个部署选择一个对外安全裁决权威；内部多模型组合由其声明并验证，不在业务调用方拼几个 provider 的布尔结果。

五份行为仍是唯一来源：[求值](01-authorization-evaluation.md)、[身份与属性](02-trusted-identity-and-attributes.md)、[时间](03-authorization-acceptance-and-revocation.md)、[管理与任职](04-authorization-administration-and-appointments.md)、[共享与委托](05-sharing-delegation-and-impersonation.md)。本页只收敛它们的输入／输出，不复制公式和生命周期。

## 权威与执行责任

| 层／属主 | 负责提供或执行 | 不能因此接管 |
| --- | --- | --- |
| 部署管理与受控签发 | 信任域、组件／实例映射、凭据和实际运行准入 | 用户业务授予、员工任职和资源事实 |
| IAM | 平台主体、精确外部链接、会话／认证与账号状态证据 | 以登录时 roles／部门替代当前授权与组织事实 |
| 组织／员工属主 | 组织、员工、任职实例、责任绑定所需事实与变更依据 | 因岗位名直接创建业务角色或审批许可 |
| 所选 Authz | 客户授予／角色／管理／个人委托记录，受控安全视图、完整求值和接受／收紧裁决 | 写别的组件数据库、为未完成事实签发新鲜证明 |
| 业务／关系属主 | 资源声明与事实、关系权威、意图 P、提交 B／Outbox、本地守卫、输出和业务结果 | 接受客户端自报 owner、用内部系统读取扩大用户响应 |
| 三语言 SDK／runtime | 受信上下文构造、证据验证、有限表示适配、查询／字段／守卫入口和错误映射 | 自行签发任意身份／许可，或替代属主持久事实 |
| 装配工具与验收工具 | 校验声明闭包、精确版本／制品与配置；验证声明实际成立 | 只凭安装成功宣称真实安全合格，或静默改风险档 |
| 前端／BFF | 声明页面需求，传播明确模式，显示资格与处理状态 | 将按钮状态／客户端缓存当作提交许可 |

外壳只改变部署。共同进程不消除各属主、真实网络、独立凭据及契约；runtime 可复用验证代码，但不共享“当前用户”或全权签发私钥。高性能成员可以优化内部索引、缓存与裁决域，不能改变本表责任。

## 共同标识与封装

以下英文名称是候选模型标签，不是新登记的权限键、错误键、组件 ID 或确定的线字段名。正式编码须逐项映射后评审，不从表名直接生成产品 API。

| 结构 | 最少语义与校验 |
| --- | --- |
| `PrincipalRef` | 部署／信任域、主体类别、稳定主体 ID；组件逻辑身份与运行实例分开，不能以版本号、邮箱或显示名作身份 |
| `ObjectRef` | 部署、权威属主、资源／记录类型、稳定 ID；按声明的命名空间定位，不能把不同类型相同 ID 当同一对象 |
| `RevisionRef` | 权威、修订域、对象或集合身份、不透明修订值及比较／兼容规则；不是全局可比的裸整数 |
| `DefinitionRef` | 声明属主、契约／模型／资源／动作／字段定义版本及内容摘要；精确匹配语义，不能只看组件的主版本相同 |
| `TimeWindow` | UTC 起止及精度／时钟 profile，左闭右开；明确无固定终点仅用于允许它的类型，缺字段不是无限期 |
| `RecordEnvelope` | 记录类别、schema 与语义版本、部署／权威、稳定实例 ID／修订、必要能力及 profile 引用；有用途的证据再附发行／终点及证明材料 |
| `EvidenceRef` | 证据类别、可信发行者、用途／目标受众、绑定记录与修订、核验时刻／终点、可验证载体或认证回读引用 |

`source_kind` 表示业务授权来源，凭据类别表示验证用途，请求模式表示实际执行路径；三者不能塞进同一个 `kind`。对象 ID、修订值和任职 ID 都不携带访问许可。安全输入要求显式存在性，区分“已知空”“已知 null”“未取得”“不支持”，未知枚举和零值不代表全集或允许。

列表型的“全部”必须有显式受限全集表达；空列表只表示空集合。十进制条件带币种／单位、精度和比较语义，不通过 float 或无单位字符串比较。集合顺序是否有业务含义、去重身份、时间精度与文本比较规则在具体编码表登记，不能由 Go／Python／TypeScript 各自猜。

内容摘要要绑定 schema／语义／编码版本和全部有授权意义的字段，并使用无歧义表示。不能把默认 protobuf 序列化结果或 deterministic 选项当作跨版本的规范摘要；官方明确其序列化不是 canonical。本稿要求后续单独确定摘要编码与正反向量，不自创密码算法。[Protobuf 序列化说明](https://protobuf.dev/programming-guides/serialization-not-canonical/)

## 身份、资格与事实证据

| 候选结构 | 必须保留的字段组 | 验证者与边界 |
| --- | --- | --- |
| `VerifiedContext` | 部署、明确请求模式、实际操作者、被代表主体、直接服务／实例、选定任职、委托／扮演引用、认证／会话证据、请求目的／截止时间 | runtime 受信入口构造；客户端只能提交选择意图，下游重新验证跨网络证据，不信 `verified=true` |
| `QualificationEvidence` | 资格属主、主体／任职实例、责任绑定、组织／法人关联、当前状态／时间窗、修订／安全下界 | 来源属主负责事实，安全裁决权威证明已完整纳入；历史任职 ID 不证明当前资格 |
| `FactEvidence` | 对象与资源定义、事实修订、所需已声明属性的类型／值或不可取得状态、来源／完整性、水位和兼容范围 | 属主提供真实旧事实／校验后候选事实；其他组件不把任意请求体包装成权威证据 |
| `SecurityViewEvidence` | 裁决权威／恢复代次、模型与能力版本、完整适用域、安全修订／依赖水位、权威核验时刻、终点及关闭状态 | 发行者具备完整处理证明；失联旧投影、缓存命中或 304 不续期 |

上下文中的原始发起人另作历史责任引用；系统续办凭已建立 B 的过程依据，不能把历史用户当当前用户。普通读取可消费合格有界证据，关键接受及敏感输出使用其声明的更强 profile。事实返回签名不自动证明全部变化已纳入；完整性是适用域和变化进度的证明，不是一个任意可填的 boolean。

跨组件证明的起始推荐是“可认证回读的属主引用”或“限定用途的属主证明”。具体选择要核对网络／恢复预算和签发信任，正式版本前确定。业务组件不拿其他属主的签发私钥；凭据验证、事实证明、读取证据与接受许可有互斥用途，不能因为同一 issuer 签名就互换。JWT 载体的验证 profile 还须明确区分各类令牌。[RFC 8725 §3.12](https://www.rfc-editor.org/rfc/rfc8725.html#section-3.12)

## 完整段、来源与治理记录

| 候选结构 | 内容与不变量 |
| --- | --- |
| `GrantSegment` | 段 ID、授予／来源引用、主体和资格绑定、一个资源类型／操作、完整合取范围与条件、读／写字段集、有效窗；不拆出可跨来源拼接的最宽维度 |
| `GrantSource` | 明确来源类型、权威记录／修订、治理单元或个人根、适用资源契约、当前必要资格与依赖引用；历史授出人独立保存 |
| `ManagementUnit`／`ManagementHolding` | 机构职责与治理父来源、目标管理域／动作／完整授出上限；另存实际持有主体、资格实例／时间窗，不把个人卸任当机构关闭 |
| `RoleRevision`／`RoleBinding` | 不可变角色内容修订、候选／退役状态、每份客户实际绑定及资格／范围；新模板不自动替换已确认绑定 |
| `ChangePlan`／`ContainmentWitness` | 请求者／确认者、目标和原／新修订、影响集合、候选完整段及每段的完整上限见证、有限证明规则版本、预算／有效期、幂等键和结果引用 |
| `InstitutionalShare` | 资源与治理资格、接收主体／受控组、读取段和字段／期限、共享规则修订；来源不默认是授出操作人的永久个人许可 |
| `DelegationEdge` | 根及父边、实际授出／受托主体、合法确认、创建上限、当前来源资格／修订、目的／任务、范围／字段／期限、再委托许可／深度与状态 |
| `ImpersonationSession` | 真实支持人员、目标主体、专门资格与确认依据、只读目标／字段上限、起止／撤销、通知引用和隔离会话标识 |

共享／委托来源的 allowed 类型集合属于版本化能力。普通共享、个人委托、机构管理父链和技术调用历史不可互相改名；每类记录的失效规则沿用第五／第四份。业务关系由关系属主提供，Authz 保存的受控视图不能反向成为修改团队／层级的入口。

求值段只是执行视图，管理、资格和资源记录仍有自己的唯一权威。临时求值结果不能直接持久化成普通授予。包含见证绑定当前管理者／目标／上限和候选内容，不是可带到未来批次永久复用的许可；生效节点重验。有限包含算法及分支展开预算仍由下一份规格确定。

## 资源、动作与副作用声明

业务组件版本必须提交完整 `ResourceDefinition`、`OperationDefinition` 和 `FieldDefinition`：稳定引用、权威属性及来源、view_key、动作与输出读取键、字段到列／派生依赖的映射、共享／代理规则、所需资格／责任分离、查询与出口能力、风险／副作用 profile。

| 声明组 | 必须明确 |
| --- | --- |
| 调用模式 | 直接用户、服务代理、系统、固定任务／事件、渠道回调或显式公开；各自证据和方法准入，不凭头是否存在猜模式 |
| 读取与动作 | 通常列表、特殊读取／导出、可执行动作集合分别声明；授权资格、业务可执行、A 与 B 不合并 |
| 字段 | 普通／受限／不可输出秘密、读取／写入键、查询用途与派生依赖；新增未分类字段使声明不合格 |
| 副作用 | 业务写、外部指令／投递、作业／订阅／文件能力创建、管理变更、必要审计／会话／通知分别登记；不能只看 HTTP 动词 |
| 风险与出口 | 有界读取、权威敏感读取、A／严格 B、严格输出屏障分别指定；分页、批量、后台、缓存、下载和冷查询映射到相同保证 |

一个动作可能产生多个副作用，按全部声明检查，不能只取其中最低风险。组件声明设最低保证；部署只能选择满足它的 profile 或明确改变所启用业务，不能用配置将付款改为陈旧读取。新增路由／resolver／任务未登记、采用未知 profile 或存在未覆盖出口时，构建／启动／装配检查失败；运行发现变化则保护受影响能力。

profile 是不可变内容版本加受控实际配置：来源健康、认证／资格、最大窗口、期限、时钟、激活、批次／字节、证明／查询预算、确认与通知、失败／停止行为都绑定版本。限制的方向逐项定义：时效上界更小较严，能力覆盖必须包含所需集合，保证级别按适用操作比较；不能将全部数字机械取 min，也不能从版本号更大推导更强。

第三份 30／5／1／10 秒及第五份 A5 15 分钟仍是待审起始值。本文只确定参数责任和验证形状，不产生默认配置键或客户性能承诺。

## 求值与查询接口

| 候选接口 | 输入 | 返回／执行义务 |
| --- | --- | --- |
| `VerifyRequest` | 入口定义、原凭据／直接服务证明、明确选择意图 | 受信上下文或验证失败；没有系统兜底主体 |
| `ResolveFacts` | 认证调用方、所需对象／属性／资格声明、用途／水位／期限 | 完整合格证据，或逐项未知／不可得；不能泄漏未获准属性 |
| `EvaluateObject` | 已验证 C、操作／资源定义、权威旧或候选事实、必要安全视图 | 允许／明确拒绝／无法证明、逐记录字段与依据／终点；这是资格决定，不是 A 许可 |
| `PlanAuthorizedQuery` | 明确列表用途、筛选／排序／字段／聚合、C、定义、数据视图／必要水位及预算 | 有完整集合证明的有限计划，或不可完成；不返回可拼接的原始 SQL |
| `ExecuteAuthorizedQuery` | 合格计划、属主数据访问适配、当前必要证据 | 全部分支授权及去重后统一分页／聚合，逐记录字段映射、内容兼容与出口截止检查 |
| `EvaluateBusinessAction` | 授权资格结果、任务／单据／业务规则及修订 | 可执行／明确业务拒绝／未知；属主实际提交仍重验必需控制 |

接口可以是本地 runtime 入口或认证 RPC，位置不改变语义。`ResolveFacts` 是每个来源的受限适配操作，不新增可任意读全组件数据库的中央属性查询服务。普通服务内部计算与用户输出的权限用途分别校验。

查询计划至少绑定类型、列表用途／操作、完整段或等价候选证明、字段可用性、筛选／排序／聚合、数据视图、C 的安全身份与模式、模型／定义、必要水位、期限和预算。SQL 编译由受信数据适配完成，参数化并执行第一份的完整集合契约；图结果截断／缺页、未知分支或冷热层缺覆盖不能冒充完整计划。

计划和游标是受保护执行状态，不是客户端可编辑的策略。可以采用服务端引用或完整性保护载体，不能因此免除当前资格、内容和截止重验。来源或模型改变后，无法证明安全集合兼容就重新查询；返回新安全上下文，不能伪称原快照的继续页。响应可以包含逐行动作未知，但不能将只证明一部分的动作集合标成完整。

字段输出由唯一受控映射执行。合法业务 null 与授权掩码分别通过值和声明的掩码元数据表达；字段未登记、不能求值或出口漏映射不是可以随便置 null 的已通过。批量按业务定义的整批／逐项边界返回每项结果，不拿总体成功隐藏未知项。

## 接受、提交、变更与输出接口

| 候选接口／记录 | 权威与输入 | 返回与限制 |
| --- | --- | --- |
| `PrepareIntent`／`IntentRef` | 业务属主；真实身份／模式、动作唯一键、内容／资源修订、关键摘要和业务定义 | 持久不可执行 P 及受控证明；准备不产生可执行事件 |
| `AcceptIntent`／`AcceptancePermit` | Authz；认证属主、P 证明、当前身份／来源及兼容水位 | 持久 A 的限定许可、风险档与激活终点；与适用收紧同域裁决，同键不同绑定拒绝 |
| `ActivateIntent`／`BusinessReceipt` | 业务属主；许可、P、当前业务事实／守卫 | 本地原子消费并提交 B／Outbox，或明确未提交终态／待查询；不在事务内等远程裁决 |
| `ReadProcessResult`／`ReportBusinessResult` | 分别从 A／B 属主认证查询／关联 | 接受与业务终态各自证明；请求超时不证明未执行，不换键续期 |
| `BeginSecurityChange`／`SecurityChangeRef` | 合格管理路径与安全权威；精确目标、收紧／放宽意图、事实／依赖域及所需保证 | 收紧先持久关闭新接受，放宽先验证已提交事实；返回处理阶段，不把受理当完成 |
| `CommitSourceChange`／`SourceChangeReceipt` | 对应资格／资源属主；变更引用、预期修订和经校验新事实 | 自己的事实提交／状态证明；不自动重新打开安全域 |
| `ReconcileSecurityChange` | 安全权威；完整属主回执／回读及视图、影响闭包 | 确认变化已完整处理或继续关闭；不能以超时自动开放 |
| `RegisterParticipants`／`InstallCommitBarrier` | Authz 管理登记，写属主安装本地守卫 | 绑定撤销代次、范围及完整参与集合版本；只有全部合格持久回执才报告 R_commit |
| `RegisterContentPublication` | 业务属主准备修订／内容意图，安全权威核对因果顺序 | 必要安全下界及限定发布证明；物理提交点更严的需求另用资源发布屏障 |
| `AdmitOutput`／`OutputEvidence` | 声明出口；合格读取／敏感准入证据和具体内容／字段 | 最小 cutoff、批次／字节预算及当前输出依据；严格停止另要输出屏障和完整回执 |

这些是逻辑接口，不要求每个接口成为一个服务或一次独立 RPC。安全与业务确由同一属主拥有时，承接第三／第四份的同事务 A／B 路线，意图绑定和接受／业务记录仍可核对；不强制另建跨库 P／A 流程。分属不同权威时执行表中准备／接受／激活协议，不能因为同外壳或共数据库就取消边界。

许可携带部署、目标属主／接口、动作键、真实／被代表主体与履职／委托依据、P／内容／资源绑定、模型／profile、安全依赖、恢复代次、A 引用／时刻和激活终点；严格 B 再绑定适用本地提交守卫代次。普通撤权推进安全修订，不自动改变恢复代次或取消合法在先 A。

四类值保持独立：权威／恢复代次、安全修订与依赖水位、属主提交守卫代次、内容修订。普通重启、撤销、恢复、内容更新各自按第三份变更，不用一个 `version` 代替。跨 provider 的水位只有声明过的转换／兼容关系，不以整数大小判新旧。

准备、接受、业务结果、收紧、参与者和通知各有持久身份／幂等域；每个域明确目标和内容绑定，不能把 HTTP request_id 当所有业务的唯一键。结果查询、清理墓碑、在途对账和外部事实继续由时间／业务协议约束，本文不新增“过期即失败”状态。

## 能力声明与准入

`CapabilityDescriptor` 至少列精确提供方／制品／契约、共同语义与 schema、每项能力版本、支持资源／操作／来源／入口／出口、表达原语、完整性与时间保证、所需属主／SDK／平台适配、profile 与预算上限，以及对应证据状态。表内名称只是本稿分类，正式命名和登记仍待确认。

| 类别 | 所需能力与依赖 | 缺少时的行为 |
| --- | --- | --- |
| 共同核心 | 类型化身份／事实、完整段与字段绑定、三态决定、定义／版本校验、时间／内容兼容及保护错误 | 不能作为本项目新安全契约的合格成员；只返回 bool 不算精简实现 |
| 受保护用户读取 | 共同核心 + 声明范围的有界证据／唯一字段映射／出口 cutoff | 不开放该读取；无可信期限不降为无限静态 |
| 完整列表／统计 | 共同核心 + 对应列表用途的完整查询／字段用途证明 + 全数据层适配 | 单对象可以独立合格，列表能力不伪装已支持；不能静默删未知分支 |
| 关键业务写入 | 完整当前资格 + 持久 A／P 证明 + 属主限定 B／幂等／业务守卫 | 阻止该写业务启用，不改成普通 Check 后写库 |
| 授权管理／授出共享 | 当前管理／完整包含 + 同属主 A／B 或等价严格管理屏障 + 变更闭包 | 没有编辑入口并不免除部署配置／导入变更的合格生效路径 |
| 任职／人员级职责分离 | 当前任职／受控责任绑定、任务／单据规则及提交检查 | 没有真实关联不能把未知账号当不同人员 |
| 团队／层级／关系图 | 明确来源、完整路径／候选集合、修订／收紧及有限深度／预算 | 不启用该继承路径；只支持直接授予也须符合共同语义 |
| 个人委托／有限再委托 | 当前个人来源 ∩ 创建上限、真实执行资格、链及声明 profile | 基础委托可只声明单层；再委托另需逐边完整证明，不从 token act 推导支持 |
| 只读扮演 | 真实／目标身份隔离、只读副作用清单、当前目标读取、短会话／通知落点 | 缺任一必要能力不启用生产扮演，不借 superuser 补齐 |
| 敏感读取／导出 | 权威准入、内容／字段绑定、后台及领取重验、有限输出 | 页面读取不自动赋予导出，旧文件／URL 不自动兼容 |
| 严格 B／严格输出停止 | 持久守卫、完整写者／出口登记、隔离与回执／恢复 | 只能声明已具备的 A 或有界出口保证，不能满足要求更严的业务 |
| agent／匿名外链 | 独立受信身份／有限授予／目的／确认及出口契约 | 当前仍预留，不在基础能力集里默认为可用 |

准入匹配具体业务、资源、动作、来源与出口，而非几项 bool 的交集。例如 provider 支持图 Check、SDK 支持 SQL 列表，不证明“图授权的库存完整列表”有合格实现；必须存在覆盖该组合的计划／数据适配路径。深度、集合规模、租约、时钟和查询预算都校验；超预算可拒绝／改为明确有界异步流程，不自动减弱安全语义。

声明已支持、实现已存在、某版本某环境验收通过分别记录。运行时能力信息来自认证目标和受控配置／制品对照，不信任任意返回的“全支持”；能力描述不是当前用户许可。安装时、配置变更、功能启用、成员／模型切换均检验全部闭包；实例启动校验自身版本／适配，运行时仍验证证据健康。滚动升级期间只路由到已证明合格的实例，不能随机打到旧能力实例后兜底。

## 实现路线的适配矩阵

下表是必须设计／验收的适配义务，不是现有成员能力测评或产品推荐。

| 路线 | 怎样承接共同语义 | 不能假定自带的能力 |
| --- | --- | --- |
| 标准角色／范围成员 | 完整段／字段、当前资格、有限查询；接入共同管理／接受／收紧与属主适配 | 当前旧维度并集和字段接口不证明新完整段已满足 |
| 静态／精简成员 | 受控不可变规则快照 + 当前身份／资格和有界视图；配置变更走合格确认／收紧 | 静态文件不等于身份不撤销；需要写入／管理时仍须合格接受／管理能力，不能用热重载绕过 |
| 关系图成员 | 有权威关系源、完整候选／路径证明；金额／字段／责任通过受控共同适配 | 单对象 Check 不证明完整列表、字段、管理包含或跨库提交保证 |
| 策略引擎成员 | 只接入声明过的有限子集或等价完整查询证明；控制模型版本与事实来源 | 任意策略不能自动下推 SQL 或证明包含，也不自带 P／A／B 与输出停止 |
| 平台身份／更大部署 | 工作负载证实、分域裁决、隔离、预算与监控按能力接入 | mesh／Kubernetes、多副本及更快轮询不自动证明当前业务资格和严格撤销 |

精简部署可使用一个持久裁决域、有限基础查询和单层委托；复杂关系、分域、高并发或更强停止按实际业务／尾延迟／锁等待／来源滞后触发。默认安全核心一致，增加组件与调整配置只适用于已经实现并验证过的适配路径。新需求超出能力或预算时，先增规范／适配／验收，再推荐客户启用。

## 结果、错误与信息边界

| 结果类别 | 内部语义与对外义务 |
| --- | --- |
| 已证明允许 | 精确对象／操作／字段／模式与终点，仍不代表业务可执行或 A／B 已完成 |
| 已证明拒绝 | 当前完整事实不匹配、必要资格不存在或必需控制明确禁止；对外遵守存在性保护 |
| 无法证明 | 来源不可得、超期／不完整、预算耗尽、修订不相容或闭包未知；不能返回假空列表或说无数据 |
| 契约／能力不相容 | 构建／启动／启用阻止，运行保护受影响路径；没有自动旧版 fallback |
| 请求／幂等／修订冲突 | 不产生新接受或业务事实，返回声明的重查／纠正方式，不自动换键 |
| 处理结果未知／处理中 | A／B／撤销有持久引用可查，查询本身也认证；未知不当失败或完整成功 |

这些是候选内部分类，不在正文临时创造生产 reason。正式错误目录须映射 HTTP／gRPC／GraphQL、重试资格、状态查询、可显示信息及审计；未知错误按保护映射，不能默认允许。不可见对象按现行存在性保护处理，内部诊断不把金额、负责人、角色内容或完整证明暴露给无权调用者。

trace／日志只记录必要稳定引用、版本、类别与结果，不记录可重放 token、许可载体、私钥和未授权属性。可靠通知意图、站内可见落点、外部投递、必需审计应用保存回执分别关联；普通请求成功或 broker ACK 不证明后两项已完成。字段列表不等于 I29 的审计可靠性方案已解决。

## 版本、旧数据与切换准入

schema 可解析、模型语义等价、能力满足、当前事实／历史与在途状态可承接是四道不同检查。安全字段的“新增可选”只有旧读者忽略后仍保持原承诺才算兼容；新的限制／来源类型／操作符须在语义／required 能力中识别，旧读者不支持时拒绝该对象或对应功能，不能忽略限制继续放行。

| 面／对象 | 已知变化 | 准入／退出条件 |
| --- | --- | --- |
| 授权族 authz/2／旧字段与范围接口 | 维度并集、全类型掩码、subjects／ExtraIDs 不等于完整段／来源 | 新语义版本或明确实验重建；先形成逐字段映射、消费者表和旧路径关闭计划，不原地改含义 |
| IAM／P5 | 旧 roles／dept_path、服务与用户类别、身份链接含义 | 新入口互斥验证及受控稳定身份映射；I14 修复与真实验证仍是门槛 |
| P6／P7／P8 与 SDK | 无界旧视图、系统标签、List(K)／Can、逐记录字段、接受／输出 | 明确新旧模式、契约与全部数据出口；旧消费者不能承载新保证 |
| 客户角色／任职／共享／委托 | 源类型、资格实例、创建上限／字段、治理与旧历史 | 来源不明列为待复核／受保护对象，不擅自全部扩权或永久删除；经客户确认迁移 |
| 接受记录／水位／守卫 | 在途 A／B、关闭域、参与集合、恢复代次 | 兼容限定消费或可靠终止／对账，隔离旧写者；不能重新签发为新宽许可 |
| 查询／游标／缓存／文件 | 不同集合语义、字段、身份模式及内容关联 | 明确失效／受限读取或重建；旧游标不延长资格，已提交／已交付事实不伪造回滚 |
| 滚动发布／客户 Fork／外壳 | 新旧代码可能真实同时执行 | 逐入口／证据／语义／数据／适配核对精确版本；不能仅用“在同一进程编译通过”证明网络及持久记录兼容 |

现行 [0302](../../docs/en/02-decisions/03-contracts-and-data/0302-contracts-are-additive-only.md) 要求破坏性变更采用并行新主契约，实验重建须满足其明确例外；用户继续设计未批准选哪条迁移执行路线。本页不新设正式 authz/3 或 SDK 版本。

protobuf 二进制的可解析性不能直接推导 JSON／业务兼容；ProtoJSON 不具有相同未知字段处理保证，必须分别测试。缺失／null／未知枚举、网关转换、日志／重序列化还要核对是否丢失限制或证据。安全关键扩展要求语义识别后才能使用；只有声明为不影响安全含义的元数据可以按相应版本规则忽略。[Protobuf 线兼容说明](https://protobuf.dev/programming-guides/proto3/#updating)，[ProtoJSON 演进说明](https://protobuf.dev/programming-guides/json/#protojson-wire-safety)

候选切换顺序：清点真实消费者／客户定制和持久对象 → 形成可验证新契约与转换 → 隔离验证 → 准备兼容部署／关闭旧不合格入口 → 处理在途许可、事实与当前安全状态 → 准入新路径 → 核对退出与回退边界。可否同时运行、谁承担写权、截止期限和故障回退逐组合制定；不默认复制旧快照回滚就安全，也不在本轮部署客户环境。

## 独立预期与后续出口

以下 SC 场景只检查共同契约边界的预期，未运行 schema、SDK 或实际路径；与 AE／TI／AT／AM／SD／PA 合并映射，避免生成重复实现镜像测试。

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| SC01 | 客户端提交 verified／系统模式／另一个 owner | 不构造可信上下文或属主证据；合法验证入口正例保留 |
| SC02 | 空列表／缺省／未知枚举／null／数字零 | 明确空和未知分开，无默认全集／允许；必要输入缺失保护 |
| SC03 | 相同 ID 属于不同部署／类型，组件升级或个人改邮箱 | 不串对象／主体，稳定身份与类型／域保持 |
| SC04 | 修订 100 来自图 provider，99 来自 IAM；普通撤权 | 不跨域比大小，不用普通安全修订改恢复代次取消合法在先 A |
| SC05 | 两份段的法人／仓库／额度／字段分别取最宽 | 不能产生第三份错配段；原完整配对的正例成立 |
| SC06 | 授予机构来源被写成个人，或技术 act 被写成链 | 不猜失效／委托语义，来源和有效链均验证 |
| SC07 | 旧 protobuf／JSON 客户端忽略新限制、未知操作符 | 不因可解析继续放行，新语义／能力不合格拒绝 |
| SC08 | 同 issuer 的用户 token／读取证据／A 许可互换 | 各验证 profile 互斥；用途／受众／绑定不符拒绝 |
| SC09 | 旧 FactEvidence 重新签当前时间或返回 304 | 没有权威完整核验不续期，内容与水位不相容保护 |
| SC10 | 全类型字段掩码代替逐记录／动作映射，字段新增未分类 | 不扩大字段，声明不合格；业务 null 与掩码可区分 |
| SC11 | 图 Check 支持 + SQL 列表支持，但组合没有完整路径 | 装配不能启用该完整列表；合法单对象另验 |
| SC12 | 计划／游标被改、未知分支删掉、先分页再筛权 | 不能冒充完整集合；计划完整性、当前证据和全分支义务生效 |
| SC13 | 同动作键不同内容、超时后换键重试、旧 A 重签扩大 | 冲突／查询恢复，许可不续期、不重复接受或扩大 |
| SC14 | Check 的 allow 被当 A，或 A 被当库存／财务已提交 | 各状态／回执独立，只有合格 B 才产生其业务事实 |
| SC15 | 管理／共享批次复用旧包含见证，管理者已失资格 | 每个生效点保护重验，不借普通 A 在先保证发布宽授权 |
| SC16 | 一个副本回执宣称所有分库／出口屏障已安装 | 缺完整参与与持久隔离证据不报告严格完成 |
| SC17 | 未登记 GET 副作用／后台出口，扮演会话调用 | 声明／路由不合格，运行按副作用拒绝，不按 HTTP 只读猜测 |
| SC18 | profile 只改版本或缩短轮询，宣称严格 B／输出停止 | 保证与完整适配分别验，不以数字更小代替屏障能力 |
| SC19 | 静态配置热重载扩大许可，或来源故障退回旧角色 claims | 无合格确认／生效协议不开放，不降级绕过当前资格 |
| SC20 | 滚动升级随机路由到旧模式实例，Fork 没实现新字段 | 目标版本／实际适配不合格不准入；无旧版自动 fallback |
| SC21 | 跨语言／编译版本直接 hash protobuf 当同内容证明 | 按版本化无歧义编码核对，未定义编码不宣称摘要兼容 |
| SC22 | 通知投递 ACK 当站内已通知，审计 broker ACK 当永久保存 | 各落点和状态分开，缺必需保证保护；不标 I29 闭环 |
| SC23 | 保留旧备份／旧许可，在切换或回退后重新启用 | 先隔离和核对当前安全／在途事实，不复活旧授权 |
| SC24 | 只跑某些能力／某语言或假 provider 自报全支持 | 证据范围如实标部分，空／跳过不算合格；声明与实际对照 |

本页形成共同语义结构、接口责任与准入矩阵；仍缺逐字段正式编码、有限算法／预算、完整状态机／DDL、各动作 profile、签发／回读机制、精确版本转换和真实合规证据。C06–C11／C16／C30／C36 与 I18／I19／I28 仍未闭环。
