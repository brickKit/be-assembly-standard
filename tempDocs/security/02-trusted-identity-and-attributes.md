# 可信身份、调用链与属性来源

> 状态：2026-10-13 第二份安全候选规格，尚未冻结。承接用户确认的推进顺序，补充授权上下文的输入边界；不修改 IAM／Authz 族契约、SDK、部署或现行组件。

## 目的与适用边界

本页为[统一授权求值](01-authorization-evaluation.md)提供可信上下文，不另定义权限组合公式。默认按小公司落地，较复杂客户可改用工作负载身份、受众更窄的令牌交换和专用观测；共同的身份与属性保证不随部署精简而取消。规模前提已答，不再询问统一容量数字。

需要证明的结果：用户不能自报角色、任职或服务名来扩权；服务凭据不能替用户取得更宽数据；跨组件、事件、后台任务和外壳均保留正确责任主体；IAM 或授权实现替换后，主体与属性含义仍可对齐。

本页提出身份结构、来源和校验行为。接受／撤权的线性先后、失效窗口、长连接的紧急停止及持久业务许可另由下一份时间协议收敛，不能因验签通过就宣称提交时仍合法。

## 凭据路线与推荐

| 路线 | 适用条件 | 代价与边界 |
| --- | --- | --- |
| 推荐基础路线：每部署独立信任根，组件使用有期限的 mTLS 证书；受控签发、文件交付和轮换 | 单机／少量主机、离线机房，尚无现成工作负载身份服务 | 不强制增加常驻身份组件；要有签发、续期、热加载、到期告警和恢复工具，不接受永久证书或共用全权私钥 |
| 平台证实与自动签发：SPIFFE／SPIRE、合格 service mesh 或平台身份适配 | 动态实例较多、跨主机／集群、运维已有平台，人工续期成本过高 | 多一个信任与可用性依赖；须将平台身份精确映射到部署和组件，不能只验证“同一 CA／集群” |
| 专用短期服务令牌，经已认证且加密的通道传递 | 平台提供令牌证实，或目标协议无法使用双向证书 | 受众、用途、持有者和重放风险须明确；不能复用用户 access 验证器，也不能悄悄退回共享 API Key |

第一条是本项目候选基础实现，不是批准自研密码协议或指定新组件。平台原生机制满足保证时优先复用；仅 Kubernetes 默认 service account token、IP 或容器网络地址不构成合格适配。证书校验交给成熟 TLS 库，令牌校验交给成熟 JOSE 库和共同验证入口。

服务证书证明调用方身份；目标组件／接口／操作的允许关系在服务端独立检查。客户端也校验目标身份，不能只检查服务器证书来自同一根。采用服务令牌时还校验目标受众，接受者不能以调用方自报的地址决定自己是谁。具体身份 URI、证书 profile、令牌类型和配置键在线协议阶段登记，不在本稿分配生产 ID。

## 权威分工与属性登记

| 信息 | 权威属主 | 接受规则 |
| --- | --- | --- |
| 部署信任域、获准运行的组件、服务身份到组件映射 | 部署管理者及受控签发／平台证实机制 | 装配声明的是意图；运行时须验证凭据，组件不能用自己的配置自行申请任意身份 |
| 平台账号、外部身份链接、账号启停、会话与认证证据 | 选定 IAM 入口 | 登录产品适配成共同语义；多个外部身份源不能在业务组件各建一份主体权威 |
| 法人、部门、岗位、汇报关系 | 业务组织组件，承接 D05 | IdP／SCIM 的组只是来源数据，经明确映射才成为业务组织事实 |
| 员工、在职状态、有效任职 | 基础员工／任职组件，承接 D06 | 不由 IAM 角色名或用户选择的部门替代；未安装的能力不能伪造为“全部有效” |
| 账号与员工／责任身份的关联 | 员工组件拥有关联（账号身份由 IAM 提供，替换 IAM 成员时关联不随之迁移）；建立与变更的确认记录由 Authz 的受保护操作保存（第八份） | 绑定变更受专门管理权限和审核约束，保存两侧身份及修订；不靠姓名／工号字符串自动认人 |
| 完整授予、管理上限、委托与共享的授权视图 | 授权属主及声明的业务关系属主 | Authz 可保存受控投影或求值视图，不接管员工／组织权威 |
| 对象归属、金额、币种、状态、修订、审批和执行依据 | 对应业务组件 | 从本地权威事实或有完整性证据的属主视图取得，命令输入先经业务校验 |
| 登录因素、真实认证时刻、客户端、设备证据 | IAM 或明确受信的认证适配 | 换令牌／刷新不是重新认证；用户填写 `mfa=true` 无效 |

每个用于授权的属性须登记类型、来源、修改权限、修订域、有效期／允许陈旧程度、缺失行为和可用路径。显示名、语言及普通追踪标签不自动成为安全属性。基础员工组件不扩张为所有联系人的通用自然人库；非员工账号仍可存在，其资格由明确的授予与业务契约提供。

## 稳定主体与身份链接

业务只引用部署内稳定的平台主体标识；姓名、邮箱、登录名和组件版本都不是主体身份。主体不复用，服务逻辑身份与运行实例身份分开：多副本可代表同一组件，但使用可分别轮换／追踪的实例凭据。版本升级不自动变成另一业务主体，权限能力升级仍经版本准入。

外部账号默认以受信身份源下的 `(issuer, subject)` 精确关联；身份源允许的客户端及 issuer 配置先受管理校验，不能从未验证的 token URL 拉取任意密钥。首次开通可创建无业务授予的普通账号，是否允许自动开通由客户配置；自动开通不自动授出员工、任职或管理员资格。

绑定已有账号、SCIM 到 OIDC 的关联、合并与身份源迁移，使用预登记且唯一的映射或显式确认流程。不把“邮箱已验证／登录名相同”当作无条件账号接管证据，也不因 IdP 的 subject 碰巧相同就跨 issuer 合并。改邮箱／登录名不改主体；解除链接、停用、删除与恢复分别处理。删除保留必要的不可复用标识和受保护历史引用，具体擦除／保全由生命周期协议定义，不能直接清空既有业务审计。

初始管理员使用限定受信身份源和精确身份的预登记，或有期限、一次性的离线部署确认；绑定与已消耗状态持久化并发唯一。仅凭公开邮箱或不区分大小写的名字抢先登录不能成为管理员。常规管理不重新使用 bootstrap；紧急恢复另走有记录的部署恢复流程，不开放绕过全部认证的接口。

IAM 更换成员保留平台主体和已审核关联，旧服务／用户密钥的验证接受范围显式切换。相同稳定 issuer 并不使旧令牌即时消失，公钥缓存、会话与旧实例必须一起纳入时间和迁移协议。

## 一个请求中的身份结构

以下是行为字段，不是已冻结的 JSON／proto 形状。

| 字段组 | 含义 |
| --- | --- |
| 部署与凭据用途 | 所属部署、受众、用户／服务／回调等已验证凭据类别、凭据和校验策略版本 |
| 直接调用服务 | 已验证对端组件、实例、凭据身份；直接浏览器／移动端请求没有内部服务身份，不能自填一个 |
| 实际操作者 | 正常请求的用户，或合法委托／扮演链中的实际行事方；完整链留作审计 |
| 被代表主体 | 正常请求与实际用户一致；合法代办时明确目标主体，不能由请求体覆盖 |
| 履职与上限 | 经验证的选定任职、有效委托身份／链、操作范围及字段上限，不等同于客户端可选参数 |
| 认证与安全状态证据 | 凭据有效期、真实认证时刻／因素、会话或安全修订、所需新鲜度及证据来源 |
| 资源与资格事实 | 按本页来源规则取得的事实与各自修订，供第一份求值规格消费 |
| 原始发起与业务依据 | 后台流程的原发起人、任务／业务接受引用；历史发起信息不冒充当前用户授权 |

同一上下文中的实际操作者、被代表主体、直接服务和历史发起人不能塞进同一个 `sub` 然后按场景猜。上下文只由 SDK 受信验证入口和受限作业启动器构造，业务代码显式传递；客户端 JSON 中的 `verified=true`、`actor` 或“系统模式”字段不是验证结果。

本地并发任务继承已验证请求上下文及取消／截止时间；长任务另建明确任务类型。上下文不得存在进程级“当前用户”或连接建立时捕获的用户槽；复用连接的每个请求分别构造，防止用户甲的身份被用户乙复用。

## 入口与调用模式

每个入口声明唯一的业务调用模式及可接受凭据 profile。公开入口也显式声明边界，业务认证与服务认证不能通过“有没有某个头”动态猜测。同一业务 handler 同时服务直接用户和内部代理时，使用明确分开的入口，或由受信监听／入口配置选择验证 profile；缺服务证据的代理不能改走同一入口的直接用户分支绕过方法许可。

| 模式 | 必需证明 | 放行后仍需检查 |
| --- | --- | --- |
| 直接用户入口 | 合格会话／平台用户访问凭据 | 当前账号与资格、完整授权、资源及业务约束 |
| 服务代理用户读取／命令 | 已认证服务和允许代理路径；原用户凭据或受信交换凭据 | 被代表主体的授权和上限；服务权限不能替代用户范围 |
| 系统查询／系统命令 | 已认证服务、目标方法许可及规定资源范围 | 系统契约的输入、业务状态、来源／接受依据和幂等，不因处于内网就免查 |
| 事件处理／固定维护任务 | 受限消费者／作业身份及类型，事件或任务来源合格 | 属主事实、当前必需控制及允许副作用 |
| 外部回调／开放 API | 对应渠道／外部应用的专用认证 | 部署、商户／对象映射、重放与幂等、业务核对；不是普通员工身份 |
| 明确公开接口 | 声明的公开用途，所需流量／输入保护 | 不返回受保护业务数据，不在凭据无效时自动退成更宽的匿名路径 |

服务端先验证凭据及部署／用途，再检查服务到目标方法的许可，然后在相应业务模式执行第一份求值规格或系统契约。用户凭据不适用于系统方法；服务凭据不适用于普通用户数据接口。缺用户证据的代理请求拒绝，不降级为系统调用；声称是系统任务的用户输入同样拒绝。

`be-caller` 至多是与验证结果核对的标签，不能创建服务身份；若保留该标签却与凭据映射不同，拒绝并记录安全事件。`be-actor-*`、trace、baggage、来源 IP 和反向代理头只提供声明或追踪，不能直接成为用户或授权属性。用户代理入口如保留当前 actor 标签，必须与受信用户证据相容；历史发起人用独立历史字段，不与当前操作者混用。

## 用户链路、系统命令与委托

基础路线允许在同一部署的已批准用户面调用中，经加密且目标已认证的链路转发原平台访问凭据；下游重新验证其部署、用途、时效与当前所需安全状态。凭据只留在请求的私有槽，不写日志、不进消息、不发第三方、不从任意 URL 选择下游。部署受众意味着允许在声明的部署内用户面使用，并非允许调用所有系统方法；重定向不得把凭据带出受信目标集合。

当客户需要进一步限制泄漏影响或跨信任边界时，使用受信交换入口签发目标／用途更窄的凭据。交换检查服务资格、原凭据、被代表主体与委托边界；不能由每个业务服务随意签“我是用户甲”。扩大受众、延长原证据期限、增加字段或动作权限均不由普通转发产生。交换成功也不证明业务动作已接受。

普通技术转发不改变业务责任，不自动变成代办。真实代办／扮演有专门授予、期限和上限，保留实际操作者与被代表主体；委托管理与链上撤销见[第五份候选](05-sharing-delegation-and-impersonation.md)与[第八份候选](08-state-and-change-protocol.md)。RFC 的 `act` 嵌套提供历史身份表达，不自动证明嵌套中每个人此刻都有资格，也不自动构成本项目的上限求值规则。

销售确认后向库存发起预占等系统命令，按跨组件业务契约取得受限调用资格；不要求用户凭空拥有每个下游系统权限键，也不允许仅带服务身份就跳过销售确认资格。上游校验责任、命令来源、单据修订和接受证据要在命令契约明确，下游检查自己拥有的业务控制。仅带历史 actor 名字不能充当接受证据；接受点和证据的持久语义由下一专题定义。

按 ID 补全不是授权例外。调用方已有 ID 不证明用户能看补全字段；系统 BatchGet 可为合法业务内部计算服务，但用户响应必须按已声明的用户读取契约和字段许可裁剪，不能用系统全量结果绕过普通读取或导出。

## 任职选择、责任主体与本人自审

客户端可以请求选用某个任职，服务端须验证它确实关联当前主体、在时间窗内有效、指向合法法人／组织／岗位，并与本动作的授予绑定相容。不能用用户名、部门路径或一个任职 ID 单独认定资格。没有选择任职的普通读取按第一份规格逐份求值，不能临时指定“最大权限的任职”。

员工和账号允许非一一对应。启用按人员责任防本人自审的流程，单据记录真实发起账号与经验证的责任主体／履职身份，审核检查实际行事方、被代表方及适用责任绑定；两个账号关联同一员工时不能被当作两个独立审批人。关联不能从姓名、邮箱或客户端填写的员工号推导。

普通无代办的单账号流程至少比较稳定发起主体；需要覆盖多账号／代办责任的流程须声明相应关联能力，无法证明责任分离时暂停或拒绝该审核，不能把未知关联当作“不同人”。本设计不宣称识别所有未登记的同一自然人；客户确需人员级分离，须完成受控绑定和业务范围准入。该保护不要求另建通用自然人组件，具体责任规则由审批契约承接 D10。

## 属性取证、修订与故障

签名证明声明由谁签发，不证明其业务内容永远正确或仍有效。新授权上下文不以登录时的 `roles`／`dept_path` 快照授予当前业务资格；权限从完整授予视图取得，组织／任职按权威来源和所需新鲜度提供。令牌只携带身份，不携带角色、部门等授权属性；属性服务不可用时，不能退回任何令牌内容放行。

资源 owner、法人、金额与当前状态从业务属主读取；新建／修改的候选输入经业务规则得到候选事实，不能用输入覆盖权威旧事实。涉及单位、汇率、组织路径及派生属性时，记录语义版本及必要来源，不能只给一个无单位数值。

普通读取可使用声明过的有界投影；关键动作要求协议规定的权威或兼容水位证据。账号状态、任职、组织树、授权、资源事实有各自版本，不比较不同聚合的裸数字，也不以 `updated_at` 大或“当前时间已同步”证明全部变化已应用。属性视图须有完整快照／增量恢复机制；本页引用 I30 的修复要求，不另复制投影协议。

必要属性未取得、过期、来源不可信或水位不相容时，无法决策并按规定保护；明确空集合和已知无任职是不同状态。装配时无所需能力，阻止功能启用；运行时无法取证，不返回伪装的空结果，不临时扩大权限。

用户账号停用、员工离职、某个任职失效和服务凭据失效是不同事件。一个任职结束撤销其绑定资格，其他合法兼任及独立直接授予按各自规则处理；是否同时停用账号由声明的身份生命周期政策确定，不由任意消费者猜。安全事件可要求更广冻结，但有明确权威与审计。具体传播、窗口和接受竞争留到时间协议。

## 事件、后台任务与外部来源

| 路径 | 候选保护规则 |
| --- | --- |
| 事件发布 | 每部署隔离 broker 身份／命名空间；组件仅能发布声明拥有的主题、订阅获准主题，不能共用全权发布账户 |
| 事件消费 | 对主题、来源成员、契约、聚合与版本作校验；`ce-source`／actor 不能独立证明来源。依赖受信 broker 和排他的发布权限映射时须记录该信任前提 |
| 重放／死信／中继 | 有独立受限工具身份、允许主题／对象和操作记录；保留原来源与重放来源，不能用宽泛通配发布权伪造原业务事实 |
| 用户查询／导出任务 | 持久化发起主体、合法代办引用与筛选意图，不保存可重放的用户 token；执行及交付按当前有效用户资格取证，结果文件同样受领取权限控制 |
| 已接受业务的后续任务 | 保留业务接受引用、限定资源／修订与原发起信息；消费者用当前受限服务资格执行，不因发起人离职删除已发生事实，不将新范围当成原许可 |
| 固定系统维护 | 由受限作业入口按类型构造服务上下文；预算、对象域、允许副作用和停止规则声明，用户不能提交任意 SQL／对象范围启动系统任务 |
| 渠道回调 | 按渠道协议验证签名／凭据、目标部署、商户、时间／重放与原始内容；核对交易／单据身份和状态，回调中的用户名不是员工授权 |

broker ACL 不校验任意消息头，也不证明发布者执行过正确业务规则。选用主题到唯一获准业务发布者的映射时，消费者仍核对 payload 来源与该映射一致；维护工具的例外明确登记。跨不受信中继需要额外来源证明或属主回读，不能直接继承这一信任。具体事件来源证明与重放许可应与消息协议共同收敛。

基础资源允许清单的编译须验证实际拒绝行为：缺配置或空清单不能被 broker 解释为无限权限。NATS 的空允许清单有此风险，应生成明确禁止对应操作的配置并验收；这属于基础设施限制，不是增加管理员可配置的业务 Deny。消费者的读取／ACK 与 stream／consumer 管理许可分别限制，不能用全权 JetStream API 权限绕过数据主题边界。配置语义依据 [NATS 授权说明](https://docs.nats.io/learn/security/authorization)，具体清单仍须在消息适配器中验证。

## 凭据生命周期、部署与外壳

部署初始化在受控管理环境建立信任根和签发权限；根／签发私钥不挂载给全部业务组件。每个组件获得限定身份的凭据、目标信任材料和服务方法许可；开发与测试也各自隔离，不能将生产根或业务凭据复制过去。多客户复用宿主、broker 或存储时，身份和授权空间显式隔离，不能只改一个环境变量。

基础证书路线允许受控工具签发、提前续期与文件轮换；工具不具备证明目标工作负载身份的机制时，登记为部署管理员承担的交付信任边界，不冒充平台自动证实。有效期、提前量、时钟偏差、刷新／缓存上限、已有连接寿命、信任重叠及故障保护组成完整 profile；缺少必要参数不能作为生产合格配置。默认数值在时间协议和代表部署实验中确定，不能用某个旧 SDK 的固定间隔作为安全保证。

常规轮换先分发下一信任材料，再切换签发／使用凭据，最后在声明的接受窗口后退役旧材料。紧急撤销不能等待常规重叠窗口；撤下公钥、停止续发或更新 CA 文件不证明已缓存公钥及已有 mTLS 连接立即失效，须通过下一份撤销协议约束每请求准入与连接处置。

续期失败、信任材料陈旧及时间异常有告警；新请求无法满足 profile 时停止放行，不自动改成明文或共享口令。恢复时核对当前冻结／撤销状态，不能从旧备份重新信任已泄漏私钥。凭据、私钥、完整 token、恢复码和敏感属性不进入日志／trace／指标标签；记录稳定主体、证据标识、版本和结果。

每个外壳成员继续经真实网络、同样的凭据／方法许可调用。成员逻辑身份防误配置和串扰；共同进程内可读其他成员内存／凭据，不能声称隔离恶意成员。需要这种隔离时拆进程并限制各自凭据和基础资源权限，不用 shell 名字统一授出全部成员权限。

## 调用面的设计约束

系统调用走 gRPC 系统面，用户请求走 HTTP 用户面；用户面的服务代理请求另加服务身份验证。以后若要支持用户 gRPC，必须单独声明调用模式与兼容版本，不能因为请求带有用户令牌就开放系统方法。（2026-10-13 按 D59 删除“当前契约的迁移边界”一节，本段保留其中唯一未在正文其他处写明的设计规则。）

## 独立验收预期与下一步

下表为预期设计，尚未执行攻击、SDK、证书或 broker 测试。每条同时安排合法正例、失败前无业务副作用及不泄露凭据的检查。

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| TI01 | 无服务凭据，仅伪造合法 `be-caller` | 系统方法拒绝；同身份的合法凭据正例可进入方法准入 |
| TI02 | 同根下另一个组件证书，或另一部署／测试环境证书 | 不匹配部署／组件／目标方法则拒绝，不因证书签名有效放行 |
| TI03 | 客户端请求打到同根下错误目标；中间人替换服务名 | 客户端验证目标失败，不发送用户凭据 |
| TI04 | 用户 access、IdP ID、refresh、服务令牌互相替换 | 错误用途拒绝；算法、issuer、audience、类型与时效负例分别覆盖 |
| TI05 | 公共入口填内部 actor／任职／verified 字段 | 不构造受信上下文，合法选择仅在权威验证后使用 |
| TI06 | 认证服务在用户路径漏用户凭据，或原用户无字段权限 | 不降级系统模式；服务自身宽权限不扩大用户结果 |
| TI07 | 服务凭据身份与 `be-caller` 不同，actor 名字与用户证据不同 | 拒绝身份冲突；原始未验证 actor 不参与授权 |
| TI08 | 复用 HTTP／gRPC 连接交替请求用户甲／乙，派生并发任务 | 每请求保留各自身份，缺上下文不默认系统主体 |
| TI09 | 选择他人任职、已失效任职、当前任职不相容授权段 | 拒绝相应履职；普通读取仍只汇总自己的合法完整段 |
| TI10 | 登录后调岗；token 仍含旧角色／部门，属性源不可用 | 不借旧 claims 恢复新资格；按声明新鲜度保护，不能假称即时传播 |
| TI11 | 相同邮箱／登录名或相同 subject、不同 issuer | 不自动接管已有平台主体；受控精确映射正例保留身份 |
| TI12 | 两个首次登录并发抢初始管理员，恢复旧 bootstrap 状态 | 只允许合格精确身份的一次绑定；不能重开授予或按名字抢占 |
| TI13 | 两账号绑定同一员工审批；代办人与被代表方涉及申请人 | 按声明责任规则防本人自审；缺必要关联证据不当作不同人 |
| TI14 | 伪造 owner／金额／部门属性，或新授权配旧资源投影 | 不覆盖权威事实；兼容证据不足不放行，合法完整快照正例成立 |
| TI15 | 事件 actor 写管理员，非属主发布主题／伪造来源头，空允许清单 | broker 拒绝越界发布；空清单不扩为无限，来源映射不匹配不产生授权／业务副作用 |
| TI16 | 宽权限重放工具、重复事件、跨不受信中继 | 只执行声明重放许可与幂等动作，不把历史 actor 恢复成当前用户凭据 |
| TI17 | 用户导出排队后被停用，结果文件仍存在 | 执行／领取按当前资格保护，不用消费者服务身份交付 |
| TI18 | 已达业务接受点的后续任务，原发起人离职／单据又冻结 | 不自动删除事实；用当前受限服务资格与业务控制判断，时间细节按下一规格 |
| TI19 | 伪造支付回调、错误商户、重复合法回调 | 认证／映射失败无副作用，合法重复不再次记账，不获得员工权限 |
| TI20 | 到期、续期失败、未知密钥、时钟异常和连接已建立 | 按 profile 停止不可证明的新请求；缓存／长连接撤销预期由时间规格补齐，不只测握手 |
| TI21 | 外壳成员共进程，拆分后使用相同逻辑身份 | 正常模式语义一致；共同进程不能被列作恶意成员隔离通过 |
| TI22 | IAM／证书提供方切换、旧密钥仍被缓存 | 平台主体保留；旧凭据退役按完整迁移／时间协议验证，不宣称地址切换即失效 |

本页补足 I19 的服务身份／属性来源候选，C06／C11／C16／C36 仍未闭环。冻结前须明确线结构、服务方法／属性注册、证书或令牌 profile、责任关联契约、配置／工具，并执行上述向量和真实跨组件路径。

## 依据与独立判断

知识库的认证集成、服务身份、架构主体和 D8／D10 提供中立参考；本项目保留独立组件和真实网络，将本地证书路线作为低部署成本候选，不强制采用知识库的具体身份产品或默认浏览器会话数值。浏览器会话、移动端安全存储与登录防护见[协议 20](../protocols/20-frontend.md#登录与会话)：会话由身份适配组件在服务端持有，边缘按会话缓存其签发的短期令牌并注入请求（D61），不新增独立的 BFF 组件。

JWT 的算法、issuer／受众及不同用途的互斥验证参考 [RFC 8725 §3](https://www.rfc-editor.org/rfc/rfc8725.html#section-3)。交换与实际行事方表达参考 [RFC 8693](https://www.rfc-editor.org/rfc/rfc8693.html)，本项目的多级资格／上限为额外应用语义。工作负载与信任域概念参考 [SPIFFE 官方说明](https://spiffe.io/docs/latest/spiffe-about/spiffe-concepts/)，共同进程不据此宣称身份隔离。[Kubernetes service account 文档](https://kubernetes.io/docs/concepts/security/service-accounts/)用于核对平台凭据及受众路线；[NATS 授权文档](https://docs.nats.io/learn/security/authorization)支持按发布／订阅主题限制权限，消息头与业务证据校验仍由本项目协议承担。
