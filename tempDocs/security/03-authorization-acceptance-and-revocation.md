# 授权接受、撤销与时间保证

> 状态：2026-10-13 第三份安全候选规格，尚未冻结。承接[完整授予求值](01-authorization-evaluation.md)与[可信身份及属性](02-trusted-identity-and-attributes.md)，提出可检验的时间协议；不修改现行契约、SDK 或部署。

## 目标与保证边界

默认小公司、按客户情形选择配置和专项能力的前提保持。本页把“权限当前有效”落实为明确节点、期限与失败行为：普通读取不无限沿用旧策略，关键动作与撤销有可证明的先后，已接受业务的后续不借机扩大范围，要求更严格的客户可以增加提交屏障。

本页给出协议行为和起始实验参数，不将高性能、零延迟或跨系统原子提交当作已实现能力。所有 provider 都遵守第一份完整授予语义；时间能力不足时阻止对应功能启用，不因实现只会返回布尔值而降低保证。

撤销权限、停用账号、任职失效、撤销服务身份、冻结业务、修改内容和撤销已接受业务是不同操作。普通撤权默认阻止其作用域内的新授权接受；取消已接受业务须走业务控制，不能凭删除用户权限回滚已发生库存或会计事实。

## 四个节点与返回含义

| 节点 | 权威与含义 | 不代表什么 |
| --- | --- | --- |
| `P`：意图准备 | 业务属主持久化不可执行的命令意图，绑定主体、动作、内容与资源修订 | 请求到达、草稿或 P 均不构成已获授权，不发业务后续 |
| `A`：授权接受 | 安全接受权威在与适用撤销同一串行裁决域内，验证资格并持久化该意图的限定许可 | 不证明业务事务已经成功，不是普通 Check 的返回时刻 |
| `B`：业务激活／提交 | 业务属主在本地事务核对限定许可、意图、当前业务控制，提交业务事实／过程状态与 Outbox | 不意味着跨组件后续或外部付款已经完成 |
| `R_auth`／`R_commit`：撤销完成 | 前者完成新接受的裁决更新；后者还完成声明范围内各提交属主的屏障 | 接收撤销请求、消息已发布或某一实例刷新不等于全部撤销保证已成立 |

客户端至少能区分未接受、已接受待激活／处理中、业务拒绝／终止、已提交及未知待查询。错误／超时不把未知结果写成未执行；具体线字段和错误键在 schema 阶段登记。本稿标签不是生产状态名。

同一动作有不同法律／业务承诺节点时，由该业务契约定义 B；不能把全 ERP 都等同于一次 SQL 更新。审批决定、单据确认、业务执行分别有自己的动作与依据，审批已提交不自动冻结后续执行者的当前服务资格或必需业务控制。

这些是逻辑节点，按实际权威边界拆分：安全与业务状态确由同一属主拥有、可在同一事务保护时，可以合并 A／B 的持久提交并保留完整绑定与记录；不能因为组件碰巧共库或处于同一外壳就跨属主合并事务。下文准备／接受／激活流程针对分属安全与业务权威的路径。

## 时间能力分档与方案比较

| 档位／路线 | 保证 | 推荐用途与代价 |
| --- | --- | --- |
| 有界读取 | 用有权威新鲜度证据的完整视图，在声明截止时间前释放数据 | 普通低风险读取的基础路线，推送用于加速，失联到期保护 |
| 推荐：按 A 裁决关键动作 | A 与 `R_auth` 串行；撤销在先不能新接受，接受在先可在激活期限内完成限定 B | 小公司也可实现的关键写入路线；需要持久接受记录和恢复，不新增跨组件共享事务 |
| 更严格：按 B 关闭提交 | `R_commit` 完成之后，声明范围内旧许可不能产生新的 B | 额外能力；需各业务属主的本地提交屏障、参与者登记与撤销恢复，故障时可能长期待完成 |
| 单次远程 Check 或短缓存后直接提交 | 只说明检查所用快照上的资格 | 不能单独满足 A／B 档，检查与提交之间仍有间隙 |

基础推荐并非将所有操作降到接受点保证。敏感读取／导出采用权威读取准入和短输出窗口，付款、授权管理、确认／审批等关键动作要求 A 档；客户或业务要求“撤销完成后未提交的旧动作全部禁止”时启用 B 档。具体动作清单由规范和组件声明共同登记，未知动作不默认归低风险。

> 2026-10-13 用户裁定 [D57](../work/02-decisions.md#d57-高风险操作默认用有界本地授权客户可选持久接受)：标准版的高风险操作默认在本地求值，但所用授权视图须在很短有效期内经过权威核验，超期拒绝或暂缓；本节的 A 档改为客户或业务可选的严格能力。上表“推荐”一行与本段关于关键动作“要求 A 档”的表述，在协议冻结工作（D56）中按此改写。

读准入的权威检查同样只保证其准入节点；已在途输出的停止边界另见下文。B 档针对声明的业务提交范围，不自动成为“所有网络字节／外部副作用即时停止”的保证。

## 裁决权威、依赖域与收紧变更

推荐由所选 Authz 成员承担安全接受与失效裁决能力，内部算法／关系 provider 可以替换；不为每个业务组件另建接受权威，不新增名为协调器的必装业务组件。账号、任职、组织和资源仍有自己的事实属主，接受权威保存的是经证明的安全视图与裁决记录。

在一个部署内，基础实现可先用保守的统一安全裁决域。关键接受事务和撤销／安全收紧事务访问同一持久守卫：接受持共享冲突锁至提交，收紧持排他冲突锁，资格视图更新和失效代次一起提交。不能用无锁 SELECT 读版本后另外 INSERT 接受记录；也不能在事务建立旧快照后获取锁，却继续按旧事实判断。锁、隔离和重试须证明实际等价行为，不能仅写“使用事务”。

多个接受可并行持共享守卫，各自按唯一动作键写记录；不要求每次接受都更新全部署热计数器。以后按主体、任职、资源关系、策略等依赖域细分锁与失效代次时，须完整声明依赖集合，固定加锁顺序，保证新规则／新增关系也命中相应守卫，防止漏掉负面查询和幻读。没有证明前继续用保守域，不能只锁一份碰巧匹配的授予就称全局安全。

本系统管理的停用、卸任、范围收紧和访问关系撤销，先由合格管理路径在裁决权威关闭相应新接受，再由事实属主完成业务变更及受控视图更新；中途崩溃保持关闭，恢复后核对状态再完成，不能超时自动重新开放。管理编排承担跨组件流程，主数据属主不因此调用所有消费者。放宽／新增资格反向处理：先取得完整已提交事实，再开放经过确认的授予，不能先开后补。

相关安全属性的所有管理、批量、导入和恢复写入口均执行该协议；属主校验所需收紧／变更依据，不能允许客户端绕过编排直接改停用或任职字段。事实提交后回执／投影丢失时仍保持保护，完整回读与对账后再完成；正向资格也不在等待完整事实期间提前开放。

外部 IdP 已停用、但本系统尚未得知，是另一段延迟：声明来源通知／轮询和对账的实际边界，无法证明就不承诺从外部停用瞬间起零延迟。本系统得知后才进入自己的收紧协议；高风险动作需要的来源健康／新鲜度也检查，不能凭旧的“账号 active”长期接受。用户界面区分请求已受理、已关闭新接受、来源／属主联动待完成和已达到目标保证。

## A 档的准备、接受与激活

1. 业务属主验证输入形状与必要旧／候选事实，创建持久 P，保存明确动作键、调用身份、资源修订、内容摘要、模型／业务规则版本和允许激活终点。P 不能发布可执行事件；相同键不同内容拒绝。
2. 属主在本地事务之外向接受权威申请 A，证明自己的服务身份、当前用户／合法代办证据和 P 的真实性。真实性来自认证属主的受控意图证明或权威回读，不信客户端自报的摘要；验证协议在 schema 阶段选定。权威核对必要安全来源与兼容水位。
3. 权威在守卫保护的同一事务里重验身份状态、完整授予、任职／委托资格、有效期、控制范围和风险要求，持久化唯一 A 及许可。许可期限不得晚于接受时已知的相关资格终点和 P 的激活终点。未提交接受记录前不返回可用许可。
4. 业务属主验证许可出处、用途和全部绑定，在本地事务核对 P 尚未终止、内容／资源修订一致、激活期限仍成立，以及冻结、期间锁、本人自审和适用审批依据等业务控制；原子标记消费许可、提交 B 与 Outbox。任一不满足则不产生 B。
5. 属主可靠回报结果，权威保留接受与最终处置关联；业务后续只从已提交 B 的过程／Outbox 启动。有 A 无 B 时，只能恢复这次限定激活或终止意图，不能借它执行任意系统任务。

资格有效期决定能否进入 B 的初次激活窗口，不给未来新动作续权。B 已合法建立的持久业务后续按其业务契约继续；它不复用已到期用户 token。跨组件的预占／执行仍按各属主状态协议检查，A 不把这些事务合成一个事务。

| 并发顺序 | A 档的固定预期 |
| --- | --- |
| `R_auth → A` | 若本次请求失去全部适用资格，拒绝；另一份仍合法的完整授予可按同一求值语义接受 |
| `A → R_auth → B` | 普通撤权不追溯取消该限定 A；仅在激活期限、意图及当前业务控制合格时允许 B |
| `Check → R_auth → 申请 A` | 旧 Check 不作许可，申请 A 必须按撤销后事实重验 |
| `A → 新修订／业务冻结 → B` | 内容或当前业务控制不合格则拒绝，不借旧接受改新内容 |
| `P → 撤权／资格到期 → 申请 A` | P 不构成接受依据，不通过新资格检查即拒绝 |

普通撤权之后恢复合法旧 A 不是重新接受动作；API 和审计要能辨认原接受引用。用户刷新页面或修改内容再提交是新动作，不能拿旧 A 的动作键获得旧资格。

## 代次与修订的区分

| 标识 | 用途 | 变化的影响 |
| --- | --- | --- |
| 裁决权威／恢复代次 | 表示当前受信裁决历史，正常无损重启保持；恢复／切换按协议更新，不复用 | 旧许可必须经过明确兼容或终止处置；旧写者须实际隔离，不能只改名称 |
| 安全修订及依赖域水位 | 表示已处理的授予、资格和收紧状态 | 新 A／新读取证据按最新适用视图求值；普通撤权不因此自动抹掉此前合法 A |
| 属主提交守卫代次 | B 档撤销范围的本地防旧提交依据 | 旧代次许可不能越过新守卫，重新开放也不恢复旧许可 |
| 资源／内容修订 | 表示许可对应的实际业务内容 | 不相容的新内容不能用旧 A 激活；读取同时检查安全下界 |

这些值分别携带域和语义，不能共用一个 `version` 随意比较。尤其不能让每次普通撤权都改变恢复代次，否则会与 A 档“合法先接受可限定继续”的保证矛盾。

## 许可绑定、幂等与未知结果

许可最少绑定部署与裁决权威代次、动作唯一键、业务属主／目标接口、真实与被代表主体、选定履职／委托引用、资源身份与修订、关键内容摘要、许可操作／范围、授权模型与资格证据、风险档、接受记录及激活终点。摘要采用版本化的无歧义编码，承接 I20，不用裸分隔字符串拼接。

许可是这一份持久接受的证明，不是通用 bearer 全权令牌；读取它不允许扩大操作、转移到另一资源或跨部署使用。可采用签名／MAC 或认证回读，但不能让全部业务组件持有可伪造任意接受的共用签发密钥。具体机制须符合第二份身份规格。

相同动作键与相同绑定重试返回原接受／结果，不延长激活终点；绑定不同拒绝。权威响应丢失先查原键，不换键制造第二次接受；属主事务响应丢失查权威业务状态，不重复扣减／付款。接受与业务两处状态不一致属于需要恢复的过程，不以响应先后猜事实。

未消费许可到期后，属主用同一业务事务守卫将 P 终止，迟到回执不重新激活。关闭接受记录前核对属主有权威终态／消费证据；属主不可达时保留待对账，不仅凭权威时钟到期把已经提交的 B 当失败。清理不得使旧动作键可重新执行；保存终态／墓碑或有证明的重放边界，具体保留与生命周期协议共同设计。

## B 档的提交屏障

B 档复用上述完整求值、意图与许可，另外要求参与业务属主具备本地持久提交守卫。其保证是针对目标撤销范围：撤销完成之后，旧代次下尚未建立 B 的动作不能再提交。普通收回一份授予仍按剩余合法授予重验；冻结整个主体／服务／动作域则按冻结范围关闭。

1. 权威在持久事务里关闭该范围的新 A，登记撤销操作、目标新代次和参与业务属主集合，状态为撤销处理中。登记／成员变更同样受裁决保护：新属主必须取得当前代次和关闭状态才能服务，不能遗漏后来启动的副本或组件。
2. 各业务属主在自己的数据库中，将目标范围的提交守卫推进到新代次／关闭状态。安装屏障与所有相应 B 事务访问同一冲突守卫，并持锁至事务结束：B 先持锁则先提交，安装等待；安装先完成则旧 B 被拒绝。所有写入口、重试和后台恢复都经过守卫。
3. 属主只在屏障持久提交后回执。回执覆盖该属主的全部写实例：它们共享权威守卫；分库或分区各是声明的参与者。只让一个进程刷新缓存不能代表属主完成。失联旧实例若仍能写入，必须有数据库／基础资源强制失效证据，不能把“从成员列表删掉”当隔离。
4. 权威收齐同一撤销代次、同一参与集合版本的合格回执，才持久标记 `R_commit` 完成。重复／乱序回执幂等，超时、分区或无法隔离旧写者时保持待完成并告警，不答撤销已达到 B 保证。
5. 恢复、扩容与重启先读取当前关闭状态并验证本地守卫，不允许从旧策略或旧数据库快照恢复写准入。重新开放由有权管理者以新的代次显式完成，不能自动复用旧许可。

各守卫只由自己的属主事务维护，不让组件直读／写别的组件数据库。该协议避免把一次 RPC 放在持锁的业务事务中：准备和接受在事务外，激活仅做本地守卫检查。小部署的 A 档不承担分布式屏障；需要 B 档时装配相应接受能力及属主适配，不能仅把轮询间隔改小就声称启用。

`R_commit` 之前可能已有 B 正在持锁或刚提交；其事实保留。已经建立 B 的后续是否停止，由撤销请求声明的业务冻结／取消范围另定。要求停止这些后续时，相关执行属主也要登记、实施自己的执行屏障并处理已在途外部动作，不能把用户资格撤销回执替代业务停止回执。

## 普通读取、敏感输出与缓存期限

普通有界读取使用发行者证明已完整处理相应安全变化的视图／租约：包含发行权威与代次、适用部署／能力／范围、资格和资源所需水位、权威核验时刻与终点。发行者必须具备相应裁决和完整性证据，不能给失联投影上的旧 bundle 不断重签新时间。收紧时同步关闭不合格范围的新读取证据发行；范围暂时关闭或事实未补齐时不得续发旧许可，其他已完整证明的合法范围分别判断。

一次请求取所有必要证据终点的最小值作为 `cutoff`，至少包含身份／会话状态、服务准入（适用时）、授权视图、任职／委托有效期及资源兼容要求。考虑时钟不确定性后，读取准入、字段计算及响应释放必须在该终点前；长查询不得只在开始检查一次，然后到期后仍完整发出数据。

缓存按部署、真实／被代表主体、履职／上限、动作、资源类型／修订、完整授权与模型版本、字段用途及风险 profile 隔离。推送、轮询和 HTTP 304 不独立续期：只有发行者重新证明当前完整视图合格，才能产生新终点。冷启动、时钟异常、版本倒退、恢复到旧代次或缺必要证据时不开放旧缓存。

敏感读／导出在权威读取准入点检查当前资格，并使用绑定内容／字段范围的短输出许可；后续页、输出批次及结果领取重验。普通有界读取也不得读取晚于许可支持的新内容，见下节。服务端不能用分页游标或静态导出文件延长旧授权。

分块／流式输出每批在交付前验证剩余期限，批次有最大持续时间与字节预算，不能在一次早期检查后无限流出。已经发送或用户已保存的数据不能追回；本协议的普通读取保证是新准入和服务器新增输出的边界，实际网络中已发字节到达客户端的时刻不受应用控制。

批次不能只在开始符合期限，还须在剩余窗口内完成服务器交付；做不到则中断未交付部分，不在下一轮补发。被中断的导出／下载不能标完整成功，续传重新检查资格与内容版本。已交给网络缓冲的字节属于已发数据，不能用应用取消声称追回。

要求“严格撤销完成后不再新增发送”的出口，须另外实施输出准入／在途批次屏障，关闭旧输出、收齐保护出口的停止证据才宣告其撤销保证。无法对直接存储预签名 URL 做逐请求控制时，选择有界 URL 到期路线或经受控代理读取；不能把应用撤权写成 URL 即刻逐个失效。未实现相应屏障的出口不能声明这一更强能力。

## 新内容、旧关系与兼容水位

有界陈旧授权不等于可以用旧权限读任何新内容。访问收紧与内容／owner／组织变化的流程，先取得相应安全变化的裁决引用，再在资源版本上保存最小安全水位；读取必须使用不早于该水位的合格授权视图。目录、冷层、搜索、报表和附件父记录保留该关联，不靠客户端传不传 revision 决定是否执行。

本系统内由不同调用者并发发起的内容变更，也不能只携带发起者知道的旧 revision。资源发布路径须在当前裁决域取得安全因果下界，并证明内容／范围使用的事实与之相容；收紧与发布重叠时，按已登记的资源发布／变更意图确定先后，无法证明则不发布为可读新版本。先受理安全收紧再异步补元组的路径，在补齐前保持该域关闭或拒绝新内容读取。

候选路径为：属主准备绑定修订／内容的发布意图，权威在同一裁决守卫内核对来源和变更状态、登记发布顺序并返回水位证明，属主只在对应修订提交时一并保存证明。收紧完成后才发起的发布登记不能取得收紧前水位；并发在先的发布登记可以稍后落库，属于明确记录的重叠顺序。若业务要求按物理内容提交时点也阻止这种旧发布，须采用 B 档的资源发布屏障，不能只多做一次 Check。

具体 provider 的一致性 token 只能代表自己的修订域，不作为可跨 provider 比大小的全局整数。它提供最低快照约束，不自动把权限库与业务库合成一个原子提交；替换成员需转换完整水位和语义，无法转换则受控重建／阻止切换。[SpiceDB 官方一致性说明](https://authzed.com/docs/spicedb/concepts/consistency)支持最低修订和内容关联，本项目的接受／提交屏障为额外协议。

## 到期、长连接与服务凭据撤销

时间窗沿用左闭右开：到达终点即不合格，不等待清理作业。时钟不确定性以保守边界检查，不能把时钟容忍简单加到资格终点上延长业务权限。期限与本地单调时钟的转换考虑网络耗时及误差；跨重启不能复用旧单调时间基准，无法证明时重新取证。

mTLS 连接建立证明握手时的对端凭据，不给连接中的未来请求永久准入。每请求还检查服务当前准入证据／代次，流式调用按批次重验；服务撤销进入同一收紧及所需屏障流程。证书或用户 token 过期与身份撤销分别验证，关闭连接用于加速，不作为唯一安全机制。

未知密钥、续期／取证失败、证据超期或 issuer／信任代次改变时，按声明的失败规则保护；尚在允许终点内的完整旧证据仅可用于获准的有界路径，不能绕过关键接受。签发、缓存和连接处置的测量范围覆盖所有实际实例，而不只验证第一次握手。

## 起始实验参数与可配置边界

以下是待审、待测的起始 profile，不是已有 SDK 默认值、客户容量或法规承诺。参数可按场景缩短或在获准风险范围调整，变更必须整体验证；不得把关键动作改成陈旧缓存路径来换性能。

| 参数 | 起始候选 | 验证要求 |
| --- | --- | --- |
| 普通读取权威核验后的最长旧视图窗口 `W_read` | 30 s；实验同时测 5 s 档 | 从权威完整核验起算，来源失联与重复缓存返回均不能续期 |
| 服务当前准入的本地证据窗口 `W_service` | 30 s；关键 A 仍在接受事务重验 | 已建连接也不越界；更严客户端选权威准入／屏障档 |
| 单次 A 到首次 B 的激活上限 `T_activate` | 30 s，且不晚于 P 和资格终点 | 不因重试延长；已建立 B 的持久后续不用这个期限伪造取消 |
| 有界输出批次最长时间 `D_chunk` | 5 s，且不晚于剩余 `cutoff` | 字节预算及慢客户端行为由出口声明，输出到期停止 |
| 可接受的时钟误差证据上限 `E_clock` | 1 s；超出或无法证明则保护 | 本机／多主机、时间回拨、恢复及网络耗时分别测，不把误差用作延长资格 |
| 一次等待提交屏障回执的交互预算 `T_barrier_wait` | 10 s | 到期只返回处理中／可查询，不使撤销自动完成或重新开放 |

外部来源通知／对账上界 `D_source`、证书寿命／续期、授权证据获取预算、投影追赶和属主执行期限由相应适配与业务 profile 声明，缺必要项不准入。无合格 `D_source` 的身份源只能声明“本系统得知后”的保证，不能把空值算作 0。

普通本地窗口保证以本系统 `R_auth` 为参照，旧证据不能在 R 后再次刷新为有效。端到端失效说明还分别报告外部发现延迟、内部关门点、旧视图终点和输出阶段；只报“30 秒轮询”不是保证，不能把多个期限相加后仍叫 30 秒撤权。

小部署先用一个持久接受裁决域和有界读取，测量守卫冲突、接受日志、证据刷新与输出成本；并发／变化量增大后，可细分依赖域、增加身份／策略适配及观测。扩展依据尾延迟、排队、锁等待、来源滞后和预算，结构保证不靠无限副本或 service mesh 自动获得。

## 恢复、替换与审计

接受、激活、终止、收紧与屏障回执均持久化，记录主体、动作、内容／资源修订、代次、依据和结果，不记录可重放凭据。审计可靠保存继续由 I29 对应协议承担，不能因有这些记录就宣布长期审计闭环。

恢复先封闭业务准入，核对备份之后的撤销、安全事件、源事实、接受／消费记录和现存业务事实，使用不会重用的恢复／签发代次隔离旧实例及许可；补齐之前不服务。不能仅在旧库中把版本加一就证明它比所有外部旧证据更新；需要独立可信恢复控制和当前安全状态。

切换 IAM／Authz 或关系 provider 时保留稳定主体、作用域和历史依据，关闭旧接受者、登记新代次、核对在途许可与屏障状态。旧 A 要么在明确兼容窗口内继续限定激活，要么可靠终止并查询结果；不能静默失去它，也不能换个签名再给新权限。旧 B 与外部执行事实按业务恢复／更正处理。

接受事务、失效代次、参与者登记及属主守卫的线结构、DDL／锁隔离、错误、证明格式和兼容版本仍须下一阶段确定；本页不声称协议已可运行。旧 P6 的无限 fail-static、落后列表只标 stale、IAM 事件／轮询停止时间和旧 token 资格规则要按这些保证调整，不能以增加一个时间字段掩盖语义变化。

## 独立验收预期

下表是后续向量与故障测试的要求，尚未执行 SDK／数据库／broker 或真实网络验收。每条有合法正例、明确拒绝／未知及业务副作用断言。

| 编号 | 场景 | 固定预期 |
| --- | --- | --- |
| AT01 | Check 成功后撤权，再请求 A | Check 不产生许可；缺剩余完整资格时 A 拒绝 |
| AT02 | A、撤销、B 的全部先后排列 | 按同域串行裁决；A 在先的普通限定许可可激活，撤销在先不能借旧资格新接受 |
| AT03 | 仅有 P／草稿，用户离职／任职失效 | 不启动系统后续，申请 A 重验后拒绝不合格请求 |
| AT04 | A 后字段、金额、owner 或资源修订变化 | 旧许可不激活新内容；合法相同意图正例只执行一次 |
| AT05 | A 后业务冻结、期间锁或审批依据失效 | B 检查当前业务守卫，不因旧授权接受跳过 |
| AT06 | 接受响应丢失、同键不同摘要、迟到旧回执 | 同键查询恢复，不扩权、不续期、不重复接受；冲突拒绝 |
| AT07 | B 已提交但结果未回报，权威认为许可已到期 | 查询属主事实恢复，不误报失败或再次执行；未达终态不清理证据 |
| AT08 | 激活期限与资格终点的边界及时间误差 | 最小终点保守检查，到期不激活；不能依靠清理才失效 |
| AT09 | B 档提交与本地屏障安装并发 | 提交先取得守卫则在屏障完成前提交，屏障先完成则旧 B 拒绝 |
| AT10 | 一个属主失联／旧实例仍可写，重复／乱序屏障回执 | 撤销保持处理中；不能因部分回执或删成员宣告 `R_commit` |
| AT11 | 撤销期间新增组件、扩容、属主分库或重启 | 登记闭包和当前代次合格前不准入，不遗漏新的写者 |
| AT12 | 窗口内／外旧视图，重复 304／缓存返回、冷启动 | 合格窗口内允许的读取可用，越界停止；无权威重新证明不续期 |
| AT13 | 查询开始合格，释放响应或下个流式批次时到期 | 停止未交付数据，不把早期检查扩成无限输出许可 |
| AT14 | 新权限视图配旧 owner；旧权限配撤销后新内容／附件 | 必要水位与事实不相容时拒绝／追赶，不靠客户端 revision 或 stale 标头放宽 |
| AT15 | 外部 IdP 停用未通知、同步心跳停止、本系统收紧中崩溃 | 区分外部发现与内部保证；证据不合格保护，收紧未完成不自动重开 |
| AT16 | 已建 mTLS 连接遇服务撤销／证据到期、仍继续发请求 | 每请求／批次准入生效，握手缓存不能永久放行 |
| AT17 | 用户导出排队后撤权、结果文件领取；旧预签名 URL | 用户路径重验；URL 按真实有限窗口或代理能力处理，不承诺即时追回 |
| AT18 | 普通用户撤权但 B 已成立；另发明确业务取消／安全冻结 | 必要限定后续和当前服务／业务控制分别判断，不混同撤权与已执行事实回滚 |
| AT19 | 恢复到撤销前备份，旧许可／证书仍持有，旧实例迟到 | 封闭恢复、补当前安全事实和新代次；不使旧许可重新激活 |
| AT20 | provider／模型切换，旧接受和水位不可直接比较 | 受控转换、兼容处置或阻止切换，不用版本数字碰巧更大放行 |
| AT21 | 撤销一份任职授予，其他完整授予仍合法且必要事实完整 | 只撤声明范围，仍合法资格按第一份模型判断；关闭／未补齐域不伪称已证明，冻结主体的正例另测 |
| AT22 | 过载、锁等待、来源滞后、证据刷新风暴与外壳争用 | 预算内恢复或保护，监控实际窗口；超时不自动完成屏障或降低风险档 |

I19 的接受／撤销分支和 C10 有了机制候选，不标已解决。冻结条件包括动作分档、接受／意图 schema、资格变化与内容发布的因果协议、B 档登记／守卫、默认参数评审和真实反例验证。管理／任职已有[第四份候选](04-authorization-administration-and-appointments.md)，其变更承接本页收紧协议；后续工作和未完细节见[接续清单](../work/04-next-steps.md)。

本轮运行[最小时间模型](../work/checks/07-authorization-time-models.py)：构造 Check 后撤销仍提交的反例，枚举 6 种接受顺序和 4 种提交屏障顺序，核对证据不因旧缓存重取续期、新内容最低水位及恢复代次。模型把守卫原子性、完整参与者集合和权威取证当作前提；不证明真实系统具备这些前提，不计作 AT／PA 向量执行通过。

## 依据与独立判断

知识库 D11、ReBAC 的一致性／双写章节是中立参考；其中按请求现查的时效不能直接推导跨库业务提交的时效。本项目因此分别定义 A、B 和撤销完成，不将某个 provider 的一致性选项当作跨组件原子性。

[Zanzibar 论文](https://research.google/pubs/zanzibar-googles-consistent-global-authorization-system/)与前述 SpiceDB 说明用于核对内容和授权的因果联系；[PostgreSQL 显式锁文档](https://www.postgresql.org/docs/18/explicit-locking.html)用于核对冲突守卫的事务结束边界。本页的分档、接受日志、属主提交屏障和恢复代次是项目候选设计，不声称这些来源已经替本项目证明正确。
