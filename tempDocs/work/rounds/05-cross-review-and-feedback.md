## 整体判断与业务链核对

没有发现必须推翻整体方向的新冲突。独立组件与部署合并、唯一业务权威、身份／授权分工、按能力选配和客户精确组合仍合理；拆分带来的协调与维护代价已明示。但这仍是推荐与已定方向构成的基线，关键协议未定和运行未验不因本次复审消失。

| 核对链 | 当前文档是否一致 | 接续工作与限制 |
| --- | --- | --- |
| 服务销售／实物销售 → 最小组合 | 服务销售可以不装库存；所选实物流程缺库存须阻止。当前实现仍强依赖库存，文档已说明 | 能力／条件、元数据、错误与旧订单切换由业务／be-ops 定义；未证明 BrickKit 缺条件依赖是 bug |
| 主体／任职 → 授予 → 列表／字段／任务 | 伙伴、组织、员工与 IAM 分工；完整授予不拆维度，当前授权覆盖查询与领取；已确认后续另分类 | 主体映射、有限表达、接受／撤销屏障和内部凭据仍待正式协议；不是换 provider 即自动成立 |
| 订单修订 → 库存／信用预占 → 确认／取消 | 各分支原子裁决，确认占用不按暂存 TTL 偷偷释放，部分／未知不报整单已确认；审批等待不延长预占 | 稳定分支身份、输入／策略绑定、取消／执行许可、最终消耗及人工恢复待 API／DDL 和时序验证 |
| 数量 → 成本 → 财务／关账 | 增量事实逐份处理，来源完整范围与关账批次／屏障明确；三者分别拥有事实 | 真实源覆盖、迟到政策与期间入口裁决待定；MQ 保留或最大版本不能证明完整性 |

| 同版单跑 → 外壳 → 独立数据目标 | 真实 HTTP／gRPC 保留；共同池只用于相同目标，独立目标先单跑或待验多池；共享信任／资源风险明示 | 真实成员、SDK／端口等价、总预算及停止／拆回待验；外壳不提供跨组件事务 |
| 多渠道／法人实现／前端 → 路由与副作用 | 多选、范围内权威、协作和模型组合分别标注；外部未知不盲切渠道 | 实际路由／身份／回调、跨法人汇总和入口兼容待规格，不把所有关系变成全局互斥 |
| 替换／Fork／升级 → 历史退出／恢复 | 候选与实际生效分开，目标新事实不能简单回旧地址；旧历史和在途须承接，受限维护继续 | 组合准入、旧执行者隔离及具体迁移／支持期待定；单纯 CLI 操作不替代业务验收 |

## BrickKit 是否需要反馈

核对本地提交 `6085c375640c19b72ea07cf29c62ef23d0c4c38e` 的中文入口、组件设计推荐、外壳开发、配置地址及相应注入／外壳代码。本轮未找到新的已证实平台问题，不提交 BrickKit issue／PR，也不据此宣称整个平台已验收。

- 族地址通过项目配置绑定、数据／权限能力准入归本项目，平台不理解授权模型或业务条件是明确边界。
- 外壳 JSON 携带成员 `extraPorts`，注入代码将成员 gRPC 地址指向外壳并保留端口；相关实际测试通过。成员／SDK 仍需真实监听，不把该测试称为 gRPC 业务往返通过。
- 组件设计页是推荐，DDD／算法拆分与依赖绑定的取舍可按项目约束调整。项目已有受控适配／Fork 路径，不将指南措辞不同自动当作功能故障。
- 外壳文档推荐每成员自己的数据库池；本项目共池是另一个有条件的 SDK 选择，已承担目标一致、角色／事务局部设置、总预算与公平控制责任。它不是平台提供的数据库隔离保证。
- 配置类型／范围、生效、新旧业务切换及运行恢复由组件／SDK／装配工具与运维协议负责；三层文件操作原子不等于外部业务切换原子。未来实际机制无法表达所需组合时，再提供精确版本与最小复现。
