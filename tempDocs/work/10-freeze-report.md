| 规模与时长 | 对齐时全量重新取回（万到十万行）的耗时与探测量；新授权成员建立水位的时长；收紧路径多出的两段写延迟；外壳中可选边造成的启动等待 |
| 恢复与消息 | 整套恢复后带旧纪元位置的补发行与消费者的配合；JetStream 与 PostgreSQL 队列两个适配器在消费者库回退后的补发与持久消费者重置；RustFS 等对象存储对版本保留的支持；计划内切换使非幂等工作项转暂停的运维成本 |
| 卡片的细节 | 采购与报销带项目参考时需要同步查询项目，卡片写“只经事件”；可选的流程引擎向业务组件报完成是事件还是调用；现场打印的打印队列属主；伙伴卡没有列出营销同意；客户组合表里没有 `ana/bi`（随重建计划确定）；预算在没有财务时的维度来源 |

## 八、建议的首批实现范围

冻结前检查建议给几项重机制标出“首批实现”还是“只保留形状”，避免三种 SDK 一开始就全量实现。只保留形状指：契约、字段、状态与预期都保留，实现时先返回“能力不支持”或走最简路径，不影响以后补上。

| 机制 | 建议 | 理由 |
| --- | --- | --- |
| 本地事务、发件表与收件表、增量事实（纪元，序号）、后台工作项 | 首批实现 | 一切的基础 |
| 授权：有界本地授权（默认路径）、生效点、安全处置、受保护操作、管理员恢复 | 首批实现 | 安全的底线 |
| 授权的严格路径（持久接受与提交屏障，D57） | 只保留形状 | 客户选用才需要；默认路径已满足撤权上界 |
| 内部来源的水位、补取与对齐（`aligned`、`aligning`、`stalled`、`blocked`） | 首批实现 | 授权判断依赖它 |
| 影子投影 | 只保留形状 | 首批的重建可以走新增投影的对齐，代价是重建期间该投影的判断无法证明 |
| 授权成员与身份成员的切换（安全 10、11） | 只保留形状 | 首批只有一个授权成员与一个身份成员；预检与导出接口留位 |
| 高可用 | 只保留形状 | D66 |
| 整套恢复：证据存储、运行档案、恢复工具的十步、证据重放、外部对账 | 首批实现 | 恢复做不到，其他保证都不成立；告警渠道的签名核验一并实现 |
| 事件签名 | 只保留形状 | 基础机制未定义（第六节） |
| 冷热分层（协议 11） | 首批只做在线层与目录 | 封存历史在数据量上来后再做 |
| 三种语言的 SDK | Go 先做完整实现；Python 与 TypeScript 先实现代表组件用到的子集，共用语义向量与一致性套件 | 工作量；语言中立的协议与一致性测试保证以后补齐时行为一致 |

最后一行与“三个官方实现”的目标有关，需要你确认。
